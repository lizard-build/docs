# CLI Reference

The `lizard` CLI is the primary interface to the platform. This page covers installation, global flags, exit codes, and runtime discovery. Every command has its own reference page in the sidebar — see [`lizard up`](/cli/up), [`lizard service`](/cli/service), [`lizard secrets`](/cli/secrets), and the rest.

> Reference written for Lizard CLI **v4.0.34**. Run `lizard <cmd> --help --json` for the exact, version-matched schema of any command.

## Install & upgrade

```bash
curl -fsSL https://lizard.build/install.sh | bash   # macOS and Linux
lizard --version
lizard upgrade            # update to the latest version
lizard upgrade --check    # check without installing
```

On Windows, run `irm https://lizard.build/api/cli/install.ps1 | iex` in PowerShell. With Node.js you can install from npm instead: `npm install -g @lizard-build/cli`.

On macOS and Linux, the binary from the install script also updates itself in the background, at most once every 6 hours. It skips the check when `CI` or `LIZARD_NO_UPDATE=1` is set. The Windows binary does not update itself: run the installer again. An npm install updates through npm: `lizard upgrade` prints the command.

Always use the globally installed `lizard` binary — **not** `npx`. See [Quickstart](/getting-started#1-install-the-cli) for permission-error fixes.

## Authentication

```bash
lizard login                  # browser OAuth
lizard login --token liz_xxx  # API key auth
lizard logout
lizard whoami                 # current user, workspace, linked project
```

API keys start with `liz_`. Create one with [`lizard keys create <name>`](/cli/keys). In CI, set `LIZARD_TOKEN` (or `LIZARD_API_KEY`) in the environment instead of running `login`.

## Global flags

| Flag | Description |
|------|-------------|
| `-V, --version` | Print the CLI version |
| `--json` | Machine-readable output. Combine with `--help` to dump a command's schema |

Most commands also accept `-p, --project` and `-s, --service` to target a specific resource instead of the linked one. `init`, `link`, and `project` also take `-w, --workspace`. `lizard add` always uses the linked project.

## Exit codes

| Code | Meaning | What to do |
|------|---------|------------|
| `0` | success | continue |
| `1` | generic error | read the message |
| `2` | auth (401/403) | run `lizard login` |
| `3` | not found (404) | check the name with `lizard ps` / `lizard project list` |
| `4` | timeout (408/504) | retry |
| `5` | cancelled by user | stop |

## Runtime discovery

The CLI is self-documenting. To see the full command tree, global flags, and exit codes:

```bash
lizard --help --json
```

For any command or subcommand's exact arguments and options:

```bash
lizard <cmd> --help --json
lizard <cmd> <sub> --help --json     # e.g. lizard service set --help --json
```

This always reflects your installed version — prefer it over guessing flag shapes. It is also how an agent learns the CLI without being trained on it: see [deploying from Claude Code](https://lizard.build/blog/deploy-from-claude-code).

## Configuration & state

- The CLI stores auth and the current directory's project link in `~/.lizard/config.json`.
- `lizard status` shows the cwd's workspace/project/service link (no auth required).
- `lizard config apply` applies a `lizard-config.json` file to a project (use `--dry-run` to preview).

## Environment variables

| Variable | Effect |
|----------|--------|
| `LIZARD_TOKEN` | API key or token to use instead of the stored login |
| `LIZARD_API_KEY` | Same as `LIZARD_TOKEN` |
| `LIZARD_API_URL` | API base URL (default `https://lizard.build`) |
| `LIZARD_HOME` | Keep CLI state in `$LIZARD_HOME/.lizard` instead of `~/.lizard` |
| `LIZARD_NO_UPDATE` | Turn off background self-update |
| `CI` | Also turns off background self-update |
| `LIZARD_SKILLS_DIR` | Read skills from this directory instead of the ones built into the CLI |

## Sandbox volumes

Use names to manage [Persistent Volumes](/sandboxes/volumes) within a project. Full reference: [`lizard volume`](/cli/volume) and [`lizard sandbox`](/cli/sandbox).

```bash
lizard volume create agent-workdir --size 10 --project proj_123
lizard volume list --project proj_123
lizard volume resize agent-workdir --size 20 --project proj_123
lizard sandbox create --volume agent-workdir --project proj_123
```

Names are unique per project: lowercase letters, digits and dashes, starting and ending with a letter or digit, up to 64 characters. New volumes allow whole GB from 1 to 50, default 5. The CLI reads the server's current limits before creating a volume, so it follows config changes. Existing larger volumes keep their size.

After detaching a volume, `lizard volume rm agent-workdir --project proj_123` deletes it and its data. `volume list` shows names; `--json` includes generated IDs.
