# lizard sandbox

Create and manage [Sandboxes](/sandboxes) from the terminal. Alias: `lizard sb`.

## Usage

```bash
lizard sandbox create [flags]
lizard sandbox list [flags]
lizard sandbox exec <id> -- <command>
lizard sandbox ssh <id>
lizard sandbox fork <id> [flags]
lizard sandbox rm <id> [flags]
```

Every sandbox belongs to a project: the one you pass with `-p`, else the one linked to the current directory, else your account's default project (the oldest project in your personal workspace).

## Subcommands

### `lizard sandbox create`

Create a sandbox and print its ID.

| Flag | Description |
|------|-------------|
| `-t, --template <name>` | Template (default `base`). Enabled templates: `base`, `interpreter`, `codex`, `desktop`, `desktop-camoufox` (US East only), `opencode`, `pi`, `prime`, `claude`. The server checks the region's list |
| `-s, --size <size>` | `small`, `medium` (default; `small` during the trial), or `large` |
| `--timeout <ms>` | Lifetime in milliseconds (default `300000`, five minutes); `0` disables expiration |
| `--region <code>` | Region to create the sandbox in |
| `--snapshot <id>` | Start from a saved snapshot; can't be combined with `--size` |
| `--volume <name-or-id>` | Attach a [Persistent Volume](/cli/volume) |
| `--with-token [key]` | Sign in `lizard` inside the sandbox with a new key limited to the sandbox's project and deleted with the sandbox. The `liz_` key you pass, or without a value the `liz_` key you run with, only authorizes the request; a browser login has none. The `base` template has no `lizard` |
| `-p, --project <id>` | Project (defaults to the linked one, else your default project) |

Lizard bills each size per second at a flat rate while it runs, including idle time. The price includes local disk and [2 TB of egress per account over a rolling 30 days](/platform/limits#sandbox-egress). A successful pause stops compute charges; storage in Persistent Volumes continues at the [volume rate](/cli/volume), whether attached or detached.

| Size | vCPU | Memory | Disk | Price |
|------|------|--------|------|-------|
| `small` | 2 | 4 GiB | 5 GB | $0.0162/h |
| `medium` | 4 | 8 GiB | 20 GB | $0.0324/h |
| `large` | 8 | 16 GiB | 50 GB | $0.0648/h |

Anything in the sandbox can read the key that `--with-token` installs and use it on the sandbox's project until the sandbox is deleted.

Until your trial or plan starts, `create` returns HTTP 402 with a Checkout link; run `lizard billing start`. Limits count the vCPU of running sandboxes: 8 during the trial, 40 on Pro after the first paid invoice, 220 on the $99 plan and 1,200 on the $499 plan. Paused sandboxes don't count. During the trial, a sandbox must be `small` and in a US region, so up to 4 run at once. `medium` or `large` returns HTTP 403 with `TRIAL_SANDBOX_SIZE`, and another region returns HTTP 403 with `TRIAL_SANDBOX_REGION`. Resuming or forking a Large sandbox, or restoring one from a snapshot, returns HTTP 403 with `SANDBOX_SIZE_NOT_ALLOWED`. Over the vCPU limit, `create` returns HTTP 429 with `SANDBOX_LIMIT_REACHED`. See [Limits](/platform/limits#sandbox-account-limits).

### `lizard sandbox list`

List sandboxes in the linked project (alias `ls`).

| Flag | Description |
|------|-------------|
| `-p, --project <id>` | List this project instead |
| `--all` | List every sandbox across all your workspaces |

### `lizard sandbox rm <id>`

Delete a sandbox (aliases `delete` and `kill`).

| Flag | Description |
|------|-------------|
| `-y, --yes` | Skip confirmation |

### `lizard sandbox timeout <id> <ms>`

Set a new lifetime, counted from now, in milliseconds (at least `1000`). It is not an idle timer: running commands does not reset it.

### `lizard sandbox exec <id> -- <command>`

Run one command inside the sandbox through `sh -c`, stream its output, and exit with its exit code.

<span id="sandbox-ssh" />

### `lizard sandbox ssh <id>`

Open an interactive shell in a running sandbox (alias `shell`). It uses your Lizard login, so there are no SSH keys to set up; a scoped API key reaches only sandboxes in its scope. Ctrl-C, arrows, and tab completion go to the sandbox. Type `exit` or press Ctrl-D to leave.

It needs an interactive terminal; in a script, use `lizard sandbox exec`. It is not the SSH protocol, so SSH clients, `scp`, and port forwarding don't work.

### `lizard sandbox expose <id> <port>`

Give a port in the sandbox an HTTPS URL. The port is private: requests need the sandbox's access token, either in the `X-Lizard-Access-Token` header or as the `lizard_token` query parameter that the printed URL already carries. Requests without it get HTTP 401. With `--json`, the result also has `hostname` and `accessToken`.

`lizard sandbox unexpose <id> <port>` removes the URL.

### `lizard sandbox desktop <id>`

Start the graphical desktop of a sandbox created with `-t desktop` and print its browser URL and a view-only URL. Treat both links like passwords.

| Flag | Description |
|------|-------------|
| `--view-only` | Print or open only the view-only URL |
| `--resolution <WxH>` | Screen size, from 640x480 to 3840x2160 |
| `--open` | Open the desktop in your browser |
| `--status` | Show the desktop's state and URLs without starting it |
| `--stop` | Stop the desktop and remove its URL |

<span id="sandbox-vnc" />

### `lizard sandbox vnc <id>`

Connect a VNC app (macOS Screen Sharing, TigerVNC, RealVNC) to the desktop of a sandbox created with `-t desktop`. The desktop has no public VNC port, so the CLI listens on `localhost` and carries each connection to the sandbox over a secure WebSocket. It starts the desktop if needed, prints the address and the VNC password, and runs until Ctrl-C.

| Flag | Description |
|------|-------------|
| `--port <port>` | Local port (default `5900`; if it's taken, the next free one) |
| `--view-only` | Use the view-only password: watch, no control |
| `--open` | Open the address in your VNC app (`vnc://`, Screen Sharing on macOS) |

### Pause, resume, and snapshots

| Command | What it does |
|---------|--------------|
| `lizard sandbox pause <id>` | Save the sandbox's memory and processes, then pause it. A successful pause stops compute charges; Persistent Volumes storage is billed separately |
| `lizard sandbox pause <id> --fast` | Pause in about a second, keeping files only: memory is not saved, running processes end, and `resume` boots the sandbox fresh with its files |
| `lizard sandbox resume <id>` | Start a paused sandbox again with its saved memory and files |
| `lizard sandbox snapshot <id> --name <name>` | Save a running sandbox, memory and files included, as a snapshot that belongs to you. `--scope` sets where it can be restored: `workspace` (the default) for any project in the sandbox's workspace, `user` for any project in any of your workspaces, `project` for its own project only |
| `lizard sandbox restore <snapshot-id>` | Start a new sandbox from a snapshot, in the snapshot's region. `-p <project>` picks the project (default: the volume's project, else the snapshot's own), `--volume <name-or-id>` mounts a volume at `/workspace`, `--timeout <ms>` sets the lifetime (default `300000`) |
| `lizard sandbox snapshots` | List the snapshots taken in the project (`-p` for another project, `--mine` for every snapshot you took) |
| `lizard sandbox snapshot-scope <snapshot-id> <scope>` | Change where a snapshot you took can be restored: `user`, `workspace`, or `project` |
| `lizard sandbox snapshot-rm <snapshot-id>` | Delete a snapshot (alias `snapshot-delete`, `-y` skips confirmation) |

`pause`, `resume`, and `snapshot` wait until the work is done; pass `--no-wait` to return once it is queued. See [Pause, resume, and snapshots](/sandboxes/quickstart#pause-and-resume) for what each step keeps.

A snapshot of a sandbox with a volume attached includes a copy of the volume's files as they were at capture. Every restore gets that copy and cannot take `--volume`, and anyone who can restore the snapshot can read those files. `--volume` works only with a snapshot of a sandbox that had no volume, and the volume must be in the snapshot's region.

<span id="sandbox-fork" />

### `lizard sandbox fork <id>`

Start live copies of a running sandbox. Lizard pauses the sandbox for a moment, captures its memory, processes, and files once, and boots every copy from that capture. The source keeps running with the same ID and lifetime. Prepare one sandbox (tools installed, app loaded), then fork it to spread work across copies without repeating the setup.

| Flag | Description |
|------|-------------|
| `-n, --count <n>` | Copies to start, from 1 to 100 (default `1`) |
| `--timeout <ms>` | Lifetime of each copy, at least `1000`; default: the source's lifetime |

Each copy is a sandbox start: it counts toward the [running and start limits](/platform/limits#sandbox-account-limits), runs at the source's size, and is billed at that size. With `--json` the output has one entry per copy, `{"sandbox": {...}}` or `{"error": "..."}`. If any copy could not start, the command exits `1`, and the copies that did start keep running until you delete them. You can't fork a paused sandbox or one with a volume attached (HTTP 409).

### `lizard sandbox files`

| Command | What it does |
|---------|--------------|
| `lizard sandbox files ls <id> [path]` | List a directory (default `/`) |
| `lizard sandbox files cat <id> <path>` | Print a file |
| `lizard sandbox files put <id> <local> <remote>` | Upload a local file |
| `lizard sandbox files get <id> <remote> <local>` | Download a file |
| `lizard sandbox files rm <id> <path>` | Delete a file or directory |

### Coding agents

Run a coding agent inside a sandbox on your own credentials. Connect them first with [`lizard agents`](/cli/agents). Create the sandbox from an agent template (`codex`, `claude`, `opencode`, `pi`, or `prime`); the `base` template has no Node.js and can't run agents.

`lizard sandbox prompt <id> <prompt...>` sends a prompt and streams what the agent does.

| Flag | Description |
|------|-------------|
| `--agent <name>` | `codex` (default), `claude`, `pi`, `opencode`, or `prime` |
| `-c, --conversation <id>` | Continue this conversation |
| `--new` | Start a new conversation |
| `-m, --model <model>` | Model to use |
| `--effort <level>` | Reasoning effort: `minimal`, `low`, `medium`, `high`, or `xhigh` |
| `--cwd <dir>` | Working directory in the sandbox (default `/workspace`) |
| `-v, --verbose` | Also print command output |
| `--no-wait` | Return once the prompt is accepted |

Ctrl-C stops watching; the agent keeps working. `lizard sandbox interrupt <id> [-c <conversation>]` stops its running turn. `lizard sandbox conversations <id>` lists the conversations, newest first.

## Examples

### Create a sandbox and run a command

```bash
lizard sandbox create --size small --timeout 600000
lizard sandbox exec genuine-toddler-jasj -- python3 -c "print(1 + 1)"
```

### Open a shell

```bash
lizard sandbox ssh genuine-toddler-jasj
```

### Attach a Persistent Volume

```bash
lizard volume create agent-workdir --size 10
lizard sandbox create --volume agent-workdir
```

### Serve a port

```bash
lizard sandbox exec genuine-toddler-jasj -- sh -c "nohup python3 -m http.server 3000 --bind 0.0.0.0 >/tmp/http.log 2>&1 &"
lizard sandbox expose genuine-toddler-jasj 3000
```

### Use a desktop from a VNC app

```bash
lizard sandbox create -t desktop
lizard sandbox vnc genuine-toddler-jasj --open
```

### Run Codex in a sandbox

```bash
lizard agents login chatgpt
lizard sandbox create -t codex
lizard sandbox prompt genuine-toddler-jasj "add a health check endpoint and test it"
```

### Save and restore a sandbox

```bash
lizard sandbox snapshot genuine-toddler-jasj --name my-app
lizard sandbox snapshots --mine                     # find the snapshot ID
lizard sandbox restore <snapshot-id> -p other-project
```

### Fork a prepared sandbox

```bash
lizard sandbox fork genuine-toddler-jasj -n 8 --json   # 8 copies with the same memory and files
lizard sandbox rm <copy-id>                            # delete a copy when its work is done
```
