# lizard add

Add a database, service, or repo to the project.

## Usage

```bash
lizard add [types...] [flags]
```

`add` works on the project linked to the current directory. Run [`lizard init`](/cli/init) or [`lizard link`](/cli/link) first.

## Flags

| Flag | Description |
|------|-------------|
| `-r, --repo <owner/repo>` | Create a service from a GitHub repo |
| `-s, --service <name>` | Create an empty service |
| `-a, --addon <type...>` | Add managed addons (`postgres` / `redis` / `s3`) |
| `-n, --name <name>` | Name used in `${{name.KEY}}` refs |
| `-v, --variables <K=V>` | Seed an env var (repeatable) |
| `--region <code>` | Region to provision in (default `us-east-1`) |
| `--no-deploy` | Attach repo but skip the first build |
| `--list` | Show available database types |

## Examples

### Create a service from a GitHub repo

```bash
lizard add -r your-org/your-app
```

This creates a `github`-source service and starts the first build, which clones the repo and auto-detects the stack. The command returns once the service exists; follow the build with `lizard logs --build`.

### Provision addons

```bash
lizard add postgres            # one addon
lizard add postgres redis s3   # several at once
lizard add --list              # show available types
```

### Create an empty service

```bash
lizard add -s worker
```

### Name a service and seed variables

```bash
lizard add -r your-org/monorepo -n api -v NODE_ENV=production -v LOG_LEVEL=info
```
