# lizard up

Upload the current directory and deploy it.

## Usage

```bash
lizard up [path] [flags]
```

`up` packages your working tree (or `path`) as a tarball, sends it to the build nodes, and deploys it. It forces `sourceType=upload` on the target service, streams build logs over SSE, and prints the live URL when finished.

If the current directory isn't linked to a project yet, `up` runs `init` first. On a TTY that's interactive; in a non-TTY (CI) environment it will **not** silently create a project — it errors and asks you to run `lizard init --name <project>` (or pass `--project <project>` to `up`), to guard against a typo spawning an empty project.

## Flags

| Flag | Description |
|------|-------------|
| `-s, --service <name>` | Target an existing service |
| `-p, --project <id>` | Project name, slug, or ID |
| `--build-command <cmd>` | Override the build command |
| `--start-command <cmd>` | Override the start command |
| `--pre-deploy-command <cmd>` | Run before the start command each time a container starts (every replica, every restart). Needs a start command; make it safe to run many times |
| `--port <number>` | Container port (`0` = worker mode). New services default to `3000` unless a Dockerfile `EXPOSE` sets it |
| `--region <code>` | Region for a new service; ignored for an existing one |
| `-d, --detach` | Start the deploy and exit without streaming logs |
| `-c, --ci` | Stream build logs only and exit when the build ends |
| `--no-gitignore` | Upload everything, ignoring `.gitignore` |

## Subcommands

### `lizard up status <app-id>`

Show a service's status, URL, and latest build status. Pass the service ID that `up --detach` prints.

## Examples

### Deploy the current directory

```bash
lizard up
```

### Deploy to a specific service with a custom start command and port

Create the named service with `lizard add --service api` first if it does not exist.

```bash
lizard up --service api --start-command "node server.js" --port 8080
```

### Deploy headlessly in CI

```bash
export LIZARD_TOKEN=liz_xxx
lizard init --name my-project
lizard add --service api
lizard up --ci --service api
```

Skip `lizard add` when the service already exists. A failed build or deploy exits with code `1`. With `--ci`, the exit code covers the build only, so check `lizard ps --json` before you mark the release done. `--detach` exits `0` once the upload is accepted. See [framework setup](/framework-guides#prepare-the-project).
