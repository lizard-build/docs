# lizard domain

Show the current domain, or attach a custom one.

## Usage

```bash
lizard domain [hostname] [flags]
```

The hostname is a positional argument — there is no `add` subcommand. Running `lizard domain` with no arguments shows the service's current domain, or generates one if it has none. Alias: `lizard domains`.

## Flags

| Flag | Description |
|------|-------------|
| `-s, --service <name>` | Service |
| `-p, --project <id>` | Project name, slug, or ID |
| `--port <n>` | Port to expose |
| `-f, --force` | Move the domain here if it's attached to another of your services |

The subcommands use the same `-s` and `-p` flags. Verify and delete a domain on the service you attached it to.

## Subcommands

### `lizard domain generate`

Generate a fresh `*.onlizard.com` subdomain.

### `lizard domain verify <hostname>`

Check the TXT record and activate the domain. TLS is provisioned automatically.

### `lizard domain delete <hostname>`

Remove a domain (alias `rm`).

| Flag | Description |
|------|-------------|
| `-y, --yes` | Skip confirmation |

## Examples

### Show the current domain

```bash
lizard domain
```

### Generate a subdomain

```bash
lizard domain generate
```

### Attach a custom domain

```bash
lizard domain app.example.com --service web
```

Lizard returns the DNS records to create: a `CNAME` for the hostname and, unless you already verified the domain, a `TXT` record at `_lizard-verify.<apex domain>` (for `app.example.com`, that is `_lizard-verify.example.com`). Add them at your DNS provider, then verify on the same service:

```bash
lizard domain verify app.example.com --service web
```

### Attach a domain to a specific port

```bash
lizard domain app.example.com --service web --port 8080
```

### Move a domain from another of your services

```bash
lizard domain app.example.com --service web --force
```

### Remove a domain

```bash
lizard domain delete app.example.com --service web
lizard domain rm app.example.com --service web --yes
```
