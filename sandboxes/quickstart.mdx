## Install and authenticate

Install the Lizard SDK and create an API key in Settings → API keys. Store it in `LIZARD_API_KEY`. Each sandbox needs a project: pass `projectId` (Python: `project_id`) or resolve an ID, slug, or name with `project`.

```sh
npm install @lizard-build/sdk
pip install lizard-sdk
export LIZARD_API_KEY="<your-api-key>"
```

## Run a command

```ts
import { Sandbox } from '@lizard-build/sdk';

const sandbox = await Sandbox.create('interpreter', {
  projectId: 'proj_123', timeoutMs: 300_000,
});
try {
  const result = await sandbox.process.exec("python -c 'print(2 ** 10)'");
  console.log(result.stdout, result.stderr, result.exitCode);
} finally {
  await sandbox.kill();
}
```

```python
from lizard import Sandbox

sandbox = Sandbox.create("interpreter", project_id="proj_123", timeout_ms=300_000)
try:
    result = sandbox.process.exec_("python -c 'print(2 ** 10)'")
    print(result.stdout, result.stderr, result.exit_code)
finally:
    sandbox.kill()
```

## Files

Use `fs.write` for text or bytes and `fs.read` for text. For binary files, write bytes and read them back with `fs.readBytes` (Python: `read_bytes`).

Files and running processes remain available while the sandbox runs. After it stops, only files written to an attached Persistent Volume at `/workspace` can be reused by a later sandbox. Without a volume, `/workspace` is temporary. Each volume attaches to one sandbox at a time and uses node-local storage; export files that must survive node loss.

```ts
await sandbox.fs.write("/tmp/task.py", "print(42)\n");
const result = await sandbox.process.exec("python /tmp/task.py");
console.log(result.stdout);
```

## Public ports

Start a server that listens on `0.0.0.0`, then call `exposePort(port)` (Python: `expose_port`). It returns `url`, `hostname`, and `accessToken`. The port is private: open `url` in a browser (it carries `?lizard_token=`), or send the token in the `X-Lizard-Access-Token` header. Requests without the token get 401. A stopped sandbox no longer serves the port.

```ts
await sandbox.process.exec(
  "nohup python -m http.server 3000 --bind 0.0.0.0 --directory /tmp >/tmp/http.log 2>&1 </dev/null &",
);
const { url, hostname, accessToken } = await sandbox.exposePort(3000);
console.log(url); // open in a browser
const res = await fetch(`https://${hostname}/`, {
  headers: { 'X-Lizard-Access-Token': accessToken },
});
```

## Reconnect to a running sandbox

Create a sandbox, run commands, then call `kill`. `connect` attaches to an existing sandbox without changing its state, so it does not resume a paused or stopped sandbox. Pause, resume, snapshot, and restore are available; see [Pause, resume, and snapshots](/sandboxes/quickstart#pause-and-resume). `fork` copies a running sandbox, memory and processes included; it returns 409 when a volume is attached and 501 for a sandbox that runs as a pod. File watching is not available yet. `lizard sandbox ssh` opens an interactive shell with your CLI credentials. SSH protocol access is not available, so SSH clients, `scp`, and port forwarding do not work.

```ts
const connected = await Sandbox.connect(sandbox.sandboxId);
console.log(await connected.getInfo());
```

## Pause, resume, and snapshots

`pause()` saves the sandbox's memory and running processes, keeps `/workspace` on its node, and stops billing. `resume()` restores the sandbox with the same ID. Both calls queue the work and return at once; wait for the new status.

```ts
await sandbox.pause();
await sandbox.waitForStatus('paused');
await sandbox.resume();
await sandbox.waitForStatus('running');
```

- Pausing closes open network connections. Programs in the sandbox must reconnect after a resume.
- If the processes cannot be saved, the sandbox keeps running and `waitForStatus` throws with the reason. If a resume fails, the sandbox stays paused with its checkpoint; call `resume()` again.
- The lifetime deadline stops while the sandbox is paused and continues after the resume. A paused sandbox does not count toward the running limit.
- A paused sandbox resumes on the same node. If that node fails, the paused state is lost; export files you need.

A snapshot saves a running sandbox's memory and `/workspace` files as a private template in its project. Each restore starts a new sandbox in the snapshot's region. Close clients and terminals and stop writes to `/workspace` before you capture. Attached Persistent Volumes are not captured.

```ts
const saved = await sandbox.snapshot('my-app', { poolSize: 5 });
await Sandbox.waitForSnapshot(saved.id);
const copy = await Sandbox.restore(saved.id);
```

A snapshot of a Firecracker sandbox is ready when the call returns and restores from disk, so `poolSize` does not apply. Each restore runs at the source's size and bills at that size's hourly price. A snapshot of a pod sandbox keeps warm copies, five by default (one to ten); when none is ready, restore can return HTTP 503 until the pool refills, and the restored sandbox is billed by measured usage. In both cases `size` does not apply to a restore. In the CLI, use `lizard sandbox pause <id>`, `lizard sandbox resume <id>`, `lizard sandbox snapshot <id> --name my-app`, and `lizard sandbox restore <snapshot-id>`.

## Current runtime limits

The SDK and CLI default to a five-minute lifetime. The raw API and dashboard default to no expiration. Set an explicit lifetime: `timeoutMs: 0` at creation disables expiration; a positive value sets a deadline. `setTimeout` accepts 1000–2147483647 ms, not zero. Commands do not reset the deadline. This is not an idle timer.

Command results contain stdout, stderr, and the exit code. Command timeouts are limited to 1–600 seconds. `process.exec` accepts `envs`, `workdir`, and `user`. Create-time `envs` reach every command in a Firecracker sandbox; a pod sandbox ignores them, so pass them per command there. `getInfo()` and `list()` return the create-time `metadata`.
