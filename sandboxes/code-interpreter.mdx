Run Python with the `interpreter` template. `CodeSandbox` keeps state between calls: Python runs in a persistent Jupyter kernel per context, and results can include the last expression's value and charts as `image/png`.

```ts
import { CodeSandbox } from '@lizard-build/sdk';

const sandbox = await CodeSandbox.create({ projectId: 'proj_123', timeoutMs: 300_000 });
try {
  await sandbox.runCode('x = 21');
  const run = await sandbox.runCode('x * 2');
  console.log(run.results[0]?.data, run.stdout, run.error);
} finally {
  await sandbox.kill();
}
```

```python
from lizard import CodeSandbox

sandbox = CodeSandbox.create(project_id="proj_123", timeout_ms=300_000)
try:
    sandbox.run_code("x = 21")
    run = sandbox.run_code("x * 2")
    print(run.results[0].data, run.stdout, run.error)
finally:
    sandbox.kill()
```

`createContext()` (Python: `create_context()`) starts a separate kernel with its own variables. JavaScript and bash run as a fresh process on each call.

## Run commands

`process.exec` starts a separate process for each command, so Python variables do not survive between calls. Save intermediate results to files. It returns stdout, stderr, and an exit code.

```ts
import { Sandbox } from '@lizard-build/sdk';

const sandbox = await Sandbox.create('interpreter', {
  projectId: 'proj_123', timeoutMs: 300_000,
});
try {
  const result = await sandbox.process.exec("python -c 'print(2 ** 10)'");
  console.log(result.stdout, result.stderr, result.exitCode);
} finally {
  await sandbox.kill();
}
```

```python
from lizard import Sandbox

sandbox = Sandbox.create("interpreter", project_id="proj_123", timeout_ms=300_000)
try:
    result = sandbox.process.exec_("python -c 'print(2 ** 10)'")
    print(result.stdout, result.stderr, result.exit_code)
finally:
    sandbox.kill()
```

## Storage and billing

Files and running processes remain available while the sandbox runs. After it stops, only files written to an attached Persistent Volume at `/workspace` can be reused by a later sandbox. Without a volume, `/workspace` is temporary. Each volume attaches to one sandbox at a time and uses node-local storage; export files that must survive node loss.
