# Sandboxes for AI agents

<span id="when-to-use-a-sandbox" />
<span id="what-makes-them-fast" />
<span id="templates" />
<span id="resources--limits" />
<span id="ways-to-drive-sandboxes" />

Sandboxes are isolated Linux machines for running code and AI agent tasks on Lizard. Each sandbox is a Firecracker microVM with its own kernel. Create one with Lizard SDK (`@lizard-build/sdk` for TypeScript, `lizard-sdk` for Python) or run `lizard sandbox create` in a terminal. You can then run commands, read and write files, and open ports. In a test on 2026-10-12, the median time from creating a sandbox to its first Python output was 228 ms.

## When to use Sandboxes

- **Run code a model wrote.** Give an LLM a [code interpreter](/sandboxes/code-interpreter) that keeps Python state between calls.
- **Give a coding agent its own machine.** Run [Claude Code](/sandboxes/guides/claude-code), [OpenCode](/sandboxes/guides/opencode) or Codex in a sandbox instead of on your laptop. Connect its credentials with [`lizard agents`](/cli/agents) and send prompts with [`lizard sandbox prompt`](/cli/sandbox#coding-agents).
- **Preview what the agent built.** Start a dev server and open it through a [private preview URL](/sandboxes/preview-urls).
- **Try several paths at once.** Fork a running sandbox, memory and processes included, or restore many copies from one snapshot.
- **Drive a browser.** The `desktop` template runs a graphical desktop that an agent controls with screenshots, clicks and keys.

For a web service or worker that should keep running, deploy an app instead; see the [app quickstart](/getting-started).

## How fast does a sandbox start?

In a test on 2026-10-12, the median time from creating a sandbox to its first Python output was 228 ms, and the 95th percentile was 310 ms. The test ran 300 times from Railway's US East region against `us-east-1`, with the `base` template and the Small size. Results of the same test for E2B, Daytona and Modal are on the [Sandboxes page](https://lizard.build/sandboxes).

## Runtime and templates

Choose a template from the current catalog: `base`, `interpreter`, `codex`, `claude`, `opencode`, `pi`, `prime`, or `desktop`. Availability depends on the region and pool capacity. `interpreter` includes Python and common data libraries. `desktop` runs a graphical desktop that you drive with `sandbox.desktop` or `lizard sandbox desktop`. Check tool versions inside your sandbox. The public CLI does not provide a custom-template upload flow.

A sandbox that attaches a pod-backed Persistent Volume, or restores a pod snapshot, runs as a Kubernetes pod with the runc runtime and shares the host kernel. `getInfo().runtime` tells you which. Restrict credentials and network access when running code you do not trust.

## Lifecycle

Create a sandbox, run commands, then call `kill`. `connect` attaches to an existing sandbox without changing its state, so it does not resume a paused or stopped sandbox. Pause, resume, snapshot, and restore are available; see [Pause, resume, and snapshots](/sandboxes/quickstart#pause-and-resume). `fork` copies a running sandbox, memory and processes included; it returns 409 when a volume is attached and 501 for a sandbox that runs as a pod. File watching is not available yet. `lizard sandbox ssh` opens an interactive shell with your CLI credentials. SSH protocol access is not available, so SSH clients, `scp`, and port forwarding do not work.

```text
create -> running -> stopped (kill / expiration)
running -> paused -> running (pause / resume)
running -> new sandboxes (fork)
snapshot -> new sandbox (restore)
```

## Resources and timeouts

Choose a size when you create a sandbox: Small (2 vCPU / 4 GB), Medium (4 vCPU / 8 GB, the default), or Large (8 vCPU / 16 GB). See [sizes and prices](/platform/limits#sandbox-sizes). Select a region explicitly when needed; a catalog entry does not guarantee free capacity.

The SDK and CLI default to a five-minute lifetime. The raw API and dashboard default to no expiration. Set an explicit lifetime: `timeoutMs: 0` at creation disables expiration; a positive value sets a deadline. `setTimeout` accepts 1000 to 2147483647 ms, not zero. Commands do not reset the deadline. This is not an idle timer.

## Storage and billing

Files and running processes remain available while the sandbox runs. After it stops, only files written to an attached Persistent Volume at `/workspace` can be reused by a later sandbox. Without a volume, `/workspace` is temporary. Each volume attaches to one sandbox at a time and uses node-local storage; export files that must survive node loss.

Each size has a flat hourly price, billed by the second while the sandbox runs, idle time included. Egress is included up to [2 TB per account](/platform/limits#sandbox-egress) over a rolling 30 days. A sandbox restored from a snapshot runs at its source's size and price; one restored from a pod snapshot is billed by measured usage. A paused sandbox is not billed; Persistent Volumes bill separately while you keep the data. Pause or kill a sandbox when the task ends. Rates for every resource are on the [billing page](/platform/billing) and [pricing](https://lizard.build/pricing).
