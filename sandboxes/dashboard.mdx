Open a project and select Sandboxes. Create a sandbox with a template from the catalog and a region. The default region is not a nearest-region guarantee. The current resource limits are fixed. Dashboard-created sandboxes have no expiration unless you set a lifetime through the API.

## Install and authenticate

Install the Lizard SDK and create an API key in Settings → API keys. Store it in `LIZARD_API_KEY`. Each sandbox needs a project: pass `projectId` (Python: `project_id`) or resolve an ID, slug, or name with `project`.

## Inspect and stop

The detail view shows status, template, region, measured usage, and exposed ports. The current Kubernetes runtime does not provide SSH credentials, so the SSH-backed terminal is unavailable. Run commands through the SDK or CLI.

Billing uses measured CPU, memory, storage, and egress. An idle sandbox can still use memory and storage. Stop it when the task ends; storage charges continue while you retain data.

## Templates and volumes

The Templates tab lists platform templates for new sandboxes. It does not contain snapshots of your running sessions. Creating user snapshots, pausing, and resuming are not supported. Kill Sandbox stops the sandbox and detaches its volume.

The Persistent Volumes tab manages named volumes and their attachments. Attach a volume when creating the sandbox and write to `/workspace`. Stop the current sandbox before attaching the volume to another.
