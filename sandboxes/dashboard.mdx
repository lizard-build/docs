The dashboard lets you create and manage Sandboxes without code. Open a project and select Sandboxes. Create a sandbox with a template from the catalog, a region, and a size: Small, Medium (the default), or Large. Choose the region you need; the default may not be the nearest one. Pick a lifetime under **Delete after**: 15 minutes, 1 hour, 4 hours, 1 day, 7 days, or Never (the default).

## API keys

To create sandboxes from code, create an API key in Settings → API keys and store it in `LIZARD_API_KEY`. Lizard SDK and the [HTTP API](/sandboxes/sdk-reference#http-api) read it; see the [quickstart](/sandboxes/quickstart).

## Inspect and stop

The detail view shows status, template, region, measured usage, and exposed ports. Its header has Pause and Resume buttons, and the Terminal tab opens a shell in a running sandbox.

A running sandbox bills by the second at its size's hourly price, idle time included; a paused one does not, so pause or kill it when the task ends. See [storage and billing](/sandboxes#storage-and-billing).

## Templates and volumes

The Templates tab lists platform templates and your project's private snapshots; start a new sandbox from either. Create snapshots with the SDK or CLI. Kill Sandbox stops the sandbox and detaches its volume.

Create and attach volumes with the SDK or CLI; the create form has no volume option. The Persistent Volumes tab appears once a project has a volume. It shows each volume's size and attached sandbox, and lets you browse files, resize, or delete it. Stop the current sandbox before attaching the volume to another.
