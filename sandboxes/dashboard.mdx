Open a project and select Sandboxes. Create a sandbox with a template from the catalog, a region, and a size: Small, Medium (the default), or Large. The default region is not a nearest-region guarantee. Dashboard-created sandboxes have no expiration unless you set a lifetime through the API.

## Install and authenticate

Install the Lizard SDK and create an API key in Settings → API keys. Store it in `LIZARD_API_KEY`. Each sandbox needs a project: pass `projectId` (Python: `project_id`) or resolve an ID, slug, or name with `project`.

## Inspect and stop

The detail view shows status, template, region, measured usage, and exposed ports. Its header has Pause and Resume buttons, and the Terminal tab opens a shell in a running sandbox.

Each size has a flat hourly price, billed by the second while the sandbox runs, idle time included. Egress is included up to [2 TB per account](/platform/limits#sandbox-egress) over a rolling 30 days. A sandbox restored from a snapshot is billed by measured usage. A paused sandbox is not billed; Persistent Volumes bill separately while you keep the data. Pause or kill a sandbox when the task ends.

## Templates and volumes

The Templates tab lists platform templates and your project's private snapshots; start a new sandbox from either. Create snapshots with the SDK or CLI. Kill Sandbox stops the sandbox and detaches its volume.

The Persistent Volumes tab manages named volumes and their attachments. Attach a volume when creating the sandbox and write to `/workspace`. Stop the current sandbox before attaching the volume to another.
