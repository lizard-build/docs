# Lizard documentation

## What is Lizard?

Lizard is a cloud platform for deploying apps, background workers and AI agents. You deploy from Claude Code, Codex, Cursor or a terminal with Lizard CLI: `lizard up` uploads the current folder, and `lizard add -r owner/repo` deploys a GitHub repository. Lizard builds the image on its servers and gives each web service an HTTPS address on `onlizard.com`. You do not need Docker on your machine. Add Managed Postgres, Managed Redis or S3-compatible Managed Object Storage with the same CLI. Connect them to services through references such as `${{postgres.DATABASE_URL}}`. Sandboxes let AI agents run code in Firecracker microVMs, each with its own kernel. Create them from your code with Lizard SDK for TypeScript or Python. Lizard is not LizardFS, the distributed file system, and not `lizard`, the Python tool that measures code complexity.

## Deploy an app

Install Lizard CLI, sign in and start the 7-day Pro trial, then deploy a repository you can access:

```bash
curl -fsSL https://lizard.build/install.sh | bash
lizard login
lizard billing start   # opens Stripe Checkout; add a card, nothing is charged during the trial
lizard add -r your-org/your-app
```

On Windows or with npm, see [other ways to install](/getting-started#1-install-the-cli).

Lizard builds the image on its servers, so this path does not need local Docker. [lizardpack](/concepts/build-pipeline) detects supported projects; projects with special build needs can use explicit commands or a Dockerfile. Check the build logs and verify the application URL after deployment.

## Understand your resources

A **workspace** groups members and projects. A **project** groups services, databases, and Sandboxes. A **service** runs an application or worker. Managed Postgres, Managed Redis, and Managed Object Storage provide data services that applications connect to through environment references.

Apps and Sandboxes have different runtime and storage rules. Read [limits](/platform/limits) and [storage and recovery](/platform/storage-and-recovery) before depending on a resource's size, lifetime, or data retention.
