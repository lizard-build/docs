<span id="scaling" />

# स्केलिंग

सर्विस के रेप्लिका जोड़ने, CPU या मेमोरी बढ़ाने, या ऐडऑन का स्टोरेज बढ़ाने के लिए `lizard scale` इस्तेमाल करें। सर्विस को शून्य तक स्केल करने के लिए उसे [आइडल होने पर स्लीप करने दें](#sleep-when-idle) या [पॉज़ करें](#pause-a-service)।

<span id="scale-a-service" />

## सर्विस को स्केल करें

```bash
lizard scale --service api --replicas 3
lizard scale --service api --cpu 2 --memory 2048
```

| फ़्लैग | किस पर लागू | अनुमत मान |
|------|-----------|----------------|
| `--replicas <n>` | ऐप्स | `1` से आपके प्लान की [लिमिट](/platform/limits#applications) तक: ट्रायल के दौरान `1`, हर पेड प्लान और Enterprise पर `5` |
| `--cpu <cores>` | ऐप्स और ऐडऑन | पूरे कोर: `1`, `2`, `3`, `4` |
| `--memory <mb>` | ऐप्स और ऐडऑन | `128` से `8192` MB (1 MB के स्टेप में) |
| `--storage <mb>` | **सिर्फ़ ऐडऑन**, सिर्फ़ बढ़ाया जा सकता है | `512`, `1024`, `2048`, `4096`, `8192`, `16384` |

एक ही कमांड में कई फ़्लैग साथ दे सकते हैं। रेप्लिका की संख्या बदलने पर रीबिल्ड नहीं होता, बदलाव सीधे रोल आउट होता है। CPU और मेमोरी बदलने पर सर्विस नई लिमिट के साथ रीस्टार्ट होती है।

<span id="horizontal-scaling" />

## हॉरिज़ॉन्टल स्केलिंग

लोड बैलेंसर के पीछे किसी ऐप के कई रेप्लिका चलाएँ:

```bash
lizard scale --service api --replicas 5
```

हर रेप्लिका एक अलग पॉड है। पक्का करें कि आपका ऐप स्टेटलेस हो (स्टेट को [Managed Postgres](/addons/postgres), [Managed Redis](/addons/redis) या [Managed Object Storage](/addons/storage) में रखें), ताकि कोई भी रेप्लिका किसी दूसरे की जगह ले सके।

<span id="vertical-scaling" />

## वर्टिकल स्केलिंग

एक रेप्लिका को ज़्यादा रिसोर्स दें:

```bash
lizard scale --service api --cpu 4 --memory 8192
```

<span id="growing-addon-storage" />

## ऐडऑन का स्टोरेज बढ़ाना

ऐडऑन के डेटा वॉल्यूम बढ़ाए जा सकते हैं, लेकिन घटाए नहीं जा सकते:

```bash
lizard scale --service postgres --storage 8192
```

<span id="sleep-when-idle" />

## आइडल होने पर स्लीप

`lizard sleep --on` से वेब सर्विस ट्रैफ़िक न आने पर स्लीप में चली जाती है और अगली रिक्वेस्ट आने पर लगभग एक सेकंड में जाग जाती है। डिफ़ॉल्ट रूप से वह 10 मिनट तक ट्रैफ़िक न आने पर स्लीप करती है; `--idle` से 5 से 1440 मिनट के बीच कोई भी समय सेट करें। इसे चालू करने पर सर्विस एक बार रीस्टार्ट होती है। यह सिर्फ़ उन सर्विसेज़ पर काम करता है जिनमें पोर्ट हो और एक ही रेप्लिका हो, इसलिए वर्कर पर नहीं। Managed Postgres और Managed Redis भी स्लीप कर सकते हैं।

```bash
lizard sleep --on --idle 30 --service api
lizard sleep --off --service api    # always on
```

[`lizard sleep`](/cli/sleep) देखें।

<span id="pause-a-service" />

## सर्विस को पॉज़ करें

`lizard pause` किसी सर्विस या डेटाबेस को डिलीट किए बिना रोक देता है: वह शून्य तक स्केल हो जाती है, और उसका URL, पासवर्ड, सेटिंग्स और डेटा बने रहते हैं। `lizard resume` उसे फिर से शुरू करता है। पॉज़ की गई GitHub सर्विस तब तक पुश को अनदेखा करती है जब तक आप उसे resume नहीं करते।

```bash
lizard pause api
lizard resume api
```

किसी प्रोजेक्ट या वर्कस्पेस की सभी सर्विसेज़ को पॉज़ करने के लिए `lizard project pause` या `lizard workspace pause` इस्तेमाल करें। [`lizard pause`](/cli/pause) देखें।

<span id="verifying" />

## जाँच

```bash
lizard ps                 # replica status + URL
lizard events             # deploy history + current replicas
lizard metrics            # live CPU / memory / network / disk
lizard metrics --cost     # cost instead of metrics
```

रेप्लिका की संख्या बदलने से कोई नया डिप्लॉय नहीं बनता, इसलिए `lizard events` में वह नहीं दिखता; इसके बजाय Replicas टेबल देखें।
