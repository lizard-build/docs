# Dockerfile से एक Docker कंटेनर डिप्लॉय करें

Lizard आपके `Dockerfile` से बने Docker कंटेनर होस्ट करता है। फ़ाइल को अपने प्रोजेक्ट के रूट में रखें और `lizard up` चलाएं, या GitHub रिपॉजिटरी कनेक्ट करें: Lizard अपनी बिल्ड मशीनों पर इमेज बनाता है, इसलिए आपको किसी लोकल Docker की आवश्यकता नहीं है। यह `EXPOSE` या `--port` से पोर्ट लेता है, इसे `PORT` में कंटेनर में पास करता है, और `onlizard.com` डोमेन पर कंटेनर को HTTPS पर सर्व करता है। Lizard रजिस्ट्री से तैयार इमेज पुल नहीं करता है; एक पब्लिक इमेज चलाने के लिए, एक-लाइन Dockerfile लिखें जो इसे `FROM` करे।

**टेस्ट स्टेटस:** यह पेज Lizard के बिल्डर, डिप्लॉयर और CLI 4.0.65 का 2026-10-21, के अनुसार वर्णन करता है, जिसे उनके सोर्स के विरुद्ध जांचा गया है। हमने इसके लिए कोई नया डिप्लॉय नहीं चलाया। [Umami guide](/guides/umami) इस तरह से एक-लाइन `FROM` Dockerfile डिप्लॉय करता है और उसके टेस्ट को रिकॉर्ड करता है।

<span id="before-you-start" />

## शुरू करने से पहले

- एक `Dockerfile` जिसका ऐप `0.0.0.0` पर सुनता है। `127.0.0.1` से बंधा सर्वर कंटेनर के बाहर से कोई कनेक्शन स्वीकार नहीं करता है।
- Lizard CLI, `lizard login` के साथ साइन इन, Pro या 7-दिन Pro ट्रायल (कार्ड आवश्यक) पर। [मूल्य निर्धारण](https://lizard.build/pricing) देखें।

यदि आपके पास कोई Dockerfile नहीं है, तो पहले उसके बिना डिप्लॉय करने का प्रयास करें: lizardpack Go, Node.js, Python, Ruby, PHP, Java, Rust और स्टैटिक साइट्स का पता लगाता है। [बिल्ड पाइपलाइन](/concepts/build-pipeline) देखें।

<span id="an-example-dockerfile" />

## एक उदाहरण Dockerfile

Node.js सर्वर के लिए, जैसे [Deploy a Node.js app](/framework-guides/nodejs) में:

```dockerfile
FROM node:22-slim
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci --omit=dev
COPY . .
ENV NODE_ENV=production
EXPOSE 3000
CMD ["node", "server.js"]
```

एक `.dockerignore` जोड़ें ताकि लोकल फाइलें इमेज में न रहें:

```text
node_modules
.git
.env*
```

<span id="deploy-with-lizard-up" />

## lizard up के साथ डिप्लॉय करें

```bash
lizard init --name my-container
lizard add --service web
lizard up --service web
```

`lizard up` लोकल `Dockerfile` की पहली `EXPOSE` लाइन पढ़ता है, `Detected port 3000 from Dockerfile` प्रिंट करता है और उसे सर्विस पोर्ट के रूप में सेट करता है। `--port <number>` पास करके कोई दूसरा चुनें। `EXPOSE` लाइन के बिना, `lizard up` द्वारा बनाया गया सर्विस पोर्ट `3000` प्राप्त करता है; देखें [कौन सा पोर्ट Lizard रूट करता है](#which-port-lizard-routes-to)। एक अपलोड हमेशा रूट `Dockerfile` को वैसे ही उपयोग करता है जैसे वह लिखा गया है। अपलोड में क्या शामिल है, इसके लिए [डिप्लॉय फ्रॉम लोकल कोड](/deploy/upload) देखें।

<span id="deploy-from-github" />

## GitHub से डिप्लॉय करें

```bash
lizard add -r your-org/your-app -n web
```

ट्रैक की गई ब्रांच पर हर पुश इमेज को फिर से बनाता है। Lizard रूट `Dockerfile` का उपयोग करता है जब तक कि वह केवल कहीं और निर्मित आउटपुट की कॉपी न करे (`COPY dist …` बिना `npm`, `pip`, `go build` या समान `RUN` स्टेप के); तब lizardpack एक रिप्लेसमेंट लिखता है। हमेशा अपना उपयोग करने के लिए, `dockerfilePath` सेट करें:

```bash
lizard service set web --set dockerfilePath=Dockerfile
```

[Dockerfile changes don't apply](/deploy/troubleshooting/incomplete-dockerfile) और [deploy from GitHub](/deploy/github) देखें।

<span id="a-dockerfile-in-a-subdirectory-or-with-another-name" />

## एक सबडायरेक्टरी में या दूसरे नाम से एक Dockerfile

`dockerfilePath` बिल्ड डायरेक्टरी के सापेक्ष है, जिसे `rootDirectory` सेट करता है। एक मोनोरिपो सर्विस के लिए:

```bash
lizard service set api --set rootDirectory=apps/api --set dockerfilePath=Dockerfile.prod
```

Dockerfile सर्विस पर `buildCommand` और `startCommand` को खाली छोड़ दें। `dockerfilePath` के बिना, कोई भी Lizard को आपके Dockerfile का उपयोग करने के बजाय कमांड से अपना Dockerfile लिखने के लिए मजबूर करता है। `dockerfilePath` सेट होने पर, एक `startCommand` अभी भी इमेज के `ENTRYPOINT` और `CMD` को बदल देता है: Lizard `sh -c "<start command>"` चलाता है।

<span id="which-port-lizard-routes-to" />

## Lizard किस पोर्ट पर रूट करता है

Lizard इस क्रम में सर्विस पोर्ट चुनता है:

1. आपके द्वारा सेट किया गया एक पोर्ट: `lizard up --port`, `lizard port`, `containerPort` `lizard service set` में, डैशबोर्ड, या `EXPOSE` लाइन जिसे `lizard up` ने पढ़ा। जब `lizard up` एक सर्विस बनाता है, तो यह हमेशा एक पोर्ट भेजता है: `--port`, लोकल `EXPOSE` लाइन, या `3000` जब Dockerfile में कोई नहीं होता है। वह आपके द्वारा सेट किए गए पोर्ट के रूप में गिना जाता है।
2. `0`, जो [वर्कर मोड](/deploy/workers) है: कोई पोर्ट नहीं, कोई रूट नहीं।
3. आपके द्वारा सर्विस पर सेट किया गया एक `PORT` वेरिएबल।
4. बिल्ट इमेज द्वारा एक्सपोज़ किया गया पहला पोर्ट, जिसमें उसके बेस इमेज के पोर्ट शामिल हैं। पोर्ट टेक्स्ट के रूप में सॉर्ट होते हैं, इसलिए `3000` `80` से पहले आता है।
5. `3000`।

स्टेप्स 3 और 4 केवल उन सर्विस पर लागू होते हैं जिनका पोर्ट कभी सेट नहीं किया गया था, जैसे कि `lizard add --service` से बनी सर्विस या उस रिपॉजिटरी से जिसका Dockerfile में कोई `EXPOSE` लाइन नहीं है। यदि आपकी इमेज अपने बेस इमेज से अपना पोर्ट लेती है, उदाहरण के लिए 80, पर `FROM nginx`, तो एक `EXPOSE` लाइन जोड़ें या `--port` पास करें: अन्यथा `lizard up` द्वारा बनाई गई सर्विस `3000` पर रूट करती है और कभी भी स्वस्थ नहीं होती है। `PORT` वेरिएबल आपके द्वारा सेट किए गए पोर्ट को नहीं ले जाता है; `lizard port` का उपयोग करें।

कंटेनर के अंदर, `PORT` चयनित पोर्ट रखता है। इसे पढ़ें, या उसी फिक्स्ड पोर्ट पर सुनें। पोर्ट को बाद में बदलने के लिए, `lizard port 8080 --service web` चलाएं, फिर `lizard redeploy --service web`। [नेटवर्किंग](/networking) देखें।

<span id="what-reaches-the-build" />

## बिल्ड तक क्या पहुँचता है

- **बिल्ड आर्गुमेंट्स:** केवल `COMMIT_SHA`। इसका उपयोग करने के लिए `ARG COMMIT_SHA` घोषित करें। अन्य `ARG` लाइनें अपने डिफ़ॉल्ट को बनाए रखती हैं या खाली रहती हैं।
- **वेरिएबल्स:** सर्विस वेरिएबल्स और सीक्रेट्स Dockerfile बिल्ड तक नहीं पहुँचते हैं, सिवाय [बिल्ड-टाइम वेरिएबल्स](/concepts/build-pipeline#build-time-variables) में वर्णित `VITE_*` और `NEXT_PUBLIC_*` मानों के एक अपवाद के। सार्वजनिक मानों को Dockerfile में लिखें या उन्हें कमिट करें; सीक्रेट्स को रन टाइम के लिए रखें।
- **बेस इमेज:** बिल्डर के पास आपकी रजिस्ट्री के लिए कोई लॉगिन नहीं है, इसलिए प्रत्येक `FROM` इमेज सार्वजनिक होनी चाहिए।
- **Lizard द्वारा किए गए परिवर्तन:** बनाने से पहले, Lizard आपके सोर्स `COPY` से पहले `ARG COMMIT_SHA` जोड़ता है और `npm`, `yarn`, `pnpm` और `bun` इंस्टॉल स्टेप्स में BuildKit कैश माउंट जोड़ता है। आपके द्वारा स्वयं लिखे गए कैश माउंट काम करते रहते हैं, इस सर्विस तक सीमित; कोट्स के साथ लिखा गया `--mount` विकल्प बिल्ड को विफल कर देता है।

`lizard logs --build --service web` के साथ बिल्ड देखें।

<span id="at-run-time" />

## रन टाइम पर

- **हेल्थ चेक:** Lizard `HEALTHCHECK` को अनदेखा करता है और जांचता है कि कंटेनर सर्विस पोर्ट पर TCP कनेक्शन स्वीकार करता है। [सर्विस कभी स्वस्थ नहीं](/deploy/troubleshooting/service-never-healthy) देखें।
- **उपयोगकर्ता:** इमेज का `USER` लागू होता है। एक नॉन-रूट उपयोगकर्ता के पास 1024, से नीचे एक पोर्ट खोलने की अनुमति नहीं हो सकती है, इसलिए ऐसी इमेज के लिए `80` पर `8080` को प्राथमिकता दें।
- **वेरिएबल्स:** कंटेनर को आपके सर्विस वेरिएबल्स, `PORT` और `LIZARD_*` प्लेटफॉर्म वेरिएबल्स मिलते हैं। [वेरिएबल्स और सीक्रेट्स](/variables) देखें।
- **फ़ाइलें:** अटैच्ड वॉल्यूम के बाहर लिखी गई फ़ाइलें अगले डिप्लॉय पर खो जाती हैं। रीस्टार्ट और डिप्लॉय में फ़ाइलों को बनाए रखने के लिए, एक वॉल्यूम अटैच करें, प्रति सर्विस एक (1 से 100 GB, `/data` पर माउंटेड जब तक आप `--mount-path` पास नहीं करते): `lizard volume create data --service web`। वॉल्यूम वाली सर्विस अपने पुराने पॉड को नए को शुरू करने से पहले रोक देती है, इसलिए प्रत्येक डिप्लॉय और रीस्टार्ट में एक छोटा गैप होता है। [Managed Postgres](/addons/postgres) या [Managed Object Storage](/addons/storage) में रिकॉर्ड रखें; [`lizard volume`](/cli/volume) और [स्टोरेज और रिकवरी](/platform/storage-and-recovery) देखें।

## एक सार्वजनिक इमेज चलाएं

Lizard हर सर्विस को सोर्स से बनाता है, इसलिए एक Dockerfile में एक सार्वजनिक इमेज को रैप करें:

```dockerfile
FROM ghcr.io/umami-software/umami:3.3.1
EXPOSE 3000
```

वांछित रिलीज़ का चयन करने के लिए `latest` के बजाय एक संस्करण टैग का उपयोग करें। [Umami चलाएं](/guides/umami) और [Flowise चलाएं](/guides/flowise) Managed Postgres के साथ इस पैटर्न का उपयोग करते हैं।

<span id="common-problems" />

## सामान्य समस्याएं

| लक्षण | समाधान |
|---|---|
| आपके Dockerfile संपादन दिखाई नहीं देते हैं | GitHub पर, Lizard फ़ाइल को अधूरा मान सकता है; `dockerfilePath` सेट करें। यह भी जांचें कि सर्विस में कोई `buildCommand` या `startCommand` नहीं है। |
| डिप्लॉय कभी स्वस्थ नहीं होता है | ऐप किसी अन्य पोर्ट पर या `127.0.0.1` पर सुन रहा है। `lizard port --service web` की लॉग से तुलना करें। |
| बेस इमेज के लिए `pull access denied` | इमेज निजी है या नाम गलत है। एक सार्वजनिक इमेज का उपयोग करें। |
| एक `ARG` मान खाली है | Lizard `COMMIT_SHA` को छोड़कर कोई बिल्ड आर्गुमेंट पास नहीं करता है। Dockerfile में एक डिफ़ॉल्ट सेट करें। |
| सर्विस चलती है लेकिन कुछ भी सर्व नहीं करती है | यह वर्कर मोड में हो सकता है: `lizard port --service web` `worker mode` प्रिंट करता है। |
