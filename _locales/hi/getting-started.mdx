# ऐप क्विकस्टार्ट

यह क्विकस्टार्ट कुछ ही मिनटों में Lizard पर एक ऐप डिप्लॉय करता है। Lizard CLI इंस्टॉल करें: इंस्टॉलर आपको साइन इन करता है और 7-दिन Pro ट्रायल प्रदान करता है। फिर GitHub रिपॉजिटरी के लिए `lizard add -r owner/repo` या स्थानीय फ़ोल्डर के लिए `lizard up` चलाएं। Lizard अपने सर्वर पर ऐप बनाता है, बिना स्थानीय Docker के, और इसे `onlizard.com` पर एक HTTPS URL देता है। Lizard पहली बार साइन इन करने पर आपका खाता बनाता है।

<span id="1-install-the-cli" />

## 1. CLI इंस्टॉल करें

macOS या Linux पर, इंस्टॉल स्क्रिप्ट चलाएं:

```bash
curl -fsSL https://lizard.build/install.sh | bash
```

यह `lizard` बाइनरी को `~/.lizard/bin` में रखता है, उस फ़ोल्डर को आपके `PATH` में `~/.zshrc` या `~/.bashrc` में जोड़ता है, और `lizard` को एक फ़ोल्डर में लिंक करता है जो पहले से ही आपके `PATH` पर है, इसलिए यह इस टर्मिनल में तुरंत काम करता है। बाइनरी तब से खुद को अपडेट करती है, सिवाय CI के। यदि स्क्रिप्ट कहती है कि `lizard` नहीं मिल सकता है, तो एक नया टर्मिनल खोलें। संस्करण जांचें:

```bash
lizard --version
```

Windows पर, इसे PowerShell में चलाएं:

```powershell
irm https://lizard.build/api/cli/install.ps1 | iex
```

दोनों इंस्टॉल स्क्रिप्ट [`lizard login`](/cli/login) चलाकर समाप्त होती हैं, जो आपके लिए 2 और 3 चरण करती है: यह आपको साइन इन करती है और Pro ट्रायल प्रदान करती है। इसे छोड़ने के लिए `LIZARD_NO_LOGIN=1` सेट करें; CI में स्क्रिप्ट अपने आप इसे छोड़ देती हैं।

**या npm से इंस्टॉल करें** (Node.js 20 या बाद का संस्करण आवश्यक है)। एक npm इंस्टॉल आपको साइन इन नहीं करता है, इसलिए चरण 2 के साथ आगे बढ़ें:

```bash
npm install -g @lizard-build/cli
```

> **`npx` का उपयोग न करें।** हमेशा विश्व स्तर पर स्थापित `lizard` बाइनरी का उपयोग करें। `npx @lizard-build/cli` चलाने से एक अस्थायी प्रतिलिपि डाउनलोड होती है जिसका संस्करण प्लेटफ़ॉर्म से भिन्न हो सकता है। बाद में npm इंस्टॉल को अपग्रेड करने के लिए, `npm install -g @lizard-build/cli@latest` चलाएं।

> **अनुमति की त्रुटि (EACCES)?** `sudo` इस्तेमाल न करें। ऊपर की इंस्टॉल स्क्रिप्ट चलाएँ, जिसे admin अधिकार नहीं चाहिए, या npm के लिए अपने स्वामित्व वाला prefix सेट करें:
> ```bash
> mkdir -p ~/.npm-global
> npm config set prefix ~/.npm-global
> echo 'export PATH=~/.npm-global/bin:$PATH' >> ~/.zshrc && source ~/.zshrc
> npm install -g @lizard-build/cli
> ```

<span id="2-log-in" />

## 2. लॉग इन करें

यदि इंस्टॉल स्क्रिप्ट ने आपको साइन इन किया है तो इस चरण को छोड़ दें। अन्यथा चलाएं:

```bash
lizard login
```

यह पूछता है कि क्या आप GitHub या Google से साइन इन करते हैं, आपके ब्राउज़र में वह पृष्ठ खोलता है और आपके स्वीकृत होने तक प्रतीक्षा करता है। यदि आपके पास पहले से ही एक खाता है, तो वह विधि चुनें जिसके साथ आपने साइन अप किया था: दूसरी विधि एक दूसरा, खाली खाता खोलती है जब तक कि दोनों एक सत्यापित ईमेल साझा न करें। `--github` या `--google` प्रश्न को छोड़ देता है। पहले से साइन इन मशीन पर, `lizard login` खाते को फिर से दिखाता है, इसलिए इसे फिर से चलाना सुरक्षित है।

आप `lizard login` को छोड़ भी सकते हैं: टर्मिनल पर चलाया गया कोई भी कमांड आपको उसी तरह साइन इन करता है, फिर आगे बढ़ता है।

CI या अन्य नॉन-इंटरैक्टिव वातावरण में, इसके बजाय टोकन से प्रमाणित करें:

```bash
export LIZARD_TOKEN=liz_xxx
# or
lizard login --token liz_xxx
```

API कीज़ `liz_` से शुरू होती हैं। `lizard keys create <name>` से एक बनाएं। `LIZARD_API_KEY`, `LIZARD_TOKEN` के स्थान पर काम करता है। `lizard login --token-stdin` की को एक पाइप से पढ़ता है, जो इसे आपके शेल हिस्ट्री से बाहर रखता है।

किसी भी समय जांचें कि आप कौन हैं:

```bash
lizard whoami
```

<span id="3-start-the-pro-trial" />

## 3. Pro ट्रायल शुरू करें

एक नए खाते में कोई प्लान नहीं होता है, और डिप्लॉयमेंट के लिए एक की आवश्यकता होती है। एक बार जब आप साइन इन कर लेते हैं, तो `lizard login` 7-दिन का Pro ट्रायल प्रदान करता है। हाँ कहें, और यह Stripe Checkout खोलता है, जहाँ आप एक कार्ड जोड़ते हैं। ट्रायल में $5 उपयोग शामिल है, और जब तक यह समाप्त नहीं हो जाता तब तक कुछ भी चार्ज नहीं किया जाता है। जिस खाते का ट्रायल हो चुका है, उसे इसके बजाय $19 प्रति माह Pro की पेशकश की जाती है।

यदि आपने नहीं कहा, तो इसे बाद में शुरू करें:

```bash
lizard billing start
```

जब तक कोई प्लान शुरू नहीं होता, कुछ भी बनाने पर HTTP 402 एक चेकआउट लिंक के साथ वापस आता है। [बिलिंग](/platform/billing) और [`lizard billing`](/cli/billing) देखें।

<span id="4-deploy" />

## 4. डिप्लॉय करें

वह पथ चुनें जो आपके कोड के स्थान से मेल खाता हो।

<span id="option-a--deploy-a-github-repo-recommended" />

### विकल्प A — GitHub रेपो से डिप्लॉय करें (अनुशंसित)

यदि आपका कोड GitHub पर है, तो सीधे रेपो से एक सेवा बनाएं। Lizard इसे क्लोन करता है, स्टैक का पता लगाता है और पहला बिल्ड शुरू करता है:

```bash
lizard add -r your-org/your-app
```

सेवा मौजूद होते ही कमांड वापस आ जाती है; बिल्ड जारी रहता है। [चरण 5](#5-watch-it-build-and-run) दिखाता है कि इसे कैसे फॉलो करें और URL कैसे खोजें।

एक निजी रेपो के लिए, और ट्रैक की गई ब्रांच पर पुश करने पर ऐप को फिर से डिप्लॉय करने के लिए, पहले Lizard GitHub ऐप को [`lizard git`](/cli/git) के साथ कनेक्ट करें:

```bash
lizard git connect
```

<span id="option-b--deploy-local-code" />

### विकल्प B — लोकल कोड डिप्लॉय करें

अपने प्रोजेक्ट डायरेक्टरी के अंदर से, वर्तमान फ़ोल्डर को अपलोड और डिप्लॉय करें (`.gitignore` का सम्मान करता है):

```bash
lizard up
```

पहली बार, यह सेवा का नाम पूछता है; फ़ोल्डर का नाम डिफ़ॉल्ट है। फिर यह बिल्ड का अनुसरण करता है और ऐप लाइव होने पर `https://your-app-x1y2z.onlizard.com` जैसा URL प्रिंट करता है।

यदि फ़ोल्डर अभी तक किसी प्रोजेक्ट से लिंक नहीं है, तो `lizard add` और `lizard up` आपके डिफ़ॉल्ट प्रोजेक्ट का उपयोग करते हैं और ऐसा कहते हैं। यह आपके व्यक्तिगत वर्कस्पेस में सबसे पुराना प्रोजेक्ट है; एक नया खाता साइन-अप पर एक प्राप्त करता है। `lizard up` फ़ोल्डर को इससे लिंक भी करता है, इसलिए अगला `lizard up` उसी सेवा को अपडेट करता है। किसी अन्य प्रोजेक्ट में डिप्लॉय करने के लिए, पहले `lizard init --name my-project` चलाएं। CI में भी ऐसा करें, ताकि डिप्लॉय वहीं हो जहाँ आप उम्मीद करते हैं।

Lizard अधिकांश स्टैक का स्वयं पता लगाता है। सटीक बिल्ड कमांड, स्टार्ट कमांड और आपके फ्रेमवर्क के पोर्ट के लिए, [Next.js](/framework-guides/nextjs), [React](/framework-guides/react), [Vue](/framework-guides/vue), [Astro](/framework-guides/astro), [SvelteKit](/framework-guides/sveltekit), [Node.js](/framework-guides/nodejs), [Django](/framework-guides/django), [FastAPI](/framework-guides/fastapi), [Rails](/framework-guides/rails) या [Go](/framework-guides/go) के लिए गाइड देखें। अपने स्वयं के Dockerfile वाले ऐप के लिए [Dockerfile के साथ डिप्लॉय करें](/deploy/dockerfile) का पालन करें।

<span id="5-watch-it-build-and-run" />

## 5. इसे बिल्ड और रन होते हुए देखें

```bash
lizard ps               # services in the project, with status + URL
lizard logs             # stream runtime logs (Ctrl+C to stop)
lizard logs --tail 100  # print the last 100 lines and exit
lizard logs --build     # the most recent build's logs
lizard open             # open the project in the dashboard
```

[`lizard open`](/cli/open) [डैशबोर्ड](/dashboard) में वही प्रोजेक्ट दिखाता है। मेट्रिक्स, लागत और डिप्लॉयमेंट इतिहास के लिए, [ऑब्जर्वेबिलिटी](/observability) देखें।

<span id="6-add-a-database-optional" />

## 6. डेटाबेस जोड़ें (वैकल्पिक)

Managed Postgres प्रोविज़न करें। प्रोजेक्ट में हर सेवा को अगले डिप्लॉयमेंट पर उसका पब्लिक `DATABASE_URL` मिलता है; इसके बजाय प्राइवेट नेटवर्क पर कनेक्ट करने के लिए, इसे अपनी सेवा से रेफर करें:

```bash
lizard add postgres
lizard secrets set DATABASE_URL='${{postgres.DATABASE_PRIVATE_URL}}' --service your-app
lizard redeploy --service your-app
```

Lizard डिप्लॉयमेंट समय पर `${{postgres.DATABASE_PRIVATE_URL}}` को हल करता है ताकि सेवा प्रोजेक्ट के प्राइवेट नेटवर्क पर कनेक्ट हो सके। यह एडऑन के वर्तमान नाम से मेल खाता है, इसलिए यदि आप एडऑन का नाम बदलते हैं तो रेफरेंस अपडेट करें। क्रेडेंशियल्स अपने आप रोटेट नहीं होते हैं; एक सेवा अपने अगले डिप्लॉयमेंट पर नए मान उठाती है। [Managed Addons](/addons) देखें।

## होस्टिंग लागत

Pro की लागत $19 प्रति माह है जिसमें $19 मासिक क्रेडिट शामिल हैं। इससे अधिक उपयोग प्रकाशित दरों पर pay as you go किया जाता है। Pro 7-दिन के ट्रायल और $5 ट्रायल क्रेडिट के साथ शुरू होता है; इसे शुरू करने के लिए आप एक कार्ड जोड़ते हैं। [बिलिंग](/platform/billing) और [मूल्य निर्धारण](https://lizard.build/pricing) देखें, और डिप्लॉय करने से पहले अपनी [सीमाओं](/platform/limits) की जांच करें।
