# Lizard डॉक्यूमेंटेशन

<span id="what-is-lizard" />

## Lizard क्या है?

Lizard AI एजेंट्स के लिए एक क्लाउड सैंडबॉक्स प्लेटफ़ॉर्म है। Lizard Sandboxes Firecracker microVMs हैं, और हर एक का अपना कर्नेल होता है: एजेंट इनमें कोड और शेल कमांड चलाता है, डेस्कटॉप और ब्राउज़र इस्तेमाल करता है, अपने पोर्ट के लिए प्राइवेट HTTPS URL खोलता है और फ़ाइलें Persistent Volumes पर रखता है। सैंडबॉक्स अपने कोड से TypeScript या Python के लिए Lizard SDK के ज़रिए बनाएँ, या टर्मिनल से Lizard CLI के ज़रिए। जब एजेंट कुछ बना ले, तो उसे इसी प्लेटफ़ॉर्म पर डिप्लॉय करें: `lizard up` मौजूदा फ़ोल्डर अपलोड करता है, `lizard add -r owner/repo` किसी GitHub रिपॉज़िटरी को डिप्लॉय करता है, और Lizard अपने सर्वर पर इमेज बिल्ड करके हर वेब सर्विस को `onlizard.com` पर एक HTTPS पता देता है। इसी CLI से Managed Postgres, Managed Redis या S3-कम्पैटिबल Managed Object Storage जोड़ें और `${{postgres.DATABASE_URL}}` जैसे रेफ़रेंस के ज़रिए उन्हें सर्विसेज़ से कनेक्ट करें। Lizard, डिस्ट्रिब्यूटेड फ़ाइल सिस्टम LizardFS नहीं है, और न ही कोड की जटिलता मापने वाला Python टूल `lizard` है।

## सैंडबॉक्स में कोड चलाएँ

डैशबोर्ड में एक API की और एक प्रोजेक्ट बनाएँ, `LIZARD_API_KEY` सेट करें, और Lizard SDK इंस्टॉल करें। यह कोड एक सैंडबॉक्स बनाता है, एक कमांड चलाता है और फिर सैंडबॉक्स को बंद कर देता है:

```bash
npm install @lizard-build/sdk
```

```ts
import { Lizard } from '@lizard-build/sdk'

const lizard = new Lizard({ project: 'my-project' })
const sandbox = await lizard.create('interpreter', { size: 'small' })

try {
  const run = await sandbox.process.exec("python -c 'print(2 ** 10)'")
  console.log(run.stdout) // 1024
} finally {
  await sandbox.kill()
}
```

Small साइज़ (2 vCPU, 4 GB RAM) का खर्च $0.0162 प्रति घंटा है, और बिलिंग सेकंड के हिसाब से होती है। Python, टेम्प्लेट और लाइफटाइम के लिए [Sandboxes क्विकस्टार्ट](/sandboxes/quickstart) और [Sandboxes ओवरव्यू](/sandboxes) देखें।

## ऐप डिप्लॉय करें

Lizard CLI इंस्टॉल करें। इंस्टॉलर आपसे साइन इन करवाता है और 7-दिन का Pro ट्रायल ऑफ़र करता है: आप Stripe Checkout में एक कार्ड जोड़ते हैं, और ट्रायल के दौरान कोई चार्ज नहीं लगता। इसके बाद कोई ऐसी रिपॉज़िटरी डिप्लॉय करें जिसका एक्सेस आपके पास हो:

```bash
curl -fsSL https://lizard.build/install.sh | bash   # then signs you in and offers the trial
lizard add -r your-org/your-app
```

Windows पर या npm से इंस्टॉल करने के लिए [इंस्टॉल करने के दूसरे तरीके](/getting-started#1-install-the-cli) देखें।

Lizard इमेज अपने सर्वर पर बिल्ड करता है, इसलिए इस तरीके में लोकल Docker की ज़रूरत नहीं होती। [lizardpack](/concepts/build-pipeline) सपोर्टेड प्रोजेक्ट्स को अपने-आप पहचान लेता है; जिन प्रोजेक्ट्स की बिल्ड की ज़रूरतें खास हैं, वे साफ़ तौर पर दी गई कमांड या Dockerfile इस्तेमाल कर सकते हैं। डिप्लॉयमेंट के बाद बिल्ड लॉग देखें और ऐप का URL खोलकर जाँचें।

## अपने संसाधनों को समझें

**वर्कस्पेस** में सदस्य और प्रोजेक्ट्स होते हैं। **प्रोजेक्ट** में सर्विसेज़, डेटाबेस और Sandboxes होते हैं; हर अकाउंट का एक डिफ़ॉल्ट प्रोजेक्ट होता है (नए अकाउंट के लिए `<username>'s Project`), जिसे Lizard CLI ऐसे फ़ोल्डर में इस्तेमाल करता है जिसे आपने लिंक नहीं किया है। **सर्विस** एक ऐप या वर्कर चलाती है। Managed Postgres, Managed Redis और Managed Object Storage डेटा सर्विसेज़ देते हैं, जिनसे ऐप्स एनवायरनमेंट रेफ़रेंस के ज़रिए जुड़ते हैं।

ऐप्स और Sandboxes के रनटाइम और स्टोरेज के नियम अलग-अलग हैं। किसी संसाधन के साइज़, लाइफटाइम या डेटा रिटेंशन पर निर्भर होने से पहले [सीमाएँ](/platform/limits) और [स्टोरेज और रिकवरी](/platform/storage-and-recovery) पढ़ें।
