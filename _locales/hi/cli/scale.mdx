# lizard scale

सर्विस को स्केल करें (रेप्लिका / CPU / मेमोरी / स्टोरेज)।

<span id="usage" />

## उपयोग

```bash
lizard scale [service] [flags]
```

<span id="flags" />

## फ्लैग्स

| फ्लैग | विवरण |
|------|-------------|
| `-s, --service <name>` | सर्विस का नाम या ID (डिफ़ॉल्ट: लिंक की गई सर्विस; `service` आर्गुमेंट जैसा ही) |
| `-p, --project <id>` | प्रोजेक्ट का नाम, स्लग या ID |
| `--replicas <n>` | रेप्लिका (ऐप्स), आपके प्लान की [लिमिट](/platform/limits#applications) तक: पहले पेड Pro इनवॉइस तक `1` (यानी ट्रायल के दौरान भी), उसके बाद हर पेड प्लान पर और Enterprise पर `5` |
| `--cpu <cores>` | `1`, `2`, `3` या `4` |
| `--memory <mb>` | `128`–`8192` MB |
| `--storage <mb>` | ऐडऑन वॉल्यूम का साइज़, जिसे सिर्फ़ बढ़ाया जा सकता है: `512`, `1024`, `2048`, `4096`, `8192` या `16384` |

<span id="examples" />

## उदाहरण

<span id="scale-replicas-horizontally" />

### रेप्लिका को हॉरिज़ॉन्टली स्केल करें

```bash
lizard scale --service api --replicas 5
```

हर रेप्लिका लोड बैलेंसर के पीछे एक अलग पॉड है। पक्का करें कि आपका ऐप स्टेटलेस हो, ताकि सभी रेप्लिका एक-दूसरे की जगह काम कर सकें। एक से ज़्यादा रेप्लिका वाला ऐप [आइडल होने पर स्लीप नहीं करता](/cli/sleep)। [पॉज़](/cli/pause) किए गए ऐप पर `--replicas` संख्या सेव कर लेता है, और वह रिज़्यूम होने पर लागू होती है।

<span id="scale-cpu-and-memory-vertically" />

### CPU और मेमोरी को वर्टिकली स्केल करें

```bash
lizard scale --service api --cpu 4 --memory 8192
```

<span id="grow-addon-storage" />

### ऐडऑन का स्टोरेज बढ़ाएँ

```bash
lizard scale --service postgres --storage 8192
```

ऐडऑन के डेटा वॉल्यूम सिर्फ़ बढ़ाए जा सकते हैं — आप स्टोरेज बढ़ा सकते हैं, लेकिन घटा नहीं सकते।
