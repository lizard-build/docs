# lizard login

Lizard में साइन इन करें, फिर यदि खाते में कोई प्लान नहीं है तो एक प्लान शुरू करें।

<span id="usage" />

## उपयोग

```bash
lizard login [flags]
```

एक टर्मिनल पर, `login` पूछता है कि क्या आप GitHub या Google से साइन इन करते हैं, उस पेज को आपके ब्राउज़र में खोलता है और आपके अप्रूव करने तक प्रतीक्षा करता है। यदि आपके पास पहले से ही एक खाता है, तो वह विधि चुनें जिससे आपने साइन अप किया था: दूसरी विधि एक दूसरा, खाली खाता खोलेगी जब तक कि दोनों में एक सत्यापित ईमेल साझा न हो। लिंक 5 मिनट के लिए काम करता है।

एक बार जब आप साइन इन कर लेते हैं, तो `login` प्लान की जांच करता है। बिना प्लान वाले खाते को 7-दिन का Pro trial, या यदि उसका trial हो चुका है तो प्रति माह $19 पर Pro की पेशकश की जाती है। हाँ कहें, और यह Stripe Checkout खोलता है। फिर यह आज़माने के लिए अगले कमांड सूचीबद्ध करता है।

उस मशीन पर जो पहले से ही साइन इन है, `login` खाते को दिखाता है और सीधे प्लान पर जाता है, इसलिए इसे फिर से चलाना सुरक्षित है। खातों को स्विच करने के लिए, पहले [`lizard logout`](/cli/logout) चलाएं।

इंस्टॉल स्क्रिप्ट अपने अंतिम चरण के रूप में `lizard login` चलाती हैं। इसे छोड़ने के लिए `LIZARD_NO_LOGIN=1` सेट करें; CI में वे इसे अपने आप छोड़ देते हैं।

आपको अन्य कमांड से पहले शायद ही कभी `login` की आवश्यकता होती है: किसी मशीन पर टर्मिनल पर चलने वाला कोई भी कमांड जो साइन इन नहीं है, पहले आपको साइन इन करता है, फिर आगे बढ़ता है।

<span id="flags" />

## फ्लैग्स

| फ्लैग | विवरण |
|------|-------------|
| `--github` | प्रश्न के बिना GitHub से साइन इन करें |
| `--google` | प्रश्न के बिना Google से साइन इन करें |
| `--token <token>` | API कुंजी (`liz_…`) से साइन इन करें |
| `--token-stdin` | stdin से API कुंजी पढ़ें, जो इसे प्रोसेस सूची और शेल इतिहास से बाहर रखता है |

<span id="output-for-agents" />

## एजेंटों के लिए आउटपुट

`--json` के साथ, या जब stdout एक टर्मिनल नहीं है, `login` एक JSON ऑब्जेक्ट प्रिंट करता है। यह कभी भी ब्राउज़र नहीं खोलता है और कभी भी प्रतीक्षा नहीं करता है।

- साइन-इन से पहले, यह `status: "pending"`, प्रत्येक विधि के लिए एक लिंक के साथ `authUrls`, `authUrl`, `expiresAt` और एक `instruction` प्रिंट करता है। लिंक उपयोगकर्ता को सौंपें, फिर ब्राउज़र द्वारा "CLI authorized" कहे जाने पर कमांड को फिर से चलाएं।
- साइन-इन के बाद, यह `status: "complete"`, उपयोगकर्ता नाम, प्लान के बारे में एक `instruction` के साथ `account.state`, और `next` कमांड प्रिंट करता है।

यह कभी भी प्लान शुरू नहीं करता है। एक शुरू करने के लिए, [`lizard billing start --json`](/cli/billing) चलाएं और उपयोगकर्ता को Checkout `url` सौंपें।

अन्य कमांड टर्मिनल के बिना भी उसी तरह काम करते हैं: वे एग्जिट कोड `2` और कोड `NOT_AUTHENTICATED` के साथ विफल हो जाते हैं, और एरर बॉडी `login` के तहत वही लिंक ले जाती है।

## उदाहरण

<span id="log-in-via-browser" />

### ब्राउज़र के माध्यम से लॉग इन करें

```bash
lizard login
lizard login --google   # skip the question
```

<span id="log-in-with-an-api-key" />

### API कुंजी के साथ लॉग इन करें

[`lizard keys create <name>`](/cli/keys) के साथ एक कुंजी बनाएं, फिर:

```bash
lizard login --token liz_xxx
# or, to keep the key out of shell history
printf '%s' "$LIZARD_TOKEN" | lizard login --token-stdin
```

<span id="log-in-non-interactively-in-ci" />

### CI में नॉन-इंटरेक्टिव रूप से लॉग इन करें

CI या अन्य नॉन-इंटरेक्टिव वातावरण में, `LIZARD_TOKEN` (या `LIZARD_API_KEY`) को `login` चलाने के बजाय पर्यावरण में सेट करें:

```bash
export LIZARD_TOKEN=liz_xxx
```
