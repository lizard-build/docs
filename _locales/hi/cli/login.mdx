# lizard login

Lizard में साइन इन करें, फिर अगर अकाउंट पर कोई प्लान नहीं है तो प्लान शुरू करें।

<span id="usage" />

## उपयोग

```bash
lizard login [flags]
```

टर्मिनल में `login` पूछता है कि आप GitHub से साइन इन करेंगे या Google से, फिर वह पेज आपके ब्राउज़र में खोलता है और आपके अप्रूव करने तक इंतज़ार करता है। अगर आपका अकाउंट पहले से है, तो वही तरीका चुनें जिससे आपने साइन अप किया था: दूसरा तरीका एक नया, खाली अकाउंट बना देगा, जब तक दोनों में एक ही वेरिफ़ाइड ईमेल न हो। लिंक 5 मिनट तक काम करता है।

साइन इन होने के बाद `login` प्लान जाँचता है। जिस अकाउंट पर कोई प्लान नहीं है, उसे 7 दिन का Pro ट्रायल ऑफ़र किया जाता है, या अगर वह पहले ट्रायल ले चुका है तो $19 प्रति माह पर Pro। हाँ कहने पर यह Stripe Checkout खोलता है। इसके बाद यह आगे आज़माने लायक कमांड की सूची दिखाता है।

जिस मशीन पर पहले से साइन इन है, वहाँ `login` अकाउंट दिखाता है और सीधे प्लान वाले स्टेप पर जाता है, इसलिए इसे दोबारा चलाना सुरक्षित है। अकाउंट बदलने के लिए पहले [`lizard logout`](/cli/logout) चलाएँ।

इंस्टॉल स्क्रिप्ट आखिरी स्टेप के रूप में `lizard login` चलाती हैं। इसे छोड़ने के लिए `LIZARD_NO_LOGIN=1` सेट करें; CI में स्क्रिप्ट इसे अपने-आप छोड़ देती हैं।

दूसरे कमांड से पहले आपको `login` की ज़रूरत कम ही पड़ती है: जिस मशीन पर साइन इन नहीं है, वहाँ टर्मिनल में चलाया गया कोई भी कमांड पहले आपको साइन इन कराता है और फिर अपना काम जारी रखता है।

<span id="flags" />

## फ़्लैग्स

| फ़्लैग | विवरण |
|------|-------------|
| `--github` | बिना सवाल पूछे GitHub से साइन इन करें |
| `--google` | बिना सवाल पूछे Google से साइन इन करें |
| `--token <token>` | API की (`liz_…`) से साइन इन करें |
| `--token-stdin` | API की stdin से पढ़ें, ताकि वह प्रोसेस लिस्ट और शेल हिस्ट्री में न दिखे |

<span id="output-for-agents" />

## एजेंट्स के लिए आउटपुट

`--json` के साथ, या जब stdout टर्मिनल नहीं है, `login` एक JSON ऑब्जेक्ट प्रिंट करता है। यह कभी ब्राउज़र नहीं खोलता और कभी इंतज़ार नहीं करता।

- साइन-इन से पहले यह `status: "pending"`, हर तरीके के लिए एक लिंक वाला `authUrls`, `authUrl`, `expiresAt` और एक `instruction` प्रिंट करता है। लिंक यूज़र को दें, और जब ब्राउज़र में "CLI authorized" दिखे तब कमांड दोबारा चलाएँ।
- साइन-इन के बाद यह `status: "complete"`, यूज़रनेम, प्लान के बारे में `instruction` वाला `account.state` और `next` कमांड प्रिंट करता है।

यह कभी खुद प्लान शुरू नहीं करता। प्लान शुरू करने के लिए [`lizard billing start --json`](/cli/billing) चलाएँ और Checkout का `url` यूज़र को दें।

टर्मिनल के बिना दूसरे कमांड भी ऐसे ही काम करते हैं: वे एग्ज़िट कोड `2` और कोड `NOT_AUTHENTICATED` के साथ फ़ेल होते हैं, और एरर बॉडी में `login` के अंदर यही लिंक होते हैं।

## उदाहरण

<span id="log-in-via-browser" />

### ब्राउज़र से लॉग इन करें

```bash
lizard login
lizard login --google   # skip the question
```

<span id="log-in-with-an-api-key" />

### API की से लॉग इन करें

[`lizard keys create <name>`](/cli/keys) से की बनाएँ, फिर:

```bash
lizard login --token liz_xxx
# or, to keep the key out of shell history
printf '%s' "$LIZARD_TOKEN" | lizard login --token-stdin
```

<span id="log-in-non-interactively-in-ci" />

### CI में नॉन-इंटरैक्टिव तरीके से लॉग इन करें

CI या दूसरे नॉन-इंटरैक्टिव एनवायरनमेंट में `login` चलाने के बजाय एनवायरनमेंट में `LIZARD_TOKEN` (या `LIZARD_API_KEY`) सेट करें:

```bash
export LIZARD_TOKEN=liz_xxx
```
