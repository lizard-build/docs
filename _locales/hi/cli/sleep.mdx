# lizard sleep

एक सेवा को तब सोने दें जब उसे कोई ट्रैफिक न मिले और अगली रिक्वेस्ट पर जाग जाए (उपनाम `lizard serverless`)। यह अपनी मेमोरी सेव करके सोता है, इसलिए यह वहीं से जागता है जहां से उसने छोड़ा था, आमतौर पर लगभग एक सेकंड में।

<span id="usage" />

## उपयोग

```bash
lizard sleep [service] [flags]
```

`--on` या `--off` के बिना, `sleep` सेटिंग और सेवा कितनी बार सोई और जागी है, यह दिखाता है। `service` आर्गुमेंट के बिना, यह फ़ोल्डर से जुड़ी सेवा का उपयोग करता है। डैशबोर्ड में, वही सेटिंग सेवा की सेटिंग्स में **Serverless** स्विच है।

<span id="flags" />

## फ्लैग्स

| फ्लैग | विवरण |
|------|-------------|
| `-s, --service <name>` | सर्विस का नाम या ID (`service` आर्गुमेंट के समान) |
| `-p, --project <id>` | प्रोजेक्ट का नाम, स्लग, या आईडी |
| `--on` | निष्क्रिय होने पर सोएं। सेवा इसे लागू करने के लिए एक बार पुनरारंभ होती है |
| `--off` | हमेशा चालू। एक सोई हुई सेवा जागती है |
| `--idle <minutes>` | सोने से पहले कोई ट्रैफिक न होने पर मिनट, `5` से `1440` तक। इसके बिना `--on`, `10` सेट करता है। अपने आप में, यह पहले से सो रही सेवा के निष्क्रिय समय को बदलता है |

<span id="how-it-works" />

## यह कैसे काम करता है

कोई ट्रैफिक न होने पर निष्क्रिय समय के बाद, Lizard सेवा की मेमोरी और प्रक्रियाओं को सेव करता है और उसके कंटेनर को बंद कर देता है। ऐप पर पहली HTTP रिक्वेस्ट, या डेटाबेस से पहला क्लाइंट कनेक्शन, इसे जगाता है: Lizard सेव की गई स्थिति को पुनर्स्थापित करता है, आमतौर पर लगभग एक सेकंड में, और फिर रिक्वेस्ट को पास कर देता है। यदि Lizard सेव की गई स्थिति को पुनर्स्थापित नहीं कर पाता है, तो सेवा इसके बजाय ताज़ा शुरू होती है, जिसमें सामान्य स्टार्ट जितना समय लगता है।

एक सेवा केवल तभी सोती है जब कुछ भी कनेक्टेड न हो:

- एक ऐप तब सोता है जब उसे निष्क्रिय समय से कोई रिक्वेस्ट नहीं मिली हो और उससे कोई कनेक्शन खुला न हो। एक खुला WebSocket उसे जगाए रखता है।
- एक डेटाबेस तब सोता है जब निष्क्रिय समय से कोई क्लाइंट कनेक्टेड न हो। कनेक्शन पूल जो कनेक्शन खुले रखता है, उसे जगाए रखता है।

एक [paused](/cli/pause) सेवा न तो सोती है और न ही जागती है।

<span id="which-services-can-sleep" />

## कौन सी सेवाएं सो सकती हैं

- एक पोर्ट वाले एक रेप्लिका वाले ऐप्स। वर्कर्स (पोर्ट `0`) और एक से अधिक रेप्लिका पर स्केल किए गए ऐप्स सो नहीं सकते।
- Managed Postgres 14 या नया, और Managed Redis।

पुराने रनटाइम पर एक ऐप को पहले रीडिप्लॉय की आवश्यकता होती है; कमांड आपको बताता है कि कब। प्रोजेक्ट का कोई भी सदस्य सेटिंग बदल सकता है।

<span id="billing" />

## बिलिंग

जब कोई सेवा सोती है, तो वह कोई सीपीयू और लगभग कोई मेमोरी का उपयोग नहीं करती है, इसलिए अगली जागृति तक उसके कंप्यूट चार्ज लगभग बंद हो जाते हैं। Lizard अभी भी स्टोरेज के रूप में रखे गए डेटा का बिल बना सकता है; [Billing](/platform/billing) देखें।

<span id="json-output" />

## JSON आउटपुट

`--json` के साथ, `sleep`, `id`, `name`, `kind` (`app` या `addon`), `enabled`, `idleMinutes`, `sleeps`, `wakes`, `lastSleptAt` और `lastWokeAt` (मिलीसेकंड में यूनिक्स टाइम, या `null`) और `lastError` प्रिंट करता है। `--on`, `--off` या `--idle` के बाद, `restarted` बताता है कि सेवा ने परिवर्तन लागू करने के लिए पुनरारंभ किया या नहीं।

<span id="examples" />

## उदाहरण

<span id="show-the-setting" />

### सेटिंग दिखाएं

```bash
lizard sleep api
```

<span id="sleep-after-30-idle-minutes" />

### 30 मिनट निष्क्रिय रहने के बाद स्लीप करें

```bash
lizard sleep api --on --idle 30
```

<span id="let-a-database-sleep" />

### डेटाबेस को स्लीप करने दें

```bash
lizard sleep --service my-db --on
```

<span id="change-the-idle-time" />

### निष्क्रिय समय बदलें

```bash
lizard sleep api --idle 60
```

<span id="keep-a-service-always-on" />

### सेवा को हमेशा चालू रखें

```bash
lizard sleep api --off
```
