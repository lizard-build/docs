# lizard sleep

सर्विस को ट्रैफ़िक न मिलने पर स्लीप करने दें और अगली रिक्वेस्ट पर जगाएँ (उपनाम `lizard serverless`)। सर्विस अपनी मेमोरी सेव करके स्लीप करती है, इसलिए जागने पर वहीं से काम जारी रखती है जहाँ रुकी थी, आम तौर पर लगभग एक सेकंड में।

<span id="usage" />

## उपयोग

```bash
lizard sleep [service] [flags]
```

`--on` या `--off` के बिना `sleep` सेटिंग दिखाता है और यह भी कि सर्विस कितनी बार स्लीप हुई और जागी। `service` आर्गुमेंट के बिना यह फ़ोल्डर से लिंक की गई सर्विस का उपयोग करता है। डैशबोर्ड में यही सेटिंग सर्विस की सेटिंग्स में **Serverless** स्विच है।

<span id="flags" />

## फ्लैग्स

| फ्लैग | विवरण |
|------|-------------|
| `-s, --service <name>` | सर्विस का नाम या ID (`service` आर्गुमेंट जैसा ही) |
| `-p, --project <id>` | प्रोजेक्ट का नाम, स्लग या ID |
| `--on` | आइडल होने पर स्लीप करें। इसे लागू करने के लिए सर्विस एक बार रीस्टार्ट होती है |
| `--off` | हमेशा चालू। स्लीप कर रही सर्विस जाग जाती है |
| `--idle <minutes>` | बिना ट्रैफ़िक के कितने मिनट बाद सर्विस स्लीप करे, `5` से `1440` तक। इसके बिना `--on` यह मान `10` रखता है। अकेले इस्तेमाल करने पर यह उस सर्विस का आइडल टाइम बदलता है जिसमें स्लीप पहले से चालू है |

<span id="how-it-works" />

## यह कैसे काम करता है

आइडल टाइम तक कोई ट्रैफ़िक न आने पर Lizard सर्विस की मेमोरी और प्रोसेस सेव करता है और उसका कंटेनर बंद कर देता है। ऐप पर पहली HTTP रिक्वेस्ट, या डेटाबेस से पहला क्लाइंट कनेक्शन, उसे जगा देता है: Lizard सेव की गई स्थिति वापस लाता है, आम तौर पर लगभग एक सेकंड में, और फिर रिक्वेस्ट आगे भेज देता है। अगर Lizard सेव की गई स्थिति वापस नहीं ला पाता, तो सर्विस शुरू से स्टार्ट होती है, जिसमें सामान्य स्टार्ट जितना ही समय लगता है।

सर्विस तभी स्लीप करती है जब उससे कुछ भी कनेक्टेड न हो:

- ऐप तब स्लीप करता है जब पूरे आइडल टाइम तक उसे कोई रिक्वेस्ट नहीं मिली हो और उससे कोई कनेक्शन खुला न हो। खुला WebSocket उसे जगाए रखता है।
- डेटाबेस तब स्लीप करता है जब पूरे आइडल टाइम तक कोई क्लाइंट कनेक्टेड न रहा हो। कनेक्शन खुले रखने वाला कनेक्शन पूल उसे जगाए रखता है।

[पॉज़ की गई](/cli/pause) सर्विस न स्लीप करती है, न जागती है।

<span id="which-services-can-sleep" />

## कौन-सी सर्विसेज़ स्लीप कर सकती हैं

- एक रेप्लिका और एक पोर्ट वाले ऐप्स। वर्कर्स (पोर्ट `0`) और एक से ज़्यादा रेप्लिका पर स्केल किए गए ऐप्स स्लीप नहीं कर सकते।
- Managed Postgres 14 या उससे नया, और Managed Redis।

पुराने रनटाइम वाले ऐप को पहले रीडिप्लॉय करना होगा; ज़रूरत होने पर कमांड आपको बता देती है। प्रोजेक्ट का कोई भी सदस्य यह सेटिंग बदल सकता है।

<span id="billing" />

## बिलिंग

स्लीप के दौरान सर्विस कोई CPU इस्तेमाल नहीं करती और मेमोरी लगभग न के बराबर, इसलिए अगली बार जागने तक उसका कंप्यूट चार्ज लगभग रुक जाता है। सर्विस जो डेटा रखती है, उसका बिल Lizard स्टोरेज के रूप में फिर भी बना सकता है; [बिलिंग](/platform/billing) देखें।

<span id="json-output" />

## JSON आउटपुट

`--json` के साथ `sleep` ये फ़ील्ड प्रिंट करता है: `id`, `name`, `kind` (`app` या `addon`), `enabled`, `idleMinutes`, `sleeps`, `wakes`, `lastSleptAt` और `lastWokeAt` (मिलीसेकंड में Unix टाइम, या `null`) और `lastError`। `--on`, `--off` या `--idle` के बाद `restarted` बताता है कि बदलाव लागू करने के लिए सर्विस रीस्टार्ट हुई या नहीं।

<span id="examples" />

## उदाहरण

<span id="show-the-setting" />

### सेटिंग दिखाएँ

```bash
lizard sleep api
```

<span id="sleep-after-30-idle-minutes" />

### 30 मिनट आइडल रहने के बाद स्लीप करें

```bash
lizard sleep api --on --idle 30
```

<span id="let-a-database-sleep" />

### डेटाबेस को स्लीप करने दें

```bash
lizard sleep --service my-db --on
```

<span id="change-the-idle-time" />

### आइडल टाइम बदलें

```bash
lizard sleep api --idle 60
```

<span id="keep-a-service-always-on" />

### सर्विस को हमेशा चालू रखें

```bash
lizard sleep api --off
```
