# lizard keys

API की बनाएँ, उनकी सूची देखें और उन्हें डिलीट करें। एलियास: `lizard apikey`।

<span id="usage" />

## उपयोग

```bash
lizard keys create <name> [flags]
lizard keys list
lizard keys rm <name-or-id> [flags]
```

API की `liz_` से शुरू होती हैं। जहाँ भी आप ब्राउज़र से लॉग इन नहीं कर सकते, वहाँ की का उपयोग करें:

- CI में CLI के लिए `LIZARD_TOKEN` या `LIZARD_API_KEY`
- किसी मशीन पर `lizard login --token liz_…`
- [Lizard SDK](/sandboxes/sdk-reference) के लिए `LIZARD_API_KEY`
- सैंडबॉक्स के अंदर `lizard` में साइन इन करने के लिए `lizard sandbox create --with-token liz_…`; [सैंडबॉक्स में की](#sign-in-lizard-inside-a-sandbox) देखें

<span id="subcommands" />

## सबकमांड

### `lizard keys create <name>`

की बनाएँ; वह सिर्फ़ एक बार प्रिंट होती है। उसे उसी समय कॉपी कर लें; Lizard उसे दोबारा नहीं दिखाता। बिना स्कोप वाली की को उन सभी वर्कस्पेस और प्रोजेक्ट्स का पूरा एक्सेस होता है जिन तक आपकी पहुँच है। की का स्कोप इन फ़्लैग्स से तय करें; हर फ़्लैग कई बार दिया जा सकता है:

| फ़्लैग | विवरण |
|------|-------------|
| `-p, --project <id>` | की को इस प्रोजेक्ट तक सीमित करें (नाम, स्लग या ID) |
| `-w, --workspace <id>` | की को इस वर्कस्पेस तक सीमित करें (नाम, स्लग या ID) |

स्कोप वाली की सिर्फ़ अपने प्रोजेक्ट्स या वर्कस्पेस के अंदर काम करती है। यह की ये काम नहीं कर सकती:

- बिलिंग, प्लान, कार्ड या पूरे अकाउंट का उपयोग देखना
- API की बनाना, उनकी सूची देखना या उन्हें डिलीट करना, इसलिए इसके साथ `lizard keys` फ़ेल हो जाता है
- वर्कस्पेस बनाना, अपने वर्कस्पेस का नाम बदलना या उसे डिलीट करना, या वर्कस्पेस की लिमिट्स या रीसेल कीमतें बदलना
- वर्कस्पेस या प्रोजेक्ट के मेंबर देखना या मैनेज करना
- किसी सर्विस को प्राइवेट GitHub रिपॉज़िटरी पर पॉइंट करना, जब तक उसके स्कोप का कोई ऐप पहले से उस रिपॉज़िटरी से बिल्ड न हो रहा हो

स्कोप वाली की से साइन इन होने पर [`lizard whoami`](/cli/whoami) की के स्कोप दिखाता है, उसके पीछे का अकाउंट नहीं। अगर वर्कस्पेस के मालिक ने [रीसेल कीमतें](/cli/workspace#lizard-workspace-resale-pricing-name-or-id) सेट की हैं, तो की को वही कीमतें दिखती हैं।

### `lizard keys list`

अपनी की की सूची दिखाएँ: छोटा प्रीव्यू, स्कोप, बनने का समय और आखिरी उपयोग (एलियास `ls`)। प्रीव्यू की का शुरुआती हिस्सा नहीं है, इसलिए की को नाम या ID से पहचानें।

### `lizard keys rm <name-or-id>`

की डिलीट करें (एलियास `delete`)। अगर दो की का नाम एक जैसा है, तो ID से डिलीट करें।

| फ़्लैग | विवरण |
|------|-------------|
| `-y, --yes` | पुष्टि न माँगें |

## उदाहरण

<span id="create-a-key-for-ci" />

### CI के लिए की बनाएँ

```bash
lizard keys create github-actions --project my-project
```

प्रिंट हुई की को `LIZARD_TOKEN` नाम के CI सीक्रेट के रूप में सेव करें।

<span id="sign-in-lizard-inside-a-sandbox" />

### सैंडबॉक्स के अंदर `lizard` में साइन इन करें

```bash
lizard sandbox create --with-token liz_xxx
```

सैंडबॉक्स को अपनी एक नई की मिलती है, जो सिर्फ़ सैंडबॉक्स के प्रोजेक्ट तक सीमित होती है और सैंडबॉक्स के साथ ही डिलीट हो जाती है। यह `lizard keys list` में `sandbox-session:<sandbox-id>` के रूप में दिखती है। आप जो `liz_` की पास करते हैं, वह सिर्फ़ रिक्वेस्ट को ऑथराइज़ करती है और कभी सैंडबॉक्स के अंदर नहीं जाती। अगर `--with-token` बिना वैल्यू के दिया जाए, तो CLI वही की इस्तेमाल करता है जिससे आप साइन इन हैं, और वह `liz_` की होनी चाहिए।

<span id="delete-a-key" />

### की डिलीट करें

```bash
lizard keys rm github-actions --yes
```
