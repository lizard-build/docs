# lizard keys

API कुंजियाँ बनाएँ, सूचीबद्ध करें और हटाएँ। उपनाम: `lizard apikey`।

<span id="usage" />

## उपयोग

```bash
lizard keys create <name> [flags]
lizard keys list
lizard keys rm <name-or-id> [flags]
```

API कुंजियाँ `liz_` से शुरू होती हैं। जहाँ भी आप ब्राउज़र के माध्यम से लॉग इन नहीं कर सकते, वहाँ एक का उपयोग करें:

- CI में CLI के लिए `LIZARD_TOKEN` या `LIZARD_API_KEY`
- मशीन पर `lizard login --token liz_…`
- `LIZARD_API_KEY` [Lizard SDK](/sandboxes/sdk-reference) के लिए
- सैंडबॉक्स के अंदर `lizard` को साइन इन करने के लिए `lizard sandbox create --with-token liz_…`; [सैंडबॉक्स में कुंजियाँ](#sign-in-lizard-inside-a-sandbox) देखें

<span id="subcommands" />

## सबकमांड

### `lizard keys create <name>`

एक कुंजी बनाएँ और उसे एक बार प्रिंट करें। फिर उसे कॉपी करें; Lizard उसे दोबारा नहीं दिखाएगा। बिना स्कोप वाली कुंजी की आपके द्वारा पहुँच योग्य हर वर्कस्पेस और प्रोजेक्ट तक पूरी पहुँच होती है। इसे इन फ़्लैग्स के साथ स्कोप करें, प्रत्येक को दोहराया जा सकता है:

| फ्लैग | विवरण |
|------|-------------|
| `-p, --project <id>` | कुंजी को इस प्रोजेक्ट तक सीमित करें (नाम, स्लग, या ID) |
| `-w, --workspace <id>` | कुंजी को इस वर्कस्पेस तक सीमित करें (नाम, स्लग, या ID) |

एक स्कोप की गई कुंजी केवल अपने प्रोजेक्ट या वर्कस्पेस के अंदर काम करती है। यह नहीं कर सकती:

- बिलिंग, प्लान, कार्ड या अकाउंट-व्यापी उपयोग देखें
- API कुंजियाँ बनाएँ, सूचीबद्ध करें या हटाएँ, इसलिए `lizard keys` इसके साथ विफल हो जाता है
- वर्कस्पेस बनाएँ, अपने वर्कस्पेस का नाम बदलें या हटाएँ, या वर्कस्पेस सीमाएँ या पुनर्विक्रय मूल्य बदलें
- वर्कस्पेस या प्रोजेक्ट सदस्यों को देखें या प्रबंधित करें
- निजी GitHub रिपॉजिटरी पर एक सेवा को इंगित करें, जब तक कि उसके दायरे में कोई ऐप पहले से ही उससे बिल्ड न हो रहा हो

एक स्कोप की गई कुंजी के साथ साइन इन करने पर, [`lizard whoami`](/cli/whoami) उसके पीछे के खाते के बजाय कुंजी के स्कोप दिखाता है। यदि वर्कस्पेस मालिक ने [पुनर्विक्रय मूल्य](/cli/workspace#lizard-workspace-resale-pricing-name-or-id) निर्धारित किए हैं, तो कुंजी उन कीमतों को देखती है।

### `lizard keys list`

अपनी कुंजियों को एक संक्षिप्त पूर्वावलोकन, स्कोप, निर्माण समय और अंतिम उपयोग (उपनाम `ls`) के साथ सूचीबद्ध करें। पूर्वावलोकन कुंजी की शुरुआत नहीं है, इसलिए नाम या ID से कुंजियों का मिलान करें।

### `lizard keys rm <name-or-id>`

एक कुंजी हटाएँ (उपनाम `delete`)। यदि दो कुंजियाँ एक ही नाम साझा करती हैं, तो ID से हटाएँ।

| फ्लैग | विवरण |
|------|-------------|
| `-y, --yes` | पुष्टि छोड़ें |

## उदाहरण

<span id="create-a-key-for-ci" />

### CI के लिए एक कुंजी बनाएँ

```bash
lizard keys create github-actions --project my-project
```

प्रिंट की गई कुंजी को `LIZARD_TOKEN` नामक CI सीक्रेट के रूप में स्टोर करें।

<span id="sign-in-lizard-inside-a-sandbox" />

### सैंडबॉक्स के अंदर `lizard` साइन इन करें

```bash
lizard sandbox create --with-token liz_xxx
```

सैंडबॉक्स को अपनी एक नई कुंजी मिलती है, जो सैंडबॉक्स के प्रोजेक्ट तक सीमित होती है और सैंडबॉक्स के साथ हटा दी जाती है। यह `lizard keys list` में `sandbox-session:<sandbox-id>` के रूप में दिखाई देती है। आपके द्वारा पास की गई `liz_` कुंजी केवल अनुरोध को अधिकृत करती है और कभी भी सैंडबॉक्स में प्रवेश नहीं करती है। एक नंगे `--with-token` के साथ, CLI आपके द्वारा साइन इन की गई कुंजी का उपयोग करता है, जो एक `liz_` कुंजी होनी चाहिए।

<span id="delete-a-key" />

### एक कुंजी हटाएँ

```bash
lizard keys rm github-actions --yes
```
