# lizard logs

किसी सेवा के रनटाइम लॉग को स्ट्रीम करें, अंतिम 200 लाइनें एक लाइव टेल के बाद। `-s` के बिना रनटाइम लॉग के लिए, `logs` लिंक की गई सेवा का उपयोग नहीं करता है: TTY पर यह पूछता है कि कौन सी सेवा दिखानी है, अन्यथा यह प्रोजेक्ट में सभी सेवाओं को दिखाता है। `--build` और `--restarts` लिंक की गई सेवा का उपयोग करते हैं।

<span id="usage" />

## उपयोग

```bash
lizard logs [flags]
```

<span id="flags" />

## फ्लैग्स

| फ्लैग | विवरण |
|------|-------------|
| `--build` | इसके बजाय बिल्ड लॉग दिखाएं |
| `--tail <n>` | अंतिम N लाइनें प्रिंट करें (अधिकतम 1000) और बाहर निकलें |
| `-l, --level <level>` | केवल इस स्तर पर रनटाइम लॉग: `error`, `warn`, `info`, या `debug` |
| `--restarts [n]` | अंतिम N रीस्टार्ट की सूची बनाएं (डिफ़ॉल्ट 20) |
| `--restart <id>` | एक विशिष्ट रीस्टार्ट के आसपास लॉग (सबसे हाल के लिए `latest`) |
| `-s, --service <id>` | Service |
| `-p, --project <id>` | प्रोजेक्ट का नाम, स्लग, या आईडी |

`--json` के साथ, `lizard logs` एक स्ट्रीम नहीं है — यह अंतिम 200 लाइनें लौटाता है (`--tail N` के साथ ओवरराइड करें, अधिकतम 1000) और बाहर निकल जाता है। स्नैपशॉट और स्क्रिप्टिंग के लिए इसका उपयोग करें; `--json` के बिना केवल लाइव स्ट्रीम करें।

<span id="examples" />

## उदाहरण

<span id="tail-runtime-logs" />

### रनटाइम लॉग देखें

```bash
lizard logs
```

<span id="tail-logs-for-a-specific-service" />

### किसी विशिष्ट सर्विस के लॉग देखें

```bash
lizard logs --service api
```

<span id="get-more-history" />

### अधिक इतिहास प्राप्त करें

```bash
lizard logs --tail 1000
```

<span id="filter-by-log-level" />

### लॉग लेवल के अनुसार फ़िल्टर करें

```bash
lizard logs --level error
```

<span id="check-the-most-recent-build" />

### सबसे हालिया बिल्ड की जाँच करें

```bash
lizard logs --build
```

<span id="inspect-a-crash-or-restart" />

### क्रैश या रीस्टार्ट का निरीक्षण करें

```bash
lizard logs --restarts
lizard logs --restart latest
lizard logs --restart <id>
```
