# lizard sandbox

टर्मिनल से [Sandboxes](/sandboxes) बनाएँ और प्रबंधित करें। उपनाम: `lizard sb`।

<span id="usage" />

## उपयोग

```bash
lizard sandbox create [flags]
lizard sandbox list [flags]
lizard sandbox exec <id> -- <command>
lizard sandbox ssh <id>
lizard sandbox fork <id> [flags]
lizard sandbox rm <id> [flags]
```

हर सैंडबॉक्स एक प्रोजेक्ट का होता है: वह जो आप `-p` के साथ पास करते हैं, अन्यथा वह जो वर्तमान डायरेक्टरी से जुड़ा है, अन्यथा आपके अकाउंट का डिफ़ॉल्ट प्रोजेक्ट (आपके पर्सनल वर्कस्पेस में सबसे पुराना प्रोजेक्ट)।

<span id="subcommands" />

## सबकमांड

### `lizard sandbox create`

एक सैंडबॉक्स बनाएँ और उसकी ID प्रिंट करें।

| फ्लैग | विवरण |
|------|-------------|
| `-t, --template <name>` | टेम्प्लेट (डिफ़ॉल्ट `base`)। सक्षम टेम्प्लेट: `base`, `interpreter`, `codex`, `desktop`, `desktop-camoufox` (केवल US East), `opencode`, `pi`, `prime`, `claude`। सर्वर क्षेत्र की सूची की जाँच करता है |
| `-s, --size <size>` | `small`, `medium` (डिफ़ॉल्ट; ट्रायल के दौरान `small`), या `large` |
| `--timeout <ms>` | लाइफटाइम मिलीसेकंड में (डिफ़ॉल्ट `300000`, पाँच मिनट); `0` एक्सपायरेशन को अक्षम करता है |
| `--region <code>` | वह सैंडबॉक्स बनाने का क्षेत्र जहाँ आप उसे बनाना चाहते हैं |
| `--snapshot <id>` | सहेजे गए स्नैपशॉट से शुरू करें; `--size` के साथ संयुक्त नहीं किया जा सकता |
| `--volume <name-or-id>` | [Persistent Volume](/cli/volume) संलग्न करें |
| `--with-token [key]` | सैंडबॉक्स के अंदर `lizard` में एक नई कुंजी के साथ साइन इन करें जो सैंडबॉक्स के प्रोजेक्ट तक सीमित हो और सैंडबॉक्स के साथ हटा दी जाए। `liz_` कुंजी जो आप पास करते हैं, या बिना मान के `liz_` कुंजी जिसके साथ आप रन करते हैं, केवल अनुरोध को अधिकृत करती है; ब्राउज़र लॉगिन में ऐसा कुछ नहीं होता। `base` टेम्प्लेट में `lizard` नहीं है |
| `-p, --project <id>` | प्रोजेक्ट (डिफ़ॉल्ट रूप से लिंक किया गया प्रोजेक्ट, अन्यथा आपका डिफ़ॉल्ट प्रोजेक्ट) |

Lizard प्रत्येक आकार को चलने के दौरान प्रति सेकंड एक फ्लैट दर पर बिल करता है, जिसमें निष्क्रिय समय भी शामिल है। कीमत में स्थानीय डिस्क और [प्रति खाते 2 TB ईग्रेस रोलिंग 30 दिनों](/platform/limits#sandbox-egress) में शामिल है। एक सफल पॉज़ कंप्यूट चार्ज को रोकता है; Persistent Volumes में स्टोरेज [वॉल्यूम दर](/cli/volume) पर जारी रहता है, चाहे वह संलग्न हो या अलग।

| आकार | vCPU | मेमोरी | डिस्क | कीमत |
|------|------|--------|------|-------|
| `small` | 2 | 4 GiB | 5 GB | $0.0162/h |
| `medium` | 4 | 8 GiB | 20 GB | $0.0324/h |
| `large` | 8 | 16 GiB | 50 GB | $0.0648/h |

सैंडबॉक्स में कुछ भी `--with-token` द्वारा स्थापित कुंजी को पढ़ सकता है और सैंडबॉक्स के हटाए जाने तक उसके प्रोजेक्ट पर उसका उपयोग कर सकता है।

जब तक आपका ट्रायल या Pro प्लान शुरू नहीं हो जाता, `create` एक चेकआउट लिंक के साथ HTTP 402 लौटाता है; `lizard billing start` चलाएँ। ट्रायल के दौरान आप एक साथ 5 सैंडबॉक्स चला सकते हैं, और पहले भुगतान किए गए इनवॉइस के बाद 100। पॉज़ किए गए सैंडबॉक्स की गिनती नहीं होती। ट्रायल के दौरान, एक सैंडबॉक्स `small` और एक अमेरिकी क्षेत्र में होना चाहिए; कोई अन्य आकार या क्षेत्र HTTP 403. लौटाता है। [सीमाएं](/platform/limits#sandbox-account-limits) देखें।

### `lizard sandbox list`

लिंक किए गए प्रोजेक्ट में सैंडबॉक्स सूचीबद्ध करें (उपनाम `ls`)।

| फ्लैग | विवरण |
|------|-------------|
| `-p, --project <id>` | इसके बजाय इस प्रोजेक्ट को सूचीबद्ध करें |
| `--all` | अपने सभी वर्कस्पेस में हर सैंडबॉक्स को सूचीबद्ध करें |

### `lizard sandbox rm <id>`

एक सैंडबॉक्स हटाएं (उपनाम `delete` और `kill`)।

| फ्लैग | विवरण |
|------|-------------|
| `-y, --yes` | पुष्टि छोड़ें |

### `lizard sandbox timeout <id> <ms>`

एक नया जीवनकाल सेट करें, जो अब से गिना जाता है, मिलीसेकंड में (कम से कम `1000`)। यह एक निष्क्रिय टाइमर नहीं है: कमांड चलाने से यह रीसेट नहीं होता है।

### `lizard sandbox exec <id> -- <command>`

`sh -c` के माध्यम से सैंडबॉक्स के अंदर एक कमांड चलाएं, उसके आउटपुट को स्ट्रीम करें, और उसके एग्जिट कोड के साथ बाहर निकलें।

<span id="sandbox-ssh" />

### `lizard sandbox ssh <id>`

चल रहे सैंडबॉक्स में एक इंटरैक्टिव शेल खोलें (उपनाम `shell`)। यह आपके Lizard लॉगिन का उपयोग करता है, इसलिए सेट करने के लिए कोई SSH कुंजी नहीं है; एक स्कोप्ड एपीआई कुंजी केवल उसके दायरे में सैंडबॉक्स तक पहुंचती है। Ctrl-C, तीर, और टैब कंप्लीशन सैंडबॉक्स में जाते हैं। बाहर निकलने के लिए `exit` टाइप करें या Ctrl-D दबाएं।

इसके लिए एक इंटरैक्टिव टर्मिनल की आवश्यकता होती है; स्क्रिप्ट में, `lizard sandbox exec` का उपयोग करें। यह SSH प्रोटोकॉल नहीं है, इसलिए SSH क्लाइंट, `scp`, और पोर्ट फ़ॉरवर्डिंग काम नहीं करते हैं।

### `lizard sandbox expose <id> <port>`

सैंडबॉक्स में एक पोर्ट को HTTPS URL दें। पोर्ट निजी है: अनुरोधों को सैंडबॉक्स के एक्सेस टोकन की आवश्यकता होती है, या तो `X-Lizard-Access-Token` हेडर में या `lizard_token` क्वेरी पैरामीटर के रूप में जो मुद्रित URL पहले से ही वहन करता है। इसके बिना अनुरोधों को HTTP 401. मिलता है। `--json` के साथ, परिणाम में `hostname` और `accessToken` भी होते हैं।

`lizard sandbox unexpose <id> <port>` URL को हटा देता है।

### `lizard sandbox desktop <id>`

`-t desktop` के साथ बनाए गए सैंडबॉक्स के ग्राफिकल डेस्कटॉप को शुरू करें और उसके ब्राउज़र URL और एक केवल-देखने योग्य URL को प्रिंट करें। दोनों लिंक को पासवर्ड की तरह मानें।

| फ्लैग | विवरण |
|------|-------------|
| `--view-only` | केवल-देखने योग्य URL प्रिंट या खोलें |
| `--resolution <WxH>` | स्क्रीन का आकार, 640x480 से 3840x2160 तक |
| `--open` | अपने ब्राउज़र में डेस्कटॉप खोलें |
| `--status` | डेस्कटॉप की स्थिति और URL को शुरू किए बिना दिखाएं |
| `--stop` | डेस्कटॉप को रोकें और उसका URL हटा दें |

<span id="sandbox-vnc" />

### `lizard sandbox vnc <id>`

`-t desktop` से बनाए गए सैंडबॉक्स के डेस्कटॉप से VNC ऐप (macOS Screen Sharing, TigerVNC, RealVNC) कनेक्ट करें। डेस्कटॉप में कोई पब्लिक VNC पोर्ट नहीं है, इसलिए CLI `localhost` पर सुनता है और प्रत्येक कनेक्शन को एक सुरक्षित WebSocket पर सैंडबॉक्स तक ले जाता है। यह आवश्यकतानुसार डेस्कटॉप शुरू करता है, एड्रेस और VNC पासवर्ड प्रिंट करता है, और Ctrl-C तक चलता है।

| फ्लैग | विवरण |
|------|-------------|
| `--port <port>` | लोकल पोर्ट (डिफ़ॉल्ट `5900`; यदि यह लिया गया है, तो अगला उपलब्ध) |
| `--view-only` | केवल-देखने के लिए पासवर्ड का उपयोग करें: watch, कोई नियंत्रण नहीं |
| `--open` | अपने VNC ऐप में एड्रेस खोलें (`vnc://`, macOS पर Screen Sharing) |

<span id="pause-resume-and-snapshots" />

### रोकें, फिर से शुरू करें, और स्नैपशॉट

| कमांड | यह क्या करता है |
|---------|--------------|
| `lizard sandbox pause <id>` | सैंडबॉक्स की मेमोरी और प्रक्रियाओं को सहेजता है, फिर उसे रोकता है। एक सफल पॉज़ कंप्यूट चार्ज को रोकता है; Persistent Volumes स्टोरेज का बिल अलग से लिया जाता है |
| `lizard sandbox resume <id>` | सहेजी गई मेमोरी और फ़ाइलों के साथ एक पॉज़ किए गए सैंडबॉक्स को फिर से शुरू करें |
| `lizard sandbox snapshot <id> --name <name>` | सैंडबॉक्स की मेमोरी और फ़ाइलों सहित एक रनिंग सैंडबॉक्स को सहेजें, एक स्नैपशॉट के रूप में जो आपका है। `--scope` सेट करता है कि इसे कहाँ रिस्टोर किया जा सकता है: `workspace` (डिफ़ॉल्ट) सैंडबॉक्स के वर्कस्पेस में किसी भी प्रोजेक्ट के लिए, `user` आपके किसी भी वर्कस्पेस में किसी भी प्रोजेक्ट के लिए, `project` केवल अपने प्रोजेक्ट के लिए |
| `lizard sandbox restore <snapshot-id>` | स्नैपशॉट से एक नया सैंडबॉक्स शुरू करें, स्नैपशॉट के क्षेत्र में। `-p <project>` प्रोजेक्ट चुनता है (डिफ़ॉल्ट: वॉल्यूम का प्रोजेक्ट, अन्यथा स्नैपशॉट का अपना), `--volume <name-or-id>` `/workspace` पर एक वॉल्यूम माउंट करता है, `--timeout <ms>` लाइफटाइम सेट करता है (डिफ़ॉल्ट `300000`) |
| `lizard sandbox snapshots` | प्रोजेक्ट में लिए गए स्नैपशॉट की सूची बनाएं (`-p` दूसरे प्रोजेक्ट के लिए, `--mine` आपके द्वारा लिए गए हर स्नैपशॉट के लिए) |
| `lizard sandbox snapshot-scope <snapshot-id> <scope>` | बदलें कि आपका लिया गया स्नैपशॉट कहाँ रिस्टोर किया जा सकता है: `user`, `workspace`, या `project` |
| `lizard sandbox snapshot-rm <snapshot-id>` | एक स्नैपशॉट हटाएं (उपनाम `snapshot-delete`, `-y` पुष्टि छोड़ देता है) |

`pause`, `resume`, और `snapshot` काम पूरा होने तक इंतज़ार करते हैं; कतार में लगने के बाद लौटने के लिए `--no-wait` पास करें। प्रत्येक चरण में क्या रखा जाता है, यह जानने के लिए [Pause, resume, and snapshots](/sandboxes/quickstart#pause-and-resume) देखें।

एक वॉल्यूम से जुड़े सैंडबॉक्स के स्नैपशॉट में कैप्चर के समय की वॉल्यूम फ़ाइलों की एक प्रति शामिल होती है। प्रत्येक रिस्टोर उस प्रति को प्राप्त करता है और `--volume` नहीं ले सकता है, और जो कोई भी स्नैपशॉट को रिस्टोर कर सकता है वह उन फ़ाइलों को पढ़ सकता है। `--volume` केवल उस सैंडबॉक्स के स्नैपशॉट के साथ काम करता है जिसमें कोई वॉल्यूम नहीं था, और वॉल्यूम स्नैपशॉट के क्षेत्र में होना चाहिए।

<span id="sandbox-fork" />

### `lizard sandbox fork <id>`

चल रहे सैंडबॉक्स की लाइव कॉपी शुरू करें। Lizard सैंडबॉक्स को एक पल के लिए रोकता है, उसकी मेमोरी, प्रक्रियाओं और फ़ाइलों को एक बार कैप्चर करता है, और हर कॉपी को उस कैप्चर से बूट करता है। स्रोत उसी आईडी और जीवनकाल के साथ चलता रहता है। एक सैंडबॉक्स तैयार करें (टूल्स इंस्टॉल किए गए, ऐप लोड किया गया), फिर सेटअप को दोहराए बिना कॉपी में काम फैलाने के लिए उसे फोर्क करें।

| फ्लैग | विवरण |
|------|-------------|
| `-n, --count <n>` | शुरू करने के लिए कॉपी, 1 से 100 तक (डिफ़ॉल्ट `1`) |
| `--timeout <ms>` | प्रत्येक कॉपी का लाइफटाइम, कम से कम `1000`; डिफ़ॉल्ट: स्रोत का लाइफटाइम |

प्रत्येक कॉपी एक सैंडबॉक्स स्टार्ट है: यह [रनिंग और स्टार्ट लिमिट](/platform/limits#sandbox-account-limits) की ओर गिनती है, स्रोत के आकार पर चलती है, और उस आकार पर बिल की जाती है। `--json` के साथ आउटपुट में प्रति कॉपी एक एंट्री होती है, `{"sandbox": {...}}` या `{"error": "..."}`। यदि कोई कॉपी शुरू नहीं हो सकी, तो कमांड `1` पर एग्जिट हो जाता है, और जो कॉपी शुरू हुईं वे तब तक चलती रहती हैं जब तक आप उन्हें हटा नहीं देते। आप एक पॉज़ किए गए सैंडबॉक्स या वॉल्यूम से जुड़े सैंडबॉक्स (HTTP 409) को फोर्क नहीं कर सकते।

### `lizard sandbox files`

| कमांड | यह क्या करता है |
|---------|--------------|
| `lizard sandbox files ls <id> [path]` | एक डायरेक्टरी की सूची बनाएं (डिफ़ॉल्ट `/`) |
| `lizard sandbox files cat <id> <path>` | एक फ़ाइल प्रिंट करें |
| `lizard sandbox files put <id> <local> <remote>` | एक लोकल फ़ाइल अपलोड करें |
| `lizard sandbox files get <id> <remote> <local>` | एक फ़ाइल डाउनलोड करें |
| `lizard sandbox files rm <id> <path>` | एक फ़ाइल या डायरेक्टरी हटाएं |

### कोडिंग एजेंट

अपने क्रेडेंशियल्स पर सैंडबॉक्स में कोडिंग एजेंट चलाएं। पहले उन्हें [`lizard agents`](/cli/agents) से कनेक्ट करें। एजेंट टेम्पलेट (`codex`, `claude`, `opencode`, `pi`, या `prime`) से सैंडबॉक्स बनाएं; `base` टेम्पलेट में कोई Node.js नहीं है और यह एजेंट नहीं चला सकता है।

`lizard sandbox prompt <id> <prompt...>` एक प्रॉम्प्ट भेजता है और एजेंट जो करता है उसे स्ट्रीम करता है।

| फ्लैग | विवरण |
|------|-------------|
| `--agent <name>` | `codex` (डिफ़ॉल्ट), `claude`, `pi`, `opencode`, या `prime` |
| `-c, --conversation <id>` | इस बातचीत को जारी रखें |
| `--new` | एक नई बातचीत शुरू करें |
| `-m, --model <model>` | उपयोग करने के लिए मॉडल |
| `--effort <level>` | तर्क प्रयास: `minimal`, `low`, `medium`, `high`, या `xhigh` |
| `--cwd <dir>` | सैंडबॉक्स में वर्किंग डायरेक्टरी (डिफ़ॉल्ट `/workspace`) |
| `-v, --verbose` | कमांड आउटपुट को भी प्रिंट करें |
| `--no-wait` | प्रॉम्प्ट स्वीकार होने पर वापस लौटें |

Ctrl-C देखने को रोकता है; एजेंट काम करता रहता है। `lizard sandbox interrupt <id> [-c <conversation>]` इसके चल रहे टर्न को रोकता है। `lizard sandbox conversations <id>` बातचीत को सूचीबद्ध करता है, सबसे नई पहले।

<span id="examples" />

## उदाहरण

<span id="create-a-sandbox-and-run-a-command" />

### एक सैंडबॉक्स बनाएं और एक कमांड चलाएं

```bash
lizard sandbox create --size small --timeout 600000
lizard sandbox exec genuine-toddler-jasj -- python3 -c "print(1 + 1)"
```

<span id="open-a-shell" />

### एक शेल खोलें

```bash
lizard sandbox ssh genuine-toddler-jasj
```

<span id="attach-a-persistent-volume" />

### एक परसिस्टेंट वॉल्यूम अटैच करें

```bash
lizard volume create agent-workdir --size 10
lizard sandbox create --volume agent-workdir
```

<span id="serve-a-port" />

### एक पोर्ट सर्व करें

```bash
lizard sandbox exec genuine-toddler-jasj -- sh -c "nohup python3 -m http.server 3000 --bind 0.0.0.0 >/tmp/http.log 2>&1 &"
lizard sandbox expose genuine-toddler-jasj 3000
```

<span id="use-a-desktop-from-a-vnc-app" />

### VNC ऐप से डेस्कटॉप का उपयोग करें

```bash
lizard sandbox create -t desktop
lizard sandbox vnc genuine-toddler-jasj --open
```

<span id="run-codex-in-a-sandbox" />

### सैंडबॉक्स में कोडेक्स चलाएं

```bash
lizard agents login chatgpt
lizard sandbox create -t codex
lizard sandbox prompt genuine-toddler-jasj "add a health check endpoint and test it"
```

<span id="save-and-restore-a-sandbox" />

### सैंडबॉक्स को सेव और रीस्टोर करें

```bash
lizard sandbox snapshot genuine-toddler-jasj --name my-app
lizard sandbox snapshots --mine                     # find the snapshot ID
lizard sandbox restore <snapshot-id> -p other-project
```

<span id="fork-a-prepared-sandbox" />

### तैयार सैंडबॉक्स को फोर्क करें

```bash
lizard sandbox fork genuine-toddler-jasj -n 8 --json   # 8 copies with the same memory and files
lizard sandbox rm <copy-id>                            # delete a copy when its work is done
```
