# lizard redeploy

मौजूदा वेरिएबल्स के साथ नया बिल्ड (लेटेस्ट कमिट / आखिरी अपलोड) ट्रिगर करें।

<span id="usage" />

## उपयोग

```bash
lizard redeploy [nameOrId] [flags]
```

<span id="flags" />

## फ्लैग्स

| फ्लैग | विवरण |
|------|--------------|
| `-s, --service <name>` | सर्विस |
| `-p, --project <id>` | प्रोजेक्ट का नाम, स्लग या ID |
| `--detach` | बिल्ड स्वीकार होते ही लौट आएँ |
| `--wait` | बिल्ड और डिप्लॉयमेंट के रेडी होने तक इंतज़ार करें; `--json` के साथ काम करता है |
| `--timeout <seconds>` | बिल्ड के बाद रेडीनेस के लिए इंतज़ार की अधिकतम अवधि; डिफ़ॉल्ट `120` |
| `--json` | स्क्रिप्ट्स के लिए JSON लौटाएँ |

<span id="examples" />

## उदाहरण

<span id="rebuild-and-redeploy-a-service" />

### सर्विस को रीबिल्ड और रीडिप्लॉय करें

```bash
lizard redeploy --service api
```

<span id="redeploy-without-streaming-logs" />

### लॉग स्ट्रीम किए बिना रीडिप्लॉय करें

```bash
lizard redeploy --service api --detach
```

<span id="wait-in-a-script" />

### स्क्रिप्ट में इंतज़ार करें

```bash
lizard --json redeploy --service api --wait --timeout 120
```

`--wait` के बिना JSON मोड बिल्ड रिक्वेस्ट स्वीकार होते ही लौट आता है। `--wait` के साथ CLI उस बिल्ड को फ़ॉलो करता है और फिर डिप्लॉयमेंट के रेडी होने का इंतज़ार करता है। JSON नतीजे में `buildId`, `ok` और `status` होते हैं। बिल्ड फ़ेल होने, रेडीनेस चेक फ़ेल होने या टाइमआउट होने पर कमांड नॉन-ज़ीरो एग्ज़िट कोड लौटाती है।

पॉज़ की गई सर्विस तब तक रीडिप्लॉय नहीं होती, जब तक आप उसे [रिज़्यूम](/cli/pause) न करें।

टाइमआउट बिल्ड पूरा होने के बाद रेडीनेस पर लागू होता है; यह बिल्ड की अवधि को सीमित नहीं करता और डिप्लॉयमेंट को रद्द नहीं करता। `containerPort=0` वाले वर्कर्स HTTP चेक के बिना बैकएंड से मिली रेडीनेस स्थिति का उपयोग करते हैं। अगर आपके वर्कफ़्लो को ऐप्लिकेशन का व्यवहार जाँचना है, तो कमांड सफल होने के बाद ऐप्लिकेशन का कोई एंडपॉइंट या सेव किया गया डेटा जाँचें।
