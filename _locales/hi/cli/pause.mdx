# lizard pause

किसी सर्विस (ऐप या डेटाबेस) को डिलीट किए बिना पॉज़ करें और बाद में रिज़्यूम करें। `lizard project pause` और `lizard workspace pause` किसी प्रोजेक्ट या वर्कस्पेस की हर चीज़ को एक साथ पॉज़ करते हैं।

<span id="usage" />

## उपयोग

```bash
lizard pause [service] [flags]
lizard resume [service] [flags]
lizard project pause [project]
lizard project resume [project]
lizard workspace pause <name-or-id>
lizard workspace resume <name-or-id>
```

`service` आर्गुमेंट के बिना `pause` और `resume` फ़ोल्डर से लिंक की गई सर्विस का उपयोग करते हैं।

<span id="flags" />

## फ़्लैग्स

`lizard pause` और `lizard resume` ये फ़्लैग्स लेते हैं:

| फ़्लैग | विवरण |
|------|-------------|
| `-s, --service <name>` | सर्विस का नाम या ID (`service` आर्गुमेंट जैसा ही) |
| `-p, --project <id>` | प्रोजेक्ट का नाम, स्लग या ID |

`project pause` और `project resume` प्रोजेक्ट का नाम, स्लग या ID लेते हैं। इसके बिना वे फ़ोल्डर से लिंक किया गया प्रोजेक्ट इस्तेमाल करते हैं, और जो फ़ोल्डर लिंक नहीं है उसमें आपके अकाउंट का डिफ़ॉल्ट प्रोजेक्ट। `workspace pause` और `workspace resume` वर्कस्पेस का नाम, स्लग या ID लेते हैं।

<span id="what-pausing-keeps" />

## पॉज़ करने पर क्या बना रहता है

पॉज़ की गई सर्विस में कोई कंटेनर नहीं चलता। उसका URL, होस्ट, पोर्ट, पासवर्ड, वेरिएबल्स, सेटिंग्स और वॉल्यूम बने रहते हैं। जब तक सर्विस पॉज़ है:

- उसका URL `503` लौटाता है, और डेटाबेस कनेक्शन स्वीकार नहीं करता;
- Lizard डिप्लॉय और रीस्टार्ट नहीं होने देता;
- [`lizard scale`](/cli/scale) से सेट की गई नई रेप्लिका संख्या और नए [सीक्रेट्स](/cli/secrets) Lizard सेव कर लेता है और सर्विस के रिज़्यूम होने पर उन्हें लागू करता है।

`resume` सर्विस को उसी इमेज से दोबारा शुरू करता है जो आखिरी बार चली थी, मौजूदा वेरिएबल्स और उसके डेटा के साथ। मेमोरी नहीं बचती: ऐप नए सिरे से शुरू होता है। अगर मेमोरी बचाए रखनी है और अगली रिक्वेस्ट पर सर्विस को जगाना है, तो इसके बजाय [`lizard sleep`](/cli/sleep) का उपयोग करें।

आप चल रहे या क्रैश हुए ऐप को पॉज़ कर सकते हैं, और चल रहे Managed Postgres या Managed Redis डेटाबेस को भी। सर्विस पर चल रहा डिप्लॉय या कोई दूसरा ऑपरेशन पूरा होने तक इंतज़ार करें। Managed Object Storage को पॉज़ नहीं किया जा सकता।

<span id="billing" />

## बिलिंग

पॉज़ की गई सर्विस कोई CPU या मेमोरी इस्तेमाल नहीं करती, इसलिए उसके कंप्यूट चार्ज रुक जाते हैं। सर्विस जो डेटा रखती है, उसका बिल Lizard स्टोरेज के रूप में फिर भी ले सकता है; [बिलिंग](/platform/billing) देखें।

ट्रायल का उपयोग खत्म होने या भुगतान फ़ेल होने पर Lizard खुद भी ऐप्स और डेटाबेस पॉज़ कर देता है। बिलिंग ठीक होते ही वे फिर से चालू हो जाते हैं; `resume` उन्हें इससे पहले चालू नहीं करता।

<span id="pause-a-whole-project" />

## पूरा प्रोजेक्ट पॉज़ करें

`lizard project pause` प्रोजेक्ट के हर ऐप और डेटाबेस को पॉज़ करता है। यह प्रोजेक्ट के चल रहे सैंडबॉक्स को भी पॉज़ करता है और उनकी मेमोरी और फ़ाइलें उसी तरह सेव करता है जैसे [`lizard sandbox pause`](/cli/sandbox) करता है। जिन सर्विसेज़ को यह पॉज़ नहीं कर पाता, उनकी सूची वजह के साथ दिखाता है।

`lizard project resume` प्रोजेक्ट के उन सभी ऐप्स और डेटाबेस को रिज़्यूम करता है जिन्हें किसी ने हाथ से पॉज़ किया था, और उन सैंडबॉक्स को भी जिन्हें `project pause` ने पॉज़ किया था। जिन सैंडबॉक्स को आपने खुद पॉज़ किया था, वे पॉज़ ही रहते हैं। सैंडबॉक्स तभी रिज़्यूम होता है जब तक आपकी [सैंडबॉक्स लिमिट्स](/platform/limits#sandbox-account-limits) में जगह बची हो।

`lizard workspace pause` और `lizard workspace resume` वर्कस्पेस के हर प्रोजेक्ट के लिए यही करते हैं। किसी प्रोजेक्ट से बाहर के सैंडबॉक्स को वे छोड़ देते हैं।

<span id="who-can-pause" />

## कौन पॉज़ कर सकता है

- प्रोजेक्ट का कोई भी मेंबर उसकी सर्विसेज़ या पूरे प्रोजेक्ट को पॉज़ और रिज़्यूम कर सकता है।
- पूरे वर्कस्पेस को सिर्फ़ वर्कस्पेस का मालिक ही पॉज़ या रिज़्यूम कर सकता है।
- रिज़्यूम करने से कंप्यूट फिर से शुरू होता है, इसलिए इसके लिए एक्टिव प्लान और वर्कस्पेस की लिमिट्स में जगह चाहिए ([`lizard workspace limits`](/cli/workspace))।

<span id="json-output" />

## JSON आउटपुट

`--json` के साथ `pause` और `resume` `id`, `name`, `kind` (`app` या `addon`) और `status` (`paused` या `running`) प्रिंट करते हैं।

प्रोजेक्ट और वर्कस्पेस वाले कमांड `id`, `done` और `skipped` प्रिंट करते हैं। हर एंट्री में `kind` (`app`, `database` या `sandbox`), `id` और `name` होते हैं; छोड़ी गई एंट्री में `reason` भी होता है।

## उदाहरण

<span id="pause-and-resume-an-app" />

### ऐप को पॉज़ और रिज़्यूम करें

```bash
lizard pause api
lizard resume api
```

<span id="pause-a-database-in-another-project" />

### दूसरे प्रोजेक्ट का डेटाबेस पॉज़ करें

```bash
lizard pause --service my-db --project my-project
```

<span id="pause-everything-in-a-project" />

### प्रोजेक्ट में सब कुछ पॉज़ करें

```bash
lizard project pause my-project --json
lizard project resume my-project
```

<span id="pause-a-workspace" />

### वर्कस्पेस पॉज़ करें

```bash
lizard workspace pause my-team
lizard workspace resume my-team
```
