# Persistent Volumes

Persistent Volumes सैंडबॉक्स स्टॉप होने के बाद भी डेटा रखते हैं। हर वॉल्यूम **`/workspace`** पर माउंट होता है और **एक समय में एक ही सैंडबॉक्स** से अटैच होता है। सैंडबॉक्स उसी नोड पर चलता है जिस पर उसका वॉल्यूम है।

<span id="create-and-attach-by-name" />

## नाम से बनाएँ और अटैच करें

किसी प्रोजेक्ट में नाम यूनिक होते हैं। छोटे अक्षर (a-z), अंक और डैश इस्तेमाल करें; नाम अक्षर या अंक से शुरू और खत्म होना चाहिए और 64 कैरेक्टर तक हो सकता है।

नाम वाले वॉल्यूम को दोबारा इस्तेमाल करने के लिए `getOrCreate` इस्तेमाल करें। इसमें दिया गया साइज़ सिर्फ़ नया वॉल्यूम बनाते समय लागू होता है; यह किसी मौजूदा वॉल्यूम का साइज़ कभी नहीं बदलता। अगर नाम पहले से लिया हुआ है, तो `Volume.create` कॉन्फ़्लिक्ट लौटाता है।

```ts
import { Sandbox, Volume } from '@lizard-build/sdk';

await Volume.getOrCreate('proj_123', 'agent-workdir', { sizeGb: 10 });
const sandbox = await Sandbox.create('base', {
  projectId: 'proj_123', volumeName: 'agent-workdir',
});
try {
  await sandbox.fs.write('/workspace/state.json', JSON.stringify({ step: 1 }));
} finally {
  await sandbox.kill();
}

// A later sandbox mounts the same data by name.
const next = await Sandbox.create('base', {
  projectId: 'proj_123', volumeName: 'agent-workdir',
});
try {
  console.log(await next.fs.read('/workspace/state.json'));
} finally {
  await next.kill();
}
```

```python
from lizard import Sandbox, Volume

Volume.get_or_create("proj_123", "agent-workdir", size_gb=10)
sandbox = Sandbox.create("base", project_id="proj_123", volume_name="agent-workdir")
try:
    sandbox.process.exec_("echo hello > /workspace/state.txt")
finally:
    sandbox.kill()
```

<span id="size-and-price" />

## साइज़ और कीमत

नए वॉल्यूम **1 से 50 GB** तक के हो सकते हैं, पूरे GB में; डिफ़ॉल्ट **5 GB** है। सर्वर `VOLUME_MAX_SIZE_GB` से अधिकतम सीमा बदल सकता है; डैशबोर्ड और CLI मौजूदा लिमिट और स्टोरेज की कीमत `GET /api/projects/:projectId/volume-limits` से पढ़ते हैं।

आप **इस्तेमाल हुई जगह** के लिए भुगतान करते हैं, पूरे आवंटित साइज़ के लिए नहीं। नई अधिकतम सीमा से बड़े मौजूदा वॉल्यूम अपना साइज़ बनाए रखते हैं और इस्तेमाल किए जा सकते हैं। एक वर्कस्पेस के सभी वॉल्यूम का कुल आवंटित साइज़ **200 GB** तक हो सकता है; इससे आगे जाने वाला create या resize कोड `volume_quota_exceeded` के साथ `403` लौटाता है।

<span id="manage-volumes" />

## वॉल्यूम मैनेज करें

```ts
await Volume.list('proj_123');
const volume = await Volume.get('proj_123', 'agent-workdir');
await volume.getInfo('proj_123');
await Volume.resize('proj_123', 'agent-workdir', 20);
await Volume.delete('proj_123', 'agent-workdir'); // detach first
```

| TypeScript | Python | काम |
|---|---|---|
| `Volume.getOrCreate(projectId, name, options)` | `Volume.get_or_create(project_id, name, size_gb=5)` | वॉल्यूम दोबारा इस्तेमाल करें या बनाएँ |
| `Volume.create(projectId, name, options)` | `Volume.create(project_id, name, size_gb=5)` | बनाएँ; नाम पहले से लिया हो तो फ़ेल होता है |
| `Volume.list(projectId)` | `Volume.list(project_id)` | प्रोजेक्ट के वॉल्यूम लिस्ट करें |
| `Volume.get(projectId, nameOrId)` | `Volume.get(project_id, name_or_id)` | वॉल्यूम ढूँढें |
| `Volume.resize(projectId, nameOrId, sizeGb)` | `Volume.resize(project_id, name_or_id, size_gb)` | साइज़ बदलें |
| `Volume.delete(projectId, nameOrId)` | `Volume.remove(project_id, name_or_id)` | डिटैच किया हुआ वॉल्यूम डिलीट करें |

जेनरेट की गई ID और `volumeId` / `volume_id` फ़ील्ड मौजूदा कोड के लिए काम करते रहते हैं। नए कोड में नाम इस्तेमाल करें।

`Volume.resize` वॉल्यूम को उसी जगह बढ़ाता है। जिस सैंडबॉक्स से वॉल्यूम अटैच है, वह चलता रहता है लेकिन उसे पुराना साइज़ ही दिखता है; वॉल्यूम को अटैच करने वाले अगले सैंडबॉक्स को नया साइज़ दिखता है। वॉल्यूम सिर्फ़ बढ़ाया जा सकता है। अक्टूबर 2026 से पहले बने कुछ वॉल्यूम छोटे भी किए जा सकते हैं, अगर नए साइज़ का कम से कम 10% खाली रहे।

## CLI

```bash
lizard volume create agent-workdir --size 10 --project proj_123
lizard volume list --project proj_123
lizard sandbox create --volume agent-workdir --project proj_123
lizard volume resize agent-workdir --size 20 --project proj_123
# After stopping the sandbox:
lizard volume rm agent-workdir --project proj_123
```

`--size` पूरे GB लेता है और वॉल्यूम बनाने से पहले सर्वर की मौजूदा लिमिट जाँचता है। `volume list` नाम दिखाता है; ID चाहिए तो `--json` इस्तेमाल करें।

## डैशबोर्ड

वॉल्यूम SDK या CLI से बनाएँ और अटैच करें। डैशबोर्ड के साइडबार में **Volumes** पेज पर हर वॉल्यूम की इस्तेमाल हुई और आवंटित जगह, स्टेटस और अटैच सैंडबॉक्स दिखते हैं। वहाँ से आप फ़ाइलें ब्राउज़ कर सकते हैं, साइज़ बदल सकते हैं या वॉल्यूम डिलीट कर सकते हैं।

<span id="storage-lifecycle" />

## स्टोरेज लाइफसाइकिल

- सैंडबॉक्स को किल करने या उसके एक्सपायर होने पर उसका वॉल्यूम डिटैच हो जाता है और डेटा बचा रहता है।
- अटैच किया हुआ वॉल्यूम न किसी दूसरे सैंडबॉक्स से अटैच हो सकता है, न डिलीट किया जा सकता है।
- वॉल्यूम डिलीट करने से उसका डेटा भी हट जाता है। वॉल्यूम नोड-लोकल स्टोरेज इस्तेमाल करते हैं; नोड फ़ेल होने के बाद जिस डेटा की ज़रूरत होगी, उसे एक्सपोर्ट करें। [स्टोरेज और रिकवरी](/platform/storage-and-recovery) देखें।

- वॉल्यूम के बिना `/workspace` सैंडबॉक्स की डिस्क का हिस्सा होता है: पॉज़ या स्नैपशॉट उसकी फ़ाइलें बचाकर रखता है, और किल या एक्सपायरी उन्हें डिलीट कर देती है।
- जिस सैंडबॉक्स से वॉल्यूम अटैच है, उसे फ़ोर्क नहीं किया जा सकता (HTTP 409)।
- वॉल्यूम अटैच वाले सैंडबॉक्स के स्नैपशॉट में वॉल्यूम की फ़ाइलों की वह कॉपी शामिल होती है जो स्नैपशॉट लेते समय थी। हर रिस्टोर को यही कॉपी मिलती है, लाइव वॉल्यूम नहीं, और ऐसे रिस्टोर में कोई दूसरा वॉल्यूम अटैच नहीं किया जा सकता। जो भी स्नैपशॉट रिस्टोर कर सकता है, वह इन फ़ाइलों को पढ़ सकता है, इसलिए स्नैपशॉट शेयर करने का मतलब वॉल्यूम का डेटा शेयर करना है; [स्नैपशॉट](/sandboxes/quickstart#pause-and-resume) देखें।

सैंडबॉक्स के विकल्पों के लिए [SDK रेफरेंस](/sandboxes/sdk-reference) और पॉज़, स्नैपशॉट और फ़ोर्क के लिए [लाइफसाइकिल](/sandboxes#lifecycle) देखें।
