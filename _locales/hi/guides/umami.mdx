# Umami चलाएं

यह गाइड Lizard पर आधिकारिक Umami Docker इमेज को एक अलग PostgreSQL डेटाबेस के साथ चलाती है। यह Lizard CLI का उपयोग करके एक छोटा स्थानीय Dockerfile डिप्लॉय करती है और Umami को HTTPS पर एक्सपोज़ करती है।

<span id="prerequisites" />

## आवश्यकताएँ

- Pro या 7-दिन Pro ट्रायल (कार्ड आवश्यक) पर एक Lizard खाता। जब तक ट्रायल शुरू नहीं होता, `lizard add` और `lizard up` एक चेकआउट लिंक लौटाते हैं; `lizard billing start` इसे खोलता है।
- सीक्रेट जेनरेट करने के लिए अपने कंप्यूटर पर OpenSSL।

Lizard CLI इंस्टॉल करें और लॉग इन करें:

```bash
curl -fsSL https://lizard.build/install.sh | bash
lizard login
```

जारी रखने से पहले अपने ब्राउज़र में लॉगिन पूरा करें। नीचे दिए गए कमांड का सितंबर 2026 में Lizard CLI 0.3.95, के साथ Lizard CLI 4, और Umami 3.3.1. से पहले परीक्षण किया गया था।

<span id="create-the-project-and-database" />

## प्रोजेक्ट और डेटाबेस बनाएं

इस डिप्लॉयमेंट के लिए एक नई डायरेक्टरी का उपयोग करें:

```bash
mkdir umami-on-lizard
cd umami-on-lizard
lizard init --name umami-on-lizard
lizard add postgres --name umami-db
lizard add --service umami
```

यदि आप एक से अधिक वर्कस्पेस से संबंधित हैं, तो एक चुनने के लिए `lizard init` को `--workspace <workspace>` पास करें। Umami को डिप्लॉय करने से पहले डेटाबेस के `running` तक पहुंचने की प्रतीक्षा करें।

<span id="set-the-image-and-secrets" />

## इमेज और सीक्रेट सेट करें

`Dockerfile` नाम की एक फ़ाइल बनाएँ:

```dockerfile
FROM ghcr.io/umami-software/umami:3.3.1
EXPOSE 3000
```

Lizard को बताएं कि इस फ़ाइल का उपयोग वैसे ही करें जैसे यह लिखी गई है:

```bash
lizard service set umami --set dockerfilePath=Dockerfile
```

डेटाबेस कनेक्ट करें और दो अलग-अलग सीक्रेट जेनरेट करें:

```bash
lizard secrets set \
  DATABASE_URL='${{umami-db.DATABASE_PRIVATE_URL}}' \
  APP_SECRET="$(openssl rand -hex 32)" \
  TWO_FACTOR_ENCRYPTION_KEY="$(openssl rand -hex 32)" \
  --service umami
```

डेटाबेस रेफरेंस के आसपास सिंगल कोट्स रखें: Lizard सेवा शुरू होने पर इसे हल करता है, प्रोजेक्ट के प्राइवेट नेटवर्क पर डेटाबेस के पते पर। मान इस सेवा के हैं, इसलिए प्रोजेक्ट में अन्य ऐप्स को वे नहीं मिलते हैं।

दोनों जेनरेट किए गए सीक्रेट को अपने पासवर्ड मैनेजर में सेव करें। सेटअप के दौरान उन्हें एक बार सेट करें; रीस्टार्ट या अपग्रेड करते समय उन्हें फिर से जेनरेट न करें। टू-फैक्टर ऑथेंटिकेशन के लिए `TWO_FACTOR_ENCRYPTION_KEY` आवश्यक है।

<span id="deploy-and-sign-in" />

## डिप्लॉय और साइन इन करें

Dockerfile वाले डायरेक्टरी से, रन करें:

```bash
lizard up --service umami --port 3000
```

Umami का इमेज स्टार्टअप पर अपना डेटाबेस सेटअप और माइग्रेशन चलाता है। इस इमेज के लिए किसी अलग माइग्रेशन कमांड की आवश्यकता नहीं है।

डिप्लॉयमेंट द्वारा लौटाए गए HTTPS URL को खोलें। एक नए Umami 3.3.1 डेटाबेस के लिए, यूज़रनेम `admin` और पासवर्ड `umami` के साथ साइन इन करें, फिर URL साझा करने से पहले तुरंत अपने प्रोफ़ाइल में पासवर्ड बदलें। एक वेबसाइट जोड़ें और अपने कंट्रोल वाले पेज पर उसका ट्रैकिंग स्क्रिप्ट इंस्टॉल करें।

यदि डिप्लॉयमेंट विफल हो जाता है, तो उसकी स्थिति और लॉग का निरीक्षण करें:

```bash
lizard events --service umami
lizard logs --build --service umami
lizard logs --service umami
```

यदि पहला स्टार्टअप टाइम आउट हो जाता है, तो कंटेनर की तत्परता के लिए `lizard events` की जांच करें। एक बार कंटेनर शुरू हो जाने के बाद, `lizard up --service umami --port 3000` के साथ अपलोड को फिर से प्रयास करें।

ऐसे डैशबोर्ड के लिए जिसे बहुत कम लोग खोलते हैं, `lizard sleep --on --service umami` के साथ [स्लीप व्हेन आइडल](/cli/sleep) चालू करें; इसे चालू करने से सेवा एक बार रीस्टार्ट हो जाती है। ट्रैक किए गए पेज व्यूज़ अनुरोधों के रूप में गिने जाते हैं, इसलिए एक व्यस्त साइट जागी रहती है। शांत अवधि के बाद, सेवा के जागने पर पहले अनुरोध में अधिक समय लगता है।

<span id="check-data-persistence" />

## डेटा दृढ़ता की जाँच करें

ट्रैक किए गए पेज पर जाएं और पुष्टि करें कि Umami एक पेज व्यू रिकॉर्ड करता है। एप्लिकेशन को रीस्टार्ट करें:

```bash
lizard restart --service umami
```

सेवा के फिर से चलने की प्रतीक्षा करें। पुष्टि करें कि आपका नया पासवर्ड काम करता है और वेबसाइट और पेज व्यू बना रहता है। फिर एक रीडिप्लॉय के बाद जांच दोहराएं:

```bash
lizard redeploy --service umami
```

Umami PostgreSQL में अकाउंट, वेबसाइट सेटिंग्स और एनालिटिक्स स्टोर करता है। एप्लिकेशन को उन रिकॉर्ड के लिए फ़ाइल वॉल्यूम की आवश्यकता नहीं है। ऐप को बदलते या अपग्रेड करते समय डेटाबेस और एन्क्रिप्शन सीक्रेट रखें। एक रीस्टार्ट चेक एक टेस्टेड डेटाबेस बैकअप और रिस्टोर प्लान का विकल्प नहीं है।

<span id="update-umami" />

## Umami अपडेट करें

अपग्रेड करने से पहले PostgreSQL का बैकअप लें और रिलीज़ नोट्स पढ़ें। लोकल Dockerfile में इमेज टैग बदलें, फिर `lizard up --service umami --port 3000` को फिर से रन करें। इस अपलोड-आधारित सेटअप के लिए, `lizard redeploy` अंतिम अपलोड की गई फ़ाइलों को फिर से बनाता है; यह लोकल एडिट्स को अपलोड नहीं करता है।

डेटाबेस एक्सेस के लिए [Lizard के PostgreSQL गाइड](https://lizard.build/docs/addons/postgres/) और बैकअप प्लानिंग के लिए [स्टोरेज और रिकवरी](https://lizard.build/docs/platform/storage-and-recovery/) देखें।
