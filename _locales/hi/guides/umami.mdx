# Umami चलाएँ

यह गाइड Lizard पर Umami की आधिकारिक Docker इमेज को एक अलग PostgreSQL डेटाबेस के साथ चलाती है। इसमें Lizard CLI से एक छोटा लोकल Dockerfile डिप्लॉय किया जाता है और Umami को HTTPS पर उपलब्ध कराया जाता है।

<span id="prerequisites" />

## ज़रूरी चीज़ें

- Pro या 7-दिन के Pro ट्रायल (कार्ड ज़रूरी) वाला Lizard अकाउंट। ट्रायल शुरू होने तक `lizard add` और `lizard up` एक Checkout लिंक लौटाते हैं; `lizard billing start` उसे खोलता है।
- सीक्रेट जेनरेट करने के लिए आपके कंप्यूटर पर OpenSSL।

Lizard CLI इंस्टॉल करें और लॉग इन करें:

```bash
curl -fsSL https://lizard.build/install.sh | bash
lizard login
```

आगे बढ़ने से पहले ब्राउज़र में लॉगिन पूरा करें। नीचे दी गई कमांड सितंबर 2026 में Lizard CLI 0.3.95 (Lizard CLI 4 से पहले) और Umami 3.3.1 के साथ टेस्ट की गई थीं।

<span id="create-the-project-and-database" />

## प्रोजेक्ट और डेटाबेस बनाएँ

इस डिप्लॉयमेंट के लिए एक नई डायरेक्टरी इस्तेमाल करें:

```bash
mkdir umami-on-lizard
cd umami-on-lizard
lizard init --name umami-on-lizard
lizard add postgres --name umami-db
lizard add --service umami
```

अगर आप एक से ज़्यादा वर्कस्पेस के सदस्य हैं, तो उनमें से एक चुनने के लिए `lizard init` को `--workspace <workspace>` दें। Umami डिप्लॉय करने से पहले डेटाबेस के `running` होने तक इंतज़ार करें।

<span id="set-the-image-and-secrets" />

## इमेज और सीक्रेट सेट करें

`Dockerfile` नाम की एक फ़ाइल बनाएँ:

```dockerfile
FROM ghcr.io/umami-software/umami:3.3.1
EXPOSE 3000
```

Lizard को बताएँ कि इस फ़ाइल को बिना बदले इस्तेमाल करे:

```bash
lizard service set umami --set dockerfilePath=Dockerfile
```

डेटाबेस कनेक्ट करें और दो अलग-अलग सीक्रेट जेनरेट करें:

```bash
lizard secrets set \
  DATABASE_URL='${{umami-db.DATABASE_PRIVATE_URL}}' \
  APP_SECRET="$(openssl rand -hex 32)" \
  TWO_FACTOR_ENCRYPTION_KEY="$(openssl rand -hex 32)" \
  --service umami
```

डेटाबेस रेफ़रेंस के चारों ओर सिंगल कोट्स रहने दें: सर्विस शुरू होने पर Lizard इसे प्रोजेक्ट के प्राइवेट नेटवर्क पर डेटाबेस के पते में बदल देता है। ये वैल्यू सिर्फ़ इसी सर्विस की हैं, इसलिए प्रोजेक्ट के दूसरे ऐप्स को ये नहीं मिलतीं।

जेनरेट किए गए दोनों सीक्रेट अपने पासवर्ड मैनेजर में सेव करें। इन्हें सेटअप के दौरान एक ही बार सेट करें; रीस्टार्ट या अपग्रेड करते समय इन्हें दोबारा जेनरेट न करें। टू-फ़ैक्टर ऑथेंटिकेशन के लिए `TWO_FACTOR_ENCRYPTION_KEY` ज़रूरी है।

<span id="deploy-and-sign-in" />

## डिप्लॉय करें और साइन इन करें

Dockerfile वाली डायरेक्टरी से चलाएँ:

```bash
lizard up --service umami --port 3000
```

Umami की इमेज स्टार्टअप पर अपना डेटाबेस सेटअप और माइग्रेशन खुद चलाती है। इस इमेज के लिए अलग से माइग्रेशन कमांड की ज़रूरत नहीं है।

डिप्लॉयमेंट से मिला HTTPS URL खोलें। Umami 3.3.1 के नए डेटाबेस के लिए यूज़रनेम `admin` और पासवर्ड `umami` से साइन इन करें, फिर URL किसी से शेयर करने से पहले तुरंत अपनी प्रोफ़ाइल में पासवर्ड बदलें। एक वेबसाइट जोड़ें और उसकी ट्रैकिंग स्क्रिप्ट ऐसे पेज पर लगाएँ जो आपके कंट्रोल में हो।

अगर डिप्लॉयमेंट फ़ेल हो जाए, तो उसकी स्थिति और लॉग देखें:

```bash
lizard events --service umami
lizard logs --build --service umami
lizard logs --service umami
```

अगर पहला स्टार्टअप टाइम आउट हो जाए, तो `lizard events` में देखें कि कंटेनर रेडी हुआ या नहीं। कंटेनर शुरू हो जाने के बाद `lizard up --service umami --port 3000` से अपलोड दोबारा करें।

अगर डैशबोर्ड कम ही लोग खोलते हैं, तो `lizard sleep --on --service umami` से [आइडल होने पर स्लीप](/cli/sleep) चालू करें; इसे चालू करने पर सर्विस एक बार रीस्टार्ट होती है। ट्रैक किए गए पेजव्यू रिक्वेस्ट के रूप में गिने जाते हैं, इसलिए ज़्यादा ट्रैफ़िक वाली साइट जागी रहती है। कुछ देर कोई ट्रैफ़िक न आने के बाद, सर्विस के जागने तक पहली रिक्वेस्ट में ज़्यादा समय लगता है।

<span id="check-data-persistence" />

## डेटा बना रहता है या नहीं, जाँचें

ट्रैक किए गए पेज पर जाएँ और पुष्टि करें कि Umami पेजव्यू दर्ज करता है। ऐप रीस्टार्ट करें:

```bash
lizard restart --service umami
```

सर्विस के फिर से चलने तक इंतज़ार करें। पुष्टि करें कि आपका नया पासवर्ड काम करता है और वेबसाइट और पेजव्यू बने हुए हैं। फिर रीडिप्लॉय के बाद यही जाँच दोहराएँ:

```bash
lizard redeploy --service umami
```

Umami अकाउंट, वेबसाइट की सेटिंग्स और एनालिटिक्स PostgreSQL में रखता है। इन रिकॉर्ड के लिए ऐप को फ़ाइल वॉल्यूम की ज़रूरत नहीं है। ऐप बदलते या अपग्रेड करते समय डेटाबेस और एन्क्रिप्शन सीक्रेट बनाए रखें। रीस्टार्ट वाली जाँच, टेस्ट किए गए डेटाबेस बैकअप और रीस्टोर प्लान की जगह नहीं ले सकती।

<span id="update-umami" />

## Umami अपडेट करें

अपग्रेड से पहले PostgreSQL का बैकअप लें और रिलीज़ नोट्स पढ़ें। लोकल Dockerfile में इमेज टैग बदलें, फिर `lizard up --service umami --port 3000` दोबारा चलाएँ। अपलोड वाले इस सेटअप में `lizard redeploy` आख़िरी बार अपलोड की गई फ़ाइलों को फिर से बिल्ड करता है; यह लोकल बदलाव अपलोड नहीं करता।

डेटाबेस एक्सेस के लिए [Lizard की PostgreSQL गाइड](https://lizard.build/docs/addons/postgres/) और बैकअप प्लानिंग के लिए [स्टोरेज और रिकवरी](https://lizard.build/docs/platform/storage-and-recovery/) देखें।
