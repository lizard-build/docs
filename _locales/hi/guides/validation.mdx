# परिदृश्य गाइड टेस्ट परिणाम

2026-09-07, पर हमने Lizard CLI 0.3.92. के साथ एक अलग टेस्ट प्रोजेक्ट में इन गाइडों की जांच की। ये परिणाम Lizard CLI 4 (सितंबर 17, 2026) और सितंबर 2026, के अंत में बिल्ड के वर्तमान बिल्डर में जाने से पहले के हैं और हमने तब से उन्हें फिर से नहीं चलाया है। एप्लिकेशन जांच बिल्ड स्थिति से अलग है। परीक्षणों ने गाइड कमांड का उपयोग किया, एक अलग प्रोजेक्ट नाम और GitHub उदाहरण के लिए प्रलेखन टेस्ट ब्रांच के साथ।

| गाइड | परिणाम | जांच |
|---|---|---|
| [रिमोट MCP](/guides/deploy-mcp-server) | स्थानीय रूप से और क्लाउड में पास हुआ | हेल्थ 200; मिसिंग और अमान्य टोकन 401; ऑथेंटिकेटेड GET 405; रिजेक्टेड ओरिजिन 403; इनिशियलाइज़, टूल्स/लिस्ट और टूल्स/कॉल; पब्लिक HTTPS पर परिणाम `5` |
| [कोडिंग एजेंट: अपलोड](/guides/deploy-from-coding-agent) | पास हुआ | `lizard up`, हेल्थ 200, डेटाबेस-बैक्ड रिस्पांस 200, अज्ञात रूट 404; एक अपडेटेड Postgres रो सेवा रीस्टार्ट के बाद बनी रही |
| [कोडिंग एजेंट: GitHub](/guides/deploy-from-coding-agent) | पास हुआ | `--no-deploy` के साथ रिपॉजिटरी अटैच की गई; ब्रांच, रूट डायरेक्टरी और एनवायरनमेंट `redeploy` से पहले कॉन्फ़िगर किया गया; पब्लिक ऐप ने वही मौजूदा Postgres रो पढ़ी |
| [Redis वर्कर](/deploy/workers) | पास हुआ | पोर्ट 0; एनक्यू और रिजल्ट; रीस्टार्ट के बाद रिजल्ट बना रहा; रीस्टार्ट के बाद नया जॉब; स्टार्टअप पर एक अधूरा प्रोसेसिंग एंट्री रिकवर हुआ |
| [Telegram बॉट](/guides/telegram-bot) | केवल लोकल टेस्ट | सात मॉक टेस्ट अपडेट, विफल सेंड, टोकन चेक और वेबहुक रिफ्यूजल को कवर करते हैं। एक वास्तविक टोकन, चैट और क्लाउड इको टेस्ट अभी भी आवश्यक हैं |

## संस्करण

MCP कंटेनर ने Node.js 22.23.2 को MCP TypeScript SDK 1.30.0. के साथ चलाया। कोडिंग-एजेंट उदाहरण `pg` 8.16.3 का उपयोग करता है और Managed Postgres पर चल रहे PostgreSQL 18.4. से जुड़ा है। वर्कर कंटेनर ने Python 3.13.15 को redis-py 6.4.0. के साथ चलाया। डिपेंडेंसी लॉकफ़ाइल या सटीक आवश्यकताएं उदाहरणों के साथ रहती हैं और अभी भी इन संस्करणों को पिन करती हैं; नए रिलीज़, जैसे MCP TypeScript SDK 1.32.1,, का परीक्षण नहीं किया गया है।

## स्कोप

MCP चेक उदाहरण के स्टेटलेस HTTP ट्रांसपोर्ट और फिक्स्ड बेयरर टोकन को कवर करता है। यह OAuth संगतता, ब्राउज़र समर्थन, लंबी अवधि की स्ट्रीमिंग या लोड क्षमता स्थापित नहीं करता है। टोकन एक घंटे के बाद समाप्त हो जाता है।

GitHub चेक ने प्रलेखन ब्रांच और `_examples/agent-app` डायरेक्टरी का उपयोग किया। कोडिंग-एजेंट टेस्ट पब्लिक `DATABASE_URL` के माध्यम से जुड़ा; गाइड अब `DATABASE_PRIVATE_URL` का उपयोग करता है, जिसका अभी तक कोई क्लाउड रन नहीं है। GitHub चेक ने एक स्पष्ट रीडिप्लॉय का परीक्षण किया; इसने हर प्राइवेट-रिपॉजिटरी अनुमति सेटअप या वेबहुक इवेंट का परीक्षण नहीं किया।

Redis रिकवरी चेक ने एक सिंगल कंज्यूमर को रीस्टार्ट करने से पहले एक अधूरी प्रोसेसिंग एंट्री को सीड किया। इसने Redis विफलता, एकाधिक वर्कर या ठीक-एक-बार बाहरी प्रभावों का परीक्षण नहीं किया। डेटाबेस चेक एप्लिकेशन रीस्टार्ट में दृढ़ता स्थापित करता है, बैकअप या आपदा रिकवरी नहीं।

टेस्ट सेवाओं के लिए रनटाइम लॉग टेल शुरू में खाली थे। एक लाइव वर्कर लॉग स्ट्रीम ने बाद में एक नया प्रोसेस्ड जॉब डिलीवर किया। पूर्णता मानदंड के रूप में HTTP, MCP क्लाइंट और जॉब-रिजल्ट चेक का उपयोग करें; एक खाली लॉग टेल अकेले सफलता या विफलता स्थापित नहीं करता है।

Telegram उदाहरण को क्लाउड-वेरिफाइड के रूप में चिह्नित नहीं किया गया है। इसके प्रीफ़्लाइट बॉट के वेबहुक को बदले बिना `getMe` और `getWebhookInfo` को पढ़ता है। इसके पोलिंग लूप को सक्षम करने से पहले एक अलग टेस्ट बॉट का उपयोग करें।

16 रेसिपी वाले अलग फ्रेमवर्क बैच के लिए [फ्रेमवर्क परीक्षण के नतीजे](/framework-guides/validation) देखें। CLI आर्काइव और विफल बिल्ड के exit code की सीमाओं के लिए [ज्ञात समस्याएँ](/platform/known-issues) देखें।
