# Claude Code, Codex या Cursor से डिप्लॉय करें

Claude Code, Codex और Cursor Lizard पर Lizard Skill और Lizard CLI का उपयोग करके ऐप को डिप्लॉय कर सकते हैं। एजेंट इंस्टॉल किए गए CLI के गाइड को पढ़ता है, टारगेट प्रोजेक्ट की जाँच करता है, बिल्ड चलाता है और लाइव URL की जाँच करता है। इसे किसी अलग MCP ट्रांसपोर्ट की आवश्यकता नहीं है। लोकल या GitHub सोर्स को डिप्लॉय करने के लिए नीचे दिए गए प्रॉम्प्ट का उपयोग करें, फिर बिल्ड, पब्लिक URL और डेटाबेस कनेक्शन की जाँच करें।

<span id="before-you-start" />

## शुरू करने से पहले

आपके पास एक वर्किंग एप्लीकेशन, उसे डिप्लॉय करने की अनुमति, और Pro पर Lizard अकाउंट या 7-दिन Pro ट्रायल (कार्ड आवश्यक) होना चाहिए। ट्रायल शुरू होने तक, `lizard add` और `lizard up` एक चेकआउट लिंक के साथ HTTP 402 लौटाते हैं; `lizard billing start` इसे खोलता है। एप्लीकेशन को `0.0.0.0` और कॉन्फ़िगर किए गए पोर्ट पर सुनना चाहिए। क्लाउड बिल्ड शुरू करने से पहले इसके लोकल चेक चलाएँ।

<span id="give-the-agent-the-current-guide" />

## एजेंट को वर्तमान गाइड दें

```bash
curl -fsSL https://lizard.build/install.sh | bash
lizard skills get core --json
lizard --help --json
```

Windows पर PowerShell में `irm https://lizard.build/api/cli/install.ps1 | iex` चलाएँ या npm से `npm install -g @lizard-build/cli` चलाकर इंस्टॉल करें।

स्किल को अपने मशीन पर हर एजेंट के लिए उपलब्ध कराने के लिए, इसे `npx skills add lizard-build/skill -g` के साथ एक बार इंस्टॉल करें; [कोडिंग एजेंट](/agents) देखें। Lizard Skill ऐसे निर्देश लोड करता है जो इंस्टॉल किए गए CLI से मेल खाते हैं। किसी विशिष्ट कमांड के लिए, फ़्लैग का अनुमान लगाने के बजाय उसके स्कीमा को पढ़ें:

```bash
lizard up --help --json
lizard service set --help --json
```

Claude Code, Codex या Cursor में पेस्ट करने के लिए एक उपयोगी प्रॉम्प्ट है:

> इस ऐप को Lizard के साथ डिप्लॉय करें। इंस्टॉल किए गए CLI गाइड को पढ़ें, लिंक किए गए प्रोजेक्ट और सर्विस की जाँच करें, ऐप के चेक चलाएँ, और बिल्ड परिणाम और एक वर्किंग URL दिखाएँ। किसी मौजूदा प्रोडक्शन सर्विस को बदलने या डेटा हटाने से पहले पूछें।

<span id="deploy-local-source" />

## लोकल सोर्स डिप्लॉय करें

एक पूर्ण परीक्षण के लिए, [एजेंट-ऐप उदाहरण](https://github.com/lizard-build/docs/tree/23635ba7e162bafce75d3f6206553b3ef2c0c48e/_examples/agent-app) का उपयोग करें। यह Node.js 22 और `pg` का उपयोग करता है। 8.16.3, पोर्ट 3000 पर सुनता है और Managed Postgres से एक पंक्ति पढ़ता है। इसका स्टार्टअप डेमो टेबल और पंक्ति बनाता है यदि वे मौजूद नहीं हैं। एक बड़े एप्लीकेशन के लिए, अपनी माइग्रेशन प्रक्रिया का उपयोग करें।

उदाहरण को अपनी डायरेक्टरी में कॉपी करें और इसके लोकल चेक चलाएँ:

```bash
npm ci
npm run check
lizard status --json
```

यह JavaScript सिंटैक्स की जाँच करता है। डेटाबेस और पब्लिक HTTP चेक डिप्लॉयमेंट के बाद आते हैं। यदि यह डायरेक्टरी पहले से लिंक है, तो जाँचें कि क्या यह इच्छित प्रोजेक्ट है। एक नए परीक्षण प्रोजेक्ट के लिए:

```bash
lizard init --name agent-example --json
lizard add --service api --json
lizard add postgres --json
lizard secrets set DATABASE_URL='${{postgres.DATABASE_PRIVATE_URL}}' --service api --json
lizard up --service api --port 3000 --json
```

यदि डेटाबेस `postgres` नहीं है तो डेटाबेस का वास्तविक नाम उपयोग करें। `DATABASE_PRIVATE_URL` प्रोजेक्ट के प्राइवेट नेटवर्क पर डेटाबेस तक पहुँचता है और उसी प्रोजेक्ट और क्षेत्र की सेवाओं से काम करता है; [Postgres कनेक्शन स्ट्रिंग](/addons/postgres#postgres-connection-string) देखें। लोकल शेल द्वारा इसे विस्तारित होने से बचाने के लिए संदर्भ को उद्धृत रखें। पहले डिप्लॉयमेंट से पहले इसे कॉन्फ़िगर करें। केवल तभी `lizard login` के साथ साइन इन करें जब कोई कमांड रिपोर्ट करे कि प्रमाणीकरण आवश्यक है।

इस कॉपी किए गए उदाहरण के लिए अपलोड का उपयोग करें। GitHub में पहले से मौजूद एप्लीकेशन के लिए, इसके बजाय अगला सेक्शन उपयोग करें। एक असफल बिल्ड कोड 1 के साथ बाहर निकलता है; फिर भी टर्मिनल `failed`/`deployed` इवेंट का निरीक्षण करें और एप्लीकेशन को सत्यापित करें। [ज्ञात समस्याएँ](/platform/known-issues) देखें।

## GitHub से डिप्लॉय करें

जब एप्लीकेशन का GitHub रिपॉजिटरी हो तो इस पाथ का उपयोग करें। पहले रिमोट की जाँच करें:

```bash
git remote get-url origin
lizard status --json
lizard ps --json
```

एक लिंक्ड टेस्ट प्रोजेक्ट का उपयोग करें या `lizard init --name YOUR_PROJECT_NAME` के साथ एक बनाएँ। बिल्ड शुरू किए बिना रिपॉजिटरी संलग्न करें ताकि इसके एनवायरनमेंट को कॉन्फ़िगर करने का समय मिल सके:

```bash
lizard add --repo YOUR_ORG/YOUR_REPO --name api-git --no-deploy --json
lizard secrets set DATABASE_URL='${{postgres.DATABASE_PRIVATE_URL}}' --service api-git --json
```

यदि इस प्रोजेक्ट में यह नहीं है तो पहले Managed Postgres को प्रोविजन करें। यह अनुक्रम ऊपर वाले समान Node.js उदाहरण का उपयोग करता है। किसी सबडायरेक्टरी में या किसी अन्य ब्रांच पर उस ऐप वाले रिपॉजिटरी के लिए, डिप्लॉयमेंट से पहले इसे कॉन्फ़िगर करें:

```bash
lizard service set api-git --set branch=YOUR_BRANCH --set rootDirectory=YOUR_APP_DIRECTORY --set containerPort=3000 --json
lizard redeploy --service api-git --json
```

`main` पर रिपॉजिटरी रूट पर ऐप के लिए, `service set` कमांड को छोड़ दें। यदि आपका एप्लीकेशन किसी अन्य पोर्ट का उपयोग करता है तो सही पोर्ट सेट करें। यदि रिपॉजिटरी Lizard के लिए उपलब्ध नहीं है, तो GitHub ऐप कनेक्ट करें; इस पाथ को चुपचाप अपलोड से न बदलें।

किसी मौजूदा GitHub सर्विस के लिए बाद के अपडेट के लिए, `lizard redeploy --service api-git` का उपयोग करें या ऑटो-डिप्लॉय सक्षम होने पर उसके ट्रैक किए गए ब्रांच पर पुश करें। `lizard up` किसी सर्विस को सोर्स अपलोड करने के लिए स्विच करता है। पहले से चल रही सर्विस पर बिल्ड सेटिंग्स बदलने से उसका अपना बिल्ड ट्रिगर हो सकता है; दूसरे का अनुरोध करने से पहले इवेंट का निरीक्षण करें।

## परिणाम सत्यापित करें

बिल्ड और रनटाइम लॉग को अलग-अलग पढ़ें:

```bash
lizard logs --build --service api --json
lizard logs --service api --json
lizard ps --json
```

GitHub पाथ के लिए `api` के बजाय `api-git` का उपयोग करें। CLI द्वारा रिपोर्ट किए गए HTTPS URL पर `APP_URL` सेट करें, फिर चलाएँ:

```bash
curl --fail "$APP_URL/health"
curl --fail "$APP_URL/data"
```

पहला रिस्पांस `App ready` है। दूसरा `{"value":"database-connected"}` है। केवल एक बिल्ड डेटाबेस संदर्भ के हल होने का प्रमाण नहीं देता है। उदाहरण केवल इस फिक्स्ड डेमो रो को एक्सपोज़ करता है, न कि डेटाबेस एडमिनिस्ट्रेशन API को।

इस टेस्ट सर्विस के लिए, रनटाइम रीस्टार्ट सत्यापित करें:

```bash
lizard restart --service api --json
```

सेवा के `lizard ps --json` में `running` पर वापस आने की प्रतीक्षा करें और दोनों HTTP अनुरोधों को दोहराएँ। रनटाइम लॉग टेल खाली हो सकता है; HTTP प्रतिक्रिया एप्लीकेशन की जाँच है। Managed Postgres रो को स्टोर करता है, इसलिए यह सेवा पुनरारंभ होने पर भी बनी रहती है। मौजूदा डेटा के पुन: उपयोग की जाँच करने के लिए, पुनरारंभ करने से पहले डेमो रो को डेटाबेस एडिटर में एक अलग मान में अपडेट करें और पुष्टि करें कि `/data` बाद में वह मान लौटाता है।

`logs --json` एक लॉग टेल लौटाता है और बाहर निकल जाता है। वास्तविक एप्लीकेशन डेटा को बदलने से पहले [स्टोरेज और रिकवरी](/platform/storage-and-recovery) पढ़ें।

<span id="when-deployment-fails" />

## जब डिप्लॉयमेंट विफल हो जाता है

विफल कमांड से एग्जिट कोड और JSON एरर का उपयोग करें। एक कंपाइल एरर, एक प्रोसेस जो एग्जिट हो जाती है, और एक अनरीचेबल पोर्ट के लिए अलग-अलग फिक्स की आवश्यकता होती है। [JSON और ऑटोमेशन](/cli/json) और [सर्विस कभी हेल्दी नहीं](/deploy/troubleshooting/service-never-healthy) देखें। `redeploy` एक नया बिल्ड है, पुराने वर्जन पर रोलबैक नहीं।

<span id="limits-and-cost" />

## सीमाएँ और लागत

एक एजेंट उसी CLI के माध्यम से बिल योग्य संसाधन बना सकता है जैसे एक व्यक्ति। [सीमाएँ](/platform/limits) और [मूल्य निर्धारण](https://lizard.build/pricing) देखें, और क्रेडेंशियल्स को प्रोजेक्ट और आवश्यक सेवाओं तक सीमित करें।

एजेंट को अपने लैपटॉप के बजाय एक अलग मशीन पर चलाने के लिए, [सैंडबॉक्स में Claude Code](/sandboxes/guides/claude-code) देखें।

जाँची गई संस्करणों, क्लाउड परिणामों और शेष सीमाओं के लिए [परिदृश्य परीक्षण परिणाम](/guides/validation) देखें।
