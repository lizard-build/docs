# एक टेलीग्राम बॉट चलाएं

एक लॉन्ग-पोलिंग बॉट एक बैकग्राउंड वर्कर है: यह अपडेट के लिए टेलीग्राम से पूछता है और इसे सार्वजनिक HTTP एंडपॉइंट की आवश्यकता नहीं होती है। इसे `containerPort=0` और प्रति बॉट टोकन एक रेप्लिका के साथ चलाएँ।

**परीक्षण स्थिति:** मॉक किए गए टेलीग्राम प्रतिक्रियाओं के साथ सात स्थानीय परीक्षण पास होते हैं। हमने इस गाइड को क्लाउड में एक वास्तविक बॉट के साथ जांचा नहीं है। एक अलग परीक्षण बॉट का उपयोग करें और नीचे दिए गए संदेश और पुनरारंभ जांचों को पूरा करें, इससे पहले कि आप इस पर भरोसा करें। [परिदृश्य परीक्षण परिणाम](/guides/validation) देखें।

<span id="before-you-start" />

## शुरू करने से पहले

BotFather के साथ एक बॉट बनाएँ और इसका टोकन निजी रखें। आपको Python 3.13, Lizard CLI, और एक प्रोजेक्ट की आवश्यकता होगी जिसे आप डिप्लॉय कर सकें। लॉन्ग पोलिंग का उपयोग करने वाले बॉट का सक्रिय वेबहुक नहीं होना चाहिए; इसे प्राप्त करने के तरीके को बदलने से पहले इसकी वर्तमान कॉन्फ़िगरेशन की जाँच करें।

[उदाहरण फ़ाइलें](https://github.com/lizard-build/docs/tree/23635ba7e162bafce75d3f6206553b3ef2c0c48e/_examples/telegram-worker) में `worker.py`, एक Dockerfile, और स्थानीय यूनिट परीक्षण शामिल हैं। परीक्षण टेलीग्राम को कॉल नहीं करते हैं। इको हैंडलर अपनी ऑफसेट को मेमोरी में संग्रहीत करता है; यह एक एक्जैक्टली-वन्स प्रोसेसिंग सिस्टम नहीं है।

<span id="check-locally" />

## स्थानीय रूप से जाँचें

उदाहरण डायरेक्टरी से:

```bash
python3 -m unittest -v
```

जाँचों में टेक्स्ट रिप्लाई, अनदेखे अपडेट, खाली पोल और विफल सेंड शामिल हैं। बॉट को स्थानीय रूप से `TELEGRAM_BOT_TOKEN` के साथ तभी चलाएँ जब आप रिप्लाई भेजने का इरादा रखते हों। होस्टेड वर्कर शुरू करने से पहले उस स्थानीय प्रक्रिया को रोक दें।

<span id="deploy-as-a-worker" />

## वर्कर के रूप में डिप्लॉय करें

```bash
lizard init --name telegram-bot
lizard add --service bot
```

यदि कोई कमांड प्रमाणीकरण की आवश्यकता होने की रिपोर्ट करता है तो `lizard login` के साथ साइन इन करें। डिप्लॉय करने से पहले **बॉट सेवा** पर `TELEGRAM_BOT_TOKEN` सेट करें। आप डैशबोर्ड के वेरिएबल्स एडिटर का उपयोग कर सकते हैं, या मान को स्थानीय `.env` फ़ाइल में डाल सकते हैं और इसे इम्पोर्ट कर सकते हैं:

```bash
lizard secrets import --service bot < .env
lizard run --service bot -- python3 check_bot.py
lizard up --service bot --port 0
```

प्रीफ़्लाइट `getMe` के साथ टोकन की जाँच करता है और सक्रिय वेबहुक वाले बॉट को अस्वीकार करता है। यह उस वेबहुक को हटाता या बदलता नहीं है। दूसरी पोलिंग प्रक्रिया अभी भी टकराव कर सकती है: डिप्लॉयमेंट से पहले किसी भी स्थानीय कॉपी को रोक दें।

एक गिट रिपॉजिटरी के अंदर, उदाहरण का `.gitignore` `.env*` को अपलोड से बाहर रखता है। गिट के बाहर, CLI `.env` अपलोड करता है, इसलिए पहले उदाहरण डायरेक्टरी में `git init` चलाएँ; इसका `.dockerignore` फ़ाइल को दोनों तरह से इमेज से बाहर रखता है। टोकन को स्रोत फ़ाइलों और स्क्रीनशॉट से बाहर रखें। सफल निकास के बावजूद अंतिम डिप्लॉयमेंट इवेंट और लॉग पढ़ें।

मौजूदा सेवा के लिए, वर्कर मोड को स्पष्ट रूप से सेट करें:

```bash
lizard service set bot --set containerPort=0
```

चल रही सेवा पर वर्कर मोड बदलने के बाद, `lizard redeploy --service bot` के साथ इसे लागू करें। एक और बिल्ड का अनुरोध करने से पहले डिप्लॉयमेंट इवेंट की जाँच करें। वर्कर मोड HTTP पोर्ट जांचों और लोड-बैलेंसर रूट को छोड़ देता है; इस प्रक्रिया को HTTP ऐप की तरह दिखाने के लिए एक डमी वेब सर्वर न जोड़ें।

<span id="verify-the-result" />

## परिणाम सत्यापित करें

```bash
lizard ps --json
lizard logs --service bot --json
lizard events --json
```

लॉग में `Telegram worker started` दिखना चाहिए। अपने बॉट को एक संदेश भेजें और एक इको रिप्लाई के लिए जाँच करें। फिर स्वीकृत परीक्षण विंडो के दौरान वर्कर को रोकें और पुनरारंभ करें और पुष्टि करें कि यह फिर से जुड़ता है। एक वर्कर जिसे चल रहा के रूप में चिह्नित किया गया है, उसे अभी भी इस एप्लिकेशन-स्तरीय जांच की आवश्यकता है।

## सामान्य विफलताएँ

| लक्षण | जाँच |
|---|---|
| प्रक्रिया तुरंत बाहर निकल जाती है | उपभोग करने वाली सेवा पर `TELEGRAM_BOT_TOKEN` सेट करें। |
| HTTP स्वास्थ्य जांच कभी पास नहीं होती | वर्कर मोड को `containerPort=0` का उपयोग करना चाहिए। |
| अपडेट रुक जाते हैं या कॉन्फ़्लिक्ट त्रुटियाँ दिखाई देती हैं | केवल एक पोलिंग प्रक्रिया को इस टोकन का उपयोग करना चाहिए; स्थानीय प्रक्रिया, अन्य रेप्लिका, या सक्रिय वेबहुक की जाँच करें। |
| विफलता के बाद बार-बार रिप्लाई | डेमो ऑफसेट को बनाए नहीं रखता या अपडेट आईडी को डी-डुप्लिकेट नहीं करता है। अपरिवर्तनीय क्रियाओं को संभालने से पहले टिकाऊ इडेम्पोटेंसी जोड़ें। |
| बार-बार पुनः प्रयास | नेटवर्क एक्सेस, टोकन वैधता, टेलीग्राम सीमाएं, और अपने हैंडलर की जाँच करें। अनुरोध URL प्रिंट न करें: उनमें टोकन होता है। |

## स्थिति और लागत

टिकाऊ बॉट स्थिति के लिए, [Managed Postgres](/addons/postgres) कनेक्ट करें। संसाधित अपडेट आईडी स्टोर करें और हैंडलर को पुनः प्रयास के लिए सुरक्षित बनाएं। लॉन्ग पोलिंग वर्कर को संदेशों के बीच सक्रिय रख सकता है; [मूल्य निर्धारण](https://lizard.build/pricing) और देखे गए संसाधन उपयोग से बजट बनाएं, न कि केवल संदेश गणना से।
