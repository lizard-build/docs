# Telegram बॉट चलाएँ

लॉन्ग-पोलिंग बॉट एक बैकग्राउंड वर्कर है: यह Telegram से अपडेट माँगता है और इसे पब्लिक HTTP एंडपॉइंट की ज़रूरत नहीं होती। इसे `containerPort=0` के साथ और हर बॉट टोकन के लिए एक रेप्लिका के साथ चलाएँ।

**टेस्ट की स्थिति:** Telegram के मॉक किए गए रिस्पॉन्स के साथ सात लोकल टेस्ट पास होते हैं। हमने यह गाइड क्लाउड में असली बॉट के साथ नहीं जाँची है। इस पर भरोसा करने से पहले एक अलग टेस्ट बॉट इस्तेमाल करें और नीचे दी गई मैसेज और रीस्टार्ट वाली जाँच पूरी करें। [सिनेरियो टेस्ट के नतीजे](/guides/validation) देखें।

<span id="before-you-start" />

## शुरू करने से पहले

BotFather से एक बॉट बनाएँ और उसका टोकन किसी को न दिखाएँ। आपको Python 3.13, Lizard CLI और ऐसा प्रोजेक्ट चाहिए जिसमें आप डिप्लॉय कर सकें। लॉन्ग पोलिंग इस्तेमाल करने वाले बॉट पर कोई एक्टिव webhook नहीं होना चाहिए; बॉट के अपडेट पाने का तरीका बदलने से पहले उसकी मौजूदा कॉन्फ़िगरेशन जाँचें।

[उदाहरण फ़ाइलों](https://github.com/lizard-build/docs/tree/23635ba7e162bafce75d3f6206553b3ef2c0c48e/_examples/telegram-worker) में `worker.py`, एक Dockerfile और लोकल यूनिट टेस्ट हैं। टेस्ट Telegram को कॉल नहीं करते। echo हैंडलर अपना offset मेमोरी में रखता है; यह exactly-once प्रोसेसिंग सिस्टम नहीं है।

<span id="check-locally" />

## लोकल में जाँचें

उदाहरण की डायरेक्टरी से:

```bash
python3 -m unittest -v
```

ये जाँच टेक्स्ट रिप्लाई, नज़रअंदाज़ किए गए अपडेट, खाली पोल और फ़ेल हुई सेंडिंग को कवर करती हैं। बॉट को लोकल में `TELEGRAM_BOT_TOKEN` के साथ तभी चलाएँ जब आप सच में रिप्लाई भेजना चाहते हों। होस्टेड वर्कर शुरू करने से पहले वह लोकल प्रोसेस बंद कर दें।

<span id="deploy-as-a-worker" />

## वर्कर के रूप में डिप्लॉय करें

```bash
lizard init --name telegram-bot
lizard add --service bot
```

अगर कोई कमांड बताए कि ऑथेंटिकेशन ज़रूरी है, तो `lizard login` से साइन इन करें। डिप्लॉय करने से पहले **bot सर्विस** पर `TELEGRAM_BOT_TOKEN` सेट करें। आप डैशबोर्ड का वेरिएबल एडिटर इस्तेमाल कर सकते हैं, या वैल्यू को लोकल `.env` फ़ाइल में रखकर इम्पोर्ट कर सकते हैं:

```bash
lizard secrets import --service bot < .env
lizard run --service bot -- python3 check_bot.py
lizard up --service bot --port 0
```

प्रीफ़्लाइट `getMe` से टोकन जाँचता है और एक्टिव webhook वाले बॉट को आगे नहीं बढ़ने देता। यह उस webhook को न हटाता है, न बदलता है। कोई दूसरा पोलिंग प्रोसेस फिर भी टकरा सकता है: डिप्लॉयमेंट से पहले हर लोकल कॉपी बंद कर दें।

git रिपॉज़िटरी के अंदर उदाहरण का `.gitignore` `.env*` फ़ाइलों को अपलोड से बाहर रखता है। git के बाहर CLI `.env` भी अपलोड कर देता है, इसलिए पहले उदाहरण की डायरेक्टरी में `git init` चलाएँ; उसका `.dockerignore` हर हाल में इस फ़ाइल को इमेज से बाहर रखता है। टोकन को सोर्स फ़ाइलों और स्क्रीनशॉट में न आने दें। कमांड सफलतापूर्वक खत्म होने पर भी आख़िरी डिप्लॉयमेंट इवेंट और लॉग पढ़ें।

किसी मौजूदा सर्विस के लिए वर्कर मोड साफ़ तौर पर सेट करें:

```bash
lizard service set bot --set containerPort=0
```

चल रही सर्विस पर वर्कर मोड बदलने के बाद उसे `lizard redeploy --service bot` से लागू करें। दूसरा बिल्ड माँगने से पहले डिप्लॉयमेंट इवेंट्स देखें। वर्कर मोड HTTP पोर्ट की जाँच और लोड-बैलेंसर रूट छोड़ देता है; इस प्रोसेस को HTTP ऐप जैसा दिखाने के लिए कोई डमी वेब सर्वर न जोड़ें।

<span id="verify-the-result" />

## नतीजा वेरिफ़ाई करें

```bash
lizard ps --json
lizard logs --service bot --json
lizard events --json
```

लॉग में `Telegram worker started` दिखना चाहिए। अपने बॉट को एक मैसेज भेजें और देखें कि एक echo रिप्लाई आता है। फिर तय किए गए टेस्ट समय में वर्कर को बंद करके दोबारा शुरू करें और पुष्टि करें कि वह फिर से कनेक्ट हो जाता है। running दिखने वाले वर्कर के लिए भी ऐप-लेवल की यह जाँच ज़रूरी है।

<span id="common-failures" />

## आम गड़बड़ियाँ

| लक्षण | जाँच |
|---|---|
| प्रोसेस तुरंत बंद हो जाता है | जो सर्विस टोकन इस्तेमाल करती है, उस पर `TELEGRAM_BOT_TOKEN` सेट करें। |
| HTTP हेल्थ चेक कभी पास नहीं होता | वर्कर मोड में `containerPort=0` होना चाहिए। |
| अपडेट आने बंद हो जाते हैं या conflict एरर दिखते हैं | इस टोकन को सिर्फ़ एक पोलिंग प्रोसेस इस्तेमाल करे; कोई लोकल प्रोसेस, दूसरी रेप्लिका या एक्टिव webhook तो नहीं है, यह जाँचें। |
| गड़बड़ी के बाद बार-बार रिप्लाई | डेमो offset सेव नहीं करता और अपडेट ID का डुप्लिकेट नहीं हटाता। ऐसे काम संभालने से पहले जिन्हें वापस नहीं लिया जा सकता, टिकाऊ idempotency जोड़ें। |
| बार-बार रीट्राई | नेटवर्क एक्सेस, टोकन की वैधता, Telegram की सीमाएँ और अपना हैंडलर जाँचें। रिक्वेस्ट URL प्रिंट न करें: उनमें टोकन होता है। |

<span id="state-and-cost" />

## स्टेट और लागत

बॉट की स्टेट लंबे समय तक रखने के लिए [Managed Postgres](/addons/postgres) कनेक्ट करें। प्रोसेस किए गए अपडेट ID सेव करें और हैंडलर ऐसे बनाएँ कि रीट्राई होने पर कोई नुकसान न हो। लॉन्ग पोलिंग की वजह से वर्कर मैसेज के बीच भी एक्टिव रह सकता है; बजट सिर्फ़ मैसेज की गिनती से नहीं, बल्कि [प्राइसिंग](https://lizard.build/pricing) और देखे गए संसाधन उपयोग से बनाएँ।
