# रिमोट MCP सर्वर होस्ट करें

जब क्लाइंट्स को रिमोट URL चाहिए, तो MCP सर्वर को HTTP ऐप के रूप में डिप्लॉय करें। यह उदाहरण गणित का एक टूल देता है, bearer टोकन जाँचता है और एक हेल्थ एंडपॉइंट खोलता है। यह Streamable HTTP ट्रांसपोर्ट इस्तेमाल करता है; लोकल `stdio` सर्वर अपने-आप रिमोट क्लाइंट्स को सर्व नहीं कर सकता।

<span id="before-you-start" />

## शुरू करने से पहले

आपको Node.js 22, Lizard CLI, ऐसा प्रोजेक्ट जिसमें आप डिप्लॉय कर सकें, और ऐसा MCP क्लाइंट चाहिए जो कॉन्फ़िगर किया गया bearer टोकन स्वीकार करता हो। उदाहरण stateless मोड में `@modelcontextprotocol/sdk` 1.30.0 इस्तेमाल करता है। इसमें OAuth लॉगिन, ब्राउज़र एक्सेस या आइडेंटिटी प्रोवाइडर नहीं है।

चलाने लायक फ़ाइलें [remote-mcp-node](https://github.com/lizard-build/docs/tree/23635ba7e162bafce75d3f6206553b3ef2c0c48e/_examples/remote-mcp-node) में हैं। रिपॉज़िटरी में मौजूद लॉकफ़ाइल ही इस्तेमाल करें। लोकल स्मोक टेस्ट इनिशियलाइज़ेशन, टूल डिस्कवरी, एक टूल कॉल, और सही टोकन के बिना रिक्वेस्ट रिजेक्ट होना जाँचता है। डिप्लॉयमेंट की जाँच में पब्लिक प्रॉक्सी और TLS पाथ की भी पुष्टि होनी चाहिए।

<span id="run-locally" />

## लोकल में चलाएँ

उदाहरण की डायरेक्टरी से:

```bash
npm ci
npm test
node issue-token.mjs
export MCP_PUBLIC_KEY="$(cat .mcp-public-key.pem)"
export MCP_ALLOWED_HOSTS=127.0.0.1,localhost
npm start
```

जेनरेट किया गया टोकन एक घंटे बाद एक्सपायर हो जाता है। प्राइवेट साइनिंग की कहीं सेव नहीं होती। लंबे समय चलने वाले डिप्लॉयमेंट के लिए अपना टोकन जारी करने और रोटेट करने का तरीका इस्तेमाल करें; उसकी प्राइवेट की सर्वर के बाहर रखें।

दूसरे टर्मिनल में:

```bash
export MCP_URL=http://127.0.0.1:8000/mcp
export MCP_TOKEN="$(cat .mcp-token)"
node client.mjs
```

क्लाइंट इनिशियलाइज़ेशन, टूल डिस्कवरी और नतीजा `5` जाँचता है, फिर `MCP initialize, tools/list and tools/call passed: 5` प्रिंट करता है। `/health` से `ok` मिलता है; सही टोकन के बिना `/mcp` पर रिक्वेस्ट भेजने पर `401` मिलता है।

<span id="deploy-the-application" />

## ऐप डिप्लॉय करें

उदाहरण का Dockerfile और लॉकफ़ाइल वैसे ही रखें। जिस डायरेक्टरी में ये हैं, वहाँ से:

```bash
lizard init --name mcp-example
lizard add --service mcp
lizard domain --service mcp --json
```

अगर कोई कमांड बताए कि ऑथेंटिकेशन ज़रूरी है, तो `lizard login` से साइन इन करें। `init` प्रोजेक्ट लिंक करता है; `add` दिए गए नाम की सर्विस बनाता है। domain कमांड डिप्लॉयमेंट से पहले ही सर्विस का होस्टनाम तय कर देती है। कमांड से लौटाया गया `hostname` नीचे की कमांड में डालें, `https://` या पाथ के बिना:

```bash
lizard secrets set MCP_PUBLIC_KEY="$(cat .mcp-public-key.pem)" --service mcp
lizard secrets set MCP_ALLOWED_HOSTS=YOUR_SERVICE_HOSTNAME --service mcp
```

पहले डिप्लॉयमेंट से पहले दोनों वैल्यू सेट करें। फिर चलाएँ:

```bash
lizard up --service mcp --port 8000
lizard logs --build --service mcp --json
lizard logs --service mcp --json
lizard ps --json
```

सिर्फ़ एग्ज़िट कोड नहीं, बल्कि आख़िरी डिप्लॉयमेंट इवेंट और पब्लिक एंडपॉइंट भी जाँचें। `server.mjs` `0.0.0.0` पर लिसन करता है और `PORT` पढ़ता है, जिसका डिफ़ॉल्ट 8000 है। डिप्लॉय कमांड सर्विस का पोर्ट 8000 पर सेट करती है। पब्लिक की को मल्टीलाइन एनवायरनमेंट वैल्यू के रूप में कॉन्फ़िगर करें; प्राइवेट साइनिंग की या टोकन फ़ाइल अपलोड न करें।

<span id="verify-the-public-endpoint" />

## पब्लिक एंडपॉइंट वेरिफ़ाई करें

`MCP_URL` को `https://YOUR_SERVICE_HOSTNAME/mcp` पर सेट करें, क्लाइंट के एनवायरनमेंट में सही टोकन रखें, और `node client.mjs` चलाएँ। तीनों नतीजे जाँचें:

1. HTTPS पर `/health` से `200` मिलता है।
2. सही टोकन के बिना क्लाइंट को `/mcp` रिजेक्ट कर देता है।
3. ऑथेंटिकेटेड क्लाइंट टूल्स की सूची लेता है और `add` को कॉल करता है, जिससे `5` लौटता है।

सिर्फ़ प्रोसेस का ठीक चलना यह साबित नहीं करता कि MCP हैंडशेक या स्ट्रीम किया गया रिस्पॉन्स पब्लिक प्रॉक्सी से होकर काम कर रहा है।

<span id="troubleshooting" />

## समस्या निवारण

| नतीजा | जाँच |
|---|---|
| स्टार्टअप के दौरान प्रोसेस बंद हो जाता है | `MCP_PUBLIC_KEY` में पब्लिक PEM की होनी चाहिए; `MCP_ALLOWED_HOSTS` में सर्विस का होस्टनाम होना चाहिए। |
| `401` | टोकन RS256 से साइन होना चाहिए, उसका issuer और audience `mcp-example` होना चाहिए, और वह एक्सपायर नहीं होना चाहिए। |
| `403` | रिक्वेस्ट का होस्टनाम `MCP_ALLOWED_HOSTS` से मिलाएँ। यह उदाहरण ब्राउज़र origins की अनुमति नहीं देता। |
| सही टोकन के साथ `405` | यह stateless MCP एंडपॉइंट प्रोटोकॉल रिक्वेस्ट सिर्फ़ POST से लेता है। MCP क्लाइंट इस्तेमाल करें। टोकन के बिना ब्राउज़र से GET करने पर पहले ही `401` मिलता है। |
| लोकल टेस्ट पास होता है लेकिन रिमोट कॉल फ़ेल होती है | पोर्ट, HTTPS, रिस्पॉन्स स्ट्रीमिंग और प्रॉक्सी टाइमआउट जाँचें। |

<span id="limits-and-cost" />

## सीमाएँ और लागत

यह उदाहरण सर्वर की मेमोरी में न यूज़र सेशन रखता है, न स्थायी फ़ाइलें। ऐप की लंबे समय तक रहने वाली स्टेट के लिए डेटाबेस जोड़ें, और प्राइवेट टूल्स खोलने से पहले हर यूज़र का एक्सेस जाँचें। जिन क्लाइंट्स को OAuth डिस्कवरी या इंटरैक्टिव लॉगिन चाहिए, उनके लिए यह टेस्ट टोकन बाँटने के बजाय कोई सपोर्टेड OAuth प्रोवाइडर जोड़ें।

सर्वर कॉल्स के बीच भी चलता रहता है, और जब तक वह चलता है, Lizard उसके मापे गए CPU और मेमोरी का बिल बनाता है। आइडल लागत घटाने के लिए [आइडल होने पर स्लीप](/cli/sleep) चालू करें: `lizard sleep --on --service mcp`। इसे चालू करने पर सर्विस एक बार रीस्टार्ट होती है। तय समय तक कोई रिक्वेस्ट न आने पर (डिफ़ॉल्ट 10 मिनट) सर्विस स्लीप में चली जाती है; अगली रिक्वेस्ट उसे जगाती है, इसलिए वह पहली कॉल ज़्यादा समय लेती है। [प्राइसिंग](https://lizard.build/pricing) और [सीमाएँ](/platform/limits) देखें।
