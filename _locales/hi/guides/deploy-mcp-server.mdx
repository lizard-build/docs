# एक रिमोट MCP सर्वर होस्ट करें

क्लाइंट्स को रिमोट URL की आवश्यकता होने पर एक MCP सर्वर को HTTP एप्लिकेशन के रूप में डिप्लॉय करें। यह उदाहरण एक अंकगणितीय टूल सर्व करता है, एक बेयरर टोकन को मान्य करता है, और एक हेल्थ एंडपॉइंट एक्सपोज़ करता है। यह स्ट्रीमएबल HTTP का उपयोग करता है; एक लोकल `stdio` सर्वर स्वयं रिमोट क्लाइंट्स को सर्व नहीं कर सकता है।

<span id="before-you-start" />

## शुरू करने से पहले

आपको Node.js 22, Lizard CLI, डिप्लॉय करने के लिए एक प्रोजेक्ट, और कॉन्फ़िगर किया हुआ बेयरर टोकन स्वीकार करने वाला एक MCP क्लाइंट चाहिए। उदाहरण स्टेटलेस मोड में `@modelcontextprotocol/sdk` 1.30.0 का उपयोग करता है। यह OAuth लॉगिन, ब्राउज़र एक्सेस, या पहचान प्रदाता प्रदान नहीं करता है।

रन करने योग्य फाइलें [remote-mcp-node](https://github.com/lizard-build/docs/tree/23635ba7e162bafce75d3f6206553b3ef2c0c48e/_examples/remote-mcp-node) में रहती हैं। चेक-इन किए गए लॉकफ़ाइल का उपयोग करें। लोकल स्मोक टेस्ट इनिशियलाइज़ेशन, टूल डिस्कवरी, एक टूल कॉल, और मान्य टोकन के बिना रिजेक्शन की जाँच करता है। एक डिप्लॉयमेंट चेक को पब्लिक प्रॉक्सी और TLS पाथ की भी पुष्टि करनी चाहिए।

<span id="run-locally" />

## स्थानीय रूप से चलाएं

उदाहरण डायरेक्टरी से:

```bash
npm ci
npm test
node issue-token.mjs
export MCP_PUBLIC_KEY="$(cat .mcp-public-key.pem)"
export MCP_ALLOWED_HOSTS=127.0.0.1,localhost
npm start
```

जेनरेट किया गया टोकन एक घंटे के बाद एक्सपायर हो जाता है। प्राइवेट साइनिंग की सेव नहीं की जाती है। स्थायी डिप्लॉयमेंट के लिए अपने स्वयं के टोकन जारीकर्ता और रोटेशन प्रक्रिया का उपयोग करें; इसकी प्राइवेट की को सर्वर के बाहर रखें।

एक अन्य टर्मिनल में:

```bash
export MCP_URL=http://127.0.0.1:8000/mcp
export MCP_TOKEN="$(cat .mcp-token)"
node client.mjs
```

क्लाइंट इनिशियलाइज़ेशन, टूल डिस्कवरी और परिणाम `5` की जाँच करता है, फिर `MCP initialize, tools/list and tools/call passed: 5` प्रिंट करता है। `/health` `ok` लौटाता है; मान्य टोकन के बिना `/mcp` के अनुरोध `401` लौटाता है।

<span id="deploy-the-application" />

## एप्लिकेशन को डिप्लॉय करें

उदाहरण की Dockerfile और लॉकफ़ाइल को रखें। उनसे युक्त डायरेक्टरी से:

```bash
lizard init --name mcp-example
lizard add --service mcp
lizard domain --service mcp --json
```

यदि कोई कमांड प्रमाणीकरण की आवश्यकता होने की रिपोर्ट करता है तो `lizard login` के साथ साइन इन करें। `init` प्रोजेक्ट को लिंक करता है; `add` नामित सेवा बनाता है। डोमेन कमांड डिप्लॉयमेंट से पहले उसका होस्टनाम असाइन करता है। नीचे दिए गए `hostname` का उपयोग करें, `https://` या पाथ के बिना:

```bash
lizard secrets set MCP_PUBLIC_KEY="$(cat .mcp-public-key.pem)" --service mcp
lizard secrets set MCP_ALLOWED_HOSTS=YOUR_SERVICE_HOSTNAME --service mcp
```

पहले डिप्लॉयमेंट से पहले दोनों मान सेट करें। फिर चलाएं:

```bash
lizard up --service mcp --port 8000
lizard logs --build --service mcp --json
lizard logs --service mcp --json
lizard ps --json
```

केवल एग्जिट कोड ही नहीं, अंतिम डिप्लॉयमेंट इवेंट और पब्लिक एंडपॉइंट की जाँच करें। `server.mjs` `0.0.0.0` पर सुनता है और `PORT` पढ़ता है, जिसमें 8000 डिफ़ॉल्ट के रूप में होता है। डिप्लॉय कमांड सेवा पोर्ट को 8000. पर सेट करता है। पब्लिक की को मल्टीलाइन एनवायरनमेंट वैल्यू के रूप में कॉन्फ़िगर करें; प्राइवेट साइनिंग की या टोकन फ़ाइल अपलोड न करें।

<span id="verify-the-public-endpoint" />

## पब्लिक एंडपॉइंट सत्यापित करें

`MCP_URL` को `https://YOUR_SERVICE_HOSTNAME/mcp` पर सेट करें, क्लाइंट एनवायरनमेंट में एक मान्य टोकन रखें, और `node client.mjs` चलाएं। सभी तीन परिणामों को सत्यापित करें:

1. `/health` HTTPS पर `200` लौटाता है।
2. `/mcp` मान्य टोकन के बिना क्लाइंट को अस्वीकार करता है।
3. प्रमाणित क्लाइंट टूल सूचीबद्ध करता है और `add` को कॉल करता है, `5` लौटाता है।

केवल एक स्वस्थ प्रक्रिया यह साबित नहीं करती है कि MCP हैंडशेक या स्ट्रीम किया गया रिस्पॉन्स पब्लिक प्रॉक्सी के माध्यम से काम करता है।

<span id="troubleshooting" />

## समस्या निवारण

| परिणाम | जाँच |
|---|---|
| प्रक्रिया स्टार्टअप के दौरान बाहर निकल जाती है | `MCP_PUBLIC_KEY` में पब्लिक PEM की होनी चाहिए; `MCP_ALLOWED_HOSTS` में सेवा होस्टनाम होना चाहिए। |
| `401` | टोकन का जारीकर्ता (issuer) और दर्शक (audience) 256, से मेल खाना चाहिए और `mcp-example` समाप्त नहीं होना चाहिए। |
| `403` | अनुरोध होस्टनाम को `MCP_ALLOWED_HOSTS` से मिलाएं। इस उदाहरण द्वारा ब्राउज़र ओरिजिन सक्षम नहीं हैं। |
| मान्य टोकन के साथ `405` | यह स्टेटलेस MCP एंडपॉइंट POST के माध्यम से प्रोटोकॉल अनुरोध स्वीकार करता है। एक MCP क्लाइंट का उपयोग करें। टोकन के बिना ब्राउज़र GET पहले `401` लौटाता है। |
| लोकल टेस्ट पास होता है लेकिन रिमोट कॉल फेल हो जाता है | पोर्ट, HTTPS, रिस्पॉन्स स्ट्रीमिंग, और प्रॉक्सी टाइमआउट की जाँच करें। |

<span id="limits-and-cost" />

## सीमाएँ और लागत

यह उदाहरण सर्वर मेमोरी में उपयोगकर्ता सत्र या स्थायी फ़ाइलें नहीं रखता है। स्थायी एप्लिकेशन स्थिति के लिए एक डेटाबेस जोड़ें और निजी टूल एक्सपोज़ करने से पहले प्रति उपयोगकर्ता एक्सेस की जाँच करें। उन क्लाइंट्स के लिए जिन्हें OAuth डिस्कवरी या इंटरैक्टिव लॉगिन की आवश्यकता होती है, इस टेस्ट टोकन को वितरित करने के बजाय एक समर्थित OAuth प्रदाता जोड़ें।

सर्वर कॉल्स के बीच चलता रहता है, और Lizard चलते समय उसके मापे गए CPU और मेमोरी का बिल बनाता है। निष्क्रिय लागत को कम करने के लिए, [स्लीप व्हेन आइडल](/cli/sleep) चालू करें: `lizard sleep --on --service mcp`। इसे चालू करने से सेवा एक बार रीस्टार्ट होती है। अनुरोधों के बिना एक निश्चित समय के बाद (डिफ़ॉल्ट रूप से 10 मिनट), सेवा सो जाती है; अगला अनुरोध उसे जगाता है, इसलिए पहला कॉल अधिक समय लेता है। [मूल्य निर्धारण](https://lizard.build/pricing) और [सीमाओं](/platform/limits) की जाँच करें।
