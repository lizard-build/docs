# कोडिंग एजेंट

Claude Code, Codex, Cursor और अन्य AI कोडिंग एजेंट Lizard पर सैंडबॉक्स बनाते हैं, ऐप्स डिप्लॉय करते हैं और उन्हें Lizard CLI के माध्यम से प्रबंधित करते हैं। `npx skills add lizard-build/skill -g` के साथ Lizard Skill को एक बार इंस्टॉल करें; एजेंट फिर CLI में निर्मित गाइड को `lizard skills get core --json` के साथ लोड करता है और `--help --json` के साथ किसी भी कमांड के फ़्लैग को पढ़ता है। MCP बोलने वाले क्लाइंट, जैसे ChatGPT और Claude, इसके बजाय [Lizard MCP](#lizard-mcp) का उपयोग कर सकते हैं। किसी एजेंट से पूर्ण डिप्लॉय रन के लिए, [Claude Code, Codex या Cursor से डिप्लॉय करें](/guides/deploy-from-coding-agent) देखें।

<span id="the-embedded-skill" />

## एम्बेडेड स्किल

CLI में इंस्टॉल किए गए संस्करण के लिए उपयोग गाइड शामिल है। एक एजेंट इसे इस प्रकार पढ़ता है:

```bash
lizard skills get core --json
```

यह `{ name, frontmatter, content, references, … }` देता है: `content` मुख्य गाइड है (सैंडबॉक्स, डिप्लॉय, डेटाबेस, सीक्रेट्स, डिस्कवरी, एग्जिट कोड), और `references` डिप्लॉय, सैंडबॉक्स और Lizard SDK के लिए विस्तृत गाइड सूचीबद्ध करता है। संबंधित सब-कमांड:

```bash
lizard skills list                     # available embedded skills
lizard skills get core                 # the core guide
lizard skills get core --ref deploys   # one reference: deploys, sandboxes or sdk
lizard skills get core --full          # the guide plus every reference
lizard skills path                     # where skills are stored
```

चूंकि गाइड बाइनरी के साथ बंडल किया गया है, `lizard upgrade` एजेंट के निर्देशों को भी अपडेट करता है।

## सेल्फ-डिस्क्राइबिंग कमांड्स

एजेंट रनटाइम पर सटीक फ़्लैग आकार की खोज करते हैं बजाय याद की गई सिंटैक्स पर निर्भर रहने के:

```bash
lizard --help --json                # full command tree + exit codes
lizard <cmd> --help --json          # a specific command's schema
```

[JSON और ऑटोमेशन](/cli/json) देखें।

## एजेंट में बूटस्ट्रैपिंग

एक विशिष्ट एजेंट प्रवाह:

1. **गाइड लोड करें:** `lizard skills get core --json` → `content` पढ़ें, फिर वह संदर्भ जिसकी कार्य को आवश्यकता है (`--ref sandboxes`, `deploys` या `sdk`)।
2. **ऑप्टिमिस्टिक रूप से प्रमाणीकरण जांचें:** उपयोगकर्ता का कार्य चलाएं। एग्जिट कोड `2` (`NOT_AUTHENTICATED`) पर, त्रुटि का `body.login` साइन-इन लिंक ले जाता है: उपयोगकर्ता से पूछें कि क्या वे GitHub या Google से साइन इन करते हैं, उन्हें `authUrls` से वह लिंक दें, फिर ब्राउज़र द्वारा "CLI अधिकृत" कहे जाने के बाद पुनः प्रयास करें। [`lizard login --json`](/cli/login#output-for-agents) वही लिंक प्रिंट करता है, और साइन-इन के बाद यह `account.state` में योजना की रिपोर्ट करता है।
3. **पूछे जाने पर परीक्षण शुरू करें:** एक नए खाते में कोई योजना नहीं होती है, इसलिए इसका पहला निर्माण HTTP 402 (`code: "PAYMENT_REQUIRED"`, एग्जिट कोड `1`) के साथ विफल हो जाता है। पहले उपयोगकर्ता से पूछें। यदि वे सहमत होते हैं, तो `lizard billing start --json` चलाएं, चेकआउट `url` उपयोगकर्ता को सौंपें, फिर उनके द्वारा कार्ड जोड़ने के बाद पुनः प्रयास करें।
4. **म्यूटेट करने से पहले संदर्भ हल करें:** `lizard status` (cwd लिंक) और `lizard ps --json` (सेवाएं)। एक फ़ोल्डर में जो लिंक नहीं है, `up`, `add`, `sandbox create` और अन्य प्रोजेक्ट कमांड खाते के डिफ़ॉल्ट प्रोजेक्ट का उपयोग करते हैं।
5. **गाइड का उपयोग करके कार्य करें:** `sandbox create`, `add`, `up`, `secrets`, `domain`, आदि, हमेशा `--json` के साथ।

यदि `lizard` बाइनरी मौजूद नहीं है, तो पहले इसे इंस्टॉल करें। macOS या Linux पर, इंस्टॉल स्क्रिप्ट का उपयोग करें:

```bash
curl -fsSL https://lizard.build/install.sh | bash
```

इसे किसी Node.js या `sudo` की आवश्यकता नहीं है, और यह `lizard` को एक ऐसे फ़ोल्डर में लिंक करता है जो पहले से ही `PATH` पर है, इसलिए एजेंट इसे उसी सत्र में कॉल कर सकता है। यदि स्क्रिप्ट कहती है कि `lizard` नहीं मिल सकता है, तो इसके बजाय `~/.lizard/bin/lizard` को कॉल करें। टर्मिनल के बिना, स्क्रिप्ट `lizard login --json` के आउटपुट के साथ समाप्त होती है: साइन-इन लिंक और एक `instruction`। लिंक उपयोगकर्ता को सौंपें। Windows पर, इसे PowerShell में चलाएं:

```powershell
irm https://lizard.build/api/cli/install.ps1 | iex
```

या किसी भी सिस्टम पर npm से इंस्टॉल करें (Node.js 20 या बाद का संस्करण आवश्यक है):

```bash
npm install -g @lizard-build/cli
```

## एजेंटों को पालन करने के लिए परंपराएं

- **हमेशा `--json` पास करें** गैर-इंटरैक्टिव कॉल पर।
- **विनाशकारी कार्यों की पुष्टि करें** (सेवा हटाएं, एडऑन ड्रॉप करें, प्रोजेक्ट-व्यापी सीक्रेट को ओवरराइट करें, प्रोड रीस्टार्ट) उपयोगकर्ता के साथ: CLI के अपने प्रॉम्प्ट केवल TTY पर फायर होते हैं।
- **डिफ़ॉल्ट रूप से सीक्रेट्स को उपभोग करने वाली सेवा तक सीमित करें**; सिद्ध-सार्वजनिक मानों के लिए `--global` आरक्षित करें। [वेरिएबल्स और सीक्रेट्स](/variables#scoping) देखें।
- **अनचाहे Dockerfiles न लिखें**: lizardpack अधिकांश स्टैक का स्वतः पता लगाता है। पहले डिप्लॉय का प्रयास करें। [बिल्ड पाइपलाइन](/concepts/build-pipeline) देखें।
- **git-backed सेवा को अपलोड करने के लिए स्विच करने के लिए `lizard up` का उपयोग न करें**: `service set` + `redeploy` का उपयोग करें।

## संपादक एकीकरण

Lizard Skill संपादक एजेंटों और सहायकों को Lizard CLI इंस्टॉल और उपयोग करने के निर्देश देता है। इसे अपने सभी एजेंटों के लिए एक बार इंस्टॉल करें:

```bash
npx skills add lizard-build/skill -g
```

यह Claude Code, Cursor, Codex, Copilot, Gemini CLI और अन्य एजेंटों के साथ काम करता है जो Agent Skills प्रारूप पढ़ते हैं। उन क्लाइंट्स के लिए जो शेल कमांड चलाने के बजाय MCP बोलते हैं, [Lizard MCP](#lizard-mcp) का उपयोग करें।

एक AI IDE एक ऐप लिख और परीक्षण कर सकता है; Lizard परिणाम होस्ट करता है। [Google Antigravity में निर्मित ऐप को डिप्लॉय करना](https://lizard.build/blog/google-antigravity-how-to-deploy-your-app-to-production#deploy-from-the-antigravity-chat) देखें, जो संपादक की चैट से शुरू किया गया डिप्लॉय है।

Claude Code या ChatGPT को Chrome में आपके द्वारा खोले गए पेज को संपादित करने देने के लिए, [Lizard Studio](/studio/getting-started) का उपयोग करें।

## Lizard MCP

Lizard MCP ChatGPT, Claude और अन्य MCP क्लाइंट्स को आपके Lizard प्रोजेक्ट्स को मैनेज करने देता है: सैंडबॉक्स बनाना, उनमें कमांड चलाना और फ़ाइलें पढ़ना या लिखना; सर्विस और एडऑन बनाना, सर्विस को फिर से डिप्लॉय करना, [रोकना और फिर से शुरू करना](/cli/pause) एक सर्विस, प्रोजेक्ट या वर्कस्पेस, सर्विस को [निष्क्रिय होने पर स्लीप होने देना](/cli/sleep), लॉग और मेट्रिक्स पढ़ना, सीक्रेट सेट करना, रेप्लिका स्केल करना और डोमेन अटैच करना। यह एक होस्टेड सर्वर है जो इस पर स्ट्रीम करने योग्य HTTP बोलता है:

```text
https://employ-woman-g1q2.us-east-1.onlizard.com/mcp
```

OAuth को सपोर्ट करने वाला क्लाइंट पहली बार उपयोग करने पर आपको साइन इन करता है। अन्य क्लाइंट `liz_` हेडर में `Authorization: Bearer` API कुंजी भेजते हैं; `lizard keys create <name>` के साथ एक बनाएं।

इसे Claude Code में जोड़ें:

```bash
claude mcp add --transport http lizard https://employ-woman-g1q2.us-east-1.onlizard.com/mcp
```

JSON द्वारा कॉन्फ़िगर किए गए Cursor और अन्य क्लाइंट्स के लिए:

```json
{
  "mcpServers": {
    "lizard": {
      "url": "https://employ-woman-g1q2.us-east-1.onlizard.com/mcp",
      "headers": { "Authorization": "Bearer liz_your_key" }
    }
  }
}
```

ट्रायल शुरू करना, भुगतान करना और Pro रद्द करना बिलिंग पेज पर होता है। जब अकाउंट को कुछ बनाने से पहले भुगतान करना होता है, तो टूल एरर में `PAYMENT_REQUIRED` और खोलने के लिए लिंक होता है।

## अपना खुद का MCP सर्वर होस्ट करना

Lizard CLI का उपयोग करने वाला एक एजेंट और MCP को एक्सपोज़ करने वाला एक एप्लिकेशन अलग-अलग वर्कफ़्लो हैं। ऊपर दिए गए CLI कमांड MCP ट्रांसपोर्ट प्रदान नहीं करते हैं। स्ट्रीम करने योग्य HTTP के साथ अपना सर्वर डिप्लॉय करने के लिए, [रिमोट MCP गाइड](/guides/deploy-mcp-server) का पालन करें।
