# एक Rails ऐप डिप्लॉय करें

Rails 7.1 और उसके बाद के संस्करण एक प्रोडक्शन `Dockerfile` जेनरेट करते हैं, और Lizard इसे वैसे ही बनाता है जैसे लिखा गया है: इमेज जेम इंस्टॉल करती है, एसेट्स को प्रीकंपाइल करती है और सर्वर शुरू होने पर हर बार `bin/rails db:prepare` चलाती है। `RAILS_MASTER_KEY` और डेटाबेस यूआरएल सेट करें, फिर Rails 8 (Thruster के लिए `HTTP_PORT=8080` के साथ) या Rails 7.1 और 7.2. के लिए `lizard up --port 3000` के लिए `lizard up --port 8080` चलाएं। बिना Dockerfile के, lizardpack `3000` पोर्ट पर एक प्लेन Ruby इमेज बनाता है।

**टेस्ट स्थिति:** हमने `Dockerfile`, `bin/docker-entrypoint`, `config/puma.rb` और `database.yml` की जांच की जो Rails जेनरेट करता है, Lizard का बिल्ड और पोर्ट नियम, और बिना Dockerfile के Rails ऐप के लिए lizardpack की योजना। हमने अभी तक इस गाइड के साथ एंड-टू-एंड Rails ऐप डिप्लॉय नहीं किया है।

<span id="before-you-start" />

## शुरू करने से पहले

- एक Rails 7.1 या बाद का ऐप जो PostgreSQL (`pg` gem) का उपयोग करता है और जिसमें अभी भी जेनरेटेड `Dockerfile` और `bin/docker-entrypoint` हैं। एक पुराना ऐप उन्हें [dockerfile-rails](https://github.com/fly-apps/dockerfile-rails) gem से प्राप्त कर सकता है: `bundle add dockerfile-rails --group development`, फिर `bin/rails generate dockerfile`।
- आपके कंप्यूटर पर `config/master.key`, या ऐप का `SECRET_KEY_BASE`।
- एक `Gemfile.lock` जो `x86_64-linux` प्लेटफ़ॉर्म को सूचीबद्ध करता है। इसे `bundle lock --add-platform x86_64-linux` के साथ जोड़ें और फ़ाइल को कमिट करें।
- Lizard CLI, `lizard login` के साथ साइन इन, Pro या 7-दिन Pro ट्रायल (कार्ड आवश्यक) पर। [मूल्य निर्धारण](https://lizard.build/pricing) देखें।

<span id="how-lizard-builds-a-rails-app" />

## Lizard एक Rails ऐप कैसे बनाता है

| आपका ऐप | Lizard बनाता है | सेवा पोर्ट |
|---|---|---|
| Rails 8 `Dockerfile` (`EXPOSE 80`, `CMD ["./bin/thrust", "./bin/rails", "server"]`) | आपका Dockerfile, जैसा लिखा गया है | `8080`, `HTTP_PORT=8080` के साथ |
| Rails 7.1 या 7.2 `Dockerfile` (`EXPOSE 3000`) | आपका Dockerfile, जैसा लिखा गया है | `3000` |
| कोई Dockerfile नहीं | lizardpack की Ruby इमेज; [नीचे](#without-a-dockerfile) देखें | `3000` |

सेवा के बिल्ड और स्टार्ट कमांड खाली छोड़ दें। किसी एक को सेट करने पर, Lizard आपके कमांड के बजाय कमांड से अपना Dockerfile लिखता है, और उस इमेज में Node.js होता है, Ruby नहीं। एक स्टार्ट कमांड इमेज के एंट्रीपॉइंट को भी बदल देता है, इसलिए `db:prepare` नहीं चलेगा। [बिल्ड निर्णय क्रम](/concepts/build-pipeline#build-decision-order) देखें।

Rails 8, Thruster को शुरू करता है, जो पोर्ट `80` पर सुनता है और उसके पीछे पोर्ट `3000` पर Puma चलाता है। इमेज एक नॉन-रूट यूजर (`USER 1000:1000`) के रूप में चलती है, और एक नॉन-रूट प्रोसेस में 1024. से नीचे का पोर्ट खोलने की अनुमति नहीं हो सकती है। `HTTP_PORT=8080` Thruster को ऐसे पोर्ट पर ले जाता है जिसे वह हमेशा खोल सकता है।

<span id="create-the-project-and-database" />

## प्रोजेक्ट और डेटाबेस बनाएं

ऐप की रूट डायरेक्टरी से:

```bash
lizard init --name rails-app
lizard add --service web
lizard add postgres
```

[Managed Postgres](/addons/postgres) `postgres` सुपरयूज़र के रूप में कनेक्ट होता है, इसलिए `db:prepare` उन डेटाबेस को बना सकता है जिनके लिए Rails पूछता है।

<span id="set-secrets-and-deploy-rails-8" />

## सीक्रेट सेट करें और डिप्लॉय करें (Rails 8)

Rails 8 का प्रोडक्शन `database.yml` चार डेटाबेस को परिभाषित करता है: `primary`, `cache`, `queue` और `cable`। `DATABASE_URL` केवल `primary` को बदलता है। दूसरों के लिए, Rails `CACHE_DATABASE_URL`, `QUEUE_DATABASE_URL` और `CABLE_DATABASE_URL` को पढ़ता है। सभी चारों को अलग-अलग डेटाबेस नामों के साथ एक ही Postgres पर इंगित करें:

```bash
PG='postgresql://postgres:${{postgres.PGPASSWORD}}@${{postgres.LIZARD_PRIVATE_DOMAIN}}:5432'
lizard secrets set \
  RAILS_MASTER_KEY="$(cat config/master.key)" \
  DATABASE_URL='${{postgres.DATABASE_PRIVATE_URL}}' \
  CACHE_DATABASE_URL="$PG/rails_cache" \
  QUEUE_DATABASE_URL="$PG/rails_queue" \
  CABLE_DATABASE_URL="$PG/rails_cable" \
  HTTP_PORT=8080 \
  SOLID_QUEUE_IN_PUMA=true \
  --service web
lizard up --service web --port 8080
```

- सिंगल कोट्स `${{…}}` को आपके शेल से दूर रखते हैं। Lizard इन [रेफरेंस](/variables/references) को डिप्लॉय समय पर हल करता है और प्रोजेक्ट के प्राइवेट नेटवर्क का उपयोग करता है।
- `SOLID_QUEUE_IN_PUMA=true` Puma को Solid Queue वर्कर चलाने के लिए बनाता है, इसलिए Active Job जॉब्स वेब सर्विस के अंदर चलती हैं। इसके बिना, यह वेब सर्विस क्यूड जॉब्स को प्रोसेस नहीं करती है।
- `RAILS_MASTER_KEY` के बजाय `SECRET_KEY_BASE` का उपयोग करें यदि ऐप कोई अन्य एन्क्रिप्टेड क्रेडेंशियल नहीं पढ़ता है।

<span id="set-secrets-and-deploy-rails-71-and-72" />

## सीक्रेट सेट करें और डिप्लॉय करें (Rails 7.1 और 7.2)

ये संस्करण एक डेटाबेस का उपयोग करते हैं:

```bash
lizard secrets set \
  RAILS_MASTER_KEY="$(cat config/master.key)" \
  DATABASE_URL='${{postgres.DATABASE_PRIVATE_URL}}' \
  --service web
lizard up --service web --port 3000
```

<span id="what-happens-on-each-deploy" />

## हर डिप्लॉय पर क्या होता है

`lizard up` डायरेक्टरी अपलोड करता है। गिट रिपॉजिटरी के अंदर यह `.gitignore` द्वारा सूचीबद्ध को छोड़ देता है, और Rails के `.gitignore` और `.dockerignore` दोनों `config/master.key` और `.env*` फ़ाइलों को बाहर रखते हैं। बिल्ड `SECRET_KEY_BASE_DUMMY=1` के साथ एसेट्स को प्रीकंपाइल करता है, क्योंकि Lizard किसी Dockerfile बिल्ड में `COMMIT_SHA` के अलावा कोई वेरिएबल पास नहीं करता है।

स्टार्ट पर, `bin/docker-entrypoint` `./bin/rails db:prepare` चलाता है: यह मिसिंग डेटाबेस बनाता है, नए में स्कीमा लोड करता है और पेंडिंग माइग्रेशन चलाता है। यह हर कंटेनर स्टार्ट पर चलता है, रीस्टार्ट सहित। माइग्रेशन को पुराने और नए दोनों कोड के खिलाफ चलाने के लिए सुरक्षित रखें।

git push to deploy के लिए, ऐप को GitHub पर पुश करें और `lizard up` चलाने के बजाय [रिपॉजिटरी कनेक्ट करें](/deploy/github)। समान सीक्रेट और पोर्ट (`lizard port 8080 --service web`) सेट करें। जेनरेटेड Dockerfile में एक `bundle install` स्टेप है, इसलिए Lizard इसे वैसे ही उपयोग करता है जैसे लिखा गया है।

<span id="check-that-it-works" />

## जांचें कि यह काम करता है

```bash
lizard logs --build --service web
lizard logs --service web --tail 100
lizard domain --service web
```

Rails 7.1 और बाद के संस्करण ऐप बूट होने के बाद HTTP 200 के साथ `/up` का जवाब देते हैं। `https://<your-domain>/up` खोलें, फिर एक पेज जो डेटाबेस से पढ़ता है। रनटाइम लॉग को `db:prepare` आउटपुट दिखाना चाहिए, फिर Puma स्टार्ट होना चाहिए।

<span id="without-a-dockerfile" />

## Dockerfile के बिना

lizardpack एक Ruby ऐप बनाता है जब उसे एक `Gemfile` मिलता है:

- Ruby संस्करण: `.ruby-version`, अन्यथा `ruby` लाइन `Gemfile` में, अन्यथा `3.4`। केवल मेजर और माइनर गिने जाते हैं: `3.4.1`, `ruby:3.4-slim` पर बनता है।
- यह `build-essential` और `libpq-dev` इंस्टॉल करता है, फिर `bundle install` चलाता है।
- स्टार्ट: Procfile `web:` लाइन, अन्यथा `bundle exec rails server -b 0.0.0.0` जब `config.ru` और `Rakefile` मौजूद हों। पोर्ट `3000`।

यह इमेज `RAILS_ENV` सेट नहीं करती है, एसेट्स प्रीकंपाइल नहीं करती है या डेटाबेस तैयार नहीं करती है, इसलिए यह एक पूर्ण Rails साइट की तुलना में छोटे ऐप्स और APIs के लिए बेहतर है। `.ruby-version` को एक नंगे नंबर के रूप में लिखें जैसे `3.4.1`। `rails new` `ruby-3.4.1` लिखता है, और lizardpack उसे एक इमेज नाम में बदल देता है जो मौजूद नहीं है। [रनटाइम संस्करण](/deploy/runtime-versions) देखें।

<span id="common-problems" />

## सामान्य समस्याएं

| लक्षण | समाधान |
|---|---|
| `bundle install` विफल: बंडल केवल अन्य प्लेटफार्मों का समर्थन करता है | `bundle lock --add-platform x86_64-linux` चलाएं और `Gemfile.lock` को कमिट करें। |
| `Missing secret_key_base` या क्रेडेंशियल डिक्रिप्ट करने में विफल | `web` सेवा पर `RAILS_MASTER_KEY` को `config/master.key` से सेट करें। |
| कैश, क्यू या केबल कनेक्शन `/var/run/postgresql` जैसे लोकल सॉकेट पर जाता है | `CACHE_DATABASE_URL`, `QUEUE_DATABASE_URL` और `CABLE_DATABASE_URL` सेट करें। |
| लॉग पोर्ट 80 के लिए `bind: permission denied` दिखाते हैं | `HTTP_PORT=8080` और सेवा पोर्ट को `8080` पर सेट करें। |
| डिप्लॉय कभी स्वस्थ नहीं होता | सुनिश्चित करें कि सेवा पोर्ट ऊपर दी गई तालिका से मेल खाता है: `lizard port --service web`। [सेवा कभी स्वस्थ नहीं](/deploy/troubleshooting/service-never-healthy) देखें। |
| जॉब कतार में ही रहती हैं | `SOLID_QUEUE_IN_PUMA=true` सेट करें। वेब प्रोसेस से अलग जॉब चलाने के लिए `dockerfilePath=Dockerfile` और `startCommand=./bin/jobs` के साथ [worker mode](/deploy/workers) में दूसरी सेवा जोड़ें। |
| डिप्लॉय के बाद अपलोड की गई फ़ाइलें गायब हो जाती हैं | Active Storage की `local` सेवा कंटेनर के अंदर लिखती है। `amazon` सेवा के साथ S3-संगत [Managed Object Storage](/addons/storage) इस्तेमाल करें। |

यदि ऐप Sidekiq या Redis Action Cable एडॉप्टर का उपयोग करता है, तो [Managed Redis](/addons/redis) जोड़ें और उस सेवा पर `REDIS_URL='${{redis.REDIS_PRIVATE_URL}}'` सेट करें जिसे इसकी आवश्यकता है।
