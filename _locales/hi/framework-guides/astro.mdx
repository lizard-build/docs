# Lizard पर Astro परिनियोजित करें

Lizard पर Astro को दो मोड में से किसी एक में परिनियोजित करें: पोर्ट `80` पर एक स्थिर `dist/` निर्देशिका परोसें, या ऑन-डिमांड रूट के लिए पोर्ट `3000` पर स्टैंडअलोन Node एडॉप्टर चलाएं। परिनियोजन से पहले मोड चुनें क्योंकि एडॉप्टर आउटपुट और रनटाइम दोनों को बदलता है।

<span id="choose-a-mode" />

## एक मोड चुनें

| मोड | कॉन्फ़िगरेशन | रनटाइम | पोर्ट |
|---|---|---|---|
| Static site | सर्वर एडॉप्टर के बिना स्थिर आउटपुट | nginx `dist/` परोसता है | `80` |
| Node server | स्टैंडअलोन मोड में `@astrojs/node` | `node ./dist/server/entry.mjs` | `3000` |

दोनों पथ `build` स्क्रिप्ट का उपयोग करते हैं जो `astro build` चलाता है। लॉकफ़ाइल कमिट करें और डिफ़ॉल्ट `dist` आउटपुट पथ रखें। डिटेक्शन Astro कॉन्फ़िगरेशन और स्थापित निर्भरताओं को पढ़ता है। एक अप्रयुक्त Node एडॉप्टर निर्भरता अकेले सर्वर पथ का चयन नहीं करती है। शाब्दिक `output` और एडॉप्टर सेटिंग्स का उपयोग करें; गतिशील मानों, कस्टम आउटपुट पथों और मिडलवेयर मोड के लिए Dockerfile की आवश्यकता होती है।

<span id="configure-a-node-server" />

## Node सर्वर कॉन्फ़िगर करें

ऑन-डिमांड पेजों के लिए, अपने Astro संस्करण के अनुकूल Node एडाप्टर संस्करण जोड़ें:

```bash
npx astro add node
```

`astro.config.mjs` की जाँच करें:

```js
import { defineConfig } from 'astro/config';
import node from '@astrojs/node';

export default defineConfig({
  output: 'server',
  adapter: node({ mode: 'standalone' }),
});
```

स्टैंडअलोन मोड अपना स्वयं का HTTP सर्वर शुरू करता है। मिडलवेयर मोड के लिए एक अलग सर्वर की आवश्यकता होती है और यह इस लॉन्च कमांड के लिए उपयुक्त नहीं है। यदि आपको मिडलवेयर या प्रीरेंडर किए गए और ऑन-डिमांड रूट का मिश्रण चाहिए तो [Astro Node एडाप्टर गाइड](https://docs.astro.build/en/guides/integrations-guide/node/) पढ़ें।

<span id="test-locally" />

## स्थानीय रूप से परीक्षण करें

```bash
npm ci
npm run build
```

Node मोड के लिए:

```bash
HOST=0.0.0.0 PORT=3000 node ./dist/server/entry.mjs
```

सर्वर पर चलने वाले रूट और एक बिल्ट एसेट का अनुरोध करें। एक स्टेटिक साइट के लिए, स्थानीय रूप से `npm run preview` का उपयोग करें और `dist/` में जेनरेट की गई रूट फ़ाइलों का निरीक्षण करें।

<span id="deploy" />

## डिप्लॉय

[CLI सेटअप](/framework-guides#prepare-the-project) के बाद, प्रोजेक्ट बनाएं:

```bash
lizard init --name astro-app
lizard add --service web
```

Node एडाप्टर के लिए:

```bash
lizard up --service web --port 3000
```

एक स्टेटिक साइट के लिए:

```bash
lizard up --service web --port 80
```

अपने चुने हुए मोड के लिए केवल कमांड का उपयोग करें। lizardpack डिटेक्शन के लिए सर्विस कमांड ओवरराइड को अनसेट छोड़ दें। `lizard logs --build --service web --json` पढ़ें, फिर रनटाइम लॉग और लाइव URL की जाँच करें।

<span id="variables-sessions-and-routes" />

## वेरिएबल्स, सेशन्स और रूट्स

स्टेटिक HTML जेनरेट करने के लिए उपयोग किए जाने वाले मान बदलने पर एक नए बिल्ड की आवश्यकता होती है। सर्वर कोड आपके Astro संस्करण द्वारा समर्थित तंत्र के माध्यम से रनटाइम वेरिएबल्स को पढ़ सकता है; उन्हें [वेरिएबल्स और सीक्रेट्स](/variables) में कॉन्फ़िगर करें। ब्राउज़र-दृश्यमान मानों में क्रेडेंशियल्स नहीं होने चाहिए।

यदि आपका ऐप सेशन्स का उपयोग करता है, तो रीस्टार्ट और मल्टीपल रेप्लिका के लिए उपयुक्त स्टोरेज चुनें। एक शेयर्ड ड्यूरेबल स्टोर के रूप में कंटेनर फाइलसिस्टम पर निर्भर न रहें। [स्टोरेज और रिकवरी](/platform/storage-and-recovery) देखें।

एक स्टेटिक कंटेंट साइट के लिए, एक मिसिंग URL का परीक्षण करें और उचित स्टेटस वापस करने के लिए [स्टेटिक रूट्स और 404s](/framework-guides/static-routing) का उपयोग करें। यदि कोई SSR डिप्लॉयमेंट एग्जिट हो जाता है या कोई रूट सर्व नहीं करता है, तो सत्यापित करें कि `dist/server/entry.mjs` मौजूद है, एडाप्टर स्टैंडअलोन मोड का उपयोग करता है, और सर्विस पोर्ट `3000` है।

सितंबर 9, 2026 डिप्लॉयमेंट चेक और उनकी सीमाओं के लिए [टेस्टेड वर्जन और क्लाउड रिजल्ट्स](/framework-guides/validation) देखें।
