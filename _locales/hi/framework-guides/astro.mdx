# Lizard पर Astro डिप्लॉय करें

Lizard पर Astro को दो में से किसी एक मोड में डिप्लॉय करें: पोर्ट `80` पर स्टैटिक `dist/` डायरेक्टरी सर्व करें, या ऑन-डिमांड रूट के लिए पोर्ट `3000` पर standalone Node एडॉप्टर चलाएँ। डिप्लॉय से पहले मोड चुन लें, क्योंकि एडॉप्टर आउटपुट और रनटाइम दोनों बदल देता है।

<span id="choose-a-mode" />

## मोड चुनें

| मोड | कॉन्फ़िगरेशन | रनटाइम | पोर्ट |
|---|---|---|---|
| स्टैटिक साइट | सर्वर एडॉप्टर के बिना स्टैटिक आउटपुट | nginx `dist/` सर्व करता है | `80` |
| Node सर्वर | standalone मोड में `@astrojs/node` | `node ./dist/server/entry.mjs` | `3000` |

दोनों तरीकों में `build` स्क्रिप्ट होती है जो `astro build` चलाती है। लॉकफ़ाइल कमिट करें और डिफ़ॉल्ट `dist` आउटपुट पाथ रहने दें। डिटेक्शन Astro कॉन्फ़िग और इंस्टॉल की गई डिपेंडेंसी पढ़ता है। सिर्फ़ इस्तेमाल न हो रही Node एडॉप्टर डिपेंडेंसी होने से सर्वर वाला तरीका नहीं चुना जाता। `output` और एडॉप्टर की सेटिंग्स सीधे मान के रूप में लिखें; डायनामिक मान, कस्टम आउटपुट पाथ और middleware मोड के लिए Dockerfile चाहिए।

<span id="configure-a-node-server" />

## Node सर्वर कॉन्फ़िगर करें

ऑन-डिमांड पेजों के लिए अपने Astro वर्ज़न के अनुकूल Node एडॉप्टर वर्ज़न जोड़ें:

```bash
npx astro add node
```

`astro.config.mjs` जाँचें:

```js
import { defineConfig } from 'astro/config';
import node from '@astrojs/node';

export default defineConfig({
  output: 'server',
  adapter: node({ mode: 'standalone' }),
});
```

standalone मोड अपना HTTP सर्वर ख़ुद शुरू करता है। middleware मोड के लिए अलग सर्वर चाहिए और वह इस लॉन्च कमांड के साथ नहीं चलता। अगर आपको middleware या प्रीरेंडर किए गए और ऑन-डिमांड रूट का मिश्रण चाहिए, तो [Astro Node एडॉप्टर गाइड](https://docs.astro.build/en/guides/integrations-guide/node/) पढ़ें।

<span id="test-locally" />

## लोकल टेस्ट करें

```bash
npm ci
npm run build
```

Node मोड के लिए:

```bash
HOST=0.0.0.0 PORT=3000 node ./dist/server/entry.mjs
```

सर्वर पर चलने वाला कोई रूट और बिल्ड किया हुआ कोई एसेट खोलकर देखें। स्टैटिक साइट के लिए लोकल `npm run preview` इस्तेमाल करें और `dist/` में जनरेट हुई रूट फ़ाइलें देखें।

<span id="deploy" />

## डिप्लॉय

[CLI सेटअप](/framework-guides#prepare-the-project) के बाद प्रोजेक्ट बनाएँ:

```bash
lizard init --name astro-app
lizard add --service web
```

Node एडॉप्टर के लिए:

```bash
lizard up --service web --port 3000
```

स्टैटिक साइट के लिए:

```bash
lizard up --service web --port 80
```

सिर्फ़ अपने चुने हुए मोड वाली कमांड चलाएँ। lizardpack डिटेक्शन के लिए सर्विस के कमांड ओवरराइड सेट न करें। `lizard logs --build --service web --json` पढ़ें, फिर रनटाइम लॉग और लाइव URL जाँचें।

<span id="variables-sessions-and-routes" />

## वेरिएबल्स, सेशन और रूट

स्टैटिक HTML जनरेट करने में इस्तेमाल होने वाले मान बदलें, तो नया बिल्ड ज़रूरी है। सर्वर कोड रनटाइम वेरिएबल्स को उन तरीकों से पढ़ सकता है जो आपका Astro वर्ज़न सपोर्ट करता है; इन्हें [वेरिएबल्स और सीक्रेट्स](/variables) में कॉन्फ़िगर करें। ब्राउज़र में दिखने वाले मानों में क्रेडेंशियल नहीं होने चाहिए।

अगर आपका ऐप सेशन इस्तेमाल करता है, तो ऐसा स्टोरेज चुनें जो रीस्टार्ट और कई रेप्लिका के साथ ठीक काम करे। कंटेनर के फ़ाइल सिस्टम को शेयर्ड, टिकाऊ स्टोर न मानें। [स्टोरेज और रिकवरी](/platform/storage-and-recovery) देखें।

स्टैटिक कंटेंट साइट के लिए कोई गैर-मौजूद URL टेस्ट करें और सही स्टेटस लौटाने के लिए [स्टैटिक रूट और 404](/framework-guides/static-routing) इस्तेमाल करें। अगर SSR डिप्लॉयमेंट बंद हो जाता है या कोई रूट सर्व नहीं करता, तो जाँचें कि `dist/server/entry.mjs` मौजूद है, एडॉप्टर standalone मोड में है और सर्विस पोर्ट `3000` है।

9 सितंबर 2026 को किए गए डिप्लॉयमेंट चेक और उनकी सीमाओं के लिए [टेस्ट किए गए वर्ज़न और क्लाउड के नतीजे](/framework-guides/validation) देखें।
