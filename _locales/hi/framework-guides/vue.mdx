# Lizard पर Vite के साथ Vue को डिप्लॉय करें

Lizard पर एक स्थिर वेब सेवा के रूप में Vite के साथ निर्मित Vue ऐप को डिप्लॉय करें। बिल्ड `dist/` उत्पन्न करता है, और nginx पोर्ट `80` पर फ़ाइलें सर्व करता है। Nuxt सर्वर रेंडरिंग और सर्वर रूट के लिए, [Nuxt गाइड](/framework-guides/nuxt) का उपयोग करें।

## Prepare the project

`package.json`, एक लॉकफ़ाइल और Vite कॉन्फ़िगरेशन के साथ Vue ऐप डायरेक्टरी से चलाएं। स्कैफोल्ड की बिल्ड स्क्रिप्ट को रखें, जिसमें `vue-tsc` भी शामिल है यदि यह आपके TypeScript कोड की जांच करता है। बिल्ड को `dist/` में Vite बंडल उत्पन्न करके समाप्त होना चाहिए।

| सेटिंग | मान |
|---|---|
| बिल्ड | `npm run build` |
| आउटपुट | `dist/` |
| स्टार्ट कमांड | स्थिर डिटेक्शन पथ के लिए कोई नहीं |
| सर्विस पोर्ट | `80` |

डोमेन रूट पर एक साइट के लिए `base: '/'` रखें। यदि आप पथ उपसर्ग का उपयोग करते हैं, तो Vite के बेस को राउटर बेस और उस URL के साथ संरेखित करें जहां ऐप वास्तव में चलता है। एक कस्टम आउटपुट डायरेक्टरी के लिए एक Dockerfile की आवश्यकता होती है जो उस डायरेक्टरी को कॉपी करता है।

<span id="check-the-build-locally" />

## स्थानीय रूप से बिल्ड की जांच करें

```bash
npm ci
npm run build
npm run preview
```

डेटा लाने वाले कंपोनेंट की जांच करने के लिए स्थानीय प्रीव्यू URL का उपयोग करें और राउटर के माध्यम से पहुंचे पृष्ठ की जांच करें। `vite preview` इस स्थानीय जांच के लिए है; nginx उत्पादन फ़ाइलों को सर्व करता है। बिल्ड आउटपुट और प्रीव्यू व्यवहार के लिए [Vite की डिप्लॉयमेंट गाइड](https://vite.dev/guide/static-deploy.html) देखें।

<span id="deploy" />

## डिप्लॉय

[CLI सेटअप](/framework-guides#prepare-the-project) के बाद, वर्तमान स्रोत डायरेक्टरी को डिप्लॉय करें:

```bash
lizard init --name vue-app
lizard add --service web
lizard up --service web --port 80
lizard logs --build --service web --json
lizard ps --json
```

स्थानीय निर्भरताओं, `dist/`, और `.env` फ़ाइलों को अपलोड से बाहर रखें। कोई मौजूदा कमांड ओवरराइड न होने पर, lizardpack Vite का पता लगाता है और स्थिर इमेज बनाता है। `npm run dev` को सर्विस स्टार्ट कमांड के रूप में न जोड़ें।

<span id="vue-router-history-mode" />

## Vue राउटर हिस्ट्री मोड

यदि आपका ऐप `createWebHistory` का उपयोग करता है, तो उसके सर्वर को क्लाइंट रूट पर सीधे अनुरोधों को संभालना चाहिए। डिफ़ॉल्ट स्थिर इमेज फ़ाइल न मिलने पर `index.html` सर्व करता है, इसलिए `/account` हार्ड रीलोड पर Vue राउटर तक पहुंच सकता है। राउटर बेस को Vite बेस से मिलाएं, उदाहरण के लिए `createWebHistory(import.meta.env.BASE_URL)` के साथ। [Vue राउटर हिस्ट्री मोड](https://router.vuejs.org/guide/essentials/history-mode.html) देखें।

होम पेज से नेविगेशन और एक नए टैब में `/account` खोलने दोनों का परीक्षण करें। गुम क्लाइंट रूट के लिए एक कैच-ऑल व्यू जोड़ें। सर्वर फ़ॉलबैक अज्ञात पथों के लिए भी HTTP 200 लौटाता है; यह खोज-अनुकूल 404 प्रतिक्रियाएं प्रदान नहीं करता है। इस सेटअप का उपयोग इंडेक्स की गई सामग्री साइट के लिए करने से पहले [स्थिर रूट और 404](/framework-guides/static-routing) पढ़ें।

## चर और API अनुरोध

Vite बिल्ड के दौरान `VITE_*` मानों को ब्राउज़र बंडल में लिखता है। उनका उपयोग केवल सार्वजनिक मानों के लिए करें, जैसे कि आपके API का सार्वजनिक HTTPS URL। `lizard up` के साथ, उन्हें `.env.production` में कमिट करें (जांचें कि `.gitignore` इसे बाहर नहीं करता है); Lizard चर केवल [GitHub सेवा](/deploy/github) पर बिल्ड तक पहुंचते हैं, जैसा कि [बिल्ड-टाइम चर](/concepts/build-pipeline#build-time-variables) में वर्णित है। फिर पुनर्निर्मित ऐप के वास्तविक नेटवर्क अनुरोध की जांच करें। रनटाइम-ओनली रीस्टार्ट निर्मित जावास्क्रिप्ट के अंदर एक मान को प्रतिस्थापित नहीं कर सकता है।

यदि अनुरोध केवल डिप्लॉयमेंट के बाद विफल होते हैं, तो API पर CORS की जांच करें और पुष्टि करें कि ब्राउज़र `localhost` या निजी बैकएंड होस्टनाम को कॉल नहीं कर रहा है। यदि HTML लोड होता है लेकिन एसेट विफल होते हैं, तो Vite के बेस और एसेट पथों का निरीक्षण करें। उन पृष्ठों के लिए जिन्हें HTML की आवश्यकता होती है इससे पहले कि जावास्क्रिप्ट चलता है, Nuxt रेंडरिंग या एक स्पष्ट प्रीरेंडरिंग चरण चुनें।

सितंबर 9, 2026 डिप्लॉयमेंट चेक और उनकी सीमाओं के लिए [टेस्टेड वर्जन और क्लाउड रिजल्ट्स](/framework-guides/validation) देखें।
