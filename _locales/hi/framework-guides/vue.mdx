# Lizard पर Vite के साथ Vue डिप्लॉय करें

Vite से बिल्ड किए गए Vue ऐप को Lizard पर स्टैटिक वेब सर्विस के रूप में डिप्लॉय करें। बिल्ड `dist/` बनाता है, और nginx फ़ाइलों को पोर्ट `80` पर सर्व करता है। Nuxt के सर्वर रेंडरिंग और सर्वर रूट्स के लिए [Nuxt गाइड](/framework-guides/nuxt) देखें।

<span id="prepare-the-project" />

## प्रोजेक्ट तैयार करें

Vue ऐप की उस डायरेक्टरी से चलाएँ जिसमें `package.json`, लॉकफ़ाइल और Vite कॉन्फ़िगरेशन हों। स्कैफ़ोल्ड की बिल्ड स्क्रिप्ट रहने दें, और अगर उसमें `vue-tsc` आपके TypeScript कोड की जाँच करता है तो उसे भी। बिल्ड के आख़िर में `dist/` में Vite बंडल बनना चाहिए।

| सेटिंग | वैल्यू |
|---|---|
| बिल्ड | `npm run build` |
| आउटपुट | `dist/` |
| स्टार्ट कमांड | स्टैटिक डिटेक्शन के लिए कोई नहीं |
| सर्विस पोर्ट | `80` |

डोमेन रूट पर चलने वाली साइट के लिए `base: '/'` रखें। अगर आप पाथ प्रीफ़िक्स इस्तेमाल करते हैं, तो Vite के base को राउटर base और उस URL से मिलाएँ जहाँ ऐप असल में चलता है। कस्टम आउटपुट डायरेक्टरी के लिए ऐसा Dockerfile चाहिए जो उस डायरेक्टरी को कॉपी करे।

<span id="check-the-build-locally" />

## बिल्ड को लोकल रूप से जाँचें

```bash
npm ci
npm run build
npm run preview
```

लोकल प्रीव्यू URL पर डेटा लाने वाला कोई कंपोनेंट और राउटर के ज़रिए खुलने वाला कोई पेज जाँचें। `vite preview` सिर्फ़ इसी लोकल जाँच के लिए है; प्रोडक्शन फ़ाइलें nginx सर्व करता है। बिल्ड आउटपुट और प्रीव्यू के व्यवहार के लिए [Vite की डिप्लॉयमेंट गाइड](https://vite.dev/guide/static-deploy.html) देखें।

<span id="deploy" />

## डिप्लॉय

[CLI सेटअप](/framework-guides#prepare-the-project) के बाद मौजूदा सोर्स डायरेक्टरी को डिप्लॉय करें:

```bash
lizard init --name vue-app
lizard add --service web
lizard up --service web --port 80
lizard logs --build --service web --json
lizard ps --json
```

लोकल डिपेंडेंसी, `dist/` और `.env` फ़ाइलों को अपलोड से बाहर रखें। अगर पहले से कोई कमांड ओवरराइड नहीं है, तो lizardpack Vite पहचानता है और स्टैटिक इमेज बिल्ड करता है। `npm run dev` को सर्विस का स्टार्ट कमांड न बनाएँ।

<span id="vue-router-history-mode" />

## Vue Router history मोड

अगर आपका ऐप `createWebHistory` इस्तेमाल करता है, तो उसके सर्वर को क्लाइंट रूट्स पर सीधी रिक्वेस्ट संभालनी होंगी। फ़ाइल न मिलने पर डिफ़ॉल्ट स्टैटिक इमेज `index.html` सर्व करती है, इसलिए हार्ड रीलोड पर भी `/account` Vue Router तक पहुँच जाता है। राउटर base को Vite base से मिलाएँ, उदाहरण के लिए `createWebHistory(import.meta.env.BASE_URL)` से। [Vue Router history मोड](https://router.vuejs.org/guide/essentials/history-mode.html) देखें।

होम पेज से नेविगेशन और नए टैब में `/account` खोलना, दोनों टेस्ट करें। न मिलने वाले क्लाइंट रूट्स के लिए catch-all व्यू जोड़ें। सर्वर फ़ॉलबैक अनजान पाथ के लिए भी HTTP 200 लौटाता है; यह सर्च के लिए सही 404 रिस्पॉन्स नहीं देता। इंडेक्स होने वाली कंटेंट साइट के लिए यह सेटअप इस्तेमाल करने से पहले [स्टैटिक रूट्स और 404](/framework-guides/static-routing) पढ़ें।

<span id="variables-and-api-requests" />

## वेरिएबल्स और API रिक्वेस्ट

Vite बिल्ड के दौरान `VITE_*` वैल्यू ब्राउज़र बंडल में लिख देता है। इन्हें सिर्फ़ पब्लिक वैल्यू के लिए इस्तेमाल करें, जैसे आपके API का पब्लिक HTTPS URL। `lizard up` के साथ इन्हें `.env.production` में कमिट करें (जाँच लें कि `.gitignore` उसे बाहर नहीं करता); Lizard के वेरिएबल्स सिर्फ़ [GitHub सर्विस](/deploy/github) पर ही बिल्ड तक पहुँचते हैं, जैसा [बिल्ड-टाइम वेरिएबल्स](/concepts/build-pipeline#build-time-variables) में बताया गया है। फिर रीबिल्ड हुए ऐप की असली नेटवर्क रिक्वेस्ट जाँचें। सिर्फ़ रनटाइम रीस्टार्ट से बिल्ड हुए JavaScript के अंदर की वैल्यू नहीं बदल सकती।

अगर रिक्वेस्ट सिर्फ़ डिप्लॉय के बाद फ़ेल होती हैं, तो API पर CORS जाँचें और पक्का करें कि ब्राउज़र `localhost` या किसी प्राइवेट बैकएंड होस्टनेम को कॉल नहीं कर रहा। अगर HTML लोड होता है लेकिन एसेट्स फ़ेल होते हैं, तो Vite का base और एसेट पाथ जाँचें। जिन पेजों को JavaScript चलने से पहले ही HTML चाहिए, उनके लिए Nuxt रेंडरिंग या अलग प्रीरेंडरिंग स्टेप चुनें।

9 सितंबर 2026 के डिप्लॉयमेंट चेक और उनकी सीमाओं के लिए [टेस्ट किए गए वर्ज़न और क्लाउड नतीजे](/framework-guides/validation) देखें।
