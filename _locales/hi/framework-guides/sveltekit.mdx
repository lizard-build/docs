# SvelteKit को Lizard पर डिप्लॉय करें

Lizard के लिए SvelteKit सर्वर बनाने के लिए `@sveltejs/adapter-node` का उपयोग करें। यह `build/` उत्पन्न करता है, जो पोर्ट `3000` पर `node build` के साथ शुरू होता है। एडॉप्टर को स्पष्ट रूप से इंस्टॉल और कॉन्फ़िगर करें; एक स्कैफोल्ड जो अभी भी `adapter-auto` का उपयोग करता है, एक Node डिप्लॉयमेंट टारगेट स्थापित नहीं करता है।

[पूर्ण स्रोत उदाहरण](https://github.com/lizard-build/docs/tree/main/_examples/sveltekit) से शुरू करें, जिसमें इस रेसिपी द्वारा उपयोग की जाने वाली कॉन्फ़िगरेशन और फ़ाइलें शामिल हैं।

<span id="configure-the-adapter" />

## एडॉप्टर को कॉन्फ़िगर करें

एडॉप्टर का मेजर संस्करण SvelteKit के संस्करण से मेल खाना चाहिए। SvelteKit 2, पर जिसे उदाहरण और क्लाउड चेक उपयोग करते हैं, adapter-node 5 इंस्टॉल करें:

```bash
npm install --save-dev @sveltejs/adapter-node@5
```

`@5` के बिना, npm adapter-node 6, चुनता है जिसे SvelteKit 3, की आवश्यकता होती है और यह `ERESOLVE` एरर के साथ रुक जाता है।

`svelte.config.js` में, अपने मौजूदा प्रीप्रोसेस और अन्य सेटिंग्स को रखें, लेकिन Node एडॉप्टर पर `kit.adapter` सेट करें:

```js
import adapter from '@sveltejs/adapter-node';

export default {
  kit: { adapter: adapter() },
};
```

SvelteKit 3, पर `npm install --save-dev @sveltejs/adapter-node` चलाएं ताकि adapter-node 6. प्राप्त हो सके। SvelteKit 3 अब `svelte.config.js` को नहीं पढ़ता है; `sveltekit()` प्लगइन को `vite.config.js` में एडॉप्टर पास करें:

```js
import adapter from '@sveltejs/adapter-node';
import { sveltekit } from '@sveltejs/kit/vite';
import { defineConfig } from 'vite';

export default defineConfig({
  plugins: [sveltekit({ adapter: adapter() })],
});
```

SvelteKit 3 को Node 22.17 या बाद के संस्करण की आवश्यकता है; डिफ़ॉल्ट Node 22 बिल्ड इमेज इसे पूरा करती है। हमने SvelteKit 3 चरणों को स्थानीय रूप से बनाया है लेकिन अभी तक उन्हें Lizard पर डिप्लॉय नहीं किया है।

केवल उस डिप्लॉयमेंट एडॉप्टर को रखें जिसका आप उपयोग करना चाहते हैं। विशेष रूप से, एक अप्रयुक्त `@sveltejs/adapter-static` निर्भरता वर्तमान डिटेक्टर में स्टैटिक पाथ का चयन कर सकती है, भले ही आपका कॉन्फ़िगरेशन adapter-node को इम्पोर्ट करता हो।

| सेटिंग | मान |
|---|---|
| बिल्ड | `npm run build`, आमतौर पर `vite build` |
| आउटपुट | `build/` |
| रनटाइम | `node build` |
| होस्ट और पोर्ट | `HOST=0.0.0.0`, `PORT=3000` |
| सर्विस पोर्ट | `3000` |

## प्रोडक्शन सर्वर का परीक्षण करें

```bash
npm ci
npm run build
HOST=0.0.0.0 PORT=3000 ORIGIN=http://localhost:3000 node build
```

सर्वर-रेंडर्ड पेज खोलें और फॉर्म एक्शन सबमिट करें यदि ऐप में एक है। इस गाइड में उपयोग किए गए डिटेक्शन के लिए एडॉप्टर के डिफ़ॉल्ट आउटपुट पाथ को रखें।

adapter-node 6, `ORIGIN` को अनदेखा करता है। यह `https` से ओरिजिन बनाता है और रिक्वेस्ट के `Host` हेडर से, इसलिए SvelteKit 3 पर `http://localhost:3000` से भेजा गया फॉर्म इस लोकल टेस्ट में 403 प्राप्त करता है। डिप्लॉयड HTTPS URL पर फॉर्म की जांच करें।

<span id="deploy-and-set-the-public-origin" />

## पब्लिक ओरिजिन को डिप्लॉय और सेट करें

[CLI सेटअप](/framework-guides#prepare-the-project) के बाद:

```bash
lizard init --name sveltekit-app
lizard add --service web
lizard up --service web --port 3000
lizard ps --json
```

SvelteKit 2, पर `ORIGIN` को डिप्लॉयमेंट आउटपुट से सटीक पब्लिक HTTPS ओरिजिन पर सेट करें, बिना पाथ के। उदाहरण के लिए, इस प्लेसहोल्डर को अपने वास्तविक URL से बदलें:

```bash
lizard secrets set ORIGIN=https://YOUR_PUBLIC_HOST --service web
```

यदि आगंतुक उसी ओरिजिन का उपयोग करेंगे तो कस्टम डोमेन का उपयोग करें। वेरिएबल परिवर्तन के बाद फॉर्म की फिर से जांच करें। कई अनुमत ओरिजिन या प्रॉक्सी-व्युत्पन्न URL के लिए, [SvelteKit Node सर्वर गाइड](https://svelte.dev/docs/kit/adapter-node) पढ़ें और जानबूझकर विश्वसनीय प्रॉक्सी हेडर कॉन्फ़िगर करें।

SvelteKit 3, पर `ORIGIN` को छोड़ दें: ऐप `Host` हेडर से अपना ओरिजिन लेता है, जो पब्लिक होस्टनाम या आपके कस्टम डोमेन को ले जाता है। एक ओरिजिन को पिन करने के लिए, `sveltekit()` विकल्पों में `paths: { origin: 'https://YOUR_PUBLIC_HOST' }` सेट करें; SvelteKit इसे बिल्ड टाइम पर पढ़ता है।

## सत्यापित करें और समस्या निवारण करें

`lizard logs --build --service web --json` और `lizard logs --service web --json` के साथ बिल्ड और रनटाइम लॉग पढ़ें। सीधे एक आंतरिक रूट खोलें, एक फ़ॉर्म सबमिट करें, और एक अनुपलब्ध रूट का अनुरोध करें।

यदि फ़ॉर्म क्रॉस-साइट सबमिशन त्रुटि की रिपोर्ट करते हैं, तो सुरक्षा जांच को अक्षम करने से पहले `ORIGIN` (SvelteKit 2) या `paths.origin` (SvelteKit 3) की जाँच करें। यदि `node build` सर्वर नहीं ढूंढ पाता है, तो सक्रिय एडाप्टर और आउटपुट पथ को सत्यापित करें। lizardpack पथ का उपयोग करने के लिए सेवा कमांड ओवरराइड को अनसेट छोड़ दें।

## स्टेटिक SvelteKit साइटें

एक ऐप जो सभी आवश्यक पृष्ठों को प्रीरेंडर कर सकता है, `@sveltejs/adapter-static`, इसके डिफ़ॉल्ट `build/` आउटपुट और सेवा पोर्ट `80` का उपयोग कर सकता है। वह आउटपुट सर्वर क्रियाएं या रनटाइम एंडपॉइंट्स का अनुरोध नहीं कर सकता है। आपको जिन रूट्स के लिए प्रीरेंडरिंग की आवश्यकता है, उन्हें कॉन्फ़िगर करें; पैकेज इंस्टॉल करना ही काफ़ी नहीं है।

SvelteKit 2, पर `@sveltejs/adapter-static@3` इंस्टॉल करें (संस्करण 4 के लिए SvelteKit 3 की आवश्यकता है) और `svelte.config.js` में एडाप्टर आयात को बदलें:

```js
import adapter from '@sveltejs/adapter-static';

export default {
  kit: { adapter: adapter() },
};
```

SvelteKit 3, पर `@sveltejs/adapter-static` इंस्टॉल करें और इसे adapter-node के स्थान पर `vite.config.js` में आयात करें।

एक साइट के लिए जिसके सभी रूट्स जेनरेट किए जा सकते हैं, `src/routes/+layout.js` में यह जोड़ें:

```js
export const prerender = true;
export const trailingSlash = 'always';
```

डिपेंडेंसी से अप्रयुक्त डिप्लॉयमेंट एडाप्टर हटा दें। `npm run build` चलाएं और जांचें कि `build/` में प्रत्येक आवश्यक पृष्ठ शामिल है। डिफ़ॉल्ट आउटपुट के लिए, सेवा कमांड ओवरराइड को अनसेट छोड़ दें और पोर्ट `80` पर एक नई सेवा डिप्लॉय करें। नए बिल्ड जेनरेट किए गए HTML को सर्व करेंगे और अनुपलब्ध पृष्ठों के लिए HTTP 404 लौटाएंगे। nginx के लिए सर्वर रेसिपी के पोर्ट `3000` का पुन: उपयोग न करें।

जेनरेट किए गए HTML रूट्स और एक SPA फ़ॉलबैक के बीच चयन करने के लिए [स्टेटिक रूट्स और 404s](/framework-guides/static-routing) का उपयोग करें। फ्रेमवर्क विकल्पों और सीमाओं के लिए [SvelteKit स्टेटिक एडाप्टर](https://svelte.dev/docs/kit/adapter-static) देखें।

सितंबर 9, 2026 डिप्लॉयमेंट चेक और उनकी सीमाओं के लिए [टेस्टेड वर्जन और क्लाउड रिजल्ट्स](/framework-guides/validation) देखें।
