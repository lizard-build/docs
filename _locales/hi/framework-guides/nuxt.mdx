# Lizard पर Nuxt डिप्लॉय करें

Nitro के `node-server` प्रीसेट के साथ Lizard पर Nuxt चलाएं। बिल्ड `.output/server/index.mjs` उत्पन्न करता है, और एक Node.js प्रक्रिया `3000` पोर्ट पर पेज और सर्वर रूट्स सर्व करती है। `80` पोर्ट पर एक जेनरेटेड साइट के लिए, नीचे दिए गए स्टैटिक रेसिपी का उपयोग करें।

<span id="configure-the-production-build" />

## प्रोडक्शन बिल्ड को कॉन्फ़िगर करें

[प्रोजेक्ट तैयार करें](/framework-guides#prepare-the-project) से वर्तमान Lizard CLI का उपयोग करें। संस्करण 0.3.95 और उसके बाद के संस्करण अपलोड के दौरान macOS आर्काइव मेटाडेटा को बाहर रखते हैं। यदि कोई पुराना CLI `._*.ts` रूट त्रुटि रिपोर्ट करता है, तो CLI को अपडेट करें और फिर से अपलोड करें।

`nuxt.config.ts` में प्रीसेट सेट करें:

```ts
export default defineNuxtConfig({
  nitro: { preset: 'node-server' },
});
```

इन स्क्रिप्ट्स को `package.json` में मर्ज करें, साथ ही आपकी ऐप को आवश्यक किसी भी अन्य स्क्रिप्ट को रखें:

```json
{
  "scripts": {
    "dev": "nuxt dev",
    "build": "nuxt build",
    "start": "HOST=0.0.0.0 PORT=3000 node .output/server/index.mjs"
  }
}
```

स्टार्ट स्क्रिप्ट डिप्लॉयमेंट कंटेनर में लिनक्स शेल का उपयोग करती है। lizardpack `nuxt` निर्भरता का पता लगाता है और बिल्ड और स्टार्ट स्क्रिप्ट चलाता है। एक नई Nuxt परियोजना में `start` शामिल नहीं हो सकता है; इसे जोड़ने के बजाय `nuxt dev` प्रोडक्शन बिल्ड को सर्व करेगा, यह मानकर इसे जोड़ें।

| सेटिंग | मान |
|---|---|
| बिल्ड | `npm run build` |
| सर्वर एंट्री | `.output/server/index.mjs` |
| स्टार्ट | `npm run start` |
| सर्विस पोर्ट | `3000` |

<span id="test-the-built-app" />

## बिल्ट ऐप का परीक्षण करें

```bash
npm ci
npm run build
npm run start
```

`http://localhost:3000` खोलें, सीधे एक आंतरिक पेज का अनुरोध करें, और यदि मौजूद हो तो अपने `server/api` रूट्स में से एक को कॉल करें। जांचें कि बिल्ड Node सर्वर प्रीसेट रिपोर्ट करता है। एक प्रदाता-विशिष्ट Nitro प्रीसेट एक अलग एंट्री पॉइंट उत्पन्न कर सकता है।

<span id="deploy" />

## डिप्लॉय

[CLI सेटअप](/framework-guides#prepare-the-project) के बाद, Nuxt ऐप डायरेक्टरी से चलाएं:

```bash
lizard init --name nuxt-app
lizard add --service web
lizard up --service web --port 3000
lizard logs --build --service web --json
lizard logs --service web --json
lizard ps --json
```

`.nuxt/`, `.output/`, `node_modules/`, और `.env` फाइलों को अपलोड से बाहर रखें। सोर्स, कॉन्फ़िगरेशन और लॉकफ़ाइल शामिल करें। मौजूदा सेवा बिल्ड/स्टार्ट ओवरराइड यहां उपयोग की जाने वाली पहचान को बायपास करते हैं; [बिल्ड निर्णय क्रम](/concepts/build-pipeline#build-decision-order) देखें।

<span id="runtime-configuration" />

## रनटाइम कॉन्फ़िगरेशन

`runtimeConfig` में रनटाइम सेटिंग्स घोषित करें और सेवा के लिए उनके मिलान वाले `NUXT_*` मानों को कॉन्फ़िगर करें। `runtimeConfig.public` के बाहर सीक्रेट्स रखें; सार्वजनिक भाग ब्राउज़र तक पहुंचता है। पेज प्रीरेंडर करने के लिए उपयोग किए जाने वाले मान अभी भी जेनरेटेड बिल्ड को प्रभावित करते हैं, इसलिए परिवर्तन के बाद रिक्वेस्ट-टाइम और प्रीरेंडर्ड दोनों रूट्स की जांच करें।

सेवा को कॉन्फ़िगर करने के लिए [वेरिएबल्स और सीक्रेट्स](/variables) और टिकाऊ डेटा के लिए [स्टोरेज और रिकवरी](/platform/storage-and-recovery) का उपयोग करें। लोकल कैश या सेशन फ़ाइल को रेप्लिका के बीच साझा स्टोरेज के रूप में न मानें।

<span id="troubleshooting" />

## समस्या निवारण

यदि प्रक्रिया एक मिसिंग `.output/server/index.mjs` रिपोर्ट करती है, तो प्रीसेट और बिल्ड आउटपुट का निरीक्षण करें। यदि यह एक मिसिंग स्टार्ट स्क्रिप्ट रिपोर्ट करती है, तो ऊपर वाली स्क्रिप्ट जोड़ें। यदि साइट कभी स्वस्थ नहीं होती है, तो होस्ट और पोर्ट की जांच करें।

पूरी तरह से जेनरेटेड Nuxt साइट के लिए, `.output/public/` को एक स्टैटिक Dockerfile और सही रूट हैंडलिंग के साथ सर्व करें। उस आउटपुट को ऊपर दिए गए Node कमांड से शुरू न करें। [Nuxt डिप्लॉयमेंट गाइड](https://nuxt.com/docs/4.x/getting-started/deployment) Node और जेनरेटेड आउटपुट की व्याख्या करता है; [स्टैटिक रूट्स और 404s](/framework-guides/static-routing) Lizard स्टैटिक सर्वर सेटअप को कवर करता है।

<span id="generate-a-static-site" />

## एक स्टैटिक साइट जेनरेट करें

जेनरेटेड HTML के लिए, Node प्रीसेट को स्पष्ट प्रीरेंडर सेटिंग्स से बदलें और बिल्ड स्क्रिप्ट को `nuxt generate` में बदलें:

```ts
export default defineNuxtConfig({
  nitro: {
    prerender: { crawlLinks: true, routes: ['/'] },
  },
});
```

जब क्रॉलर उन्हें खोज नहीं पाता है तो अनलिंक्ड या डायनामिक रूट्स को `routes` में जोड़ें। `npm run build` चलाएं और जांचें कि `.output/public/index.html` और आपकी आंतरिक रूट फाइलें मौजूद हैं। Nuxt 4.5.2, के साथ परीक्षण में `preset: 'node-server'` रखते हुए केवल `nuxt generate` पर स्विच करने से साइट के रूट्स के बिना फ़ॉलबैक पेज उत्पन्न हुए। बिल्ड सफल रहा, भले ही एक्सपोर्ट में साइट के रूट्स नहीं थे।

[स्टैटिक रूट्स और 404s](/framework-guides/static-routing) में Dockerfile और nginx कॉन्फ़िगरेशन का उपयोग करें, बिल्ड स्क्रिप्ट `build`, आउटपुट डायरेक्टरी `.output/public`, और सेवा पोर्ट `80` के साथ। स्टैटिक कंटेनर Nuxt सर्वर रूट्स नहीं चलाता है या पहले से जेनरेटेड पेजों के लिए रनटाइम कॉन्फ़िगरेशन नहीं पढ़ता है।

सितंबर 9, 2026 डिप्लॉयमेंट चेक और उनकी सीमाओं के लिए [टेस्टेड वर्जन और क्लाउड रिजल्ट्स](/framework-guides/validation) देखें।
