# Lizard पर Nuxt डिप्लॉय करें

Nitro के `node-server` प्रीसेट के साथ Lizard पर Nuxt चलाएँ। बिल्ड `.output/server/index.mjs` बनाता है, और एक Node.js प्रोसेस पोर्ट `3000` पर पेज और सर्वर रूट्स सर्व करता है। पोर्ट `80` पर जेनरेट की गई साइट के लिए नीचे दी गई स्टैटिक रेसिपी इस्तेमाल करें।

<span id="configure-the-production-build" />

## प्रोडक्शन बिल्ड कॉन्फ़िगर करें

[प्रोजेक्ट तैयार करें](/framework-guides#prepare-the-project) में बताया गया मौजूदा Lizard CLI इस्तेमाल करें। वर्ज़न 0.3.95 और उसके बाद के वर्ज़न अपलोड के दौरान macOS आर्काइव मेटाडेटा को बाहर रखते हैं। अगर कोई पुराना CLI `._*.ts` रूट एरर दिखाता है, तो CLI अपडेट करें और फिर से अपलोड करें।

`nuxt.config.ts` में प्रीसेट सेट करें:

```ts
export default defineNuxtConfig({
  nitro: { preset: 'node-server' },
});
```

ये स्क्रिप्ट्स `package.json` में मर्ज करें, और आपके ऐप को जिन दूसरी स्क्रिप्ट्स की ज़रूरत है उन्हें भी रहने दें:

```json
{
  "scripts": {
    "dev": "nuxt dev",
    "build": "nuxt build",
    "start": "HOST=0.0.0.0 PORT=3000 node .output/server/index.mjs"
  }
}
```

स्टार्ट स्क्रिप्ट डिप्लॉयमेंट कंटेनर के Linux शेल में चलती है। lizardpack `nuxt` डिपेंडेंसी पहचानता है और बिल्ड व स्टार्ट स्क्रिप्ट चलाता है। नए Nuxt प्रोजेक्ट में `start` स्क्रिप्ट शायद न हो; यह मानकर न चलें कि `nuxt dev` प्रोडक्शन बिल्ड सर्व कर देगा, बल्कि यह स्क्रिप्ट जोड़ें।

| सेटिंग | वैल्यू |
|---|---|
| बिल्ड | `npm run build` |
| सर्वर एंट्री | `.output/server/index.mjs` |
| स्टार्ट | `npm run start` |
| सर्विस पोर्ट | `3000` |

<span id="test-the-built-app" />

## बिल्ड किए गए ऐप को टेस्ट करें

```bash
npm ci
npm run build
npm run start
```

`http://localhost:3000` खोलें, किसी अंदरूनी पेज को सीधे खोलें, और अगर आपके `server/api` रूट्स हैं तो उनमें से किसी एक को कॉल करें। जाँचें कि बिल्ड Node सर्वर प्रीसेट दिखाता है। किसी ख़ास प्रोवाइडर का Nitro प्रीसेट अलग एंट्री पॉइंट बना सकता है।

<span id="deploy" />

## डिप्लॉय

[CLI सेटअप](/framework-guides#prepare-the-project) के बाद Nuxt ऐप डायरेक्टरी से चलाएँ:

```bash
lizard init --name nuxt-app
lizard add --service web
lizard up --service web --port 3000
lizard logs --build --service web --json
lizard logs --service web --json
lizard ps --json
```

`.nuxt/`, `.output/`, `node_modules/` और `.env` फ़ाइलों को अपलोड से बाहर रखें। सोर्स, कॉन्फ़िगरेशन और लॉकफ़ाइल शामिल करें। सर्विस पर पहले से मौजूद बिल्ड/स्टार्ट ओवरराइड यहाँ इस्तेमाल होने वाले डिटेक्शन को बायपास कर देते हैं; [बिल्ड का निर्णय-क्रम](/concepts/build-pipeline#build-decision-order) देखें।

<span id="runtime-configuration" />

## रनटाइम कॉन्फ़िगरेशन

रनटाइम सेटिंग्स `runtimeConfig` में घोषित करें और सर्विस के लिए उनसे मेल खाने वाली `NUXT_*` वैल्यू कॉन्फ़िगर करें। सीक्रेट्स को `runtimeConfig.public` से बाहर रखें; पब्लिक हिस्सा ब्राउज़र तक पहुँचता है। पेज प्रीरेंडर करने में इस्तेमाल हुई वैल्यू जेनरेट हुए बिल्ड पर असर डालती रहती हैं, इसलिए कोई बदलाव करने के बाद रिक्वेस्ट-टाइम और प्रीरेंडर किए गए, दोनों तरह के रूट्स जाँचें।

सर्विस कॉन्फ़िगर करने के लिए [वेरिएबल्स और सीक्रेट्स](/variables) और स्थायी डेटा के लिए [स्टोरेज और रिकवरी](/platform/storage-and-recovery) देखें। लोकल कैश या सेशन फ़ाइल को रेप्लिका के बीच साझा स्टोरेज न मानें।

<span id="troubleshooting" />

## समस्या का समाधान

अगर प्रोसेस बताता है कि `.output/server/index.mjs` नहीं मिली, तो प्रीसेट और बिल्ड आउटपुट जाँचें। अगर स्टार्ट स्क्रिप्ट न होने की बात आती है, तो ऊपर वाली स्क्रिप्ट जोड़ें। अगर साइट कभी हेल्दी नहीं होती, तो होस्ट और पोर्ट जाँचें।

पूरी तरह जेनरेट की गई Nuxt साइट के लिए `.output/public/` को स्टैटिक Dockerfile और सही रूट हैंडलिंग के साथ सर्व करें। इस आउटपुट को ऊपर दिए गए Node कमांड से शुरू न करें। [Nuxt डिप्लॉयमेंट गाइड](https://nuxt.com/docs/4.x/getting-started/deployment) Node और जेनरेट किए गए, दोनों आउटपुट समझाती है; [स्टैटिक रूट्स और 404](/framework-guides/static-routing) में Lizard के स्टैटिक सर्वर का सेटअप है।

<span id="generate-a-static-site" />

## स्टैटिक साइट जेनरेट करें

जेनरेट किए गए HTML के लिए Node प्रीसेट की जगह साफ़ तौर पर प्रीरेंडर सेटिंग्स दें और बिल्ड स्क्रिप्ट को `nuxt generate` में बदलें:

```ts
export default defineNuxtConfig({
  nitro: {
    prerender: { crawlLinks: true, routes: ['/'] },
  },
});
```

जिन रूट्स पर कोई लिंक नहीं है या जो डायनामिक हैं और जिन्हें क्रॉलर नहीं ढूँढ पाता, उन्हें `routes` में जोड़ें। `npm run build` चलाएँ और जाँचें कि `.output/public/index.html` और आपके अंदरूनी रूट्स की फ़ाइलें मौजूद हैं। Nuxt 4.5.2 के साथ टेस्ट में `preset: 'node-server'` रखते हुए सिर्फ़ `nuxt generate` पर स्विच करने से साइट के रूट्स के बिना केवल फ़ॉलबैक पेज बने। एक्सपोर्ट में साइट के रूट्स न होने के बावजूद बिल्ड सफल रहा।

[स्टैटिक रूट्स और 404](/framework-guides/static-routing) में दिया गया Dockerfile और nginx कॉन्फ़िगरेशन इस्तेमाल करें, बिल्ड स्क्रिप्ट `build`, आउटपुट डायरेक्टरी `.output/public` और सर्विस पोर्ट `80` के साथ। स्टैटिक कंटेनर न तो Nuxt के सर्वर रूट्स चलाता है और न ही पहले से जेनरेट हुए पेजों के लिए रनटाइम कॉन्फ़िगरेशन पढ़ता है।

9 सितंबर 2026 के डिप्लॉयमेंट चेक और उनकी सीमाओं के लिए [टेस्ट किए गए वर्ज़न और क्लाउड नतीजे](/framework-guides/validation) देखें।
