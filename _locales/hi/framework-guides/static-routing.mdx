# स्टेटिक रूट्स और 404s

एक जेनरेटेड कंटेंट साइट को प्रत्येक रूट के HTML को सर्व करना चाहिए और एक गुम पेज के लिए HTTP 404 लौटाना चाहिए। Astro स्टेटिक, Docusaurus, VitePress, Hugo, और SvelteKit adapter-static के लिए नए lizardpack बिल्ड उस नीति का उपयोग करते हैं। React और Vue SPA ब्राउज़र राउटर द्वारा आवश्यक `index.html` फ़ॉलबैक को बनाए रखते हैं।

वे बिल्ड nginx के अपने 404 पेज के साथ एक गुम पेज का जवाब देते हैं, कभी भी साइट के `404.html` का नहीं। अपने स्वयं के 404 पेज के लिए, नीचे दिए गए nginx कॉन्फ़िगरेशन और Dockerfile का उपयोग करें।

एक फ़ोल्डर URL जिसमें एक ट्रेलिंग स्लैश नहीं है, जैसे `/guide`, `guide/index.html` के लिए, 301 रीडायरेक्ट को `http://YOUR_PUBLIC_HOST/guide/` पर प्राप्त करता है, और Lizard फिर उसे HTTPS पर रीडायरेक्ट करता है। दोनों हॉप्स को छोड़ने के लिए ट्रेलिंग-स्लैश फ़ॉर्म से लिंक करें, या नीचे दिए गए कॉन्फ़िगरेशन का उपयोग करें, जो HTTPS पर रीडायरेक्ट रखता है।

नीचे दिया गया कस्टम कॉन्फ़िगरेशन वैकल्पिक है। इसका उपयोग उस रूटिंग नीति के लिए करें जो डिटेक्टेड फ्रेमवर्क प्रदान नहीं करता है। मौजूदा इमेज उन्हें फिर से बनाने तक अपने पुराने नियम बनाए रखती हैं।

<span id="choose-the-routing-policy" />

## रूटिंग नीति चुनें

| ऐप प्रकार | रूट व्यवहार |
|---|---|
| React या Vue SPA | एक मान्य क्लाइंट रूट `index.html` लोड करता है, फिर क्लाइंट राउटर इसे रेंडर करता है। |
| जेनरेटेड डॉक्यूमेंटेशन या कंटेंट | एक रूट उसके जेनरेटेड HTML पर हल होता है; एक अज्ञात पाथ HTTP 404. लौटाता है |
| सर्वर-रेंडर्ड ऐप | एप्लिकेशन सर्वर रूट्स को हल करता है और स्टेटस लौटाता है। |

एक SPA कैच-ऑल व्यू एक गुम-पेज संदेश दिखा सकता है, लेकिन ब्राउज़र कोड पहले से भेजे गए HTML प्रतिक्रिया की HTTP स्थिति को नहीं बदल सकता है। यदि आपको SPA के लिए रूट-जागरूक HTTP स्थिति की आवश्यकता है, तो एक सर्वर या प्री-रेंडर्ड रूट सेटअप का उपयोग करें जो जानता है कि कौन से पाथ मौजूद हैं।

<span id="configure-nginx-for-generated-pages" />

## जेनरेटेड पेजों के लिए nginx कॉन्फ़िगर करें

एप्लिकेशन रूट पर `nginx.conf` बनाएं:

```nginx
server {
  listen 80;
  server_name _;
  root /usr/share/nginx/html;
  index index.html;
  absolute_redirect off;

  location / {
    try_files $uri $uri.html $uri/ =404;
  }

  error_page 404 /404.html;
  location = /404.html {
    internal;
  }
}
```

यह `guide.html` और `guide/index.html` आउटपुट लेआउट दोनों का समर्थन करता है। `error_page` साइट के उत्पन्न `404.html` को 404 स्थिति के साथ परोसता है; यदि साइट में कोई `404.html` नहीं है, तो nginx के डिफ़ॉल्ट त्रुटि बॉडी का उपयोग करने के लिए `error_page` और सटीक-स्थान ब्लॉक छोड़ दें। `absolute_redirect off` फ़ोल्डर रीडायरेक्ट को एक सापेक्ष `Location: /guide/` के रूप में भेजता है, इसलिए ब्राउज़र HTTPS पर रहता है। साइट के लिंक और साइटमैप में एक कैनोनिकल URL शैली रखें; यह लुकअप नियम कैनोनिकल रीडायरेक्ट नहीं जोड़ता है।

<span id="build-the-site-with-the-config" />

## कॉन्फ़िगरेशन के साथ साइट बनाएँ

एक प्रतिबद्ध लॉकफ़ाइल के साथ npm प्रोजेक्ट के लिए इस पूर्ण Dockerfile का उपयोग करें। नीचे दी गई तालिका से मिलान करने के लिए `BUILD_SCRIPT` और `OUTPUT_DIR` डिफ़ॉल्ट बदलें:

```dockerfile
FROM node:22-slim AS build
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
ARG BUILD_SCRIPT=build
RUN npm run "$BUILD_SCRIPT"

FROM nginx:alpine
ARG OUTPUT_DIR=dist
COPY --from=build /app/${OUTPUT_DIR}/ /usr/share/nginx/html/
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
```

| साइट | `BUILD_SCRIPT` | `OUTPUT_DIR` |
|---|---|---|
| Astro स्थैतिक | `build` | `dist` |
| Docusaurus | `build` | `build` |
| `docs/` रूट के साथ VitePress | `docs:build` | `docs/.vitepress/dist` |
| प्रोजेक्ट रूट पर VitePress | `docs:build` या आपका वास्तविक स्क्रिप्ट | `.vitepress/dist` |
| adapter-static के साथ SvelteKit | `build` | `build` |
| Next.js निर्यात | `build` | `out` |
| Nuxt उत्पन्न करें | `nuxt generate` के साथ `build` | `.output/public` |

जनरेटेड-पेज पॉलिसी का उपयोग केवल तब करें जब ऐप में वे रूट फ़ाइलें हों। उदाहरण के लिए, एक SvelteKit SPA फ़ॉलबैक को अपनी रूटिंग पॉलिसी की आवश्यकता होती है। [Next.js स्थैतिक निर्यात](/framework-guides/nextjs/static-export) में एक ट्रेलिंग-स्लैश लेआउट के साथ एक पूर्ण रेसिपी है।

निर्भरता, बिल्ड आउटपुट, `.git`, और `.dockerignore` में `.env*` को बाहर करें। यदि बिल्ड को सार्वजनिक चर की आवश्यकता है, तो उन्हें बिल्ड कमांड से पहले `ENV` लाइनों के रूप में लिखें। Lizard `COMMIT_SHA` को छोड़कर कोई बिल्ड आर्गुमेंट पास नहीं करता है, इसलिए एक `ARG` खाली रहता है। निजी रहस्यों को इमेज या ब्राउज़र आउटपुट में कॉपी न करें।

[CLI सेटअप](/framework-guides#prepare-the-project) के बाद, `lizard add --service web` के साथ एक सेवा बनाएँ, फिर इस स्रोत को `lizard up --service web --port 80` के साथ परिनियोजित करें। जब सेवा पहले से मौजूद हो तो ऐड स्टेप छोड़ दें। मौजूदा सेवा पर, [बिल्ड निर्णय क्रम](/concepts/build-pipeline#build-decision-order) की जाँच करें: कमांड ओवरराइड डॉकरफ़ाइल पर प्राथमिकता ले सकते हैं। केवल एक कॉन्फ़िगरेशन फ़ाइल उत्पन्न nginx कॉन्फ़िगरेशन को प्रतिस्थापित नहीं करती है; डॉकरफ़ाइल को इसे इमेज में कॉपी करना होगा।

## HTTP प्रतिक्रियाओं को सत्यापित करें

वास्तविक स्थानीय परीक्षण URL या परिनियोजित मूल के लिए `SITE_URL` सेट करें, फिर मौजूद पृष्ठ के साथ `/guide/` को बदलें:

```bash
SITE_URL=https://YOUR_PUBLIC_HOST
curl -sS -o /dev/null -w '%{http_code}\n' "$SITE_URL/"
curl -sS -o /dev/null -w '%{http_code}\n' "$SITE_URL/guide/"
curl -sS -o /dev/null -w '%{http_code}\n' "$SITE_URL/this-page-does-not-exist"
```

वास्तविक पृष्ठों के लिए 200 और अनुपलब्ध पथ के लिए 404 की अपेक्षा करें। यदि एक मान्य मार्ग अपने कैनोनिकल रूप में रीडायरेक्ट करता है, तो रीडायरेक्ट का निरीक्षण करें और फिर गंतव्य को सत्यापित करें। एक वास्तविक संपत्ति और एक मनगढ़ंत `.js` पथ का भी परीक्षण करें: एक अनुपलब्ध स्क्रिप्ट को स्थिति 200. के साथ HTML के रूप में होम पेज वापस नहीं करना चाहिए।

अंत में, आंतरिक मार्ग को सीधे ब्राउज़र में खोलें और इसे रीलोड करें। केवल सही क्लाइंट नेविगेशन सर्वर रूटिंग त्रुटि को छिपा सकता है। अनुक्रमित साइट प्रकाशित करने से पहले फ्रेमवर्क की कैनोनिकल URL और साइटमैप सेटिंग्स की HTTP स्थिति के साथ जाँच करें।
