# Lizard पर Hugo डिप्लॉय करें

Lizard Hugo सोर्स साइट को `hugo --minify` से बिल्ड कर सकता है और `public/` को nginx के ज़रिए पोर्ट `80` पर सर्व कर सकता है। सिर्फ़ जनरेट किया गया HTML अपलोड करने के बजाय Hugo की सोर्स डायरेक्टरी से शुरू करें, जिसमें Hugo कॉन्फ़िगरेशन और `content/` हो।

[पूरे सोर्स वाले उदाहरण](https://github.com/lizard-build/docs/tree/main/_examples/hugo) में इस गाइड में इस्तेमाल हुई कॉन्फ़िगरेशन और फ़ाइलें शामिल हैं।

<span id="prepare-the-source" />

## सोर्स तैयार करें

अपना Hugo कॉन्फ़िग, कंटेंट, लेआउट, एसेट्स और बिल्ड के लिए ज़रूरी सभी थीम फ़ाइलें शामिल करें। Hugo डिटेक्टर `hugo.toml`, `hugo.yaml` या `config/_default/` जैसी कॉन्फ़िगरेशन और साथ में `content/` डायरेक्टरी ढूँढता है।

| सेटिंग | मान |
|---|---|
| बिल्ड | `hugo --minify` |
| आउटपुट | `public/` |
| प्रोडक्शन सर्वर | nginx |
| सर्विस पोर्ट | `80` |

`baseURL` को साइट के इच्छित पब्लिक URL पर सेट करें, आख़िरी स्लैश समेत। कोई दूसरा होस्टनेम देने के बाद रीबिल्ड करें, ताकि लिंक और जनरेट की गई साइटमैप एंट्री में वही होस्टनेम आए। [Hugo की बिल्ड और आउटपुट गाइड](https://gohugo.io/getting-started/usage/) देखें।

<span id="check-build-dependencies" />

## बिल्ड की डिपेंडेंसी जाँचें

Hugo की डिफ़ॉल्ट बिल्ड इमेज `hugomods/hugo:base` है; वह आपके प्रोजेक्ट के लिए Hugo का वर्ज़न पिन नहीं करती। अगर किसी थीम को Hugo का कोई ख़ास वर्ज़न, Hugo extended एडिशन या Node टूलिंग चाहिए, तो इन डिपेंडेंसी और आपके टेस्ट किए वर्ज़न वाला पूरा Dockerfile इस्तेमाल करें।

Hugo कॉन्फ़िग और `content/` होने पर Go या Node की डिटेक्शन से पहले ही Hugo बिल्डर चुन लिया जाता है। `go.mod` वाले Hugo Modules प्रोजेक्ट Go सपोर्ट वाली बिल्ड इमेज इस्तेमाल करते हैं। `package.json` होने पर बिल्ड रुक जाता है और Dockerfile माँगा जाता है: उसमें Node डिपेंडेंसी इंस्टॉल करें, एसेट्स बिल्ड करें, फिर `hugo --minify` चलाएँ। [बिल्ड का निर्णय क्रम](/concepts/build-pipeline#build-decision-order) देखें।

<span id="build-locally-and-deploy" />

## लोकल बिल्ड करें और डिप्लॉय करें

```bash
hugo --minify
hugo server
```

पहली कमांड के बाद `public/` देखें। कंटेंट और थीम की रेंडरिंग जाँचने के लिए लोकल सर्वर इस्तेमाल करें; `hugo server` प्रोडक्शन की स्टार्ट कमांड नहीं है।

[CLI सेटअप](/framework-guides#prepare-the-project) के बाद सोर्स डायरेक्टरी डिप्लॉय करें:

```bash
lizard init --name hugo-site
lizard add --service web
lizard up --service web --port 80
lizard logs --build --service web --json
lizard ps --json
```

अगर आप जनरेट किया गया होस्टनेम इस्तेमाल करते हैं, तो पहले डिप्लॉय के बाद उसे देख लें:

```bash
lizard service show web --json
```

`hugo.toml` में `baseURL` को उसी होस्टनेम पर सेट करें:

```toml
baseURL = "https://YOUR_PUBLIC_HOST/"
```

बदला हुआ कॉन्फ़िग अपलोड करें, ताकि बिल्ड पब्लिक URL इस्तेमाल करे:

```bash
lizard up --service web --port 80
```


लोकल जनरेट हुआ आउटपुट और सीक्रेट्स अपलोड से बाहर रखें। थीम की सोर्स फ़ाइलें अपलोड डायरेक्टरी में शामिल करें। रिमोट सबमॉड्यूल का रेफ़रेंस देने से वे फ़ाइलें शामिल नहीं होतीं।

<span id="verify-the-deployed-site" />

## डिप्लॉय हुई साइट जाँचें

लाइव होम पेज, कोई अंदर का आर्टिकल और कोई इमेज खोलें। जनरेट किए गए canonical URL और `sitemap.xml` जाँचें। किसी मनगढ़ंत पाथ का HTTP स्टेटस टेस्ट करें। Hugo के नए बिल्ड जनरेट किया गया HTML सर्व करते हैं और गैर-मौजूद पेजों के लिए HTTP 404 लौटाते हैं, लेकिन आपके `404.html` लेआउट के बजाय nginx के डिफ़ॉल्ट एरर पेज के साथ। इस गाइड के सरल सोर्स लेआउट के लिए कस्टम Dockerfile की ज़रूरत नहीं है। रूटिंग के मौजूदा नियम लागू करवाने के लिए पुरानी इमेज रीबिल्ड करें।

अगर आपको कस्टम nginx नियम या अपना 404 पेज चाहिए, तो [स्टैटिक रूट और 404](/framework-guides/static-routing) इस्तेमाल करें। कस्टम Hugo बिल्ड स्टेज में थीम के लिए ज़रूरी Hugo वर्ज़न और टूल होने चाहिए, उसे `hugo --minify` चलाना चाहिए और `public/` को सर्व करने वाली इमेज में कॉपी करना चाहिए।

अगर थीम के एसेट्स नहीं मिल रहे, तो बिल्ड लॉग, थीम का सोर्स और `baseURL` जाँचें। अगर गलत बिल्डर शुरू होता है, तो देखें कि Hugo कॉन्फ़िग और `content/` अपलोड के रूट में हैं, और सर्विस पर पहले से सेट ओवरराइड जाँचें। Hugo स्टैटिक फ़ाइलें बनाता है, इसलिए कंटेंट बदलने पर नया बिल्ड ज़रूरी है।

9 सितंबर 2026 को किए गए डिप्लॉयमेंट चेक और उनकी सीमाओं के लिए [टेस्ट किए गए वर्ज़न और क्लाउड के नतीजे](/framework-guides/validation) देखें।
