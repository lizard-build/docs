# Lizard पर Hugo को परिनियोजित करें

Lizard, `hugo --minify` के साथ एक Hugo स्रोत साइट बना सकता है और `public/` को पोर्ट `80` पर nginx के माध्यम से सेवा दे सकता है। Hugo स्रोत निर्देशिका से शुरू करें, जिसमें Hugo कॉन्फ़िगरेशन और `content/` हो, न कि केवल उत्पन्न HTML अपलोड करने के बजाय।

[संपूर्ण स्रोत उदाहरण](https://github.com/lizard-build/docs/tree/main/_examples/hugo) में इस गाइड में उपयोग की गई कॉन्फ़िगरेशन और फ़ाइलें शामिल हैं।

<span id="prepare-the-source" />

## स्रोत तैयार करें

अपने Hugo कॉन्फ़िगरेशन, सामग्री, लेआउट, संपत्ति और बिल्ड द्वारा आवश्यक सभी थीम फ़ाइलों को शामिल करें। Hugo डिटेक्टर `hugo.toml`, `hugo.yaml`, या `config/_default/` जैसी कॉन्फ़िगरेशन और एक `content/` निर्देशिका की तलाश करता है।

| सेटिंग | मान |
|---|---|
| बिल्ड | `hugo --minify` |
| आउटपुट | `public/` |
| प्रोडक्शन सर्वर | nginx |
| सर्विस पोर्ट | `80` |

`baseURL` को इच्छित पब्लिक साइट URL पर सेट करें, जिसमें उसका ट्रेलिंग स्लैश शामिल हो। एक अलग होस्टनाम असाइन करने के बाद फिर से बनाएं ताकि लिंक और उत्पन्न साइटमैप प्रविष्टियां इसका उपयोग करें। [Hugo की बिल्ड और आउटपुट गाइड](https://gohugo.io/getting-started/usage/) देखें।

<span id="check-build-dependencies" />

## बिल्ड निर्भरताओं की जाँच करें

डिफ़ॉल्ट Hugo बिल्ड इमेज `hugomods/hugo:base` है; यह आपके प्रोजेक्ट के लिए Hugo संस्करण को पिन नहीं करता है। यदि किसी थीम को विशेष Hugo संस्करण, विस्तारित संस्करण, या Node टूलिंग की आवश्यकता है, तो उन निर्भरताओं और आपके द्वारा परीक्षण किए गए संस्करण के साथ एक पूर्ण Dockerfile का उपयोग करें।

एक Hugo कॉन्फ़िगरेशन और `content/` Go या Node डिटेक्शन से पहले Hugo बिल्डर का चयन करते हैं। `go.mod` के साथ Hugo मॉड्यूल प्रोजेक्ट Go समर्थन के साथ एक बिल्ड इमेज का उपयोग करते हैं। एक `package.json` बिल्ड को Dockerfile के लिए अनुरोध के साथ रोकता है: Node निर्भरताओं को स्थापित करें, संपत्ति बनाएं, फिर `hugo --minify` चलाएं। [बिल्ड निर्णय क्रम](/concepts/build-pipeline#build-decision-order) देखें।

<span id="build-locally-and-deploy" />

## स्थानीय रूप से बिल्ड करें और परिनियोजित करें

```bash
hugo --minify
hugo server
```

पहले कमांड के बाद `public/` का निरीक्षण करें। सामग्री और थीम रेंडरिंग की जांच के लिए स्थानीय सर्वर का उपयोग करें; `hugo server` प्रोडक्शन स्टार्ट कमांड नहीं है।

[CLI सेटअप](/framework-guides#prepare-the-project) के बाद, स्रोत निर्देशिका को परिनियोजित करें:

```bash
lizard init --name hugo-site
lizard add --service web
lizard up --service web --port 80
lizard logs --build --service web --json
lizard ps --json
```

यदि आप जेनरेट किए गए होस्टनाम का उपयोग करते हैं, तो इसे पहले डिप्लॉय के बाद पढ़ें:

```bash
lizard service show web --json
```

`hugo.toml` में `baseURL` को उस होस्टनाम पर सेट करें:

```toml
baseURL = "https://YOUR_PUBLIC_HOST/"
```

बिल्ड पब्लिक यूआरएल का उपयोग करे, इसके लिए बदली हुई कॉन्फ़िग अपलोड करें:

```bash
lizard up --service web --port 80
```


स्थानीय रूप से उत्पन्न आउटपुट और रहस्यों को बाहर करें। अपलोड निर्देशिका में थीम की स्रोत फ़ाइलों को शामिल करें। एक रिमोट सबमॉड्यूल संदर्भ में वे फ़ाइलें शामिल नहीं होती हैं।

<span id="verify-the-deployed-site" />

## परिनियोजित साइट को सत्यापित करें

लाइव होम पेज, एक आंतरिक लेख और एक छवि खोलें। उत्पन्न कैनोनिकल URL और `sitemap.xml` की जांच करें। एक मनगढ़ंत पथ के HTTP स्थिति का परीक्षण करें। नए Hugo बिल्ड उत्पन्न HTML की सेवा करते हैं और आपके `404.html` लेआउट के बजाय nginx के डिफ़ॉल्ट त्रुटि पृष्ठ के साथ गुम पृष्ठों के लिए HTTP 404 लौटाते हैं। इस गाइड में सरल स्रोत लेआउट के लिए किसी कस्टम Dockerfile की आवश्यकता नहीं है। वर्तमान रूटिंग नियमों को चुनने के लिए पुराने इमेज को फिर से बनाएं।

यदि आपको कस्टम nginx नीति या अपना 404 पृष्ठ चाहिए तो [स्थिर रूट और 404s](/framework-guides/static-routing) का उपयोग करें। एक कस्टम Hugo बिल्ड चरण में थीम की आवश्यक Hugo संस्करण और उपकरण शामिल होने चाहिए, `hugo --minify` चलाना चाहिए, और `public/` को सेवा देने वाली इमेज में कॉपी करना चाहिए।

यदि थीम संपत्ति गुम हैं, तो बिल्ड लॉग, थीम स्रोत और `baseURL` का निरीक्षण करें। यदि गलत बिल्डर शुरू होता है, तो जांचें कि Hugo कॉन्फ़िगरेशन और `content/` अपलोड रूट में हैं और मौजूदा सेवा ओवरराइड का निरीक्षण करें। Hugo स्थिर फ़ाइलें उत्पन्न करता है, इसलिए सामग्री परिवर्तन के लिए एक नए बिल्ड की आवश्यकता होती है।

सितंबर 9, 2026 डिप्लॉयमेंट चेक और उनकी सीमाओं के लिए [टेस्टेड वर्जन और क्लाउड रिजल्ट्स](/framework-guides/validation) देखें।
