# Lizard पर Vite के साथ React डिप्लॉय करें

Lizard एक React ऐप बनाता है जो Vite का उपयोग करता है और `dist/` डायरेक्टरी को पोर्ट `80` पर nginx के माध्यम से सर्व करता है। यह गाइड ब्राउज़र-रेंडर्ड ऐप को कवर करती है। सर्वर की आवश्यकता वाले React पेजों के लिए, [Next.js गाइड](/framework-guides/nextjs) का पालन करें या अपने चुने हुए React फ्रेमवर्क के लिए प्रोडक्शन सर्वर प्रदान करें।

<span id="prepare-the-build" />

## बिल्ड तैयार करें

एक मौजूदा React और Vite प्रोजेक्ट का उपयोग करें जिसमें लॉकफ़ाइल कमिटेड हो। इसके `package.json` में एक प्रोडक्शन बिल्ड स्क्रिप्ट की आवश्यकता है:

```json
{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview"
  }
}
```

यदि आपका स्कैफोल्ड `vite build` से पहले टाइपस्क्रिप्ट जाँच चलाता है, तो उन जाँचों को बनाए रखें। Vite के डिफ़ॉल्ट `dist` आउटपुट डायरेक्टरी को बनाए रखें। एक कस्टम `build.outDir` के लिए एक मिलान Dockerfile की आवश्यकता होती है क्योंकि मानक डिटेक्शन पाथ `dist` को कॉपी करता है।

| सेटिंग | मान |
|---|---|
| डिटेक्शन | डिपेंडेंसी या डेव डिपेंडेंसी में `vite` |
| बिल्ड | `npm run build` |
| आउटपुट | `dist/` |
| प्रोडक्शन सर्वर | nginx; किसी Node स्टार्ट स्क्रिप्ट की आवश्यकता नहीं है |
| सर्विस पोर्ट | `80` |

<span id="test-locally" />

## स्थानीय रूप से परीक्षण करें

```bash
npm ci
npm run build
npm run preview
```

लोकल प्रीव्यू URL खोलें और अपने API को कॉल करने वाले पेज का परीक्षण करें। प्रीव्यू कमांड लोकल रूप से बिल्ड की जाँच करता है; `vite preview` को प्रोडक्शन स्टार्ट कमांड के रूप में सेट न करें। [Vite डिप्लॉयमेंट](https://vite.dev/guide/static-deploy.html) देखें।

<span id="deploy-the-source" />

## सोर्स डिप्लॉय करें

[CLI सेटअप](/framework-guides#prepare-the-project) के बाद, `package.json` वाली डायरेक्टरी से चलाएँ:

```bash
lizard init --name react-app
lizard add --service web
lizard up --service web --port 80
lizard logs --build --service web --json
lizard ps --json
```

सोर्स और लॉकफ़ाइल अपलोड करें, `node_modules/`, `dist/`, और सीक्रेट्स को छोड़कर। स्टेटिक डिटेक्शन पाथ का उपयोग करने के लिए सर्विस बिल्ड/स्टार्ट ओवरराइड्स को अनसेट छोड़ दें। nginx कंटेनर पोर्ट 80, पर सुनता है, जो `--port` के साथ पास किया गया पोर्ट है, भले ही डेवलपमेंट और प्रीव्यू सर्वर अन्य पोर्ट का उपयोग करते हों।

<span id="connect-an-api" />

## API कनेक्ट करें

API के ब्राउज़र-पहुँच योग्य HTTPS पते के लिए `VITE_API_URL` जैसे पब्लिक वेरिएबल का उपयोग करें। इसे `import.meta.env.VITE_API_URL` के रूप में पढ़ें। `lizard up` के साथ, Lizard बिल्ड को कोई वेरिएबल पास नहीं करता है: `.env.production` में मान को कमिट करें (जाँचें कि `.gitignore` इसे बाहर नहीं करता है) और बदलने पर फिर से अपलोड करें। [GitHub सर्विस](/deploy/github) पर, इसे [वेरिएबल्स और सीक्रेट्स](/variables) के माध्यम से सेट करें और परिवर्तन ऐप को फिर से बनाएगा। [बिल्ड-टाइम वेरिएबल्स](/concepts/build-pipeline#build-time-variables) देखें। कभी भी डेटाबेस URL, API क्रेडेंशियल, या आंतरिक-केवल सर्विस एड्रेस को `VITE_*` वेरिएबल के माध्यम से उजागर न करें।

किसी अन्य ऑरिजिन पर API के लिए, उसके अनुमत ऑरिजिन को फ्रंटएंड URL शामिल करने के लिए कॉन्फ़िगर करें। एक निजी सर्विस होस्टनाम जो बैकएंड सेवाओं के बीच काम करता है, विज़िटर के ब्राउज़र में हल नहीं होगा।

<span id="verify-routing" />

## रूटिंग सत्यापित करें

लाइव ऐप खोलें, एक क्लाइंट रूट का अनुसरण करें, फिर सीधे उस URL को रीलोड करें। डिफ़ॉल्ट स्टेटिक सर्वर `index.html` पर वापस आ जाता है ताकि क्लाइंट राउटर एक आंतरिक रूट को रेंडर कर सके। React ऐप में अज्ञात पाथ के लिए भी एक रूट जोड़ें। वह फ़ॉलबैक अभी भी HTTP 200 लौटाता है; उन पेजों के लिए सर्वर नीति चुनने के लिए [स्टेटिक रूट्स और 404s](/framework-guides/static-routing) का उपयोग करें जिन्हें वास्तविक HTTP 404 प्रतिक्रियाओं की आवश्यकता होती है।

यदि कोई एसेट HTML लौटाता है या पेज खाली हो जाता है, तो Vite के `base`, अनुरोधित एसेट URL और आउटपुट डायरेक्टरी की जाँच करें। यदि ऐप कभी भी स्वस्थ नहीं होता है, तो जाँचें कि सर्विस पोर्ट `80` है और किसी पुराने स्टार्ट-कमांड ओवरराइड ने अलग बिल्ड पाथ का चयन नहीं किया है।

उन पेजों के लिए जो सर्च में दिखाई देने वाले हैं, प्रारंभिक HTML प्रतिक्रिया का निरीक्षण करें। ब्राउज़र-रेंडर्ड शेल में वह टेक्स्ट नहीं हो सकता है जिसकी आप सर्च इंजन या उत्तर इंजन से अपेक्षा करते हैं। जब आपको उस टेक्स्ट की प्रतिक्रिया में आवश्यकता हो तो प्री-रेंडरिंग या सर्वर फ्रेमवर्क चुनें।

सितंबर 9, 2026 डिप्लॉयमेंट चेक और उनकी सीमाओं के लिए [टेस्टेड वर्जन और क्लाउड रिजल्ट्स](/framework-guides/validation) देखें।
