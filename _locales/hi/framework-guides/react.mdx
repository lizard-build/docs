# Lizard पर Vite के साथ React डिप्लॉय करें

Lizard Vite इस्तेमाल करने वाले React ऐप को बिल्ड करता है और उसकी `dist/` डायरेक्टरी को nginx के ज़रिए पोर्ट `80` पर सर्व करता है। यह गाइड ब्राउज़र में रेंडर होने वाले ऐप के लिए है। जिन React पेजों को सर्वर चाहिए, उनके लिए [Next.js गाइड](/framework-guides/nextjs) देखें या अपने चुने हुए React फ्रेमवर्क के लिए प्रोडक्शन सर्वर दें।

<span id="prepare-the-build" />

## बिल्ड तैयार करें

ऐसा मौजूदा React और Vite प्रोजेक्ट इस्तेमाल करें जिसमें लॉकफ़ाइल कमिट की हुई हो। उसके `package.json` में प्रोडक्शन बिल्ड स्क्रिप्ट होनी चाहिए:

```json
{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview"
  }
}
```

अगर आपका स्कैफ़ोल्ड `vite build` से पहले TypeScript चेक चलाता है, तो उन्हें रहने दें। Vite की डिफ़ॉल्ट `dist` आउटपुट डायरेक्टरी न बदलें। कस्टम `build.outDir` के लिए उसी से मेल खाता Dockerfile चाहिए, क्योंकि स्टैंडर्ड डिटेक्शन `dist` को ही कॉपी करता है।

| सेटिंग | वैल्यू |
|---|---|
| डिटेक्शन | dependencies या dev dependencies में `vite` |
| बिल्ड | `npm run build` |
| आउटपुट | `dist/` |
| प्रोडक्शन सर्वर | nginx; Node स्टार्ट स्क्रिप्ट की ज़रूरत नहीं |
| सर्विस पोर्ट | `80` |

<span id="test-locally" />

## लोकल रूप से टेस्ट करें

```bash
npm ci
npm run build
npm run preview
```

लोकल प्रीव्यू URL खोलें और ऐसा पेज टेस्ट करें जो आपके API को कॉल करता हो। प्रीव्यू कमांड बिल्ड को लोकल रूप से जाँचने के लिए है; `vite preview` को प्रोडक्शन स्टार्ट कमांड न बनाएँ। [Vite डिप्लॉयमेंट](https://vite.dev/guide/static-deploy.html) देखें।

<span id="deploy-the-source" />

## सोर्स डिप्लॉय करें

[CLI सेटअप](/framework-guides#prepare-the-project) के बाद `package.json` वाली डायरेक्टरी से चलाएँ:

```bash
lizard init --name react-app
lizard add --service web
lizard up --service web --port 80
lizard logs --build --service web --json
lizard ps --json
```

सोर्स और लॉकफ़ाइल अपलोड करें, लेकिन `node_modules/`, `dist/` और सीक्रेट्स को छोड़कर। स्टैटिक डिटेक्शन इस्तेमाल करने के लिए सर्विस के बिल्ड/स्टार्ट ओवरराइड सेट न करें। nginx कंटेनर पोर्ट 80 पर सुनता है, यानी वही पोर्ट जो `--port` से दिया गया है, भले ही डेवलपमेंट और प्रीव्यू सर्वर दूसरे पोर्ट इस्तेमाल करते हों।

<span id="connect-an-api" />

## API कनेक्ट करें

API के उस HTTPS पते के लिए, जिस तक ब्राउज़र पहुँच सके, `VITE_API_URL` जैसा पब्लिक वेरिएबल इस्तेमाल करें। उसे `import.meta.env.VITE_API_URL` के रूप में पढ़ें। `lizard up` के साथ Lizard बिल्ड को कोई वेरिएबल नहीं देता: वैल्यू को `.env.production` में कमिट करें (जाँच लें कि `.gitignore` उसे बाहर नहीं करता) और वैल्यू बदलने पर फिर से अपलोड करें। [GitHub सर्विस](/deploy/github) पर इसे [वेरिएबल्स और सीक्रेट्स](/variables) से सेट करें; बदलाव होने पर ऐप रीबिल्ड हो जाता है। [बिल्ड-टाइम वेरिएबल्स](/concepts/build-pipeline#build-time-variables) देखें। डेटाबेस URL, API क्रेडेंशियल या सिर्फ़ अंदरूनी सर्विस का पता कभी भी `VITE_*` वेरिएबल से उजागर न करें।

अगर API किसी दूसरे origin पर है, तो उसके allowed origins में फ्रंटएंड का URL जोड़ें। बैकएंड सर्विसेज़ के बीच काम करने वाला प्राइवेट सर्विस होस्टनेम विज़िटर के ब्राउज़र में resolve नहीं होगा।

<span id="verify-routing" />

## रूटिंग की जाँच करें

लाइव ऐप खोलें, किसी क्लाइंट रूट पर जाएँ, फिर उसी URL को सीधे रीलोड करें। डिफ़ॉल्ट स्टैटिक सर्वर फ़ॉलबैक के रूप में `index.html` देता है, ताकि क्लाइंट राउटर अंदरूनी रूट रेंडर कर सके। React ऐप में अनजान पाथ के लिए भी एक रूट जोड़ें। यह फ़ॉलबैक फिर भी HTTP 200 लौटाता है; जिन पेजों के लिए असली HTTP 404 रिस्पॉन्स चाहिए, उनके लिए सर्वर की नीति चुनने के लिए [स्टैटिक रूट्स और 404](/framework-guides/static-routing) देखें।

अगर कोई एसेट HTML लौटाता है या पेज खाली दिखता है, तो Vite का `base`, माँगा गया एसेट URL और आउटपुट डायरेक्टरी जाँचें। अगर ऐप कभी हेल्दी नहीं होता, तो जाँचें कि सर्विस पोर्ट `80` है और किसी पुराने स्टार्ट-कमांड ओवरराइड ने दूसरा बिल्ड तरीका तो नहीं चुन लिया।

जो पेज सर्च में दिखने चाहिए, उनके शुरुआती HTML रिस्पॉन्स की जाँच करें। हो सकता है कि ब्राउज़र में रेंडर होने वाले शेल में वह टेक्स्ट न हो जिसे आप चाहते हैं कि सर्च इंजन या answer engine पढ़े। जब आपको वह टेक्स्ट रिस्पॉन्स में ही चाहिए, तो प्रीरेंडरिंग या सर्वर फ्रेमवर्क चुनें।

9 सितंबर 2026 के डिप्लॉयमेंट चेक और उनकी सीमाओं के लिए [टेस्ट किए गए वर्ज़न और क्लाउड नतीजे](/framework-guides/validation) देखें।
