# Docusaurus को Lizard पर डिप्लॉय करें

Docusaurus को Lizard पर बिल्ड करें और nginx के माध्यम से `80` पोर्ट पर जेनरेट की गई `build/` डायरेक्टरी को सर्व करें। प्रोडक्शन डिप्लॉयमेंट स्टैटिक फ़ाइलों को सर्व करता है; यह `docusaurus start` डेवलपमेंट सर्वर नहीं चलाता है।

[संपूर्ण सोर्स उदाहरण](https://github.com/lizard-build/docs/tree/main/_examples/docusaurus) से शुरू करें, जिसमें इस रेसिपी द्वारा उपयोग की जाने वाली कॉन्फ़िगरेशन और फ़ाइलें शामिल हैं।

<span id="prepare-the-site" />

## साइट तैयार करें

Docusaurus डायरेक्टरी से चलाएं जिसमें `package.json`, इसकी लॉकफ़ाइल और `docusaurus.config.*` शामिल हैं। `@docusaurus/core` को डिपेंडेंसी में रखें और एक बिल्ड स्क्रिप्ट जो `docusaurus build` चलाती है।

| सेटिंग | मान |
|---|---|
| बिल्ड | `npm run build` |
| आउटपुट | `build/` |
| रनटाइम | nginx |
| सर्विस पोर्ट | `80` |

Docusaurus कॉन्फ़िग में `url` को साइट के इच्छित पब्लिक ओरिजिन पर और `baseUrl` को उस पाथ पर सेट करें जहाँ यह चलेगा। डोमेन रूट पर साइट के लिए, `baseUrl` `/` है। एक बार जब आप अंतिम होस्टनाम जान जाते हैं, तो उस होस्टनाम के साथ फिर से बिल्ड करें ताकि जेनरेट किए गए कैनोनिकल यूआरएल और साइटमैप एंट्री इसका उपयोग करें।

एक सुसंगत ट्रेलिंग-स्लैश पॉलिसी चुनें और परिणामी फ़ाइलों की जाँच करें। डिफ़ॉल्ट आउटपुट डायरेक्टरी रखें जब तक कि आप एक कस्टम डायरेक्टरी कॉपी करने वाली Dockerfile प्रदान न करें। [Docusaurus डिप्लॉयमेंट गाइड](https://docusaurus.io/docs/deployment) इन फ्रेमवर्क सेटिंग्स को समझाता है।

<span id="build-and-check-locally" />

## स्थानीय रूप से बिल्ड और जांचें

```bash
npm ci
npm run build
npm run serve
```

अंतिम कमांड मानता है कि आपके प्रोजेक्ट में स्कैफोल्ड की `serve` स्क्रिप्ट है। होम पेज, एक नेस्टेड डॉक्यूमेंटेशन पेज, एक इमेज और यदि आप डॉक्स संस्करणों का उपयोग करते हैं तो एक संस्करणित पेज की जाँच करें। डिप्लॉयमेंट से पहले बिल्ड द्वारा रिपोर्ट किए गए टूटे हुए लिंक को ठीक करें।

<span id="deploy" />

## डिप्लॉय

[CLI सेटअप](/framework-guides#prepare-the-project) के बाद:

```bash
lizard init --name docusaurus-docs
lizard add --service web
lizard up --service web --port 80
lizard logs --build --service web --json
lizard ps --json
```

यदि आप जेनरेट किए गए होस्टनाम का उपयोग करते हैं, तो इसे पहले डिप्लॉय के बाद पढ़ें:

```bash
lizard service show web --json
```

`docusaurus.config.js` में `url` को उस होस्टनाम पर सेट करें:

```js
url: 'https://YOUR_PUBLIC_HOST',
```

बिल्ड पब्लिक यूआरएल का उपयोग करे, इसके लिए बदली हुई कॉन्फ़िग अपलोड करें:

```bash
lizard up --service web --port 80
```


सोर्स, प्लगइन्स, कॉन्फ़िगरेशन और लॉकफ़ाइल को कमिट करें। अपलोड से `node_modules/`, `build/`, `.docusaurus/`, और `.env` फ़ाइलों को बाहर रखें। सर्विस कमांड ओवरराइड को अनसेट छोड़ दें ताकि Docusaurus डिटेक्शन पाथ का उपयोग किया जा सके।

<span id="serve-inner-routes-and-missing-pages" />

## आंतरिक रूट और गुम पृष्ठों को सर्व करें

नए Docusaurus बिल्ड जेनरेटेड रूट फ़ाइलों को सर्व करते हैं और अज्ञात पाथ के लिए HTTP 404 लौटाते हैं, साइट के `404.html` के बजाय nginx के डिफ़ॉल्ट एरर पेज के साथ। इस रूटिंग पॉलिसी के लिए एक कस्टम Dockerfile की आवश्यकता नहीं है। यदि आपकी सेवा अभी भी सितंबर 2026 रूटिंग फिक्स से पहले बनाई गई इमेज का उपयोग करती है, तो इसे फिर से बनाएं। कस्टम nginx व्यवहार, जैसे कि अपना 404 पेज सर्व करना, की आवश्यकता होने पर ही [स्टैटिक रूट और 404s](/framework-guides/static-routing) का उपयोग करें।

डिप्लॉयमेंट के बाद, सीधे एक नेस्टेड डॉक्स यूआरएल का अनुरोध करें, इसे रीफ़्रेश करें, और एक बनाए गए यूआरएल की स्थिति की जाँच करें। अंतिम होस्टनाम पर कैनोनिकल यूआरएल और साइटमैप का भी निरीक्षण करें। HTTP 200 के साथ एक दृश्यमान एरर पेज अभी भी एक सॉफ्ट 404. है।

यदि एसेट गुम हैं, तो उनके यूआरएल की `baseUrl` से तुलना करें। यदि कोई आंतरिक रूट होम पेज लौटाता है, तो जेनरेटेड फ़ाइल लेआउट और nginx नियमों का निरीक्षण करें। यदि किसी एनवायरनमेंट वैल्यू या मार्कडाउन फ़ाइल को संपादित करने के बाद पुराना कंटेंट बना रहता है, तो सत्यापित करें कि एक नया बिल्ड वास्तव में पूरा हो गया था; स्टैटिक HTML केवल बिल्ड के साथ बदलता है।

सितंबर 9, 2026 डिप्लॉयमेंट चेक और उनकी सीमाओं के लिए [टेस्टेड वर्जन और क्लाउड रिजल्ट्स](/framework-guides/validation) देखें।
