# Lizard पर Docusaurus डिप्लॉय करें

Lizard पर Docusaurus बिल्ड करें और उसकी जनरेट की गई `build/` डायरेक्टरी को nginx के ज़रिए पोर्ट `80` पर सर्व करें। प्रोडक्शन डिप्लॉयमेंट स्टैटिक फ़ाइलें सर्व करता है; वह `docusaurus start` डेवलपमेंट सर्वर नहीं चलाता।

[पूरे सोर्स वाले उदाहरण](https://github.com/lizard-build/docs/tree/main/_examples/docusaurus) से शुरू करें, जिसमें इस रेसिपी में इस्तेमाल हुई कॉन्फ़िगरेशन और फ़ाइलें शामिल हैं।

<span id="prepare-the-site" />

## साइट तैयार करें

कमांड उस Docusaurus डायरेक्टरी से चलाएँ जिसमें `package.json`, उसकी लॉकफ़ाइल और `docusaurus.config.*` हों। डिपेंडेंसी में `@docusaurus/core` और ऐसी build स्क्रिप्ट रखें जो `docusaurus build` चलाती हो।

| सेटिंग | मान |
|---|---|
| बिल्ड | `npm run build` |
| आउटपुट | `build/` |
| रनटाइम | nginx |
| सर्विस पोर्ट | `80` |

Docusaurus कॉन्फ़िग में `url` को साइट के इच्छित पब्लिक origin पर और `baseUrl` को उस पाथ पर सेट करें जहाँ साइट चलेगी। डोमेन के रूट पर चलने वाली साइट के लिए `baseUrl` `/` होता है। फ़ाइनल होस्टनेम पता चलते ही उसी होस्टनेम के साथ रीबिल्ड करें, ताकि जनरेट हुए canonical URL और साइटमैप एंट्री में वही होस्टनेम आए।

आख़िरी स्लैश (trailing slash) के लिए एक ही नीति चुनें और बनने वाली फ़ाइलें जाँचें। डिफ़ॉल्ट आउटपुट डायरेक्टरी ही रखें, जब तक आप ऐसा Dockerfile न दें जो आपकी कस्टम डायरेक्टरी कॉपी करता हो। [Docusaurus की डिप्लॉयमेंट गाइड](https://docusaurus.io/docs/deployment) फ़्रेमवर्क की इन सेटिंग्स को समझाती है।

<span id="build-and-check-locally" />

## लोकल बिल्ड करें और जाँचें

```bash
npm ci
npm run build
npm run serve
```

आख़िरी कमांड मानकर चलती है कि आपके प्रोजेक्ट में scaffold वाली `serve` स्क्रिप्ट है। होम पेज, अंदर का कोई डॉक्यूमेंटेशन पेज, कोई इमेज और, अगर आप डॉक्स के वर्ज़न इस्तेमाल करते हैं, तो किसी वर्ज़न वाला पेज जाँचें। डिप्लॉयमेंट से पहले बिल्ड में रिपोर्ट हुए टूटे लिंक ठीक करें।

<span id="deploy" />

## डिप्लॉय

[CLI सेटअप](/framework-guides#prepare-the-project) के बाद:

```bash
lizard init --name docusaurus-docs
lizard add --service web
lizard up --service web --port 80
lizard logs --build --service web --json
lizard ps --json
```

अगर आप जनरेट किया गया होस्टनेम इस्तेमाल करते हैं, तो पहले डिप्लॉय के बाद उसे देख लें:

```bash
lizard service show web --json
```

`docusaurus.config.js` में `url` को उसी होस्टनेम पर सेट करें:

```js
url: 'https://YOUR_PUBLIC_HOST',
```

बदला हुआ कॉन्फ़िग अपलोड करें, ताकि बिल्ड पब्लिक URL इस्तेमाल करे:

```bash
lizard up --service web --port 80
```


सोर्स, प्लगइन, कॉन्फ़िगरेशन और लॉकफ़ाइल कमिट करें। `node_modules/`, `build/`, `.docusaurus/` और `.env` फ़ाइलें अपलोड से बाहर रखें। Docusaurus की डिटेक्शन इस्तेमाल करने के लिए सर्विस के कमांड ओवरराइड सेट न करें।

<span id="serve-inner-routes-and-missing-pages" />

## अंदर के रूट और गैर-मौजूद पेज सर्व करना

Docusaurus के नए बिल्ड जनरेट की गई रूट फ़ाइलें सर्व करते हैं और अनजान पाथ के लिए HTTP 404 लौटाते हैं, लेकिन साइट के `404.html` के बजाय nginx के डिफ़ॉल्ट एरर पेज के साथ। इस रूटिंग नीति के लिए कस्टम Dockerfile की ज़रूरत नहीं है। अगर आपकी सर्विस अब भी सितंबर 2026 के रूटिंग फ़िक्स से पहले बिल्ड हुई इमेज इस्तेमाल करती है, तो उसे रीबिल्ड करें। [स्टैटिक रूट और 404](/framework-guides/static-routing) सिर्फ़ तब इस्तेमाल करें, जब आपको nginx का कस्टम व्यवहार चाहिए, जैसे अपना 404 पेज सर्व करना।

डिप्लॉयमेंट के बाद डॉक्स का कोई अंदर का URL सीधे खोलें, पेज रीफ़्रेश करें, और किसी मनगढ़ंत (मौजूद न होने वाले) URL का स्टेटस जाँचें। फ़ाइनल होस्टनेम पर canonical URL और साइटमैप भी देखें। HTTP 200 के साथ दिखने वाला एरर पेज भी soft 404 ही है।

अगर एसेट्स नहीं मिल रहे, तो उनके URL की `baseUrl` से तुलना करें। अगर कोई अंदर का रूट होम पेज लौटाता है, तो जनरेट हुई फ़ाइलों का लेआउट और nginx के नियम जाँचें। अगर एनवायरनमेंट वेरिएबल या Markdown फ़ाइल बदलने के बाद भी पुराना कंटेंट दिखता है, तो पक्का करें कि नया बिल्ड सच में पूरा हुआ; स्टैटिक HTML सिर्फ़ बिल्ड से बदलता है।

9 सितंबर 2026 को किए गए डिप्लॉयमेंट चेक और उनकी सीमाओं के लिए [टेस्ट किए गए वर्ज़न और क्लाउड के नतीजे](/framework-guides/validation) देखें।
