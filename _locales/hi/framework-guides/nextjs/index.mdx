# Lizard पर Next.js डिप्लॉय करें

Lizard पर Next.js को `next build` और `next start` के साथ Node.js सर्वर के रूप में चलाएँ। सर्वर रिक्वेस्ट-टाइम रेंडरिंग, Route Handlers और Server Actions संभालता है। अगर हर रूट पहले से बिल्ड किया जा सकता है, तो इसके बजाय [Next.js स्टैटिक एक्सपोर्ट](/framework-guides/nextjs/static-export) गाइड देखें।

<span id="build-settings" />

## बिल्ड सेटिंग्स

| सेटिंग | वैल्यू |
|---|---|
| प्रोजेक्ट रूट | `package.json` और Next.js कॉन्फ़िगरेशन वाली डायरेक्टरी |
| बिल्ड स्क्रिप्ट | `next build` |
| स्टार्ट स्क्रिप्ट | `next start --hostname 0.0.0.0 --port 3000` |
| बिल्ड आउटपुट | `.next/` |
| सर्विस पोर्ट | `3000` |
| रनटाइम | Node.js |

<span id="prepare-the-app" />

## ऐप तैयार करें

`next`, `react` और `react-dom` को अपनी डिपेंडेंसी में रखें और अपनी लॉकफ़ाइल कमिट करें। ये स्क्रिप्ट्स `package.json` में मर्ज करें:

```json
{
  "scripts": {
    "dev": "next dev",
    "build": "next build",
    "start": "next start --hostname 0.0.0.0 --port 3000"
  }
}
```

इस गाइड के लिए Next.js का स्टैंडर्ड आउटपुट इस्तेमाल करें। `output: 'export'` को स्टैटिक सर्वर चाहिए, और `output: 'standalone'` को अपना `server.js` लॉन्च और एसेट लेआउट चाहिए। इनमें से कोई भी यह `next start` रेसिपी बिना बदलाव के इस्तेमाल नहीं करता।

`.nvmrc` में Node का कोई सपोर्टेड major वर्ज़न चुनें, जैसे `22`। अपलोड किए जाने वाले सोर्स से `.next/`, `node_modules/` और `.env*` को बाहर रखें; ज़रूरत हो तो बिना सीक्रेट्स वाली एक सैंपल env फ़ाइल रखें।

<span id="test-the-production-build-locally" />

## प्रोडक्शन बिल्ड को लोकल रूप से टेस्ट करें

```bash
npm ci
npm run build
npm run start
```

दूसरे टर्मिनल में `http://localhost:3000` खोलें और कोई अंदरूनी रूट (होम पेज के अलावा) टेस्ट करें। अगर ऐप में कोई API या Server Action है, तो उसे भी टेस्ट करें। सिर्फ़ डेवलपमेंट सर्वर पर चेक पास होने से यह साबित नहीं होता कि प्रोडक्शन बिल्ड काम करता है।

<span id="deploy" />

## डिप्लॉय

[Lizard CLI इंस्टॉल करने और साइन इन करने](/framework-guides#prepare-the-project) के बाद ऐप डायरेक्टरी से चलाएँ:

```bash
lizard init --name nextjs-app
lizard add --service web
lizard up --service web --port 3000
lizard logs --build --service web --json
lizard logs --service web --json
lizard ps --json
```

Lizard `next` डिपेंडेंसी पहचानता है और बिल्ड व स्टार्ट स्क्रिप्ट चलाता है। ये कमांड मानकर चलते हैं कि सर्विस में पहले से कोई बिल्ड या स्टार्ट ओवरराइड नहीं है। डिप्लॉय आउटपुट में दिए गए URL पर लोकल चेक दोहराएँ।

<span id="environment-variables-and-data" />

## एनवायरनमेंट वेरिएबल्स और डेटा

`NEXT_PUBLIC_*` वैल्यू बिल्ड के दौरान ब्राउज़र बंडल का हिस्सा बन जाती हैं। `lizard up` के साथ Lizard बिल्ड को कोई वेरिएबल नहीं देता: पब्लिक वैल्यू `.env.production` में कमिट करें (`create-next-app` की `.gitignore` में `.env*` बाहर रखा जा सकता है; इस फ़ाइल को अपवाद के रूप में अनुमति दें)। [GitHub सर्विस](/deploy/github) पर Lizard सर्विस के `NEXT_PUBLIC_*` वेरिएबल्स बिल्ड में लिख देता है; [बिल्ड-टाइम वेरिएबल्स](/concepts/build-pipeline#build-time-variables) देखें। क्रेडेंशियल्स को सिर्फ़ सर्वर वाले वेरिएबल्स में रखें और उन्हें [वेरिएबल्स और सीक्रेट्स](/variables) के ज़रिए सर्विस के लिए कॉन्फ़िगर करें। सर्विस के दूसरे वेरिएबल्स बिल्ड तक नहीं पहुँचते, इसलिए बिल्ड के दौरान डेटा लाने वाला कोड उन्हें नहीं पढ़ सकता। रनटाइम रीस्टार्ट से पहले से बने HTML या JavaScript में कोई बदलाव नहीं होता।

लोकल कैश फ़ाइलें और अपलोड की गई फ़ाइलें रेप्लिका के बीच साझा स्टोर नहीं बनातीं। एक से ज़्यादा रेप्लिका तक स्केल करने से पहले Next.js कैश और Server Action की ज़रूरतें देख लें। ऐप का स्थायी डेटा डेटाबेस या ऑब्जेक्ट स्टोरेज में रखें, और [स्टोरेज और रिकवरी](/platform/storage-and-recovery) पढ़ें।

<span id="troubleshooting" />

## समस्या का समाधान

| लक्षण | क्या जाँचें |
|---|---|
| `Missing script: start` | ऊपर दी गई प्रोडक्शन स्टार्ट स्क्रिप्ट जोड़ें; `next dev` लोकल डेवलपमेंट के लिए है। |
| ऐप कभी हेल्दी नहीं होता | `--port 3000` को स्टार्ट कमांड से मिलाएँ और `0.0.0.0` पर बाइंड करें। |
| पब्लिक API URL में अब भी पुरानी वैल्यू है | उसे `.env.production` में बदलें और फिर से अपलोड करें, या GitHub सर्विस पर वेरिएबल बदलें ताकि ऐप रीबिल्ड हो। |
| बिल्ड डेटाबेस तक नहीं पहुँच पाता | जाँचें कि कोई रूट बिल्ड के समय डेटा लाता है या नहीं, और क्या वह डिपेंडेंसी उस समय पहुँच में है। |
| `next start` के साथ स्टैटिक एक्सपोर्ट फ़ेल होता है | स्टैटिक एक्सपोर्ट की अलग गाइड देखें। |

[Next.js सेल्फ़-होस्टिंग गाइड](https://nextjs.org/docs/app/guides/self-hosting) फ्रेमवर्क के स्तर पर कैश, इमेज और मल्टी-इंस्टेंस व्यवहार समझाती है। डिप्लॉयमेंट एरर के लिए [सर्विस कभी हेल्दी नहीं होती](/deploy/troubleshooting/service-never-healthy) देखें।
