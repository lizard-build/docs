# Deploy Next.js on Lizard

Lizard पर Next.js को `next build` और `next start` के साथ Node.js सर्वर के रूप में चलाएँ। सर्वर रिक्वेस्ट-टाइम रेंडरिंग, रूट हैंडलर, और सर्वर एक्शन संभालता है। यदि हर रूट पहले से बनाया जा सकता है, तो इसके बजाय [Next.js static export](/framework-guides/nextjs/static-export) का पालन करें।

## Build settings

| सेटिंग | मान |
|---|---|
| प्रोजेक्ट रूट | `package.json` और Next.js कॉन्फ़िगरेशन वाली डायरेक्टरी |
| बिल्ड स्क्रिप्ट | `next build` |
| स्टार्ट स्क्रिप्ट | `next start --hostname 0.0.0.0 --port 3000` |
| बिल्ड आउटपुट | `.next/` |
| सर्विस पोर्ट | `3000` |
| रनटाइम | Node.js |

<span id="prepare-the-app" />

## ऐप तैयार करें

अपनी डिपेंडेंसी में `next`, `react`, और `react-dom` रखें और अपनी लॉकफ़ाइल को कमिट करें। इन स्क्रिप्ट्स को `package.json` में मर्ज करें:

```json
{
  "scripts": {
    "dev": "next dev",
    "build": "next build",
    "start": "next start --hostname 0.0.0.0 --port 3000"
  }
}
```

इस गाइड के लिए मानक Next.js आउटपुट का उपयोग करें। `output: 'export'` को एक स्टैटिक सर्वर की आवश्यकता है, और `output: 'standalone'` को अपने स्वयं के `server.js` लॉन्च और एसेट लेआउट की आवश्यकता है। दोनों इस `next start` रेसिपी को बिना बदले उपयोग नहीं करते हैं।

`.nvmrc` में एक समर्थित Node मेजर संस्करण चुनें, जैसे `22`। अपलोड किए गए स्रोत से `.next/`, `node_modules/`, और `.env*` को बाहर रखें; यदि आवश्यक हो तो रहस्यों से मुक्त एक नमूना पर्यावरण फ़ाइल रखें।

<span id="test-the-production-build-locally" />

## प्रोडक्शन बिल्ड को स्थानीय रूप से टेस्ट करें

```bash
npm ci
npm run build
npm run start
```

एक अन्य टर्मिनल में, `http://localhost:3000` खोलें और एक आंतरिक रूट का परीक्षण करें। यदि ऐप में कोई API या सर्वर एक्शन है, तो उसका भी परीक्षण करें। केवल डेवलपमेंट सर्वर चेक पास करने से यह साबित नहीं होता है कि प्रोडक्शन बिल्ड काम करता है।

<span id="deploy" />

## डिप्लॉय

[Lizard CLI इंस्टॉल करने और साइन इन करने](/framework-guides#prepare-the-project) के बाद, ऐप डायरेक्टरी से चलाएँ:

```bash
lizard init --name nextjs-app
lizard add --service web
lizard up --service web --port 3000
lizard logs --build --service web --json
lizard logs --service web --json
lizard ps --json
```

Lizard `next` डिपेंडेंसी का पता लगाता है और बिल्ड और स्टार्ट स्क्रिप्ट चलाता है। ये कमांड मानते हैं कि सेवा में कोई मौजूदा बिल्ड या स्टार्ट ओवरराइड नहीं है। स्थानीय जांचों को दोहराने के लिए डिप्लॉय आउटपुट में यूआरएल का उपयोग करें।

## पर्यावरण चर और डेटा

`NEXT_PUBLIC_*` मान बिल्ड के दौरान ब्राउज़र बंडल का हिस्सा बन जाते हैं। `lizard up` के साथ, Lizard बिल्ड में कोई चर पास नहीं करता है: `.env.production` में सार्वजनिक मानों को कमिट करें (`create-next-app` से `.gitignore` `.env*` को बाहर कर सकता है; उस फ़ाइल की अनुमति दें)। [GitHub सेवा](/deploy/github) पर, Lizard सेवा के `NEXT_PUBLIC_*` चर को बिल्ड में लिखता है; [बिल्ड-टाइम चर](/concepts/build-pipeline#build-time-variables) देखें। क्रेडेंशियल्स को सर्वर-ओनली चर में रखें और उन्हें [चर और रहस्यों](/variables) के माध्यम से सेवा के लिए कॉन्फ़िगर करें। कोई अन्य सेवा चर बिल्ड तक नहीं पहुँचते हैं, इसलिए बिल्ड के दौरान डेटा प्राप्त करने वाला कोड उन्हें पढ़ नहीं सकता है। रनटाइम पुनरारंभ पहले से उत्पन्न HTML या JavaScript को नहीं बदलता है।

स्थानीय कैश फ़ाइलें और अपलोड की गई फ़ाइलें प्रतिकृतियों के बीच एक साझा स्टोर नहीं बनाती हैं। एक से अधिक प्रतिकृति तक स्केल करने से पहले Next.js कैश और सर्वर एक्शन आवश्यकताओं की समीक्षा करें। डेटाबेस या ऑब्जेक्ट स्टोरेज में स्थायी ऐप डेटा डालें, और [स्टोरेज और रिकवरी](/platform/storage-and-recovery) पढ़ें।

<span id="troubleshooting" />

## समस्या निवारण

| लक्षण | जाँच |
|---|---|
| `Missing script: start` | प्रोडक्शन स्टार्ट स्क्रिप्ट ऊपर जोड़ें; `next dev` स्थानीय विकास के लिए है। |
| ऐप कभी स्वस्थ नहीं होता | स्टार्ट कमांड से `--port 3000` का मिलान करें और `0.0.0.0` से बाइंड करें। |
| सार्वजनिक API URL में अभी भी उसका पुराना मान है | इसे `.env.production` में बदलें और फिर से अपलोड करें, या GitHub सेवा पर चर बदलें ताकि वह फिर से बन जाए। |
| बिल्ड डेटाबेस तक नहीं पहुँच सकता | जांचें कि क्या कोई रूट बिल्ड समय पर डेटा प्राप्त करता है और क्या वह डिपेंडेंसी तब पहुँच योग्य है। |
| `next start` के तहत स्टैटिक एक्सपोर्ट विफल हो जाता है | अलग स्टैटिक एक्सपोर्ट गाइड का पालन करें। |

[Next.js सेल्फ-होस्टिंग गाइड](https://nextjs.org/docs/app/guides/self-hosting) फ्रेमवर्क-स्तरीय कैश, इमेज और मल्टी-इंस्टेंस व्यवहार को कवर करती है। डिप्लॉयमेंट त्रुटियों के लिए, [सेवा कभी स्वस्थ नहीं होती](/deploy/troubleshooting/service-never-healthy) देखें।
