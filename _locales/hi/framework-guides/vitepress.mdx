# Lizard पर VitePress डिप्लॉय करें

Lizard VitePress डॉक्यूमेंटेशन साइट को बिल्ड कर सकता है और जेनरेट हुए HTML को nginx के ज़रिए पोर्ट `80` पर सर्व कर सकता है। npm स्क्रिप्ट और आउटपुट डायरेक्टरी को अपने docs रूट से मिलाएँ: `vitepress build docs` आउटपुट `docs/.vitepress/dist` में लिखता है, जबकि `vitepress build` उसे `.vitepress/dist` में लिखता है।

[पूरे सोर्स उदाहरण](https://github.com/lizard-build/docs/tree/main/_examples/vitepress) में इस गाइड में इस्तेमाल हुई कॉन्फ़िगरेशन और फ़ाइलें शामिल हैं।

<span id="set-the-build-script" />

## बिल्ड स्क्रिप्ट सेट करें

अगर Markdown फ़ाइलें `docs/` में हैं, तो `package.json` में ये स्क्रिप्ट्स रखें:

```json
{
  "scripts": {
    "docs:dev": "vitepress dev docs",
    "docs:build": "vitepress build docs",
    "docs:preview": "vitepress preview docs"
  }
}
```

| सेटिंग | इस गाइड में वैल्यू |
|---|---|
| बिल्ड | `npm run docs:build` |
| docs रूट | `docs/` |
| आउटपुट | `docs/.vitepress/dist/` |
| प्रोडक्शन सर्वर | nginx |
| सर्विस पोर्ट | `80` |

डिटेक्टर `vitepress build` वाली स्क्रिप्ट ढूँढता है और उसके रूट आर्गुमेंट का उपयोग करता है। ऐसी स्क्रिप्ट रखें जो बिल्ड कमांड को सीधे चलाए। शेल रैपर, मेल खाने वाली कई स्क्रिप्ट्स या कस्टम `outDir` होने पर अलग से बिल्ड कॉन्फ़िगरेशन या Dockerfile चाहिए।

<span id="check-the-site-locally" />

## साइट को लोकल रूप से जाँचें

```bash
npm ci
npm run docs:build
npm run docs:preview
```

कोई अंदरूनी Markdown पेज और कोई एसेट जाँचें। `cleanUrls: true` होने पर VitePress बिना एक्सटेंशन वाले रूट्स से लिंक करता है; प्रोडक्शन सर्वर को इन URL को जेनरेट हुई HTML फ़ाइलों पर resolve करना होगा। `base` को असली पाथ प्रीफ़िक्स पर सेट करें, या डोमेन रूट के लिए `/` रखें। [VitePress डिप्लॉयमेंट](https://vitepress.dev/guide/deploy) देखें।

<span id="deploy" />

## डिप्लॉय

[CLI सेटअप](/framework-guides#prepare-the-project) के बाद `package.json` वाली डायरेक्टरी से चलाएँ, `docs/` के अंदर से नहीं:

```bash
lizard init --name vitepress-docs
lizard add --service web
lizard up --service web --port 80
lizard logs --build --service web --json
lizard ps --json
```

VitePress कॉन्फ़िगरेशन, Markdown, सोर्स एसेट्स, पैकेज मैनिफ़ेस्ट और लॉकफ़ाइल शामिल करें। लोकल डिपेंडेंसी, जेनरेट हुआ आउटपुट, कैश और सीक्रेट्स बाहर रखें। `vitepress dev` या `vitepress preview` को सर्विस का स्टार्ट कमांड न बनाएँ।

<span id="check-clean-routes-and-http-status" />

## क्लीन रूट्स और HTTP स्टेटस जाँचें

नए VitePress बिल्ड बिना एक्सटेंशन वाले रूट्स को उनकी जेनरेट हुई `.html` फ़ाइलों पर resolve करते हैं और न मिलने वाले URL के लिए HTTP 404 लौटाते हैं, लेकिन जेनरेट हुए `404.html` के बजाय nginx के डिफ़ॉल्ट एरर पेज के साथ। डिटेक्शन का यही तरीका इस्तेमाल करने के लिए कमांड ओवरराइड सेट न करें। स्टैंडर्ड आउटपुट के लिए कस्टम Dockerfile की ज़रूरत नहीं है। कस्टम रूटिंग या अपने 404 पेज के लिए [स्टैटिक रूट्स और 404](/framework-guides/static-routing) देखें।

किसी क्लीन URL को सीधे खोलें और उसे रीलोड करें। ऐसे पाथ की रिक्वेस्ट भेजें जो मौजूद नहीं है और पुष्टि करें कि HTTP 404 मिलता है। अगर कोई पुरानी इमेज न मिलने वाले पाथ पर होम पेज सर्व करती है, तो मौजूदा रूटिंग नियम लागू करने के लिए सर्विस को रीबिल्ड करें।

अगर बिल्ड `Missing script: build` दिखाता है, तो जाँचें कि चुना गया तरीका VitePress डिटेक्टर का उपयोग करता है और कोई सर्विस कमांड ओवरराइड उसकी जगह नहीं ले रहा। अगर बिल्ड सफल होता है लेकिन nginx कोई डॉक्स सर्व नहीं करता, तो स्क्रिप्ट के docs रूट की तुलना कॉपी की गई आउटपुट डायरेक्टरी से करें। कंटेंट या कॉन्फ़िगरेशन बदलने के बाद रीबिल्ड करें।

9 सितंबर 2026 के डिप्लॉयमेंट चेक और उनकी सीमाओं के लिए [टेस्ट किए गए वर्ज़न और क्लाउड नतीजे](/framework-guides/validation) देखें।
