# Node.js ऐप (Express) डिप्लॉय करें

Lizard पर Node.js ऐप होस्ट करने के लिए, `package.json` के साथ एक फ़ोल्डर डिप्लॉय करें। lizardpack आपकी लॉक फ़ाइल से पैकेज मैनेजर चुनता है, डिपेंडेंसी इंस्टॉल करता है, यदि कोई हो तो `build` स्क्रिप्ट चलाता है और पोर्ट `3000` पर `start` स्क्रिप्ट के साथ ऐप शुरू करता है। यह Node.js 22 का उपयोग करता है जब तक कि `.nvmrc` या `engines.node` कोई अन्य प्रमुख संस्करण निर्दिष्ट न करे। Lizard पोर्ट को `PORT` में पास करता है; इसे अपने ऐप के लिसनर में पढ़ें।

**टेस्ट स्टेटस:** नीचे दिया गया एक्सप्रेस सैंपल एक्सप्रेस 5.3.0, और डेटाबेस रूट के साथ pg 8.23.1 का उपयोग करके PostgreSQL 14. के विरुद्ध स्थानीय रूप से चला। हमने lizardpack के साथ इसके बिल्ड प्लान की जाँच की, बिल्ड प्लानर Lizard चलता है। हमने अभी तक इस गाइड के साथ इसे एंड-टू-एंड डिप्लॉय नहीं किया है।

<span id="before-you-start" />

## शुरू करने से पहले

- लॉक फ़ाइल बनाने और स्थानीय रूप से टेस्ट करने के लिए आपके कंप्यूटर पर Node.js और npm।
- Lizard CLI, `lizard login` के साथ साइन इन, Pro या 7-दिन Pro ट्रायल (कार्ड आवश्यक) पर। [मूल्य निर्धारण](https://lizard.build/pricing) देखें।

Next.js, Nuxt, Astro, SvelteKit और Vite ऐप्स के अपने गाइड हैं: [फ्रेमवर्क गाइड](/framework-guides) देखें।

<span id="a-minimal-express-app" />

## एक न्यूनतम Express ऐप

`package.json`:

```json
{
  "name": "express-app",
  "private": true,
  "type": "module",
  "scripts": {
    "start": "node server.js"
  },
  "engines": {
    "node": "22.x"
  },
  "dependencies": {
    "express": "^5.1.0"
  }
}
```

`server.js`:

```js
import express from "express";

const app = express();
const port = Number(process.env.PORT) || 3000;

app.get("/", (req, res) => {
  res.send("Hello from Express on Lizard");
});

app.get("/healthz", (req, res) => {
  res.json({ status: "ok" });
});

app.listen(port, "0.0.0.0", () => {
  console.log(`listening on ${port}`);
});
```

`package-lock.json` बनाएं, दोनों फ़ाइलों को कमिट करें, और `node_modules` और `.env` को `.gitignore` में जोड़ने के लिए `npm install` चलाएं। इसे स्थानीय रूप से जांचें:

```bash
npm start
curl http://localhost:3000/healthz
```

<span id="what-lizardpack-does-with-a-nodejs-app" />

## lizardpack Node.js ऐप के साथ क्या करता है

| चरण | क्या होता है |
|---|---|
| पैकेज मैनेजर | `bun.lock` या `bun.lockb`: Bun. `pnpm-lock.yaml`: pnpm. `yarn.lock`: Yarn. `package-lock.json`: `npm ci`. कोई लॉक फ़ाइल नहीं: `npm install`। |
| Node.js संस्करण | `.nvmrc`, फिर `.node-version`, फिर `.tool-versions`, फिर `engines.node`। `node:<major>-slim` पर केवल प्रमुख संस्करण। डिफ़ॉल्ट `22`। |
| बिल्ड | `package.json` में यदि कोई हो तो `build` स्क्रिप्ट, एक अलग स्टेज में जिसमें आपके devDependencies हों |
| स्टार्ट | `start` स्क्रिप्ट; अन्यथा `node <main>`; अन्यथा `server.js`, `index.js`, `app.js`, `main.js`, `dist/index.js` में से पहला |
| रनटाइम | `NODE_ENV=production`, पोर्ट `3000` |

`build` स्क्रिप्ट के बिना, इमेज पैकेज इंस्टॉल करने से पहले `NODE_ENV=production` सेट करती है, इसलिए devDependencies छोड़ दिए जाते हैं। एक स्टार्ट स्क्रिप्ट जो devDependencies से `nodemon`, `tsx` या `ts-node` को कॉल करती है, वह विफल हो जाती है। TypeScript के लिए, `build` में कंपाइल करें और आउटपुट शुरू करें:

```json
{
  "scripts": {
    "build": "tsc",
    "start": "node dist/index.js"
  }
}
```

संस्करण फ़ाइलों और पार्सिंग नियमों के लिए, [रनटाइम संस्करण](/deploy/runtime-versions) देखें। सेवा के बिल्ड और स्टार्ट कमांड को खाली छोड़ दें: किसी एक को सेट करने पर, Lizard `node:22-alpine` पर अपना Dockerfile लिखता है और आपकी संस्करण फ़ाइलों को अनदेखा करता है। [बिल्ड पाइपलाइन](/concepts/build-pipeline) देखें।

<span id="deploy" />

## डिप्लॉय

ऐप के रूट से:

```bash
lizard init --name node-app
lizard add --service web
lizard up --service web --port 3000
```

`lizard up` फ़ोल्डर अपलोड करता है, इसे Lizard पर बनाता है और URL प्रिंट करता है। गिट रिपॉजिटरी के अंदर यह `.gitignore` द्वारा सूचीबद्ध को छोड़ देता है; गिट के बाहर यह `node_modules` को छोड़ देता है लेकिन `.env` फ़ाइलों को अपलोड करता है। [स्थानीय कोड से डिप्लॉय करें](/deploy/upload) देखें।

git push to deploy के लिए, रिपॉजिटरी को GitHub पर पुश करें और इसे `lizard add -r your-org/your-app -n web` से कनेक्ट करें। [GitHub से डिप्लॉय करें](/deploy/github) देखें।

<span id="set-variables" />

## वेरिएबल्स सेट करें

```bash
lizard secrets set SESSION_SECRET="$(openssl rand -hex 32)" --service web
```

`process.env.SESSION_SECRET` के साथ मान पढ़ें। एक वेरिएबल परिवर्तन के बिना रीबिल्ड के सेवा को पुनरारंभ करता है। [वेरिएबल्स और सीक्रेट्स](/variables) देखें।

<span id="add-managed-postgres" />

## Managed Postgres जोड़ें

```bash
lizard add postgres
lizard secrets set DATABASE_URL='${{postgres.DATABASE_PRIVATE_URL}}' --service web
npm install pg
```

सिंगल कोट्स `${{…}}` को आपके शेल से दूर रखते हैं; Lizard डिप्लॉय समय पर [संदर्भ](/variables/references) को प्रोजेक्ट के निजी नेटवर्क पर डेटाबेस के पते पर हल करता है। एक पूल और `server.js` के लिए एक रूट जोड़ें:

```js
import pg from "pg";

const pool = new pg.Pool({ connectionString: process.env.DATABASE_URL });

app.get("/db", async (req, res) => {
  const { rows } = await pool.query("SELECT now() AS now");
  res.json(rows[0]);
});
```

Express 5 एक रूट से अस्वीकृत प्रॉमिस को उसके एरर हैंडलर को पास करता है, इसलिए एक विफल क्वेरी प्रोसेस को क्रैश करने के बजाय HTTP 500 लौटाती है। डेटाबेस के पब्लिक URL के साथ अपने कंप्यूटर से माइग्रेशन चलाएं:

```bash
lizard run --service postgres -- npm run migrate
```

कैश या जॉब क्यू के लिए, [Managed Redis](/addons/redis) को उसी तरह जोड़ें: `lizard add redis`, फिर `REDIS_URL='${{redis.REDIS_PRIVATE_URL}}'`।

<span id="check-that-it-works" />

## जांचें कि यह काम करता है

```bash
lizard logs --build --service web
lizard logs --service web --tail 100
lizard ps
```

रनटाइम लॉग `listening on 3000` दिखाता है। `lizard up` द्वारा प्रिंट किए गए URL पर `/healthz` और `/db` का अनुरोध करें।

<span id="common-problems" />

## सामान्य समस्याएं

| लक्षण | समाधान |
|---|---|
| `npm ci` लॉक फ़ाइल के सिंक से बाहर होने के कारण विफल हो जाता है | `npm install` को स्थानीय रूप से चलाएं और `package-lock.json` को कमिट करें। |
| `nodemon: not found` या `tsx: not found` | वे टूल्स devDependencies हैं और स्टार्ट के लिए इंस्टॉल नहीं किए जाते हैं। `build` स्टेप जोड़ें, या टूल को `dependencies` में ले जाएं। |
| Deploy कभी स्वस्थ नहीं होता | `process.env.PORT` पर सुनें। `5000` जैसा एक निश्चित पोर्ट सेवा पोर्ट से मेल नहीं खाता। [सेवा कभी स्वस्थ नहीं होती](/deploy/troubleshooting/service-never-healthy) देखें। |
| गलत Node.js संस्करण | `.nvmrc` में प्रमुख संस्करण डालें, उदाहरण के लिए `24`, और फिर से डिप्लॉय करें। |
| `Cannot use import statement outside a module` | `"type": "module"` को `package.json` में जोड़ें, या `require` का उपयोग करें। |

एक Node.js प्रक्रिया जो कोई HTTP सर्व नहीं करती है, जैसे कि एक क्यू कंज्यूमर या एक [Discord बॉट](/guides/discord-bot), एक [बैकग्राउंड वर्कर](/deploy/workers) के रूप में चलती है।
