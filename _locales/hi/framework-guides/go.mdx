# एक Go ऐप डिप्लॉय करें

Lizard पर एक Go ऐप डिप्लॉय करने के लिए, `go.mod` फ़ाइल के साथ एक मॉड्यूल अपलोड या पुश करें। lizardpack इसे `go` लाइन से Go संस्करण के साथ बनाता है, एक स्थिर बाइनरी (`CGO_ENABLED=0`) संकलित करता है और इसे Alpine Linux पर चलाता है। सेवा पोर्ट `8080` है, और Lizard इसे `PORT` में आपकी प्रक्रिया में पास करता है, इसलिए अपने ऐप में `PORT` पढ़ें और सभी इंटरफेस पर सुनें।

**परीक्षण स्थिति:** नीचे दिया गया नमूना ऐप Go 1.27, के साथ स्थानीय रूप से बनता और चलता है और हमने lizardpack के साथ इसकी बिल्ड योजना की जाँच की है, बिल्ड प्लानर Lizard चलता है। हमने अभी तक इस गाइड के साथ इसे एंड-टू-एंड डिप्लॉय नहीं किया है।

<span id="before-you-start" />

## शुरू करने से पहले

- एक Go मॉड्यूल जिसमें आपके द्वारा डिप्लॉय किए जाने वाले डायरेक्टरी में `go.mod` है, और यदि इसमें निर्भरताएँ हैं तो `go.sum`।
- Lizard CLI, `lizard login` के साथ साइन इन, Pro पर या 7-दिन Pro ट्रायल (कार्ड आवश्यक) पर। [मूल्य निर्धारण](https://lizard.build/pricing) देखें।

<span id="a-minimal-app" />

## एक न्यूनतम ऐप

`go.mod`:

```text
module example.com/hello

go 1.27
```

`main.go`:

```go
package main

import (
	"fmt"
	"log"
	"net/http"
	"os"
)

func main() {
	port := os.Getenv("PORT")
	if port == "" {
		port = "8080"
	}

	http.HandleFunc("/", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintln(w, "Hello from Go on Lizard")
	})
	http.HandleFunc("/healthz", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintln(w, "ok")
	})

	log.Printf("listening on :%s", port)
	log.Fatal(http.ListenAndServe(":"+port, nil))
}
```

`":"+port` हर इंटरफ़ेस पर सुनता है। `127.0.0.1:8080` जैसा पता केवल कंटेनर के अंदर से कनेक्शन स्वीकार करता है, और डिप्लॉय कभी स्वस्थ नहीं होता है।

इसे स्थानीय रूप से जांचें:

```bash
go run .
curl http://localhost:8080/healthz
```

<span id="what-lizardpack-builds" />

## lizardpack क्या बनाता है

| चरण | क्या होता है |
|---|---|
| पहचान | `go.mod`, `go.work` या कोई भी `.go` फ़ाइल। lizardpack Go की जाँच Python और Node.js से पहले करता है। |
| Go संस्करण | `go.mod` में `go` लाइन, केवल प्रमुख और लघु: `go 1.27.3` `golang:1.27-alpine` पर बनता है। `go.mod` के बिना, Go 1.24, जो अब सुरक्षा फिक्स प्राप्त नहीं करता है। |
| बिल्ड | `go mod download`, फिर `CGO_ENABLED=0 GOOS=linux go build -ldflags='-s -w' -o /app/server <package>` |
| मुख्य पैकेज | `./cmd` यदि `cmd/main.go` मौजूद है; अन्यथा वर्णानुक्रम में पहला `cmd/<name>/main.go`; अन्यथा रूट डायरेक्टरी। `cmd/` या `cmd/<name>/` में एक `main.go` रूट `main.go` पर जीतता है। |
| रनटाइम | `alpine:3.19` `ca-certificates` और `tzdata` के साथ। lizardpack पूरे स्रोत डायरेक्टरी को बाइनरी के बगल में `/app` में कॉपी करता है, इसलिए `templates/` और `static/` जैसे सापेक्ष पथ अभी भी काम करते हैं। |
| प्रारंभ और पोर्ट | `/app/server` पोर्ट `8080` पर |

उत्पन्न Dockerfile:

```dockerfile
FROM golang:1.27-alpine AS build
WORKDIR /app
COPY go.mod go.sum* ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 GOOS=linux go build -ldflags='-s -w' -o /app/server .

FROM alpine:3.19
RUN apk add --no-cache ca-certificates tzdata
WORKDIR /app
COPY --from=build /app /app
EXPOSE 8080
CMD ["/app/server"]
```

इस इमेज को प्राप्त करने के लिए सेवा के बिल्ड और स्टार्ट कमांड को खाली छोड़ दें। किसी एक को सेट करने पर, Lizard उन कमांड से एक अलग Dockerfile लिखता है और `go` लाइन को अनदेखा करता है: एक `go build …` कमांड Go 1.24, पर बनता है जो अब सुरक्षा फिक्स प्राप्त नहीं करता है। अन्य बिल्ड चरणों के लिए, अपना स्वयं का `Dockerfile` कमिट करें; [Dockerfile से एक Docker कंटेनर डिप्लॉय करें](/deploy/dockerfile) देखें।

<span id="deploy" />

## डिप्लॉय

मॉड्यूल के रूट से:

```bash
lizard init --name go-app
lizard add --service api
lizard up --service api --port 8080
```

`lizard up` डायरेक्टरी को अपलोड करता है, इसे Lizard के बिल्ड मशीनों पर बनाता है और URL प्रिंट करता है। आपको कमांड चलाने वाली मशीन पर Docker या Go की आवश्यकता नहीं है। git push to deploy के लिए, [एक GitHub रिपॉजिटरी कनेक्ट करें](/deploy/github) `lizard add -r your-org/your-app -n api` के साथ, फिर जांचें कि `lizard port --service api` `8080` प्रिंट करता है।

<span id="frameworks" />

## फ्रेमवर्क

- **net/http, chi, gorilla/mux:** `":" + os.Getenv("PORT")` को `http.ListenAndServe` पर पास करें, जैसा कि ऊपर है।
- **Gin:** बिना एड्रेस के `r.Run()` `PORT` को पढ़ता है और `:8080` पर वापस आ जाता है। सेवा पर `GIN_MODE=release` सेट करें।
- **Echo, Fiber:** एड्रेस स्वयं पास करें: `e.Start(":" + os.Getenv("PORT"))` या `app.Listen(":" + os.Getenv("PORT"))`।

<span id="variables-and-databases" />

## वेरिएबल्स और डेटाबेस

सेवा पर कॉन्फ़िगरेशन सेट करें और इसे `os.Getenv` के साथ पढ़ें:

```bash
lizard secrets set GIN_MODE=release API_KEY=change-me --service api
```

डेटाबेस के लिए, [Managed Postgres](/addons/postgres) जोड़ें और [संदर्भ](/variables/references) के साथ इसका निजी URL पास करें:

```bash
lizard add postgres
lizard secrets set DATABASE_URL='${{postgres.DATABASE_PRIVATE_URL}}' --service api
```

फिर इसे अपने ड्राइवर से खोलें, उदाहरण के लिए `pgxpool.New(ctx, os.Getenv("DATABASE_URL"))`। एक वेरिएबल परिवर्तन रीबिल्ड के बिना सेवा को पुनरारंभ करता है।

<span id="check-that-it-works" />

## जांचें कि यह काम करता है

```bash
lizard logs --build --service api
lizard logs --service api --tail 100
lizard ps
```

`/healthz` द्वारा प्रिंट किए गए URL पर `lizard up` का अनुरोध करें, फिर एक ऐसा रूट जो वास्तविक काम करता हो। बिल्ड लॉग `golang:` इमेज दिखाता है जिसका बिल्ड ने उपयोग किया।

<span id="common-problems" />

## सामान्य समस्याएं

| लक्षण | समाधान |
|---|---|
| `no Go files in /app` | `main` पैकेज रूट पर या `cmd/` के नीचे नहीं है। इसे ले जाएं, या एक Dockerfile जोड़ें। |
| गलत बाइनरी शुरू होती है | `cmd/` या `cmd/<name>/` में एक `main.go`, रूट `main.go` पर जीत जाता है, और कई `cmd/<name>/main.go` के साथ, lizardpack वर्णानुक्रम में पहला नाम बनाता है। वह बनाने के लिए एक Dockerfile जोड़ें जो आप चाहते हैं। |
| SQLite `CGO_ENABLED=0` के साथ विफल | बिल्ड cgo को बंद कर देता है, इसलिए `mattn/go-sqlite3` काम नहीं कर सकता। एक शुद्ध-Go ड्राइवर का उपयोग करें, या [Managed Postgres](/addons/postgres): कंटेनर फ़ाइलें प्रत्येक परिनियोजन पर खो जाती हैं। |
| परिनियोजन कभी स्वस्थ नहीं होता | प्रक्रिया को सभी इंटरफेस पर `PORT` (या `8080`) पर सुनना चाहिए। [सेवा कभी स्वस्थ नहीं](/deploy/troubleshooting/service-never-healthy) देखें। |
| आपको एक नया Go चाहिए | `go` लाइन बदलें, उदाहरण के लिए `go mod edit -go=1.27`, और फिर से परिनियोजित करें। [रनटाइम संस्करण](/deploy/runtime-versions) देखें। |

एक Go प्रक्रिया जो कोई HTTP सेवा नहीं देती है, जैसे कि एक क्यू उपभोक्ता, `--port 0` के साथ [बैकग्राउंड वर्कर](/deploy/workers) के रूप में चलती है।
