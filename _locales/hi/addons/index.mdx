# प्रबंधित ऐडऑन

Lizard आपके प्रोजेक्ट में तीन प्रबंधित addons चलाता है: Managed Postgres, Managed Redis और S3-संगत Managed Object Storage। `lizard add postgres redis s3` एक कमांड में तीनों बनाता है। हर addon environment variables का तय सेट देता है, जैसे `DATABASE_URL`। आपकी सेवाएँ `${{postgres.DATABASE_URL}}` जैसे [references](/concepts/architecture#cross-resource-references) से उन्हें पढ़ती हैं। जब ऐप के डेटा को डिप्लॉय या रीस्टार्ट के बाद भी रखना हो, तब इन्हें इस्तेमाल करें।

<span id="provision-an-addon" />

## एक ऐडऑन प्रोविज़न करें

```bash
lizard add postgres            # one addon
lizard add postgres redis s3   # several at once
lizard add --list              # show available types
```

<span id="naming" />

## नामकरण

प्रत्येक प्रकार का पहला ऐडऑन अपने नाम के रूप में प्रकार का उपयोग करता है, इसलिए `${{postgres.DATABASE_URL}}` अतिरिक्त सेटअप के बिना काम करता है। एक ही प्रकार के अतिरिक्त ऐडऑन को `postgres-autumn-bear` जैसा उत्पन्न नाम मिलता है। डिलीट किया गया ऐडऑन 3 दिनों तक ट्रैश में अपना नाम रखता है, इसलिए उस विंडो में जोड़ा गया नया ऐडऑन एक उत्पन्न नाम प्राप्त करता है; पुराने को पुनर्स्थापित करें या नए नाम पर संदर्भ इंगित करें।

कोई टाइप-एलियास फ़ॉलबैक नहीं है: एक संदर्भ को ऐडऑन के **वर्तमान** नाम का उपयोग करना चाहिए। किसी ऐडऑन का नाम बदलने से पुराने नाम के संदर्भ टूट जाते हैं, इसलिए नाम बदलने के बाद उन्हें अपडेट करें:

```bash
lizard service rename main-db --service postgres   # addons rename through the same command
lizard secrets set DATABASE_URL='${{main-db.DATABASE_URL}}' --service api
```

<span id="consuming-an-addon" />

## एक ऐडऑन का उपभोग करना

किसी भी सेवा से ऐडऑन के चर का संदर्भ लें। संदर्भ डिप्लॉय समय पर हल होता है, इसलिए सेवा अपने अगले डिप्लॉय पर ऐडऑन के वर्तमान मानों को उठाती है:

```bash
lizard secrets set DATABASE_URL='${{postgres.DATABASE_URL}}' --service api
lizard redeploy --service api
```

Lizard हर चल रहे पोस्टग्रेएस और रेडिस ऐडऑन से `DATABASE_URL` और `REDIS_URL` को प्रोजेक्ट में हर सेवा में इंजेक्ट करता है, सबसे कम प्राथमिकता पर। एक स्पष्ट संदर्भ उन्हें ओवरराइड करता है और एक विशिष्ट ऐडऑन चुनता है। एक ही प्रोजेक्ट और क्षेत्र में सेवाओं के लिए, निजी यूआरएल को प्राथमिकता दें:

```bash
lizard secrets set DATABASE_URL='${{postgres.DATABASE_PRIVATE_URL}}' --service api
```

[सीक्रेट स्कोपिंग](/variables#scoping) देखें।

<span id="variables-by-type" />

## प्रकार के अनुसार चर

| ऐडऑन | चर |
|-------|-----------|
| **postgres** | `DATABASE_URL`, `DATABASE_PRIVATE_URL`, `PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD`, `PGDATABASE`, `POSTGRES_USER`, `POSTGRES_DB`, `POSTGRES_PASSWORD` |
| **redis** | `REDIS_URL`, `REDIS_PRIVATE_URL` |
| **s3** | `S3_ENDPOINT`, `S3_DEFAULT_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_REGION` |

`DATABASE_URL` और `REDIS_URL` सार्वजनिक एंडपॉइंट का उपयोग करते हैं। `DATABASE_PRIVATE_URL` और `REDIS_PRIVATE_URL` [निजी नेटवर्क](/networking#private-networking) पर `<name>.lizard.internal` का उपयोग करते हैं और केवल एक ही प्रोजेक्ट और एक ही क्षेत्र की सेवाओं से काम करते हैं। किसी अन्य क्षेत्र की सेवा को `DATABASE_URL` या `REDIS_URL` का उपयोग करना चाहिए; उसे निजी यूआरएल देने के लिए, उसके क्षेत्र में ऐडऑन बनाएं, उदाहरण के लिए `lizard add postgres --region <code>`। `<name>` वह नाम है जो ऐडऑन का था जब उसे उसका निजी पता मिला था, और नाम बदलने से यह नहीं बदलता है।

<span id="dashboard-browsers" />

## डैशबोर्ड ब्राउज़र

[डैशबोर्ड](/dashboard) में ऐडऑन डेटा का निरीक्षण और संपादन करें। इसमें Managed Postgres के लिए एक SQL/टेबल एडिटर, Managed Redis के लिए एक की ब्राउज़र और Managed Object Storage के लिए एक बकेट/ऑब्जेक्ट ब्राउज़र है।

<span id="storage" />

## स्टोरेज

पोस्टग्रेएस और रेडिस डेटा वॉल्यूम **केवल-बढ़ने वाले** हैं। क्षमता बढ़ाने के लिए इसका उपयोग करें:

```bash
lizard scale --service postgres --storage 8192
```

आकार 512, 1024, 2048, 4096, 8192 या 16384 MB हैं। वॉल्यूम को बढ़ाने से डेटाबेस बंद हो जाता है जबकि Lizard अपने डेटा को एक बड़े वॉल्यूम में कॉपी करता है, फिर उसे फिर से शुरू करता है, इसलिए एक छोटी रुकावट की उम्मीद करें। इसे आकार बदलने से पहले [`lizard resume`](/cli/pause) के साथ रुके हुए डेटाबेस को फिर से शुरू करें।
