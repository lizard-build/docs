# Managed ऐडऑन

Lizard आपके प्रोजेक्ट में तीन managed ऐडऑन चलाता है: Managed Postgres, Managed Redis और S3-संगत Managed Object Storage। `lizard add postgres redis s3` एक ही कमांड में तीनों बना देता है। हर ऐडऑन एनवायरनमेंट वेरिएबल्स का एक तय सेट देता है, जैसे `DATABASE_URL`, और आपकी सर्विसेज़ उन्हें `${{postgres.DATABASE_URL}}` जैसे [रेफरेंस](/concepts/architecture#cross-resource-references) से पढ़ती हैं। जब ऐप का डेटा डिप्लॉय या रीस्टार्ट के बाद भी बना रहना चाहिए, तब इनका उपयोग करें।

<span id="provision-an-addon" />

## ऐडऑन प्रोविज़न करें

```bash
lizard add postgres            # one addon
lizard add postgres redis s3   # several at once
lizard add --list              # show available types
```

<span id="naming" />

## नामकरण

हर टाइप के पहले ऐडऑन का नाम उसी टाइप पर रखा जाता है, इसलिए `${{postgres.DATABASE_URL}}` बिना किसी अतिरिक्त सेटअप के काम करता है। उसी टाइप के बाद वाले ऐडऑन को `postgres-autumn-bear` जैसा जेनरेट किया गया नाम मिलता है। डिलीट किया गया ऐडऑन 3 दिनों तक ट्रैश में अपना नाम रोके रखता है, इसलिए इस दौरान जोड़े गए नए ऐडऑन को जेनरेट किया गया नाम मिलता है; पुराने ऐडऑन को रीस्टोर करें या रेफरेंस को नए नाम पर पॉइंट करें।

टाइप के नाम पर कोई फ़ॉलबैक नहीं है: रेफरेंस में ऐडऑन का **मौजूदा** नाम ही होना चाहिए। ऐडऑन का नाम बदलने पर पुराने नाम वाले रेफरेंस टूट जाते हैं, इसलिए नाम बदलने के बाद उन्हें अपडेट करें:

```bash
lizard service rename main-db --service postgres   # addons rename through the same command
lizard secrets set DATABASE_URL='${{main-db.DATABASE_URL}}' --service api
```

<span id="consuming-an-addon" />

## ऐडऑन का उपयोग करना

किसी भी सर्विस से ऐडऑन के वेरिएबल्स को रेफरेंस करें। रेफरेंस डिप्लॉय के समय रिज़ॉल्व होता है, इसलिए सर्विस को अपने अगले डिप्लॉय पर ऐडऑन की मौजूदा वैल्यू मिल जाती हैं:

```bash
lizard secrets set DATABASE_URL='${{postgres.DATABASE_URL}}' --service api
lizard redeploy --service api
```

Lizard हर चल रहे Postgres और Redis ऐडऑन से `DATABASE_URL` और `REDIS_URL` को प्रोजेक्ट की हर सर्विस में सबसे कम प्राथमिकता पर इंजेक्ट भी करता है। स्पष्ट रेफरेंस इन्हें ओवरराइड करता है और किसी खास ऐडऑन को चुनता है। एक ही प्रोजेक्ट और रीजन की सर्विसेज़ के लिए प्राइवेट URL को प्राथमिकता दें:

```bash
lizard secrets set DATABASE_URL='${{postgres.DATABASE_PRIVATE_URL}}' --service api
```

[सीक्रेट स्कोपिंग](/variables#scoping) देखें।

<span id="variables-by-type" />

## टाइप के अनुसार वेरिएबल्स

| ऐडऑन | वेरिएबल्स |
|-------|-----------|
| **postgres** | `DATABASE_URL`, `DATABASE_PRIVATE_URL`, `PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD`, `PGDATABASE`, `POSTGRES_USER`, `POSTGRES_DB`, `POSTGRES_PASSWORD` |
| **redis** | `REDIS_URL`, `REDIS_PRIVATE_URL` |
| **s3** | `S3_ENDPOINT`, `S3_DEFAULT_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_REGION` |

`DATABASE_URL` और `REDIS_URL` पब्लिक एंडपॉइंट का उपयोग करते हैं। `DATABASE_PRIVATE_URL` और `REDIS_PRIVATE_URL` [प्राइवेट नेटवर्क](/networking#private-networking) पर `<name>.lizard.internal` का उपयोग करते हैं और सिर्फ़ उसी प्रोजेक्ट और उसी रीजन की सर्विसेज़ से काम करते हैं। किसी दूसरे रीजन की सर्विस को `DATABASE_URL` या `REDIS_URL` का उपयोग करना होगा; उसे प्राइवेट URL देने के लिए ऐडऑन को उसी के रीजन में बनाएँ, उदाहरण के लिए `lizard add postgres --region <code>`। `<name>` वह नाम है जो प्राइवेट एड्रेस मिलते समय ऐडऑन का था; नाम बदलने से यह नहीं बदलता।

<span id="dashboard-browsers" />

## डैशबोर्ड ब्राउज़र

[डैशबोर्ड](/dashboard) में ऐडऑन का डेटा देखें और एडिट करें। इसमें Managed Postgres के लिए SQL/टेबल एडिटर, Managed Redis के लिए key ब्राउज़र और Managed Object Storage के लिए बकेट/ऑब्जेक्ट ब्राउज़र है।

<span id="storage" />

## स्टोरेज

Postgres और Redis के डेटा वॉल्यूम **सिर्फ़ बढ़ाए जा सकते हैं**, घटाए नहीं जा सकते। क्षमता बढ़ाने के लिए:

```bash
lizard scale --service postgres --storage 8192
```

साइज़ 512, 1024, 2048, 4096, 8192 या 16384 MB हो सकते हैं। वॉल्यूम बढ़ाने पर डेटाबेस तब तक बंद रहता है जब तक Lizard उसका डेटा बड़े वॉल्यूम में कॉपी नहीं कर लेता, फिर उसे दोबारा चालू कर दिया जाता है, इसलिए थोड़ी देर के आउटेज के लिए तैयार रहें। पॉज़ किए गए डेटाबेस का साइज़ बदलने से पहले उसे [`lizard resume`](/cli/pause) से फिर से चालू करें।
