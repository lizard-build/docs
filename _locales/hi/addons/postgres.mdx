# Managed Postgres

Managed Postgres on Lizard एक PostgreSQL डेटाबेस है जिसे आप `lizard add postgres` के साथ प्रोजेक्ट में जोड़ते हैं। नए डेटाबेस डिफ़ॉल्ट रूप से PostgreSQL 18 चलाते हैं। Lizard कनेक्शन स्ट्रिंग को `DATABASE_URL` में और उसके हिस्सों को `PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD` और `PGDATABASE` में स्टोर करता है। `${{postgres.DATABASE_PRIVATE_URL}}` जैसी रेफरेंस के साथ सेवाओं को कनेक्ट करें। डेटाबेस ऐप्स के समान CPU, मेमोरी और स्टोरेज [दरों](/platform/billing#resource-rates) का उपयोग करता है। आप इसे डैशबोर्ड के SQL एडिटर में क्वेरी कर सकते हैं। अवलोकन और कीमतों के लिए, [Managed Postgres पेज](https://lizard.build/postgres) देखें।

<span id="provision" />

## प्रोविज़न

```bash
lizard add postgres
```

पहला Postgres एडऑन `postgres` नाम का है, इसलिए `${{postgres.DATABASE_URL}}` तुरंत काम करता है।

<span id="environment-variables" />

## एनवायरनमेंट वेरिएबल्स

एडऑन कनेक्शन वेरिएबल्स का एक मानक सेट प्रदान करता है:

| वेरिएबल | विवरण |
|----------|-------------|
| `DATABASE_URL` | पब्लिक एंडपॉइंट (`postgresql://…`) पर फुल कनेक्शन स्ट्रिंग |
| `DATABASE_PRIVATE_URL` | प्रोजेक्ट के प्राइवेट नेटवर्क (`<name>.lizard.internal:5432`) पर कनेक्शन स्ट्रिंग |
| `PGHOST` | होस्ट |
| `PGPORT` | पोर्ट |
| `PGUSER` | यूजर |
| `PGPASSWORD` | पासवर्ड |
| `PGDATABASE` | डेटाबेस का नाम |
| `POSTGRES_USER` | यूजर के लिए एलियास |
| `POSTGRES_DB` | डेटाबेस के लिए एलियास |
| `POSTGRES_PASSWORD` | पासवर्ड के लिए एलियास |

<span id="postgres-connection-string" />

## Postgres कनेक्शन स्ट्रिंग

प्रत्येक डेटाबेस में दो कनेक्शन स्ट्रिंग होती हैं। दोनों `postgres` यूजर और `postgres` डेटाबेस का उपयोग करती हैं:

| वेरिएबल | इससे उपयोग करें | फॉर्मेट |
|---|---|---|
| `DATABASE_PRIVATE_URL` | एक ही प्रोजेक्ट और रीजन में सेवाएं | `postgresql://postgres:<password>@<name>.lizard.internal:5432/postgres` |
| `DATABASE_URL` | आपकी मशीन, CI, या किसी अन्य प्रोजेक्ट या रीजन में सेवा | `postgresql://postgres:<password>@<host>:<port>/postgres` |

`<name>` वह नाम है जो डेटाबेस का था जब उसे उसका प्राइवेट एड्रेस मिला, पहले वाले के लिए `postgres`; डेटाबेस का नाम बदलने से यह नहीं बदलता है। Lizard डेटाबेस बनाते समय पब्लिक होस्ट और पोर्ट असाइन करता है। होस्ट को टाइप करने के बजाय `DATABASE_PRIVATE_URL`, `DATABASE_URL`, `PGHOST` और `PGPORT` से पढ़ें।

प्राइवेट एड्रेस केवल उसी प्रोजेक्ट और उसी रीजन की सेवाओं से काम करता है; [प्राइवेट नेटवर्किंग](/networking#private-networking) देखें। किसी अन्य रीजन की सेवा को `DATABASE_URL` का उपयोग करना चाहिए। इसे प्राइवेट एड्रेस देने के लिए, सेवा के रीजन में डेटाबेस बनाएं: `lizard add postgres --region <code>`।

अधिकांश ड्राइवर स्ट्रिंग को वैसे ही लेते हैं:

```js
// Node.js with pg
import pg from 'pg';
const pool = new pg.Pool({ connectionString: process.env.DATABASE_URL });
```

```python
# Python with psycopg
import os, psycopg
conn = psycopg.connect(os.environ["DATABASE_URL"])
```

`psql` और अन्य libpq टूल्स `PG*` वेरिएबल्स को पढ़ते हैं, इसलिए वे बिना किसी आर्गुमेंट के कनेक्ट होते हैं।

<span id="how-do-i-see-the-connection-string" />

### मैं कनेक्शन स्ट्रिंग कैसे देख सकता हूँ?

- **डैशबोर्ड:** अपने प्रोजेक्ट में डेटाबेस खोलें। **ओवरव्यू** टैब `DATABASE_URL` और कॉपी बटनों के साथ प्राइवेट URL दिखाता है। **सीक्रेट्स** टैब हर कनेक्शन वेरिएबल और सेवा में पेस्ट करने के लिए `${{…}}` रेफरेंस को सूचीबद्ध करता है।
- **CLI:** `lizard run --service postgres -- printenv DATABASE_URL` पब्लिक स्ट्रिंग प्रिंट करता है। इसमें पासवर्ड होता है, इसलिए इसे लॉग या चैट में पेस्ट न करें।

स्ट्रिंग एक क्रेडेंशियल है। इसे सीक्रेट में कॉपी करने के बजाय रेफरेंस के साथ सेवाओं को पॉइंट करें, ताकि उन्हें हर डिप्लॉय पर वर्तमान मान मिल सके।

<span id="connect-a-service" />

## एक सेवा कनेक्ट करें

कंज्यूमर सेवा से प्राइवेट कनेक्शन स्ट्रिंग को रेफरेंस करें और पुनः डिप्लॉय करें:

```bash
lizard secrets set DATABASE_URL='${{postgres.DATABASE_PRIVATE_URL}}' --service api
lizard redeploy --service api
```

रेफरेंस डिप्लॉय समय पर रिजोल्व होता है, इसलिए हर कंज्यूमर अपने अगले डिप्लॉय पर एडऑन के वर्तमान मानों को उठाता है। प्रोजेक्ट के बाहर या किसी अन्य रीजन में क्लाइंट के लिए इसके बजाय `DATABASE_URL` का उपयोग करें। प्रोजेक्ट में हर सेवा को सबसे कम प्रेसिडेंस पर एडऑन का पब्लिक `DATABASE_URL` भी मिलता है; एक स्पष्ट रेफरेंस इसे ओवरराइड करता है।

कनेक्शन स्ट्रिंग को प्रिंट किए बिना अपनी मशीन से कनेक्टिविटी सत्यापित करें:

```bash
lizard run --service postgres -- sh -c 'psql "$DATABASE_URL" -c "SELECT 1"'
```

`lizard run --service postgres` डेटाबेस के पब्लिक कनेक्शन मानों के साथ आपकी मशीन पर कमांड चलाता है, इसलिए इसे स्थानीय रूप से `psql` इंस्टॉल करने की आवश्यकता है। `lizard run --service api` `${{…}}` रेफरेंस को लिटरल टेक्स्ट के रूप में पास करेगा; [`lizard run`](/cli/run) देखें।

<span id="run-migrations-on-deploy" />

## डिप्लॉय पर माइग्रेशन चलाएँ

माइग्रेशन के लिए प्री-डिप्लॉय कमांड का उपयोग करें। यह केवल तब चलता है जब एक स्टार्ट कमांड भी सेट होता है, जैसे हर कंटेनर की शुरुआत में `sh -c "<pre> && exec <start>"`: हर रेप्लिका, हर रीस्टार्ट। माइग्रेशन को कई बार और एक ही समय में चलाने के लिए सुरक्षित बनाएं, और पुराने और नए एप्लिकेशन संस्करण दोनों के साथ संगत बनाएं:

```bash
lizard service set api --set preDeployCommand="npm run migrate" --set startCommand="npm start"
lizard redeploy --service api
```

Django ऐप के लिए कमांड `python manage.py migrate` है; [Django गाइड](/framework-guides/django) और [Python ऐप होस्टिंग](https://lizard.build/blog/python-app-hosting#django-postgres-and-celery-need-separate-checks) देखें। [Umami](/guides/umami) और [Flowise](/guides/flowise) गाइड Managed Postgres पर पूर्ण ऐप्स दिखाते हैं।

<span id="browse-and-query-data" />

## डेटा ब्राउज़ करें और क्वेरी करें

SQL चलाने और टेबल को सीधे ब्राउज़ करने के लिए डैशबोर्ड (`lizard open`) में **Postgres एडिटर** खोलें। एड-हॉक लोकल काम के लिए, एडऑन के कनेक्शन मानों के साथ एक कमांड चलाएं:

```bash
lizard run --service postgres -- sh -c 'exec psql "$DATABASE_URL"'
```

<span id="grow-storage" />

## स्टोरेज बढ़ाएं

डेटा वॉल्यूम ग्रो-ओनली होते हैं:

```bash
lizard scale --service postgres --storage 8192
```

आकार 512, 1024, 2048, 4096, 8192 या 16384 MB हैं। वॉल्यूम को बढ़ाने से डेटाबेस बंद हो जाता है जबकि Lizard अपने डेटा को एक बड़े वॉल्यूम में कॉपी करता है, फिर उसे फिर से शुरू करता है, इसलिए एक छोटी रुकावट की उम्मीद करें। इसे आकार बदलने से पहले [`lizard resume`](/cli/pause) के साथ रुके हुए डेटाबेस को फिर से शुरू करें।

<span id="multiple-databases" />

## एकाधिक डेटाबेस

दूसरा Postgres जोड़ने पर उसे एक जेनरेट किया गया नाम (जैसे `postgres-autumn-bear`) मिलता है। इसे स्पष्ट रूप से रेफर करें:

```bash
lizard add postgres
lizard secrets set ANALYTICS_URL='${{postgres-autumn-bear.DATABASE_PRIVATE_URL}}' --service api
```

<span id="backups-and-restore" />

## बैकअप और रिस्टोर

शेड्यूल किए गए बैकअप या पॉइंट-इन-टाइम रिकवरी को न मानें। किसी जोखिम भरे माइग्रेशन से पहले, डेटाबेस को स्वयं एक्सपोर्ट करें और किसी अलग डेटाबेस में रिस्टोर का परीक्षण करें। उदाहरण के लिए, स्थानीय रूप से `pg_dump` 18 या नए संस्करण के साथ:

```bash
lizard run --service postgres -- sh -c 'pg_dump "$DATABASE_URL" > backup.sql'
```

रिस्टोर प्लान के लिए [स्टोरेज और रिकवरी](/platform/storage-and-recovery) देखें।
