# Managed Postgres

Lizard पर Managed Postgres एक PostgreSQL डेटाबेस है, जिसे आप `lizard add postgres` से प्रोजेक्ट में जोड़ते हैं। नए डेटाबेस डिफ़ॉल्ट रूप से PostgreSQL 18 पर चलते हैं। Lizard कनेक्शन स्ट्रिंग को `DATABASE_URL` में और उसके हिस्सों को `PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD` और `PGDATABASE` में रखता है। `${{postgres.DATABASE_PRIVATE_URL}}` जैसे रेफरेंस से सर्विसेज़ को कनेक्ट करें। डेटाबेस पर CPU, मेमोरी और स्टोरेज की वही [दरें](/platform/billing#resource-rates) लगती हैं जो ऐप्स पर। आप डैशबोर्ड के SQL एडिटर में इस पर क्वेरी चला सकते हैं। ओवरव्यू और कीमतों के लिए [Managed Postgres पेज](https://lizard.build/postgres) देखें।

<span id="provision" />

## प्रोविज़न

```bash
lizard add postgres
```

पहले Postgres ऐडऑन का नाम `postgres` होता है, इसलिए `${{postgres.DATABASE_URL}}` तुरंत काम करता है।

<span id="environment-variables" />

## एनवायरनमेंट वेरिएबल्स

ऐडऑन कनेक्शन वेरिएबल्स का एक स्टैंडर्ड सेट देता है:

| वेरिएबल | विवरण |
|----------|-------------|
| `DATABASE_URL` | पब्लिक एंडपॉइंट के ज़रिए पूरा कनेक्शन स्ट्रिंग (`postgresql://…`) |
| `DATABASE_PRIVATE_URL` | प्रोजेक्ट के प्राइवेट नेटवर्क के ज़रिए कनेक्शन स्ट्रिंग (`<name>.lizard.internal:5432`) |
| `PGHOST` | होस्ट |
| `PGPORT` | पोर्ट |
| `PGUSER` | यूज़र |
| `PGPASSWORD` | पासवर्ड |
| `PGDATABASE` | डेटाबेस का नाम |
| `POSTGRES_USER` | यूज़र के लिए एलियास |
| `POSTGRES_DB` | डेटाबेस के लिए एलियास |
| `POSTGRES_PASSWORD` | पासवर्ड के लिए एलियास |

<span id="postgres-connection-string" />

## Postgres कनेक्शन स्ट्रिंग

हर डेटाबेस के दो कनेक्शन स्ट्रिंग होते हैं। दोनों में यूज़र `postgres` और डेटाबेस `postgres` होता है:

| वेरिएबल | कहाँ से उपयोग करें | फ़ॉर्मेट |
|---|---|---|
| `DATABASE_PRIVATE_URL` | उसी प्रोजेक्ट और रीजन की सर्विसेज़ | `postgresql://postgres:<password>@<name>.lizard.internal:5432/postgres` |
| `DATABASE_URL` | आपकी मशीन, CI, या किसी दूसरे प्रोजेक्ट या रीजन की सर्विस | `postgresql://postgres:<password>@<host>:<port>/postgres` |

`<name>` वह नाम है जो प्राइवेट एड्रेस मिलते समय डेटाबेस का था; पहले डेटाबेस के लिए यह `postgres` है। डेटाबेस का नाम बदलने से यह नहीं बदलता। पब्लिक होस्ट और पोर्ट Lizard डेटाबेस बनाते समय असाइन करता है। होस्ट हाथ से टाइप करने के बजाय उन्हें `DATABASE_PRIVATE_URL`, `DATABASE_URL`, `PGHOST` और `PGPORT` से पढ़ें।

प्राइवेट एड्रेस सिर्फ़ उसी प्रोजेक्ट और उसी रीजन की सर्विसेज़ से काम करता है; [प्राइवेट नेटवर्किंग](/networking#private-networking) देखें। किसी दूसरे रीजन की सर्विस को `DATABASE_URL` का उपयोग करना होगा। उसे प्राइवेट एड्रेस देने के लिए डेटाबेस को उसी सर्विस के रीजन में बनाएँ: `lizard add postgres --region <code>`।

ज़्यादातर ड्राइवर इस स्ट्रिंग को सीधे ले लेते हैं:

```js
// Node.js with pg
import pg from 'pg';
const pool = new pg.Pool({ connectionString: process.env.DATABASE_URL });
```

```python
# Python with psycopg
import os, psycopg
conn = psycopg.connect(os.environ["DATABASE_URL"])
```

`psql` और libpq के दूसरे टूल `PG*` वेरिएबल्स पढ़ते हैं, इसलिए वे बिना किसी आर्गुमेंट के कनेक्ट हो जाते हैं।

<span id="how-do-i-see-the-connection-string" />

### कनेक्शन स्ट्रिंग कैसे देखें?

- **डैशबोर्ड:** अपने प्रोजेक्ट में डेटाबेस खोलें। **ओवरव्यू** टैब में `DATABASE_URL` और प्राइवेट URL कॉपी बटन के साथ दिखते हैं। **सीक्रेट्स** टैब में हर कनेक्शन वेरिएबल और सर्विस में पेस्ट करने के लिए `${{…}}` रेफरेंस की सूची होती है।
- **CLI:** `lizard run --service postgres -- printenv DATABASE_URL` पब्लिक स्ट्रिंग प्रिंट करता है। इसमें पासवर्ड होता है, इसलिए इसे लॉग या चैट में पेस्ट न करें।

यह स्ट्रिंग एक क्रेडेंशियल है। इसे किसी सीक्रेट में कॉपी करने के बजाय सर्विसेज़ को रेफरेंस से इस पर पॉइंट करें, ताकि हर डिप्लॉय पर उन्हें मौजूदा वैल्यू मिले।

<span id="connect-a-service" />

## सर्विस कनेक्ट करें

जिस सर्विस को डेटाबेस चाहिए, उसमें प्राइवेट कनेक्शन स्ट्रिंग को रेफरेंस करें और रीडिप्लॉय करें:

```bash
lizard secrets set DATABASE_URL='${{postgres.DATABASE_PRIVATE_URL}}' --service api
lizard redeploy --service api
```

रेफरेंस डिप्लॉय के समय रिज़ॉल्व होता है, इसलिए हर कंज्यूमर सर्विस को अपने अगले डिप्लॉय पर ऐडऑन की मौजूदा वैल्यू मिलती हैं। प्रोजेक्ट के बाहर या किसी दूसरे रीजन के क्लाइंट के लिए इसके बजाय `DATABASE_URL` का उपयोग करें। प्रोजेक्ट की हर सर्विस को ऐडऑन का पब्लिक `DATABASE_URL` सबसे कम प्राथमिकता पर भी मिलता है; स्पष्ट रेफरेंस इसे ओवरराइड करता है।

कनेक्शन स्ट्रिंग प्रिंट किए बिना अपनी मशीन से कनेक्टिविटी जाँचें:

```bash
lizard run --service postgres -- sh -c 'psql "$DATABASE_URL" -c "SELECT 1"'
```

`lizard run --service postgres` डेटाबेस की पब्लिक कनेक्शन वैल्यू के साथ कमांड आपकी मशीन पर चलाता है, इसलिए आपकी मशीन पर `psql` इंस्टॉल होना चाहिए। `lizard run --service api` `${{…}}` रेफरेंस को जस का तस टेक्स्ट के रूप में पास करेगा; [`lizard run`](/cli/run) देखें।

<span id="run-migrations-on-deploy" />

## डिप्लॉय पर माइग्रेशन चलाएँ

माइग्रेशन के लिए प्री-डिप्लॉय कमांड का उपयोग करें। यह तभी चलता है जब स्टार्ट कमांड भी सेट हो, और हर कंटेनर के शुरू होने पर `sh -c "<pre> && exec <start>"` के रूप में चलता है: हर रेप्लिका पर, हर रीस्टार्ट पर। माइग्रेशन ऐसे लिखें कि उन्हें कई बार और एक साथ चलाना सुरक्षित हो, और वे ऐप्लिकेशन के पुराने और नए, दोनों वर्ज़न के साथ काम करें:

```bash
lizard service set api --set preDeployCommand="npm run migrate" --set startCommand="npm start"
lizard redeploy --service api
```

Django ऐप के लिए कमांड `python manage.py migrate` है; [Django गाइड](/framework-guides/django) और [Python ऐप होस्टिंग](https://lizard.build/blog/python-app-hosting#django-postgres-and-celery-need-separate-checks) देखें। [Umami](/guides/umami) और [Flowise](/guides/flowise) गाइड में Managed Postgres पर चलने वाले पूरे ऐप दिखाए गए हैं।

<span id="browse-and-query-data" />

## डेटा ब्राउज़ करें और क्वेरी चलाएँ

SQL चलाने और टेबल सीधे ब्राउज़ करने के लिए डैशबोर्ड (`lizard open`) में **Postgres एडिटर** खोलें। लोकल मशीन पर ज़रूरत के हिसाब से काम करने के लिए ऐडऑन की कनेक्शन वैल्यू के साथ कमांड चलाएँ:

```bash
lizard run --service postgres -- sh -c 'exec psql "$DATABASE_URL"'
```

<span id="grow-storage" />

## स्टोरेज बढ़ाएँ

डेटा वॉल्यूम सिर्फ़ बढ़ाए जा सकते हैं, घटाए नहीं जा सकते:

```bash
lizard scale --service postgres --storage 8192
```

साइज़ 512, 1024, 2048, 4096, 8192 या 16384 MB हो सकते हैं। वॉल्यूम बढ़ाने पर डेटाबेस तब तक बंद रहता है जब तक Lizard उसका डेटा बड़े वॉल्यूम में कॉपी नहीं कर लेता, फिर उसे दोबारा चालू कर दिया जाता है, इसलिए थोड़ी देर के आउटेज के लिए तैयार रहें। पॉज़ किए गए डेटाबेस का साइज़ बदलने से पहले उसे [`lizard resume`](/cli/pause) से फिर से चालू करें।

<span id="multiple-databases" />

## कई डेटाबेस

दूसरा Postgres जोड़ने पर उसे जेनरेट किया गया नाम मिलता है (जैसे `postgres-autumn-bear`)। उसे नाम से स्पष्ट रूप से रेफरेंस करें:

```bash
lizard add postgres
lizard secrets set ANALYTICS_URL='${{postgres-autumn-bear.DATABASE_PRIVATE_URL}}' --service api
```

<span id="backups-and-restore" />

## बैकअप और रीस्टोर

यह मानकर न चलें कि शेड्यूल्ड बैकअप या पॉइंट-इन-टाइम रिकवरी उपलब्ध है। किसी जोखिम भरे माइग्रेशन से पहले डेटाबेस को खुद एक्सपोर्ट करें और किसी अलग डेटाबेस में रीस्टोर करके जाँचें। उदाहरण के लिए, जब आपकी मशीन पर `pg_dump` 18 या उससे नया वर्ज़न इंस्टॉल हो:

```bash
lizard run --service postgres -- sh -c 'pg_dump "$DATABASE_URL" > backup.sql'
```

रीस्टोर प्लान के लिए [स्टोरेज और रिकवरी](/platform/storage-and-recovery) देखें।
