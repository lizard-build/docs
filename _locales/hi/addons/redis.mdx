# Managed Redis

Lizard पर Managed Redis कैशिंग, क्यू, रेट लिमिटिंग और पब/सब के लिए एक Redis सर्वर है। नए इंस्टेंस डिफ़ॉल्ट रूप से Redis 8 चलाते हैं। `lizard add redis` के साथ एक जोड़ें; आपकी सेवाएं `${{redis.REDIS_PRIVATE_URL}}` जैसे रेफरेंस के माध्यम से `REDIS_PRIVATE_URL` या `REDIS_URL` पढ़ती हैं। इसकी कोई इविक्शन पॉलिसी और कोई अपेंड-ओनली फ़ाइल नहीं है, इसलिए इसमें केवल वही डेटा रखें जिसे आप फिर से बना सकते हैं। अवलोकन और कीमतों के लिए, [Managed Redis पेज](https://lizard.build/redis) देखें।

<span id="provision" />

## प्रोविज़न

```bash
lizard add redis
```

पहला Redis एडऑन `redis` नाम का है, इसलिए `${{redis.REDIS_URL}}` तुरंत काम करता है।

<span id="environment-variables" />

## एनवायरनमेंट वेरिएबल्स

| वेरिएबल | विवरण |
|----------|-------------|
| `REDIS_URL` | पब्लिक एंडपॉइंट (`redis://…`) पर पूरा कनेक्शन स्ट्रिंग |
| `REDIS_PRIVATE_URL` | प्रोजेक्ट के प्राइवेट नेटवर्क (`<name>.lizard.internal:6379`) पर कनेक्शन स्ट्रिंग |

दोनों स्ट्रिंग `redis://default:<password>@<host>:<port>` के रूप में हैं। प्राइवेट वाला केवल एक ही प्रोजेक्ट और एक ही रीजन की सेवाओं से काम करता है; [प्राइवेट नेटवर्किंग](/networking#private-networking) देखें। किसी दूसरे रीजन की सेवा को `REDIS_URL` का उपयोग करना चाहिए; उसे प्राइवेट URL देने के लिए, उसके रीजन में `lizard add redis --region <code>` के साथ Redis बनाएं। `<name>` वह नाम है जो एडऑन का था जब उसे उसका प्राइवेट एड्रेस मिला था, `redis` पहले वाले के लिए; नाम बदलने से यह नहीं बदलता है।

<span id="connect-a-service" />

## एक सेवा कनेक्ट करें

```bash
lizard secrets set REDIS_URL='${{redis.REDIS_PRIVATE_URL}}' --service api
lizard redeploy --service api
```

रेफरेंस डिप्लॉय टाइम पर रिजॉल्व होता है; उपभोक्ता अपने अगले डिप्लॉय पर एडऑन के वर्तमान मानों को उठाते हैं। प्रोजेक्ट के बाहर या किसी दूसरे रीजन में क्लाइंट के लिए `REDIS_URL` का उपयोग करें। प्रोजेक्ट की हर सेवा को सबसे कम प्रेसिडेंस पर एडऑन का पब्लिक `REDIS_URL` भी मिलता है; एक स्पष्ट रेफरेंस इसे ओवरराइड करता है।

<span id="does-managed-redis-keep-data" />

## क्या Managed Redis डेटा रखता है?

Managed Redis हाल की राइट्स खो सकता है। इसकी कोई इविक्शन पॉलिसी और कोई अपेंड-ओनली फ़ाइल नहीं है। यदि यह मेमोरी से बाहर हो जाता है, तो इंस्टेंस रीस्टार्ट हो जाता है और वे राइट्स खो सकता है। इसका उपयोग उन डेटा के लिए करें जिन्हें आप फिर से बना सकते हैं, और उस डेटा को रखें जिसे आप [Managed Postgres](/addons/postgres) में नहीं खो सकते।

<span id="common-uses" />

## सामान्य उपयोग

- **कैश**: अनुरोध द्वारा की गई गणनाओं के परिणामों को स्टोर करें।
- **क्यू / वर्कर**: Redis को [वर्कर-मोड सेवा](/deploy/workers) के साथ पेयर करें जो जॉब्स का उपभोग करती है। [क्यू कंज्यूमर चलाएं](/deploy/workers#run-a-queue-consumer) Redis-वर्कर उदाहरण के माध्यम से चलता है।
- **रेट लिमिटिंग / सेशन**: [रेप्लिका](/deploy/scaling) में तेज साझा स्थिति।

```bash
# A worker that drains a Redis queue
lizard add -r your-org/worker -n jobs --no-deploy
lizard service set jobs --set containerPort=0
lizard secrets set REDIS_URL='${{redis.REDIS_PRIVATE_URL}}' --service jobs
lizard redeploy --service jobs
```

<span id="browse-keys" />

## कुंजी ब्राउज़ करें

कुंजी और मानों का निरीक्षण करने के लिए डैशबोर्ड (`lizard open`) में **Redis ब्राउज़र** खोलें। एडऑन के कनेक्शन मानों के साथ स्थानीय एक्सेस के लिए:

```bash
lizard run --service redis -- sh -c 'exec redis-cli -u "$REDIS_URL"'
```

<span id="grow-storage" />

## स्टोरेज बढ़ाएं

```bash
lizard scale --service redis --storage 4096
```

स्टोरेज ग्रो-ओनली है। आकार 512, 1024, 2048, 4096, 8192 या 16384 MB हैं। वॉल्यूम को बढ़ाना Redis को तब तक रोकता है जब तक Lizard अपने डेटा को बड़े वॉल्यूम में कॉपी नहीं कर लेता, फिर उसे फिर से शुरू करता है, इसलिए एक छोटी आउटेज की उम्मीद करें। इसे रीसाइज़ करने से पहले [`lizard resume`](/cli/pause) के साथ एक पॉज़ किए गए इंस्टेंस को फिर से शुरू करें।
