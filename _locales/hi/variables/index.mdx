# चर और सीक्रेट

Lizard कॉन्फ़िगरेशन को **सीक्रेट्स** के रूप में स्टोर करता है। वे दो स्कोप में आते हैं - **सर्विस** (डिफ़ॉल्ट) और **प्रोजेक्ट** (`--global`) - और एक परिभाषित प्रेसिडेंस ऑर्डर में आपके ऐप के एनवायरनमेंट में मर्ज हो जाते हैं। कोई वर्कस्पेस-लेवल ग्लोबल स्कोप नहीं है।

<span id="setting-variables" />

## वेरिएबल सेट करना

`lizard secrets set` वेरिऐडिक है - एक बार में एक या कई सेट करें। डिफ़ॉल्ट रूप से यह **लिंक्ड सर्विस** में लिखता है:

```bash
lizard secrets set DATABASE_URL=postgres://… LOG_LEVEL=info
lizard secrets set API_KEY=sk_live_… --service api
```

 **प्रोजेक्ट** स्कोप में लिखने के लिए `--global` जोड़ें (प्रोजेक्ट की हर सर्विस इसे देखती है):

```bash
lizard secrets set NODE_ENV=production --global
```

<span id="listing-deleting-importing" />

## लिस्ट करना, डिलीट करना, इम्पोर्ट करना

```bash
lizard secrets list                       # current scope
lizard secrets list --show                # reveal values
lizard secrets delete OLD_KEY ANOTHER_KEY # variadic; add -y in scripts
cat .env | lizard secrets import          # KEY=value lines from stdin
```

`secrets import` प्लेन `KEY=value` लाइनों को पढ़ता है और कोट्स को वैल्यू के हिस्से के रूप में रखता है। `secrets delete` पुष्टि के लिए पूछता है; जब यह टर्मिनल के बाहर चलता है तो `-y` पास करें।

हर फ़्लैग के लिए [`lizard secrets` कमांड रेफरेंस](/cli/secrets) देखें।

<span id="scoping" />

## स्कोपिंग

| स्कोप | कमांड | के रूप में स्टोर किया गया | किसके लिए दृश्यमान |
|-------|---------|-----------|------------|
| **सर्विस** (डिफ़ॉल्ट) | `lizard secrets set K=v --service <svc>` | `secrets.services[<svc>]` | केवल उस सर्विस के लिए |
| **प्रोजेक्ट** (ग्लोबल) | `lizard secrets set K=v --global` | `secrets.shared` | प्रोजेक्ट की हर सर्विस के लिए |

**सर्विस स्कोप पर डिफ़ॉल्ट करें।** एक कॉम्प्रोमाइज्ड सर्विस अपने एनवायरनमेंट को पढ़ सकती है - व्यापक स्कोप का मतलब बिना किसी कारण के अधिक क्रेडेंशियल्स का एक्सपोज होना है। `--global` को नॉन-सीक्रेट, सिद्ध-सार्वजनिक मानों जैसे `LOG_LEVEL`, `NODE_ENV`, फ़ीचर फ़्लैग्स, या फ्रंटएंड `SENTRY_DSN` के लिए आरक्षित करें। यदि आप अनिश्चित हैं कि कोई मान सीक्रेट है या नहीं, तो उसे सीक्रेट मानें और उसे सर्विस तक स्कोप करें।

प्रत्येक सर्विस को प्रोजेक्ट के पोस्टग्रेस और रेडिस एडऑन (चल रहे या रुके हुए) से पहले से ही एक `DATABASE_URL` और एक `REDIS_URL` मिलता है, सबसे कम प्रेसिडेंस पर। एक प्रकार के कई एडऑन के साथ, आपको कौन सा मिलता है यह परिभाषित नहीं है। किसी विशिष्ट एडऑन को चुनने या उसके प्राइवेट URL का उपयोग करने के लिए, `--global` के बजाय [रेफरेंस](/variables/references) के साथ प्रति कंज्यूमर इसे बाइंड करें:

```bash
lizard secrets set DATABASE_URL='${{postgres.DATABASE_PRIVATE_URL}}' --service api
lizard secrets set DATABASE_URL='${{postgres.DATABASE_PRIVATE_URL}}' --service worker
```

यदि एडऑन के मान बदलते हैं, तो प्रत्येक कंज्यूमर अपने अगले डिप्लॉय या वेरिएबल परिवर्तन पर नया मान उठाता है।

<span id="precedence" />

## प्रेसिडेंस

जब एक ही की (key) कई जगहों पर परिभाषित होती है, तो **आखिरी लिखने वाला जीतता है**:

```
addon-issued env  <  project secrets  <  project env  <  app env  <  app secrets  <  platform vars
```

इसलिए **ऐप सीक्रेट्स प्रोजेक्ट सीक्रेट्स को ओवरराइड करते हैं**, और **प्लेटफ़ॉर्म वेरिएबल्स** (`PORT`, `LIZARD_SERVICE_NAME`, `LIZARD_PROJECT_ID`, `LIZARD_PUBLIC_DOMAIN`, `LIZARD_PRIVATE_DOMAIN`) सबसे आखिर में लागू होते हैं और उन्हें शैडो नहीं किया जा सकता। `PORT` केवल तब सेट होता है जब सर्विस में एक HTTP पोर्ट होता है। आपके द्वारा सेट किया गया `PORT` वेरिएबल केवल उस सर्विस पर रूटिंग को मूव करता है जिसका पोर्ट कभी सेट नहीं किया गया था। `lizard up` द्वारा बनाई गई सर्विस, या `--port`, `lizard port`, `containerPort` या डैशबोर्ड के साथ पोर्ट दी गई सर्विस, उस पोर्ट को रखती है, और Lizard आपके `PORT` को उससे ओवरराइट करता है। पोर्ट बदलने के लिए, `lizard port <n>` चलाएं और फिर से डिप्लॉय करें। देखें कि [कौन सा पोर्ट Lizard रूट करता है](/deploy/dockerfile#which-port-lizard-routes-to)।

<span id="build-time-vs-runtime" />

## बिल्ड-टाइम बनाम रनटाइम

अधिकांश वेरिएबल परिवर्तन **बिना रीबिल्ड** के लागू होते हैं - सर्विस उन्हें उठाने के लिए रीस्टार्ट होती है, जिसमें कुछ सेकंड लगते हैं। अपवाद बिल्ड-टाइम मान हैं जो इमेज में बेक किए जाते हैं:

- `lizard secrets set` या सर्विस की सेटिंग्स में `VITE_*` या `NEXT_PUBLIC_*` मान को बदलने से प्रभावित रनिंग सर्विसेज का तुरंत रीबिल्ड शुरू हो जाता है (`--global` के लिए हर रनिंग सर्विस)। डैशबोर्ड के प्रोजेक्ट सीक्रेट्स पेज पर एक एडिट केवल उन्हें रीस्टार्ट करता है; उसके बाद `lizard redeploy` चलाएं।
- Lizard इन मानों को GitHub सर्विसेज (Dockerfile lizardpack जेनरेट करता है, या रेपो का रूट Dockerfile) और `buildCommand` / `startCommand` से बने Node सर्विसेज के लिए `ENV` लाइनों के रूप में बेक करता है। कस्टम `dockerfilePath` वाली सर्विस, या उन कमांड्स के बिना `lizard up` के साथ अपलोड की गई सर्विस, बिल्ड टाइम पर कोई Lizard वेरिएबल प्राप्त नहीं करती है; `COMMIT_SHA` को छोड़कर कोई भी सर्विस बिल्ड आर्ग्स प्राप्त नहीं करती है। उन मामलों में सार्वजनिक मानों के लिए, उन्हें `.env.production` में कमिट करें या उन्हें अपने Dockerfile में `ENV` लाइनों के रूप में लिखें। अपने स्वयं के Dockerfile के बिना अपलोड किए गए Node ऐप के लिए, बिल्ड कमांड सेट करना भी काम करता है।

[बिल्ड पाइपलाइन → रीबिल्ड ट्रिगर](/concepts/build-pipeline#what-triggers-a-rebuild) देखें।

## सत्यापन

सेवाओं में शेल की पहुँच (`lizard ssh`) बंद है, इसलिए मान दूसरे तरीके से जाँचें:

```bash
lizard logs --build --service api          # warns about every empty ${{…}} reference
lizard secrets list --service api --show   # stored values
lizard secrets list --service api --ref    # addon keys and each service's LIZARD_* / PORT keys
```

`--ref` दूसरी सेवा के अपने variables और secrets की सूची नहीं दिखाता। उनके references काम करते हैं; कुंजियाँ `lizard secrets list --service <target>` से जाँचें।

अगर कोई अपेक्षित मान नहीं मिले, तो [समस्या सुलझाएँ → secret या reference दिखाई नहीं दे रहा](/variables/troubleshooting/reference-not-applied) देखें।

<span id="local-development" />

## लोकल डेवलपमेंट

सेवा के प्रोजेक्ट और सेवा secrets के साथ एक कमांड **अपने कंप्यूटर पर** चलाएँ:

```bash
lizard run --service api -- node scripts/seed.js
```

मान उसी रूप में मिलते हैं जिस रूप में सेव हैं: `${{…}}` references टेक्स्ट ही रहते हैं, और प्लेटफ़ॉर्म variables (`PORT`, `LIZARD_*`) नहीं मिलते। डेटाबेस की ज़रूरत वाली स्क्रिप्ट को addon के असली कनेक्शन मानों के साथ चलाएँ:

```bash
lizard run --service postgres -- node scripts/seed.js
```

देखें [`lizard run` कौन से मान देता है](/cli/run#what-run-injects)।
