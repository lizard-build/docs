# मेरी सेवा में एक रहस्य या संदर्भ प्रदर्शित नहीं हो रहा

आपने एक रहस्य या `${{name.KEY}}` संदर्भ सेट किया, रीडिप्लॉय किया, और चल रही सेवा अभी भी आपके द्वारा अपेक्षित मान नहीं देख रही।

<span id="what-this-means" />

## इसका क्या मतलब है

आपने सेट किया गया मान सेवा के संलिप्त वातावरण में कभी पहुंच नहीं पाया — या फिर संलेपन से पहले कुछ और ने इसे ओवरराइड कर दिया।

<span id="why-this-can-happen" />

## यह क्यों हो सकता है

- **रिफ़रेंस लक्ष्य या कुंजी अस्तित्व में नहीं है।** एक लुप्त सेवा/एड-ऑन नाम या ऐसी कुंजी जिसे वह एड-ऑन प्रदर्शित नहीं करता है, का रिफ़रेंस डिप्लॉय को फेल करने के बजाय **एक खाला स्ट्रिंग** में हल होता है। बिल्ड लॉग हर खाले रिफ़रेंस के लिए एक चेतावनी प्रदर्शित करता है जिसका कारण बताता है; कोई बिल्ड के बिना वारियेबल बदलाव चेतावनी प्रदर्शित नहीं करता। एक नामबदलित लक्ष्य रिफ़रेंसेज़ के लिए लुप्त माना जाता है जो `lizard secrets set` या डैशबोर्ड से सेट किए गए हैं: वे वर्तमान नाम से मेल खाते हैं। एक सेवा लक्ष्य उसके द्वारा Lizard द्वारा संकलित `DATABASE_URL` या `REDIS_URL` को प्रदर्शित नहीं करता है; उनके लिए एड-ऑन का संदर्भ दें।
- **कुछ और ने उच्च प्राथमिकता से इसे ओवरराइड कर दिया।** मान एक निर्धारित क्रम में संलिप्ट होते हैं — `addon-issued env < project secrets < project env < app env < app secrets < platform vars` — इसलिए एक प्रोजेक्ट-स्कोपित (`--global`) रहस्य को एक सेवा-स्कोपित जिसमें समान कुंजी है, चुपचाप छाया में डाल दिया जा सकता है, और प्लेटफॉर्च चर (`PORT`, `LIZARD_SERVICE_NAME`, `LIZARD_PROJECT_ID`, `LIZARD_PUBLIC_DOMAIN`, `LIZARD_PRIVATE_DOMAIN`) हमेशा जीत लेते हैं। आपके द्वारा सेट `PORT` केवल उस सेवा पर रूटिंग बदलता है जिसकी पोर्ट कभी सेट नहीं की गई थी। `lizard up` द्वारा बनाई गई सेवा में, या जिसे `--port`, `lizard port` या डैशबोर्ड द्वारा पोर्ट दी गई हो, Lizard इसे ओवरराइड कर देता है; पोर्ट को `lizard port <n>` से बदलें।
- **एक बिल्ड-टाइम मान बिल्ड तक नहीं पहुंचा।** अधिकांश चर बदलाव कोई पुनर्निर्माण के बिना लागू होते हैं — सेवा इन्हें लेने के लिए पुनर्स्टार्ट हो जाती है। `VITE_*` और `NEXT_PUBLIC_*` मान बिल्ड किए गए एसेट्स में बेक हो जाते हैं, और एक को `lizard secrets set` या किसी सेवा की सेटिंग्स में बदलने से चल रही सेवाओं का तुरंत पुनर्निर्माण शुरू हो जाता है। डैशबोर्ड के प्रोजेक्ट सीक्रेट्स पृष्ठ पर संपादित करने से कोई पुनर्निर्माण नहीं शुरू होता। एक सेवा जो समय पर दुर्घटित या बंद थी, वह छोड़ दी जाती है, और एक सेवा जिसका कस्टम `dockerfilePath` है या जिसे `lizard up` से बिल्ड/स्टार्ट कमांड के बिना अपलोड किया गया है, वह बिल्ड टाइम पर ये मान कभी प्राप्त नहीं करती।

<span id="possible-solutions" />

## संभावित समाधान

<span id="check-the-build-log-for-empty-references" />

### खाले रिफ़रेंसेज़ के लिए बिल्ड लॉग जांचें

सेवाओं के लिए शेल एक्सेस (`lizard ssh`) बंद है। बिल्ड लॉग वह जगह है जहाँ देखें: हर खाला रिफ़रेंस एक ऐसी पंक्ति प्रदर्शित करता है जैसे `==> Warning: ... is empty` जिसका कारण बताता है।

```bash
lizard logs --build --service api
```

फिर हर एड-ऑन की कुंजियाँ और हर सेवा के `LIZARD_*` और `PORT` कुंजियों की सूची लें, और अपने साथ नाम और कुंजी की तुलना करें। दूसरी सेवा के अपने चर और रहस्यों के लिए रिफ़रेंसेज़ काम करते हैं लेकिन सूची नहीं होते; उन्हें `lizard secrets list --service <target>` से जांचें। कुंजियों को एड-ऑन के [दस्तावेज़ किए गए चर](/addons) से तुलना करें:

```bash
lizard secrets list --service api --ref
```

<span id="check-for-a-scope-collision" />

### स्कोप कollision के लिए जांचें

दोनों स्कोपों में रहस्यों की सूची लें और तुलना करें:

```bash
lizard secrets list --service api --show
lizard secrets list --global --show
```

याद रखें **एप्पीक सीक्रेट्स प्रोजेक्ट सीक्रेट्स से ओवरराइड करते हैं** — अगर समान कुंजी के लिए सेवा-स्कोपित मान मौजूद है, तो यह `--global` से सेट किए गए किसी भी चीज़ पर जीत लेता है।

<span id="rebuild-after-a-build-time-change" />

### बिल्ट-टाइम बदलाव के बाद पुनर्निर्माण करें

अगर बदली गई कुंजी `VITE_*` या `NEXT_PUBLIC_*` है, और सेवा आपने इसे बदलने समय दुर्घटित या बंद थी या आपने इसे डैशबोर्ड के प्रोजेक्ट सीक्रेट्स पृष्ठ पर बदला था, तो एक पुनर्निर्माण ट्रिगर करें:

```bash
lizard redeploy --service api
```

देखें [बिल्ड-टाइम बनाम रन-टाइम](/variables#build-time-vs-runtime) और [बिल्ड पाइपलाइन → पुनर्निर्माण ट्रिगर करने वाली घटनाएँ](/concepts/build-pipeline#what-triggers-a-rebuild)।
