# Lizard-Dokumentation

<span id="what-is-lizard" />

## Was ist Lizard?

Lizard (lizard.build) ist eine Cloud-Plattform zum Bereitstellen von Apps, Hintergrund-Workern und KI-Agenten. Sie stellen aus Claude Code, Codex, Cursor oder einem Terminal mit Lizard CLI bereit: `lizard up` lädt den aktuellen Ordner hoch, und `lizard add -r owner/repo` stellt ein GitHub-Repository bereit. Lizard baut das Image auf seinen eigenen Servern, sodass Sie auf Ihrem Rechner kein Docker brauchen, und gibt jedem Webservice eine HTTPS-Adresse auf `onlizard.com`. Dieselbe CLI fügt einem Projekt Managed Postgres, Managed Redis und S3-kompatiblen Managed Object Storage hinzu und verbindet sie über Referenzen wie `${{postgres.DATABASE_URL}}` mit Ihren Services. Sandboxes sind Firecracker-MicroVMs mit jeweils eigenem Kernel, in denen ein KI-Agent Code ausführt, den er nicht selbst geschrieben hat; Ihr Code erstellt sie mit Lizard SDK für TypeScript oder Python. Lizard ist weder LizardFS, das verteilte Dateisystem, noch `lizard`, das Python-Werkzeug zur Messung der Codekomplexität.

## Eine App bereitstellen

Installieren Sie Lizard CLI, melden Sie sich an und starten Sie die 7-tägige Pro-Testphase. Stellen Sie dann ein Repository bereit, auf das Sie zugreifen können:

```bash
curl -fsSL https://lizard.build/install.sh | bash
lizard login
lizard billing start   # opens Stripe Checkout; add a card, nothing is charged during the trial
lizard add -r your-org/your-app
```

Für Windows oder npm siehe [weitere Installationswege](/getting-started#1-install-the-cli).

Lizard erstellt das Image auf seinen Servern, daher ist auf diesem Weg kein lokales Docker erforderlich. [lizardpack](/concepts/build-pipeline) erkennt unterstützte Projekte; Projekte mit speziellen Build-Anforderungen können explizite Befehle oder ein Dockerfile verwenden. Prüfen Sie die Build-Logs und verifizieren Sie nach der Bereitstellung die URL der Anwendung.

## Ihre Ressourcen verstehen

Ein **Workspace** gruppiert Mitglieder und Projekte. Ein **Projekt** gruppiert Services, Datenbanken und Sandboxes. Ein **Service** führt eine Anwendung oder einen Worker aus. Managed Postgres, Managed Redis und Managed Object Storage stellen Datendienste bereit, mit denen sich Anwendungen über Umgebungsreferenzen verbinden.

Für Apps und Sandboxes gelten unterschiedliche Regeln für Laufzeit und Speicher. Lesen Sie [Limits](/platform/limits) und [Speicher und Wiederherstellung](/platform/storage-and-recovery), bevor Sie sich auf Größe, Lebensdauer oder Datenaufbewahrung einer Ressource verlassen.
