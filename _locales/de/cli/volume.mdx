# lizard volume

Verwalte [Persistent Volumes](/sandboxes/volumes) für Sandboxes und Services. Alias: `lizard vol`.

<span id="usage" />

## Verwendung

```bash
lizard volume list [flags]
lizard volume create <name> [flags]
lizard volume resize <volume> --size <gb> [flags]
lizard volume rm <volume> [flags]
```

Der Name eines Volumes ist sein Schlüssel innerhalb des Projekts. Jeder Befehl akzeptiert einen Namen oder eine ID sowie `-p, --project`, um ein anderes als das verknüpfte Projekt anzusprechen. In einem nicht verknüpften Ordner nutzen die Befehle das Standardprojekt deines Kontos.

<span id="subcommands" />

## Unterbefehle

### `lizard volume list`

Listet die Volumes des Projekts mit Größe, Status und der Sandbox auf, an die sie angehängt sind (Alias `ls`). `--json` enthält zusätzlich die generierten IDs. `-s, --service <name>` zeigt stattdessen das Volume, das an diesen Service angehängt ist.

### `lizard volume create <name>`

Erstellt ein Volume. Namen bestehen aus Kleinbuchstaben, Ziffern und Bindestrichen, beginnen und enden mit einem Buchstaben oder einer Ziffer, sind höchstens 64 Zeichen lang und im Projekt eindeutig.

| Flag | Beschreibung |
|------|-------------|
| `--size <gb>` | Größe in ganzen GB (Standard 5); ein Sandbox-Volume erlaubt 1 bis 50. Die CLI liest zuerst die aktuellen Limits des Servers |
| `--region <code>` | Region für das Volume; sie muss zur Sandbox passen, die es einbindet |
| `-s, --service <name>` | Erstellt das Volume und hängt es stattdessen an diesen Service an. Ein Service hat höchstens ein Volume, und dessen Dateien überstehen Neustarts und Redeploys |
| `--mount-path <path>` | Mit `--service`: wo der Service das Volume sieht (Standard `/data`) |
| `-p, --project <id>` | Projektname, Slug oder ID |

Die Sandbox-Volumes eines Workspaces dürfen zusammen höchstens 200 GB zugewiesene Größe haben. Ein `create` oder `resize` darüber hinaus schlägt mit HTTP 403 und dem Code `volume_quota_exceeded` fehl.

### `lizard volume resize <volume> --size <gb>`

Vergrößert ein Volume direkt; dabei werden keine Daten kopiert. Eine Sandbox, an die das Volume angehängt ist, läuft weiter, sieht aber noch die alte Größe. Die nächste Sandbox, die das Volume anhängt, sieht die neue Größe. Um sie sofort zu nutzen, lösche die Sandbox und erstelle eine neue mit `--volume`. Ein Volume kann nur wachsen. Manche Volumes, die vor Oktober 2026 erstellt wurden, lassen sich auch verkleinern, wenn mindestens 10 % der neuen Größe frei bleiben.

### `lizard volume rm <volume>`

Löscht ein Volume und seine Daten (Alias `delete`). Der Befehl schlägt fehl, solange das Volume angehängt ist; lösche zuerst die Sandbox.

| Flag | Beschreibung |
|------|-------------|
| `-y, --yes` | Bestätigung überspringen |

Der Speicher von Sandbox-Volumes kostet 0,14 $ pro GB und Monat für belegten Speicherplatz. Siehe [Größe und Preis](/sandboxes/volumes#size-and-price).

<span id="examples" />

## Beispiele

<span id="create-a-volume-and-attach-it" />

### Ein Volume erstellen und anhängen

```bash
lizard volume create agent-workdir --size 10
lizard sandbox create --volume agent-workdir
```

<span id="grow-a-volume" />

### Ein Volume vergrößern

```bash
lizard volume resize agent-workdir --size 20
```

<span id="delete-a-volume" />

### Ein Volume löschen

```bash
lizard volume rm agent-workdir --yes
```
