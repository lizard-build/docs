# lizard login

Bei Lizard anmelden und einen Plan starten, falls das Konto keinen hat.

<span id="usage" />

## Verwendung

```bash
lizard login [flags]
```

Im Terminal fragt `login`, ob du dich mit GitHub oder Google anmeldest, öffnet diese Seite im Browser und wartet auf deine Bestätigung. Wenn du schon ein Konto hast, wähle die Methode, mit der du dich registriert hast: Die andere legt ein zweites, leeres Konto an, sofern beide keine gemeinsame bestätigte E-Mail-Adresse haben. Der Link gilt 5 Minuten.

Nach der Anmeldung prüft `login` den Plan. Ein Konto ohne Plan bekommt die 7-tägige Pro-Testphase angeboten, oder Pro für $19 im Monat, wenn es seine Testphase schon hatte. Wenn du zustimmst, öffnet sich Stripe Checkout. Zum Schluss listet der Befehl auf, was du als Nächstes ausführen kannst.

Auf einem Rechner, der bereits angemeldet ist, zeigt `login` das Konto an und geht direkt zum Plan über. Du kannst den Befehl also gefahrlos erneut ausführen. Um das Konto zu wechseln, führe zuerst [`lizard logout`](/cli/logout) aus.

Die Installationsskripte führen `lizard login` als letzten Schritt aus. Mit `LIZARD_NO_LOGIN=1` überspringst du das; in CI überspringen die Skripte es von selbst.

Vor anderen Befehlen brauchst du `login` selten: Jeder Befehl, den du im Terminal auf einem nicht angemeldeten Rechner ausführst, meldet dich zuerst an und läuft dann weiter.

## Flags

| Flag | Beschreibung |
|------|-------------|
| `--github` | Mit GitHub anmelden, ohne Rückfrage |
| `--google` | Mit Google anmelden, ohne Rückfrage |
| `--token <token>` | Mit einem API-Key (`liz_…`) anmelden |
| `--token-stdin` | Den API-Key von stdin lesen, damit er nicht in der Prozessliste und im Shell-Verlauf erscheint |

<span id="output-for-agents" />

## Ausgabe für Agents

Mit `--json`, oder wenn stdout kein Terminal ist, gibt `login` ein einziges JSON-Objekt aus. Es öffnet keinen Browser und wartet nie.

- Vor der Anmeldung gibt es `status: "pending"`, `authUrls` mit einem Link pro Methode, `authUrl`, `expiresAt` und eine `instruction` aus. Gib den Link an den Nutzer weiter und führe den Befehl erneut aus, sobald der Browser „CLI authorized“ anzeigt.
- Nach der Anmeldung gibt es `status: "complete"`, den Benutzernamen, `account.state` mit einer `instruction` zum Plan und `next`-Befehle aus.

Einen Plan startet es nie selbst. Dafür führst du [`lizard billing start --json`](/cli/billing) aus und gibst dem Nutzer die Checkout-`url`.

Andere Befehle verhalten sich ohne Terminal genauso: Sie enden mit Exit-Code `2` und dem Code `NOT_AUTHENTICATED`, und der Fehler-Body enthält dieselben Links unter `login`.

## Beispiele

<span id="log-in-via-browser" />

### Über den Browser anmelden

```bash
lizard login
lizard login --google   # skip the question
```

<span id="log-in-with-a-token" />

<span id="log-in-with-an-api-key" />

### Mit einem API-Key anmelden

Erstelle einen Key mit [`lizard keys create <name>`](/cli/keys) und führe dann aus:

```bash
lizard login --token liz_xxx
# or, to keep the key out of shell history
printf '%s' "$LIZARD_TOKEN" | lizard login --token-stdin
```

<span id="log-in-non-interactively-in-ci" />

### In CI nicht-interaktiv anmelden

In CI oder anderen nicht-interaktiven Umgebungen setze `LIZARD_TOKEN` (oder `LIZARD_API_KEY`) als Umgebungsvariable, statt `login` auszuführen:

```bash
export LIZARD_TOKEN=liz_xxx
```
