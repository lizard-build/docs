# lizard service

Verwalte die Konfiguration, Source und den Lebenszyklus eines einzelnen Service.

<span id="usage" />

## Verwendung

```bash
lizard service set [service] [flags]
lizard service show [service] [flags]
lizard service rename <new-name> [flags]
lizard service delete [service] [flags]
lizard service logs [service] [flags]
lizard service link [name]
```

<span id="subcommands" />

## Unterbefehle

### `lizard service set`

Wende Änderungen an Build/Start/Source/Variablen/Umbenennen auf einen Service an.

| Flag | Beschreibung |
|------|-------------|
| `--set <path>=<value>` | Ein Feld setzen (wiederholbar; benötigt das Argument `service`) |
| `-f, --file <path>` | JSON-Konfigurationsdatei zum Anwenden |
| `--force` | Auch dann überschreiben, wenn es remote geändert wurde |

Häufige Felder sind flach und entsprechen 1:1 dem Wire-Schema: `sourceType`, `repoUrl`, `branch`, `rootDirectory`, `dockerfilePath`, `buildCommand`, `startCommand`, `preDeployCommand`, `watchPatterns`, `containerPort`, `cpuLimit` (zum Beispiel `2000m`), `memoryLimit` (zum Beispiel `2Gi`), `name`. `variables.<KEY>=<value>` setzt ein Service-Secret, genauso wie `lizard secrets set --service`.

`service set` verwendet optimistische Nebenläufigkeit über `configRevision`. Bei einem `409` lies die Konfiguration mit `lizard service show` erneut, gleiche sie ab und versuche es noch einmal — oder übergib `--force`.

### `lizard service show`

Zeige die aktuelle Service-Konfiguration als JSON an. Verwende `-s`, um sie auf einen Service zu beschränken.

### `lizard service rename <new-name>`

Benenne einen Service oder ein Add-on um: den verknüpften oder den, den du mit `-s` übergibst. Verweise verwenden den aktuellen Namen des Ziels, aktualisiere daher nach dem Umbenennen jedes `${{old-name.KEY}}` auf den neuen Namen.

### `lizard service delete`

Lösche einen Service (Alias `rm`). `-y, --yes` überspringt die Bestätigung; ohne TTY ist es erforderlich.

### `lizard service logs`

Streame die Logs eines Service (siehe auch [lizard logs](/cli/logs)).

| Flag | Beschreibung |
|------|-------------|
| `--build` | Die Logs des letzten Builds anzeigen |
| `-n, --tail <n>` | Die letzten N Zeilen ausgeben (bis zu 2000) und beenden; `--tail all` gibt 2000 aus |
| `--page <n>` | Durch ältere Logs blättern, 200 Zeilen pro Seite (1 = neueste) |

### `lizard service link`

Verknüpfe einen Service mit dem aktuellen Verzeichnis.

## Beispiele

<span id="update-a-services-build-and-start-commands" />

### Build- und Start-Befehle eines Service aktualisieren

```bash
lizard service set api --set branch=main --set buildCommand="npm run build"
```

<span id="inspect-a-services-full-configuration" />

### Vollständige Konfiguration eines Service prüfen

```bash
lizard service show -s api
```

<span id="delete-a-service-without-a-confirmation-prompt" />

### Einen Service ohne Bestätigungsabfrage löschen

```bash
lizard service delete -y
```
