# lizard logs

Streamt die Laufzeit-Logs eines Service, die letzten 200 Zeilen gefolgt von einem Live-Tail. Für Laufzeit-Logs ohne `-s` verwendet `logs` nicht den verknüpften Service: In einem TTY wird gefragt, welcher Service angezeigt werden soll, andernfalls werden alle Services im Projekt angezeigt. `--build` und `--restarts` verwenden den verknüpften Service.

<span id="usage" />

## Verwendung

```bash
lizard logs [flags]
```

## Flags

| Flag | Beschreibung |
|------|-------------|
| `--build` | Stattdessen Build-Logs anzeigen |
| `--tail <n>` | Die letzten N Zeilen ausgeben (max. 1000) und beenden |
| `-l, --level <level>` | Nur Laufzeit-Logs mit diesem Level: `error`, `warn`, `info` oder `debug` |
| `--restarts [n]` | Die letzten N Neustarts auflisten (Standard 20) |
| `--restart <id>` | Logs rund um einen bestimmten Neustart (`latest` für den neuesten) |
| `-s, --service <id>` | Service |
| `-p, --project <id>` | Projektname, Slug oder ID |

Mit `--json` ist `lizard logs` kein Stream — es gibt die letzten 200 Zeilen zurück (mit `--tail N` überschreibbar, max. 1000) und beendet sich. Verwende das für Snapshots und Skripting; live streamen nur ohne `--json`.

<span id="examples" />

## Beispiele

<span id="tail-runtime-logs" />

### Laufzeit-Logs tailen

```bash
lizard logs
```

<span id="tail-logs-for-a-specific-service" />

### Logs für einen bestimmten Service tailen

```bash
lizard logs --service api
```

<span id="get-more-history" />

### Mehr Verlauf abrufen

```bash
lizard logs --tail 1000
```

<span id="filter-by-log-level" />

### Nach Log-Level filtern

```bash
lizard logs --level error
```

<span id="check-the-most-recent-build" />

### Den neuesten Build prüfen

```bash
lizard logs --build
```

<span id="inspect-a-crash-or-restart" />

### Einen Absturz oder Neustart untersuchen

```bash
lizard logs --restarts
lizard logs --restart latest
lizard logs --restart <id>
```
