# Managed Redis

Managed Redis auf Lizard (lizard.build) ist ein Redis-Server für Caching, Warteschlangen, Rate Limiting und Pub/Sub. Neue Instanzen laufen standardmäßig mit Redis 8. Fügen Sie eine mit `lizard add redis` hinzu; Ihre Services lesen `REDIS_PRIVATE_URL` oder `REDIS_URL` über einen Verweis wie `${{redis.REDIS_PRIVATE_URL}}`. Die Instanz hat keine Eviction-Richtlinie und keine Append-only-Datei. Speichern Sie darin nur Daten, die sich neu aufbauen lassen. Einen Überblick und die Preise finden Sie auf der [Seite zu Managed Redis](https://lizard.build/redis).

<span id="provision" />

## Bereitstellen

```bash
lizard add redis
```

Das erste Redis-Add-on heißt `redis`, daher funktioniert `${{redis.REDIS_URL}}` sofort.

<span id="environment-variables" />

## Umgebungsvariablen

| Variable | Beschreibung |
|----------|-------------|
| `REDIS_URL` | Vollständige Verbindungszeichenfolge über den öffentlichen Endpunkt (`redis://…`) |
| `REDIS_PRIVATE_URL` | Verbindungszeichenfolge über das private Netzwerk des Projekts (`<name>.lizard.internal:6379`) |

Beide Zeichenfolgen haben die Form `redis://default:<password>@<host>:<port>`. Die private funktioniert nur von Services im selben Projekt aus; siehe [privates Netzwerk](/networking#private-networking).

<span id="connect-a-service" />

## Einen Service verbinden

```bash
lizard secrets set REDIS_URL='${{redis.REDIS_PRIVATE_URL}}' --service api
lizard redeploy --service api
```

Der Verweis wird beim Bereitstellen aufgelöst; Services erhalten die aktuellen Werte des Addons beim nächsten Deploy. Verwenden Sie `REDIS_URL` für Clients außerhalb des Projekts. Jeder Service im Projekt erhält außerdem die öffentliche `REDIS_URL` des Addons mit der niedrigsten Priorität; ein expliziter Verweis überschreibt sie.

<span id="memory-and-durability" />
<span id="does-managed-redis-keep-data" />

## Behält Managed Redis Daten?

Managed Redis speichert nicht jeden Schreibvorgang dauerhaft. Managed Redis hat keine Eviction-Richtlinie und keine Append-only-Datei. Wenn der Arbeitsspeicher ausgeht, startet die Instanz neu, und kürzlich geschriebene Daten können verloren gehen. Verwenden Sie sie für Daten, die sich neu aufbauen lassen, und speichern Sie Daten, die Sie nicht verlieren dürfen, in [Managed Postgres](/addons/postgres).

<span id="common-uses" />

## Häufige Anwendungsfälle

- **Cache** — speichert berechnete Ergebnisse anhand der Anfrage.
- **Warteschlange / Worker**: Kombinieren Sie Redis mit einem [Service im Worker-Modus](/deploy/workers), der Jobs verarbeitet. [Einen Queue-Consumer ausführen](/deploy/workers#run-a-queue-consumer) zeigt das Beispiel redis-worker Schritt für Schritt.
- **Rate Limiting / Sitzungen** — schneller gemeinsam genutzter Status über [Replikate](/deploy/scaling) hinweg.

```bash
# A worker that drains a Redis queue
lizard add -r your-org/worker -n jobs --no-deploy
lizard service set jobs --set containerPort=0
lizard secrets set REDIS_URL='${{redis.REDIS_PRIVATE_URL}}' --service jobs
lizard redeploy --service jobs
```

<span id="browse-keys" />

## Schlüssel durchsuchen

Öffnen Sie den **Redis-Browser** im Dashboard (`lizard open`), um Schlüssel und Werte zu prüfen. Für lokalen Zugriff mit den Verbindungswerten des Addons:

```bash
lizard run --service redis -- sh -c 'exec redis-cli -u "$REDIS_URL"'
```

<span id="grow-storage" />

## Speicher erweitern

```bash
lizard scale --service redis --storage 4096
```
