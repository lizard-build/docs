# Coding-Agents

Lizard ist so konzipiert, dass es sich von KI-Coding-Agents genauso einfach steuern lässt wie von Menschen. Lizard CLI enthält ein **eingebettetes Skill**, das einem Agenten die gesamte Plattform vermittelt, und jeder Befehl ist über `--json` **selbstbeschreibend**, sodass Agents nie raten müssen.

<span id="the-embedded-skill" />

## Das eingebettete Skill

Die maßgebliche Nutzungsanleitung befindet sich in der CLI und ist mit ihr versioniert, sodass sie immer zur installierten Version passt. Ein Agent liest sie mit:

```bash
lizard skills get core --json
```

Dies gibt `{ name, frontmatter, content, … }` zurück — `content` ist die vollständige Anleitung (Build-Pipeline, env-Priorität, Add-ons, Discovery, Exit-Codes). Zugehörige Unterbefehle:

```bash
lizard skills list        # available embedded skills
lizard skills get core    # the core guide
lizard skills path        # where skills are stored
```

Da die Anleitung mit dem Binary gebündelt ist, aktualisiert `lizard upgrade` auch die Anweisungen des Agenten.

<span id="self-describing-commands" />

## Selbstbeschreibende Befehle

Agents ermitteln die exakten Flag-Formen zur Laufzeit, statt sich auf auswendig gelernte Syntax zu verlassen:

```bash
lizard --help --json                # full command tree + exit codes
lizard <cmd> --help --json          # a specific command's schema
```

Siehe [JSON & Automatisierung](/cli/json).

<span id="bootstrapping-in-an-agent" />

## Bootstrapping in einem Agenten

Ein typischer Agent-Ablauf:

1. **Anleitung laden:** `lizard skills get core --json` → `content` lesen.
2. **Authentifizierung optimistisch prüfen:** Führe die Aufgabe des Nutzers aus; bei Exit-Code `2` führe `lizard login` aus, gib die ausgegebene URL an den Nutzer weiter und versuche es dann erneut.
3. **Testphase starten, wenn gewünscht:** Ein neues Konto hat keinen Plan, daher schlägt das erste Erstellen mit HTTP 402 fehl (`code: "PAYMENT_REQUIRED"`, Exit-Code `1`). Führe `lizard billing start --json` aus, gib die Checkout-`url` an den Nutzer weiter und versuche es erneut, sobald eine Karte hinzugefügt wurde.
4. **Kontext vor Änderungen auflösen:** `lizard status` (cwd-Link) und `lizard ps --json` (Services).
5. **Handeln** mithilfe der Anleitung — `add`, `up`, `secrets`, `domain` usw., immer mit `--json`.

Wenn das Binary `lizard` nicht vorhanden ist, installiere es zuerst. Verwende unter macOS oder Linux das Installationsskript:

```bash
curl -fsSL https://lizard.build/install.sh | bash
```

Es braucht weder Node.js noch `sudo` und verlinkt `lizard` in einen Ordner, der bereits im `PATH` liegt. So kann der Agent es in derselben Sitzung aufrufen. Meldet das Skript, dass `lizard` eventuell nicht gefunden wird, rufe stattdessen `~/.lizard/bin/lizard` auf. Führe unter Windows Folgendes in PowerShell aus:

```powershell
irm https://lizard.build/api/cli/install.ps1 | iex
```

Oder installiere es auf jedem System über npm:

```bash
npm install -g @lizard-build/cli
```

<span id="conventions-agents-should-follow" />

## Konventionen, denen Agents folgen sollten

- **Übergib bei nicht interaktiven Aufrufen immer `--json`**.
- **Bestätige destruktive Aktionen** (Service löschen, Add-on entfernen, ein projektweites Secret überschreiben, Prod-Neustart) mit dem Nutzer — die eigenen Prompts der CLI werden nur in einer TTY ausgelöst.
- **Beschränke Secrets standardmäßig auf den Service, der sie verwendet**; reserviere `--global` für nachweislich öffentliche Werte. Siehe [Variablen & Secrets](/variables#scoping).
- **Schreibe Dockerfiles nicht ungefragt** — lizardpack erkennt die meisten Stacks automatisch. Versuche zuerst ein Deployment. Siehe [Build-Pipeline](/concepts/build-pipeline).
- **Verwende `lizard up` nicht, um einen git-basierten Service auf Upload umzustellen** — verwende `service set` + `redeploy`.

<span id="editor-integrations" />

## Editor-Integrationen

Lizard Skill wird als öffentliches Bootstrap verteilt, damit Agents in Editoren und Assistenten es bei Bedarf installieren und laden und dann dieselbe CLI steuern können, die in dieser Dokumentation beschrieben wird. Installiere es einmal für alle deine Agents:

```bash
npx skills add lizard-build/skill -g
```

Es funktioniert mit Claude Code, Cursor, Codex, Copilot, Gemini CLI und anderen Agents, die das Agent-Skills-Format lesen. Für Clients, die MCP sprechen, statt Shell-Befehle auszuführen, verwende [Lizard MCP](#lizard-mcp).

Das gilt auch für KI-IDEs: Sie schreiben und testen eine App, hosten sie aber nicht. Siehe [Deployment einer in Google Antigravity gebauten App](https://lizard.build/blog/google-antigravity-how-to-deploy-your-app-to-production#deploy-from-the-antigravity-chat), wo ein einziger Prompt das gesamte Deployment steuert.

<span id="lizard-mcp" />

## Lizard MCP

Mit Lizard MCP können ChatGPT, Claude und andere MCP-Clients deine Lizard-Projekte verwalten: Services und Add-ons erstellen, neu deployen, Logs und Metriken lesen, Secrets setzen, Replicas skalieren und Domains anhängen. Es ist ein gehosteter Server, der Streamable HTTP spricht unter:

```text
https://employ-woman-g1q2.us-east-1.onlizard.com/mcp
```

Ein Client, der OAuth unterstützt, meldet dich bei der ersten Nutzung an. Andere Clients senden einen `liz_`-API-Key im Header `Authorization: Bearer`; erstelle einen mit `lizard keys create <name>`.

Füge es zu Claude Code hinzu:

```bash
claude mcp add --transport http lizard https://employ-woman-g1q2.us-east-1.onlizard.com/mcp
```

Für Cursor und andere Clients, die per JSON konfiguriert werden:

```json
{
  "mcpServers": {
    "lizard": {
      "url": "https://employ-woman-g1q2.us-east-1.onlizard.com/mcp",
      "headers": { "Authorization": "Bearer liz_your_key" }
    }
  }
}
```

Das Starten der Testphase, das Bezahlen und das Kündigen von Pro erfolgen auf der Billing-Seite. Muss das Konto zahlen, bevor etwas erstellt werden kann, enthält der Tool-Fehler `PAYMENT_REQUIRED` und den Link, der geöffnet werden muss.

<span id="hosting-your-own-mcp-server" />

## Eigenen MCP-Server hosten

Ein Agent, der Lizard CLI verwendet, und eine Anwendung, die MCP bereitstellt, sind getrennte Workflows. Die oben genannten CLI-Befehle stellen keinen MCP-Transport bereit. Um deinen eigenen Server mit Streamable HTTP zu deployen, folge der [Remote-MCP-Anleitung](/guides/deploy-mcp-server).
