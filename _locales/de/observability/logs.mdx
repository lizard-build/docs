# Logs

Lizard erfasst **Laufzeit**-Logs, **Build**-Logs und den Log-Tail rund um **Abstürze**. Streame sie live in deinem Terminal oder sieh sie dir im Dashboard an.

Laufzeit-Logs werden erfasst, solange ein Log-Stream geöffnet ist (`lizard logs` oder die Logs-Seite im Dashboard, plus 60 Sekunden nach dem Schließen), rund um Bereitstellungen und Neustarts sowie während ein Service in einer Crash-Schleife steckt. Beim Öffnen eines Streams werden die letzten 500 Zeilen pro Replik nachgeladen.

<span id="runtime-logs" />

## Laufzeit-Logs

```bash
lizard logs                       # last 200 runtime lines, then live tail
lizard logs --service api         # a specific service
lizard logs --tail 1000           # print the last 1000 lines and exit (max 1000)
lizard logs --level error         # filter by level
```

<span id="behavior-with---json" />

### Verhalten mit `--json`

`lizard logs --json` gibt die letzten 200 Zeilen zurück (überschreibbar mit `--tail N`, maximal 1000) und beendet sich dann. Nutze das für Snapshots und Skripting. Ein Snapshot, der aufgenommen wird, während niemand streamt, kann aktuelle Zeilen verpassen; öffne zuerst einen Stream, wenn du sie brauchst.

Ohne Terminal (Ausgabe in eine Pipe, CI, ein Agent) verhält sich `lizard logs` so, als hättest du `--json` übergeben: Es gibt die letzten 200 Zeilen aus und beendet sich. Um Logs live zu verfolgen, führe es in einem Terminal ohne `--json` aus.

<span id="build-logs" />

## Build-Logs

```bash
lizard logs --build               # the most recent build's logs
```

Das ist das Erste, was du prüfen solltest, wenn ein Bereitstellen fehlschlägt — lies die Logs, behebe die Ursache und dann `lizard redeploy`. Siehe [Build-Pipeline](/concepts/build-pipeline).

<span id="restart--crash-logs" />

## Neustart- / Crash-Logs

Wenn eine Replik abstürzt, speichert Lizard den Log-Tail rund um den Absturz. Manuelle Neustarts und Variablenänderungen erscheinen ebenfalls in der Liste, haben aber keinen Tail.

```bash
lizard logs --restarts            # list recent restarts with their ids
lizard logs --restart <id>        # the log tail of one crash
lizard logs --restart latest      # the most recent event, which may be a manual restart
```

<span id="paging-through-history" />

## Durch den Verlauf blättern

`lizard service logs` unterstützt das Blättern durch ältere Fenster:

```bash
lizard service logs --service api --tail all     # last 2,000 lines (no follow)
lizard service logs --service api --page 2       # older window (implies --tail 200)
```

<span id="dashboard" />

## Dashboard

Das Dashboard (`lizard open`) streamt Laufzeit- und Build-Logs mit Such- und Level-Filtern. Öffne einen Service und klicke in dessen Verlauf auf ein Bereitstellen, um die Build-Ausgabe dieses Bereitstellens zu sehen.
