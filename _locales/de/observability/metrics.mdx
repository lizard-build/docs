# Metriken & Kosten

Verfolge CPU, Arbeitsspeicher, Netzwerk, Festplatte und Kosten eines Service mit [`lizard metrics`](/cli/metrics) oder über das Dashboard.

<span id="view-metrics" />

## Metriken anzeigen

```bash
lizard metrics                    # CPU / memory / network / disk
lizard metrics --service api      # a specific service
lizard metrics --range 24h        # time window: 1h (default), 6h, 24h, 7d, 14d, 30d
lizard metrics --watch            # live-updating view
```

`--range` gilt für einen Service: den verknüpften oder den aus `--service`. Die Projektübersicht (`--all` oder ein Ordner ohne verknüpften Service) zeigt nur aktuelle Werte.

<span id="include-cost" />

## Kosten einbeziehen

```bash
lizard metrics --cost
```

Dieser Befehl zeigt Kosten statt Metriken: den Preis pro Stunde jeder laufenden Ressource, die Nutzung im aktuellen Abrechnungszeitraum (inklusive Egress) und wie viel der in deinem Plan enthaltenen Nutzung du in diesem Zeitraum verbraucht hast (während der 7-tägigen Testphase deren $5, danach den Betrag, den dein Plan jeden Monat enthält: $19, $99 oder $499). Er umfasst das gesamte Projekt, ignoriert `--service` und `--range`, und nur der Workspace-Eigentümer kann die Kosten sehen.

<span id="dashboard" />

## Dashboard

Das Dashboard (`lizard open`) stellt diese als Diagramme in der Ansicht **Metriken** dar, und die Ansicht **Nutzung** schlüsselt Verbrauch und Abrechnung im gesamten Projekt auf. Öffne es mit:

```bash
lizard open
```

<span id="acting-on-what-you-see" />

## Auf Basis der Werte handeln

- Hohe CPU-/Arbeitsspeicherauslastung → hochskalieren: `lizard scale --service api --cpu 2 --memory 2048`.
- Anhaltende Last → Replikate hinzufügen: `lizard scale --service api --replicas 3`. Dein Plan erlaubt 1 Replikat pro Service während der Testphase und 5 nach der ersten bezahlten Rechnung.
- Speicherengpass bei einem Add-on → Speicher erweitern: `lizard scale --service postgres --storage 8192`.

Siehe [Scaling](/deploy/scaling).
