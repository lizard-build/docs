<span id="regions" />

# Regionen

Services und Addons werden in einer Region bereitgestellt. Listen Sie die für Ihr Konto verfügbaren Regionen auf und wählen Sie beim Erstellen eine aus.

<span id="list-regions" />

## Regionen auflisten

```bash
lizard regions
lizard regions --json
```

<span id="choose-a-region" />

## Eine Region auswählen

Übergeben Sie `--region <code>` beim Erstellen eines Service oder Add-on:

```bash
lizard add -r your-org/your-app --region <code>
lizard add postgres --region <code>
lizard up --region <code>          # new services only
```

Projekte haben keine Standardregion. Ohne `--region` erstellt `lizard add` in `us-east-1`, und `lizard up` erstellt einen neuen Service in der Region des API-Servers, der die Anfrage verarbeitet. Übergeben Sie `--region`, um eine Region auszuwählen.

> **Zustandsbehaftete Ressourcen gemeinsam platzieren.** Platzieren Sie einen Service und die Addons, mit denen er kommuniziert (Managed Postgres, Managed Redis, Managed Object Storage), in **derselben Region**, um die Latenz niedrig zu halten und regionenübergreifende Datengebühren zu vermeiden.

<span id="generated-domains" />

## Generierte Domains

Jeder Service erhält eine generierte Domain mit automatischem TLS: `<name>-<suffix>.onlizard.com` für neue Services, während ältere Services `<words>.<region>.onlizard.com` behalten. [Managed Object Storage](/addons/storage) verwendet einen Gateway-Host pro Region: `s3-us-east-1.onlizard.com` für `us-east-1` und `s3-eu-west-1.onlizard.com` für `eu-west-lim-a`. Informationen zum Zuweisen Ihres eigenen Hostnamens finden Sie unter [Networking](/networking).
