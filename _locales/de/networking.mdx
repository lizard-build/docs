# Netzwerk

Jeder Service erhält beim Deployment sofort eine generierte `*.onlizard.com`-Domain mit automatischem TLS, unabhängig von der Region. Füge deinen eigenen Hostnamen hinzu, wenn du live gehen willst.

<span id="generated-domains" />

## Generierte Domains

Die Standarddomain eines Service wird automatisch für dich erstellt, in der Form `<name>-<suffix>.onlizard.com`. Ältere Services behalten `<words>.<region>.onlizard.com`. Zeige sie an:

```bash
lizard domain                    # show the service's current domain
lizard domain generate           # claim a *.onlizard.com subdomain if the service has none
```

`lizard domain generate` gibt die vorhandene generierte Domain zurück, falls es eine gibt, und schlägt fehl, solange der Service eine benutzerdefinierte Domain hat. Dateien, die über [Managed Object Storage](/addons/storage) bereitgestellt werden, verwenden stattdessen einen Gateway-Host: `s3-eu-west-1.onlizard.com` oder `s3-us-east-1.onlizard.com`.

<span id="attach-a-custom-domain" />

## Eine benutzerdefinierte Domain hinzufügen

Der Hostname ist ein **Positionsargument** — es gibt kein `add`-Subcommand:

```bash
lizard domain app.example.com --service web
```

Lizard gibt die zu erstellenden DNS-Einträge zurück (einen `CNAME` für den Hostnamen und einen `TXT`-Eintrag zur Verifizierung). Füge sie bei deinem DNS-Anbieter hinzu.

<span id="verify" />

## Verifizieren

Sobald DNS propagiert wurde, aktiviere die Domain:

```bash
lizard domain verify app.example.com --service web
```

Dabei wird der `TXT`-Eintrag geprüft und die Domain aktiviert. TLS wird automatisch bereitgestellt.

<span id="remove-a-domain" />

## Eine Domain entfernen

```bash
lizard domain delete app.example.com --service web
lizard domain rm app.example.com --service web --yes   # alias, skip confirmation
```

<span id="exposing-a-specific-port" />

<span id="change-the-port-your-service-listens-on" />

## Den Port ändern, auf dem dein Service lauscht

Domains leiten zum Container-Port des Service. Wenn dein Service auf einem anderen Port lauscht, ändere den Container-Port und führe ein Redeploy durch:

```bash
lizard port 8080 --service web
lizard redeploy --service web
```

## Worker-Services

Ein [Service im Worker-Modus](/deploy/workers) (`containerPort=0`) kann weiterhin eine generierte Domain anzeigen, stellt aber nichts bereit — es gibt keinen Listener und keine Load-Balancer-Route. Füge einem Worker keine benutzerdefinierte Domain hinzu.

<span id="private-networking" />

## Privates Netzwerk

Services im selben Projekt erreichen sich unter `<service>.lizard.internal`, auf jedem Port, auf dem der Service lauscht, ohne öffentliche Domain. Verweise auf den Hostnamen mit `${{api.LIZARD_PRIVATE_DOMAIN}}`. Managed Postgres und Managed Redis stellen im selben Netzwerk `DATABASE_PRIVATE_URL` und `REDIS_PRIVATE_URL` bereit. Diese Namen werden nur innerhalb des Projekts aufgelöst.

```bash
lizard secrets set API_URL='http://${{api.LIZARD_PRIVATE_DOMAIN}}:8080' --service web
```

<span id="manage-in-the-dashboard" />

## Im Dashboard verwalten

Öffne einen Service im Dashboard (`lizard open`) und gehe zu **Settings → Networking**. Dort siehst du den Verifizierungs- und DNS-Status jeder Domain und kannst Hostnamen hinzufügen oder entfernen.
