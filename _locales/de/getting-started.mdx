# App-Schnellstart

Dieser Schnellstart stellt in wenigen Minuten eine App auf Lizard (lizard.build) bereit. Installieren Sie Lizard CLI, melden Sie sich an, starten Sie die 7-tägige Pro-Testphase und führen Sie dann `lizard add -r owner/repo` für ein GitHub-Repository oder `lizard up` für einen lokalen Ordner aus. Lizard baut die App auf seinen Servern, ohne lokales Docker, und liefert eine HTTPS-URL auf `onlizard.com`. Ihr Konto wird erstellt, wenn Sie zum ersten Mal `lizard login` ausführen.

<span id="1-install-the-cli" />

## 1. Die CLI installieren

Führen Sie unter macOS oder Linux das Installationsskript aus:

```bash
curl -fsSL https://lizard.build/install.sh | bash
```

Das Skript legt die `lizard`-Binärdatei in `~/.lizard/bin` ab, fügt diesen Ordner in `~/.zshrc` oder `~/.bashrc` zu Ihrem `PATH` hinzu und verlinkt `lizard` in einen Ordner, der bereits in Ihrem `PATH` liegt. So funktioniert es sofort in diesem Terminal. Danach aktualisiert sich die Binärdatei selbst, außer in CI. Meldet das Skript, dass `lizard` eventuell nicht gefunden wird, öffnen Sie ein neues Terminal. Prüfen Sie die Version:

```bash
lizard --version
```

Unter Windows führen Sie in PowerShell diesen Befehl aus:

```powershell
irm https://lizard.build/api/cli/install.ps1 | iex
```

**Oder installieren Sie über npm** (benötigt Node.js 18+):

```bash
npm install -g @lizard-build/cli
```

> **Verwenden Sie nicht `npx`.** Verwenden Sie immer die global installierte `lizard`-Binärdatei. Beim Ausführen von `npx @lizard-build/cli` wird eine Wegwerfkopie geladen, deren Version von der Plattform abweichen kann. Eine npm-Installation aktualisieren Sie später mit `npm install -g @lizard-build/cli@latest`.

> **Berechtigungsfehler (EACCES)?** Verwenden Sie nicht `sudo`. Nutzen Sie das Installationsskript oben, das keine Administratorrechte benötigt, oder setzen Sie für npm ein Präfix in einem Verzeichnis, das Ihrem Benutzer gehört:
> ```bash
> mkdir -p ~/.npm-global
> npm config set prefix ~/.npm-global
> echo 'export PATH=~/.npm-global/bin:$PATH' >> ~/.zshrc && source ~/.zshrc
> npm install -g @lizard-build/cli
> ```

<span id="2-log-in" />

## 2. Anmelden

```bash
lizard login
```

Dadurch wird Ihr Browser zur Authentifizierung geöffnet und Sie kehren nach der Bestätigung in Ihr Terminal zurück. In CI oder anderen nicht interaktiven Umgebungen authentifizieren Sie sich stattdessen mit einem Token:

```bash
export LIZARD_TOKEN=liz_xxx
# or
lizard login --token liz_xxx
```

API-Schlüssel beginnen mit `liz_`. Erstellen Sie einen mit `lizard keys create <name>`. `LIZARD_API_KEY` funktioniert anstelle von `LIZARD_TOKEN`.

Sie können jederzeit prüfen, wer Sie sind:

```bash
lizard whoami
```

<span id="3-start-the-pro-trial" />

## 3. Die Pro-Testphase starten

Ein neues Konto hat keinen Plan, daher gibt das Erstellen von Ressourcen HTTP 402 mit einem Checkout-Link zurück. Starten Sie zuerst die 7-tägige Pro-Testphase:

```bash
lizard billing start
```

Dadurch wird Stripe Checkout geöffnet, wo Sie eine Karte hinzufügen. Die Testphase enthält $5 Nutzung, und es wird nichts abgebucht, bis sie endet. Siehe [Abrechnung](/platform/billing) und [`lizard billing`](/cli/billing).

<span id="4-deploy" />

## 4. Bereitstellen

Wählen Sie den Weg, der zu dem Ort passt, an dem Ihr Code liegt.

<span id="option-a--deploy-a-github-repo-recommended" />

### Option A — Ein GitHub-Repo bereitstellen (empfohlen)

Wenn Ihr Code auf GitHub liegt, erstellen Sie einen Service direkt aus dem Repo. Lizard klont es, erkennt den Stack automatisch, baut ihn und gibt eine Live-URL zurück:

```bash
lizard add -r your-org/your-app
```

Pushes auf den verfolgten Branch lösen ab dann automatisch eine erneute Bereitstellung aus. Bei privaten Repos verbinden Sie zuerst die GitHub App mit [`lizard git`](/cli/git):

```bash
lizard git connect
```

<span id="option-b--deploy-local-code" />

### Option B — Lokalen Code bereitstellen

Laden Sie im Projektverzeichnis den aktuellen Ordner hoch und stellen Sie ihn bereit (berücksichtigt `.gitignore`):

```bash
lizard up
```

Wenn das Verzeichnis noch nicht mit einem Projekt verknüpft ist, erstellt oder wählt `up` es interaktiv aus. In CI verknüpfen Sie es vorher explizit mit `lizard init --name my-project`.

In beiden Fällen erhalten Sie nach Abschluss des Builds eine generierte URL wie `https://your-app-x1y2z.onlizard.com`.

Lizard erkennt die meisten Stacks selbst. Den genauen Build-Befehl, Startbefehl und Port Ihres Frameworks finden Sie in der Anleitung für [Next.js](/framework-guides/nextjs), [React](/framework-guides/react), [Vue](/framework-guides/vue), [Astro](/framework-guides/astro), [SvelteKit](/framework-guides/sveltekit), [Node.js](/framework-guides/nodejs), [Django](/framework-guides/django), [FastAPI](/framework-guides/fastapi), [Rails](/framework-guides/rails) oder [Go](/framework-guides/go). Für eine App mit eigener Dockerfile folgen Sie [Mit einer Dockerfile bereitstellen](/deploy/dockerfile).

<span id="5-watch-it-build-and-run" />

## 5. Build und Ausführung beobachten

```bash
lizard ps          # services in the project, with status + URL
lizard logs        # last runtime log lines
lizard logs --build  # the most recent build's logs
lizard open        # open the project in the dashboard
```

[`lizard open`](/cli/open) zeigt dasselbe Projekt im [Dashboard](/dashboard). Metriken, Kosten und den Bereitstellungsverlauf finden Sie unter [Observability](/observability).

<span id="6-add-a-database-optional" />

## 6. Eine Datenbank hinzufügen (optional)

Stellen Sie Managed Postgres bereit und referenzieren Sie es aus Ihrem Service:

```bash
lizard add postgres
lizard secrets set DATABASE_URL='${{postgres.DATABASE_PRIVATE_URL}}' --service your-app
lizard redeploy --service your-app
```

Die Referenz `${{postgres.DATABASE_PRIVATE_URL}}` wird beim Bereitstellen aufgelöst und verbindet über das private Netzwerk des Projekts. Sie entspricht dem aktuellen Namen des Add-ons, aktualisieren Sie die Referenz also, wenn Sie das Add-on umbenennen. Zugangsdaten rotieren nicht von selbst; ein Service übernimmt neue Werte bei seiner nächsten Bereitstellung. Siehe [Managed Addons](/addons).
