# App-Dashboard

Das Lizard-Dashboard ist die visuelle Ergänzung zu Lizard CLI. Alles, was Sie mit `lizard …` tun, wird hier angezeigt, plus Dinge, die sich mit einer UI einfacher erledigen lassen — Live-Logs, Diagramme, die Datenbrowser, Sandboxes und die Team-/Abrechnungsverwaltung.

Wenn Sie lieber gar kein Terminal öffnen möchten, lassen Sie den Agenten die Befehle ausführen und verfolgen Sie das Ergebnis hier — die Anleitung unter [Bereitstellen einer Antigravity-App in der Produktion](https://lizard.build/blog/google-antigravity-how-to-deploy-your-app-to-production#deploy-from-the-antigravity-chat), bei der ein einziger Prompt das Deployment steuert.

Öffnen Sie es aus der CLI:

```bash
lizard open          # open the current project
lizard docs          # open this documentation
```

## Was im Dashboard enthalten ist

### Services

**Apps & Datenbanken** in der Seitenleiste listet jeden Service mit seinem Status-Badge, der generierten Domain und einem schnellen Zugriff auf Logs, Metriken, Secrets und Einstellungen auf. Erstellen Sie einen Service mit **Neuer Service**: aus einem GitHub-Repository, aus einem Ordner auf Ihrem Computer oder als Datenbank (Managed Postgres, Managed Redis) oder Managed Object Storage.

Im Tab **Einstellungen** eines Service finden Sie außerdem **Serverless**, damit er im Leerlauf schläft ([`lizard sleep`](/cli/sleep)), und **Pausieren**, das ihn stoppt, ohne etwas zu löschen ([`lizard pause`](/cli/pause)).

<span id="deployments" />

### Bereitstellungen

Der Tab **Übersicht** jedes Service listet seine Deploys auf. Öffnen Sie einen, um Status, Auslöser, Quelle, Build-Logs und Neustarts zu sehen. Das ist das visuelle Gegenstück zu `lizard events` + `lizard logs --build`.

### Logs

Live-Streaming von Laufzeit- und Build-Logs mit Such- und Level-Filtern — das UI-Gegenstück zu [`lizard logs`](/observability/logs).

<span id="metrics--usage" />

### Metriken & Nutzung

CPU-, Speicher-, Netzwerk- und Datenträgerdiagramme pro Service sowie die Seite **Nutzung**, die Verbrauch und Kosten im gesamten Projekt aufschlüsselt. Entspricht [`lizard metrics --cost`](/observability/metrics).

<span id="variables--secrets" />

### Variablen & Secrets

Verwalten Sie Secrets auf Service-Ebene im Tab **Secrets** eines Service und Secrets auf Projektebene unter **Globale Secrets**, mit maskierten Werten und Unterstützung für Referenzen (`${{…}}`). Siehe [Variablen & Secrets](/variables).

### Domains

Fügen Sie im Tab **Einstellungen** eines Service benutzerdefinierte Domains hinzu, sehen Sie DNS-Einträge ein und verfolgen Sie den Verifizierungs- und TLS-Status. Siehe [Networking](/networking).

<span id="data-browsers" />

### Datenbrowser

Jedes Managed Addon enthält einen Datenbrowser:

- **Managed Postgres** — ein SQL-/Tabelleneditor zum Abfragen und Bearbeiten von Daten.
- **Managed Redis** — ein Key/Wert-Browser.
- **Managed Object Storage** — ein Bucket- und Objektbrowser mit Upload/Download und Einstellungen für den Bucket-Zugriff.

### Sandboxes

Die Seitenleiste enthält **Sandboxes**, **Volumes** (Persistent Volumes), **Vorlagen** und **Agenten**. Erstellen Sie eine Sandbox mit **Neue Sandbox** auf der Seite Sandboxes; die Zahl daneben zeigt, wie viele Sandboxes im Verhältnis zu Ihrem Limit laufen. In der Testphase bietet der Dialog nur die Größe Small in US-Regionen an. Siehe [Sandboxes quickstart](/sandboxes/quickstart).

### GitHub-Integration

Verbinden Sie GitHub unter **Neuer Service → GitHub-Repository**. Danach öffnet **Zugriff konfigurieren** unter der Repository-Liste die Einstellungen der GitHub-App, in denen Sie wählen, welche Repos Lizard bauen darf. Ein öffentliches Repository lässt sich auch ohne Verbindung über seine eingefügte URL deployen. Siehe [Von GitHub bereitstellen](/deploy/github).

<span id="settings-team--billing" />

### Einstellungen, Team & Abrechnung

**Einstellungen** unten in der Seitenleiste enthält die Projekt- und Workspace-Einstellungen, Einladungen und Rollen für Mitglieder (**Team**) sowie Ihre Kontoeinstellungen. Öffnen Sie **Abrechnung** in den Kontoeinstellungen oder per Klick auf Ihren Plan oben im Dashboard. Die Seite zeigt Ihren Plan, die Testphase, die Nutzung im laufenden Zeitraum, Rechnungen und Ihre Karte. Siehe [Abrechnung](/platform/billing).

## CLI ↔ Dashboard

| Aufgabe | CLI | Dashboard-Ansicht |
|------|-----|----------------|
| Deploy-Verlauf | `lizard events` | Service → Übersicht |
| Logs streamen | `lizard logs` | Logs |
| Ressourcendiagramme | `lizard metrics` | Metriken / Nutzung |
| Secrets verwalten | `lizard secrets` | Secrets / Globale Secrets |
| Benutzerdefinierte Domains | `lizard domain` | Service → Einstellungen |
| Service pausieren oder fortsetzen | `lizard pause` / `lizard resume` | Service → Einstellungen |
| Im Leerlauf schlafen | `lizard sleep` | Service → Einstellungen → Serverless |
| Managed Postgres, Managed Redis oder Managed Object Storage abfragen | `lizard run --service <addon> -- <cmd>` | Datenbrowser |
| Teammitglieder einladen | — | Einstellungen → Team |

Verwenden Sie einfach das, was gerade am besten passt — beide arbeiten mit denselben Projekten und Services.
