# Dashboard

Öffnen Sie ein Projekt und wählen Sie Sandboxes. Wählen Sie beim Erstellen eine Vorlage und eine Region. Die Standardregion ist nicht zwingend die nächste. Die Ressourcenlimits sind fest. Im Dashboard erstellte Sandboxes laufen ohne Ablaufdatum, sofern Sie keine Laufzeit über die API setzen.

## Installation und Anmeldung

Installieren Sie das Lizard SDK und erstellen Sie unter Settings → API keys einen API-Schlüssel. Speichern Sie ihn in `LIZARD_API_KEY`. Jede Sandbox braucht ein Projekt: übergeben Sie `projectId` (Python: `project_id`) oder ID, Slug oder Name über `project`.

## Prüfen und stoppen

Die Detailansicht zeigt Status, Vorlage, Region, gemessene Nutzung und offene Ports. Die aktuelle Kubernetes-Laufzeit stellt keine SSH-Zugangsdaten bereit; daher ist das SSH-Terminal nicht verfügbar. Führen Sie Befehle über SDK oder CLI aus.

Die Abrechnung erfasst CPU, Arbeitsspeicher, Speicherplatz und ausgehenden Traffic. Eine inaktive Sandbox kann weiterhin Arbeitsspeicher und Speicherplatz nutzen. Stoppen Sie sie nach der Aufgabe; gespeicherte Daten verursachen weiter Kosten.

## Vorlagen und Volumes

Der Reiter Templates zeigt Plattformvorlagen für neue Sandboxes, keine Snapshots laufender Sitzungen. Eigene Snapshots, Pause und Resume werden nicht unterstützt. Kill Sandbox stoppt die Sandbox und trennt ihr Volume.

Der Reiter Persistent Volumes verwaltet benannte Volumes und ihre Verbindungen. Hängen Sie ein Volume bei der Erstellung an und schreiben Sie nach `/workspace`. Stoppen Sie die aktuelle Sandbox, bevor Sie das Volume an eine andere hängen.
