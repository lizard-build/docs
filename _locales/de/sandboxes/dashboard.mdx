Im Dashboard erstellen und verwalten Sie Sandboxes ohne Code. Öffnen Sie ein Projekt und wählen Sie Sandboxes. Wählen Sie beim Erstellen eine Vorlage, eine Region und eine Größe: Small, Medium (Standard) oder Large. Die Standardregion ist nicht zwingend die nächste. Wählen Sie unter **Delete after** eine Laufzeit: 15 Minuten, 1 Stunde, 4 Stunden, 1 Tag, 7 Tage oder Never (Standard).

<span id="api-keys" />

## API-Schlüssel

Für den Zugriff aus Code erstellen Sie unter Settings → API keys einen API-Schlüssel und speichern ihn in `LIZARD_API_KEY`. Lizard SDK und die [HTTP-API](/sandboxes/sdk-reference#http-api) lesen ihn; siehe den [Schnellstart](/sandboxes/quickstart).

<span id="inspect-and-stop" />

## Prüfen und stoppen

Die Detailansicht zeigt Status, Vorlage, Region, gemessene Nutzung und offene Ports. Im Kopfbereich stehen die Schaltflächen Pause und Resume, und der Reiter Terminal öffnet eine Shell in einer laufenden Sandbox.

Eine laufende Sandbox wird sekundengenau zum Stundenpreis ihrer Größe abgerechnet, Leerlauf eingeschlossen; eine pausierte nicht. Pausieren oder beenden Sie sie daher, wenn die Aufgabe erledigt ist. Siehe [Speicher und Abrechnung](/sandboxes#storage-and-billing).

<span id="templates-and-volumes" />

## Vorlagen und Volumes

Der Reiter Templates zeigt Plattformvorlagen und die privaten Snapshots Ihres Projekts; aus beiden können Sie eine neue Sandbox starten. Snapshots erstellen Sie mit dem SDK oder der CLI. Kill Sandbox stoppt die Sandbox und trennt ihr Volume.

Volumes erstellen und hängen Sie mit dem SDK oder der CLI an; das Erstellungsformular bietet keine Volume-Option. Der Reiter Persistent Volumes erscheint, sobald ein Projekt ein Volume hat. Er zeigt Größe und angehängte Sandbox jedes Volumes und erlaubt es, Dateien zu durchsuchen, die Größe zu ändern oder das Volume zu löschen. Stoppen Sie die aktuelle Sandbox, bevor Sie das Volume an eine andere hängen.
