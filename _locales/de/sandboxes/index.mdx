Sandboxes auf Lizard (lizard.build) sind isolierte Linux-Maschinen, in denen ein KI-Agent Code und Aufgaben ausführt. Sandboxes unterstützen Firecracker microVMs mit eigenem Kernel; unter den unten beschriebenen Bedingungen laufen sie in Containern. Ihr Code erstellt eine mit Lizard SDK (`@lizard-build/sdk` für TypeScript, `lizard-sdk` für Python), oder Sie führen `lizard sandbox create` in einem Terminal aus; danach führen Sie Befehle aus, lesen und schreiben Dateien und öffnen Ports. In einem Test am 2026-10-12 dauerte es vom Erstellen einer Sandbox bis zur ersten Python-Ausgabe im Median 228 ms.

<span id="when-to-use-sandboxes" />

## Wann Sie Sandboxes verwenden

- **Code ausführen, den ein Modell geschrieben hat.** Geben Sie einem LLM einen [Code Interpreter](/sandboxes/code-interpreter), der den Python-Zustand zwischen Aufrufen behält.
- **Einem Coding-Agenten eine eigene Maschine geben.** Führen Sie [Claude Code](/sandboxes/guides/claude-code), [OpenCode](/sandboxes/guides/opencode) oder Codex in einer Sandbox statt auf Ihrem Laptop aus. Verbinden Sie seine Zugangsdaten mit [`lizard agents`](/cli/agents) und senden Sie Prompts mit [`lizard sandbox prompt`](/cli/sandbox#coding-agents).
- **Ansehen, was der Agent gebaut hat.** Starten Sie einen Dev-Server und öffnen Sie ihn über eine [private Vorschau-URL](/sandboxes/preview-urls).
- **Mehrere Wege gleichzeitig ausprobieren.** Forken Sie eine laufende Sandbox einschließlich Arbeitsspeicher und Prozessen, oder stellen Sie viele Kopien aus einem Snapshot wieder her.
- **Einen Browser steuern.** Die Vorlage `desktop` führt einen grafischen Desktop aus, den ein Agent mit Screenshots, Klicks und Tasten steuert.

Für einen Webservice oder Worker, der dauerhaft laufen soll, stellen Sie stattdessen eine App bereit; siehe den [App-Schnellstart](/getting-started).

<span id="how-fast-does-a-sandbox-start" />

## Wie schnell startet eine Sandbox?

In einem Test am 2026-10-12 dauerte es vom Erstellen einer Sandbox bis zur ersten Python-Ausgabe im Median 228 ms; das 95. Perzentil lag bei 310 ms. Der Test lief 300-mal aus der Region US East von Railway gegen `us-east-1`, mit der Vorlage `base` und der Größe Small. Ergebnisse desselben Tests für E2B, Daytona und Modal stehen auf der [Sandboxes-Seite](https://lizard.build/sandboxes).

## Laufzeit und Vorlagen

Wählen Sie eine Vorlage aus dem aktuellen Katalog: `base`, `interpreter`, `codex`, `claude`, `opencode`, `pi`, `prime` oder `desktop`. Die Verfügbarkeit hängt von Region und Pool-Kapazität ab. `interpreter` enthält Python und gängige Datenbibliotheken. `desktop` führt einen grafischen Desktop aus, den Sie mit `sandbox.desktop` oder `lizard sandbox desktop` steuern. Prüfen Sie die Werkzeugversionen in der Sandbox. Die öffentliche CLI bietet keinen Upload eigener Vorlagen.

Lizard Sandboxes unterstützen Firecracker microVMs mit eigenem Kernel. Eine Sandbox kann auch in einem Kubernetes-Container laufen, der den Kernel des Hosts teilt: mit einem älteren Pod-Volume oder Pod-Snapshot, wenn Konto- oder Regionseinstellungen Container wählen oder nach bestimmten Fehlern beim Firecracker-Start. Prüfen Sie `getInfo().runtime`, bevor Sie Code ausführen, der einen eigenen Kernel braucht. Geben Sie dem Agenten nur die Zugangsdaten und Rechte, die er für seine Aufgabe braucht. Ein Firecracker-Snapshot oder Firecracker-Volume benötigt Firecracker. Schlägt der Start fehl, endet die Erstellung mit einem Fehler, ohne auf einen Container zu wechseln.

<span id="lifecycle" />

## Lebenszyklus

Erstellen Sie eine Sandbox, führen Sie Befehle aus und rufen Sie danach `kill` auf. `connect` verbindet mit einer bestehenden Sandbox, ohne ihren Zustand zu ändern; eine pausierte oder gestoppte Sandbox wird dadurch nicht fortgesetzt. Pause, Fortsetzen, Snapshot und Restore sind verfügbar; siehe [Pause, Fortsetzen und Snapshots](/sandboxes/quickstart#pause-and-resume). `fork` kopiert eine laufende Sandbox einschließlich Arbeitsspeicher und Prozessen; bei angehängtem Volume gibt es 409 zurück, bei einer Sandbox, die als Pod läuft, 501. Dateiüberwachung ist noch nicht verfügbar. `lizard sandbox ssh` öffnet eine interaktive Shell mit Ihren CLI-Zugangsdaten. Zugriff über das SSH-Protokoll gibt es nicht, daher funktionieren SSH-Clients, `scp` und Portweiterleitung nicht.

```text
create -> running -> stopped (kill / expiration)
running -> paused -> running (pause / resume)
running -> new sandboxes (fork)
snapshot -> new sandbox (restore)
```

<span id="resources-and-timeouts" />

## Ressourcen und Laufzeit

Wählen Sie beim Erstellen eine Größe: Small (2 vCPU / 4 GB), Medium (4 vCPU / 8 GB, Standard) oder Large (8 vCPU / 16 GB). Siehe [Größen und Preise](/platform/limits#sandbox-sizes). Geben Sie bei Bedarf eine Region an; ein Katalogeintrag garantiert keine freie Kapazität.

SDK und CLI setzen standardmäßig eine Laufzeit von fünf Minuten. Die direkte API und das Dashboard setzen standardmäßig kein Ablaufdatum. Geben Sie die Laufzeit ausdrücklich an: `timeoutMs: 0` bei der Erstellung deaktiviert den Ablauf; ein positiver Wert setzt eine Frist. `setTimeout` akzeptiert 1000–2147483647 ms, nicht null. Befehle verlängern die Frist nicht. Dies ist kein Leerlauf-Timer.

<span id="storage-and-billing" />

## Speicher und Abrechnung

Dateien und laufende Prozesse bleiben verfügbar, solange die Sandbox läuft. Nach dem Stopp kann eine spätere Sandbox nur Dateien auf einem angehängten Volume aus Persistent Volumes unter `/workspace` wiederverwenden. Ohne Volume ist `/workspace` temporär. Ein Volume hängt jeweils an einer Sandbox und liegt auf einem einzelnen Knoten. Exportieren Sie Dateien, die einen Knotenausfall überstehen müssen.

Jede Größe hat einen festen Stundenpreis, sekundengenau abgerechnet, solange die Sandbox läuft, Leerlauf eingeschlossen. Ausgehender Traffic ist bis [2 TB pro Konto](/platform/limits#sandbox-egress) in rollierenden 30 Tagen enthalten. Eine aus einem Snapshot wiederhergestellte Sandbox läuft mit Größe und Preis ihrer Quelle; eine aus einem Pod-Snapshot wiederhergestellte wird nach gemessener Nutzung abgerechnet. Eine erfolgreiche Pause stoppt die Rechenkosten; Persistent Volumes werden getrennt abgerechnet, solange Sie die Daten behalten. Pausieren oder beenden Sie eine Sandbox, wenn die Aufgabe erledigt ist. Die Tarife für jede Ressource stehen auf der [Abrechnungsseite](/platform/billing) und unter [Preise](https://lizard.build/pricing).
