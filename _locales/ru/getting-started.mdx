# Быстрый старт приложения

По этому руководству вы развернёте приложение на Lizard (lizard.build) за несколько минут. Установите Lizard CLI: установщик сам выполнит вход и предложит 7-дневный пробный период Pro. Затем выполните `lizard add -r owner/repo` для репозитория GitHub или `lizard up` для локальной папки. Lizard собирает приложение на своих серверах, без локального Docker, и дает ему HTTPS-адрес на `onlizard.com`. Аккаунт создается при первом входе.

<span id="1-install-the-cli" />

## 1. Установите CLI

На macOS или Linux запустите скрипт установки:

```bash
curl -fsSL https://lizard.build/install.sh | bash
```

Скрипт кладет бинарный файл `lizard` в `~/.lizard/bin`, добавляет эту папку в `PATH` через `~/.zshrc` или `~/.bashrc` и создает ссылку на `lizard` в папке, которая уже есть в `PATH`, поэтому команда сразу работает в этом терминале. Дальше бинарный файл обновляется сам, кроме CI. Если скрипт пишет, что `lizard` может быть не найден, откройте новый терминал. Проверьте версию:

```bash
lizard --version
```

На Windows выполните в PowerShell:

```powershell
irm https://lizard.build/api/cli/install.ps1 | iex
```

Оба скрипта установки в конце запускают [`lizard login`](/cli/login), который выполняет шаги 2 и 3 за вас: входит в систему и предлагает пробный период Pro. Чтобы пропустить это, задайте `LIZARD_NO_LOGIN=1`; в CI скрипты пропускают этот шаг сами.

**Или установите из npm** (нужен Node.js 20 или новее). Установка из npm не выполняет вход, поэтому переходите к шагу 2:

```bash
npm install -g @lizard-build/cli
```

> **Не используйте `npx`.** Всегда используйте глобально установленный бинарный файл `lizard`. Запуск `npx @lizard-build/cli` загружает временную копию, версия которой может отличаться от платформы. Чтобы позже обновить установку из npm, выполните `npm install -g @lizard-build/cli@latest`.

> **Ошибки прав доступа (EACCES)?** Не используйте `sudo`. Используйте скрипт установки выше, ему не нужны права администратора, или укажите npm пользовательский префикс:
> ```bash
> mkdir -p ~/.npm-global
> npm config set prefix ~/.npm-global
> echo 'export PATH=~/.npm-global/bin:$PATH' >> ~/.zshrc && source ~/.zshrc
> npm install -g @lizard-build/cli
> ```

<span id="2-log-in" />

## 2. Войдите в систему

Пропустите этот шаг, если скрипт установки уже выполнил вход. Иначе выполните:

```bash
lizard login
```

Команда спросит, как вы входите, через GitHub или Google, откроет эту страницу в браузере и дождется подтверждения. Если аккаунт у вас уже есть, выберите способ, которым регистрировались: другой способ создаст второй, пустой аккаунт, если у них нет общего подтвержденного email. Флаг `--github` или `--google` пропускает вопрос. На машине, где вход уже выполнен, `lizard login` просто покажет аккаунт, поэтому команду можно запускать повторно.

`lizard login` можно и не запускать: любая команда, запущенная в терминале, сначала так же выполнит вход, а потом продолжит работу.

В CI или других неинтерактивных средах аутентифицируйтесь с токеном:

```bash
export LIZARD_TOKEN=liz_xxx
# or
lizard login --token liz_xxx
```

API-ключи начинаются с `liz_`. Создайте ключ командой `lizard keys create <name>`. `LIZARD_API_KEY` работает вместо `LIZARD_TOKEN`. `lizard login --token-stdin` читает ключ из канала (pipe), поэтому он не попадает в историю команд.

Проверьте, под кем вы вошли, в любой момент:

```bash
lizard whoami
```

<span id="3-start-the-pro-trial" />

## 3. Начните пробный период Pro

У нового аккаунта нет тарифа, а для деплоя он нужен. Сразу после входа `lizard login` предлагает 7-дневный пробный период Pro. Если согласиться, откроется Stripe Checkout, где вы добавляете карту. Пробный период включает использование ресурсов на $5. До его окончания Lizard ничего не списывает. Аккаунту, у которого пробный период уже был, вместо него предлагается Pro за $19 в месяц.

Если вы отказались, начните его позже:

```bash
lizard billing start
```

Пока тариф не подключен, при создании чего-либо возвращается HTTP 402 со ссылкой на Checkout. См. [Оплата](/platform/billing) и [`lizard billing`](/cli/billing).

<span id="4-deploy" />

## 4. Разверните

Выберите способ в зависимости от того, где находится ваш код.

<span id="option-a--deploy-a-github-repo-recommended" />

### Вариант А — Развертывание репозитория GitHub (рекомендуется)

Если ваш код на GitHub, создайте сервис прямо из репозитория. Lizard клонирует его, определит стек и запустит первую сборку:

```bash
lizard add -r your-org/your-app
```

Команда завершается, как только сервис создан, а сборка идет дальше. Как следить за ней и узнать URL, показано в [шаге 5](#5-watch-it-build-and-run).

Для приватного репозитория, а также чтобы пуши в отслеживаемую ветку переразвертывали приложение, сначала подключите Lizard GitHub App через [`lizard git`](/cli/git):

```bash
lizard git connect
```

<span id="option-b--deploy-local-code" />

### Вариант Б — Развертывание локального кода

Изнутри директории проекта загрузите и разверните текущую папку (с учетом `.gitignore`):

```bash
lizard up
```

В первый раз команда спросит имя сервиса; по умолчанию это имя папки. Затем она следит за сборкой и выводит URL вроде `https://your-app-x1y2z.onlizard.com`, когда приложение заработает.

Если папка еще не привязана к проекту, `lizard add` и `lizard up` используют ваш проект по умолчанию и сообщают об этом. Это самый старый проект в вашем личном рабочем пространстве; новый аккаунт получает такой проект при регистрации. `lizard up` также привязывает к нему папку, поэтому следующий `lizard up` обновит тот же сервис. Чтобы развернуть приложение в другом проекте, сначала выполните `lizard init --name my-project`. Делайте так и в CI, чтобы деплой попал туда, куда вы ждете.

Lizard сам определяет большинство стеков. Команды сборки и запуска, а также порт для вашего фреймворка см. в руководстве по [Next.js](/framework-guides/nextjs), [React](/framework-guides/react), [Vue](/framework-guides/vue), [Astro](/framework-guides/astro), [SvelteKit](/framework-guides/sveltekit), [Node.js](/framework-guides/nodejs), [Django](/framework-guides/django), [FastAPI](/framework-guides/fastapi), [Rails](/framework-guides/rails) или [Go](/framework-guides/go). Приложение со своим Dockerfile разворачивайте по руководству [Развертывание с Dockerfile](/deploy/dockerfile).

<span id="5-watch-it-build-and-run" />

## 5. Следите за сборкой и работой

```bash
lizard ps               # services in the project, with status + URL
lizard logs             # stream runtime logs (Ctrl+C to stop)
lizard logs --tail 100  # print the last 100 lines and exit
lizard logs --build     # the most recent build's logs
lizard open             # open the project in the dashboard
```

[`lizard open`](/cli/open) показывает тот же проект в [дашборде](/dashboard). Метрики, стоимость и историю деплоев см. в разделе [Наблюдаемость](/observability).

<span id="6-add-a-database-optional" />

## 6. Добавьте базу данных (по желанию)

Создайте Managed Postgres. Каждый сервис проекта получит его публичный `DATABASE_URL` при следующем развертывании; чтобы подключаться через приватную сеть, сошлитесь на базу из своего сервиса:

```bash
lizard add postgres
lizard secrets set DATABASE_URL='${{postgres.DATABASE_PRIVATE_URL}}' --service your-app
lizard redeploy --service your-app
```

Ссылка `${{postgres.DATABASE_PRIVATE_URL}}` разрешается во время развертывания и подключается через приватную сеть проекта. Она соответствует текущему имени аддона, поэтому обновите ссылку, если переименуете аддон. Учетные данные сами не ротируются; сервис получает новые значения при следующем развертывании. См. [Управляемые аддоны](/addons).

## Стоимость хостинга

Pro стоит $19 в месяц, и в него входят $19 на использование. В тарифы Pro 5x ($99) и Pro 20x ($499) входит использование на сумму их цены, и лимиты у них выше. Расход сверх этого оплачивается по модели pay as you go по опубликованным ставкам. Пробный период есть только у Pro: 7 дней и $5 на использование; чтобы начать его, вы добавляете карту. См. [Оплата](/platform/billing) и [цены](https://lizard.build/pricing), а перед развёртыванием проверьте свои [лимиты](/platform/limits).
