# lizard ssh

Выполняет команду внутри контейнера работающего сервиса, передавая его вывод и возвращая удалённый код выхода.

## run vs. ssh

`lizard run` и `lizard ssh` выполняют команду в контексте сервиса, но запускают её в разных местах — понимайте, какой именно вам нужен.

| Команда | Где запускается | Использовать для |
|---------|----------------|------------------|
| `lizard run` | **Локально**, с внедрёнными секретами проекта и сервиса | Миграции, сид-скрипты, локальные инструменты, требующие продакшн-конфигурации |
| `lizard ssh` | **Внутри работающего контейнера сервиса** | Инспекция живого контейнера, разовые удалённые команды, отладка |

`lizard run` показывает вашу локальную внедрённую копию окружения, которая обычно совпадает с продакшн — но `lizard ssh` авторитетен для того, что видит живой контейнер на самом деле.

<span id="usage" />

## Использование

```bash
lizard ssh --service <name> -- <command>
```

<span id="examples" />

## Примеры

<span id="inspect-the-environment-the-running-app-sees" />

### Инспектировать окружение, которое видит работающее приложение

```bash
lizard ssh --service api -- env
```

<span id="list-files-in-the-deployed-image" />

### Посмотреть файлы в развёрнутом образе

```bash
lizard ssh --service api -- ls -la /app
```

<span id="check-the-os-in-the-container" />

### Узнать ОС в контейнере

```bash
lizard ssh --service api -- cat /etc/os-release
```

<span id="confirm-a-secret-landed-in-the-live-container" />

### Подтвердить, что секрет попал в живой контейнер

```bash
lizard ssh --service api -- env | grep DATABASE_URL
```
