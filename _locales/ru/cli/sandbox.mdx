# lizard sandbox

Создавайте Sandboxes и управляйте ими из терминала: [Sandboxes](/sandboxes). Псевдоним: `lizard sb`.

<span id="usage" />

## Использование

```bash
lizard sandbox create [flags]
lizard sandbox list [flags]
lizard sandbox exec <id> -- <command>
lizard sandbox ssh <id>
lizard sandbox fork <id> [flags]
lizard sandbox rm <id> [flags]
```

Каждый sandbox принадлежит проекту: тому, который вы укажете через `-p`, иначе тому, который связан с текущей директорией, иначе проекту по умолчанию вашего аккаунта (самому старому проекту в вашем личном рабочем пространстве).

<span id="subcommands" />

## Подкоманды

### `lizard sandbox create`

Создаёт sandbox и выводит его ID.

| Флаг | Описание |
|------|-------------|
| `-t, --template <name>` | Шаблон (по умолчанию `base`). Доступные шаблоны: `base`, `interpreter`, `codex`, `desktop`, `desktop-camoufox` (только US East), `opencode`, `pi`, `prime`, `claude`. Сервер проверяет список региона |
| `-s, --size <size>` | `small`, `medium` (по умолчанию; в пробном периоде `small`) или `large` |
| `--timeout <ms>` | Время жизни в миллисекундах (по умолчанию `300000`, пять минут); `0` отключает истечение срока |
| `--region <code>` | Регион, в котором создаётся sandbox |
| `--snapshot <id>` | Запустить из сохранённого снапшота; нельзя сочетать с `--size` |
| `--volume <name-or-id>` | Подключить [Persistent Volume](/cli/volume) |
| `--with-token [key]` | Выполнить вход в `lizard` внутри sandbox с новым ключом, который ограничен проектом sandbox и удаляется вместе с sandbox. Ключ `liz_`, который вы передаёте, а без значения — ключ `liz_`, с которым вы запускаете команду, только авторизует запрос; при входе через браузер такого ключа нет. В шаблоне `base` нет `lizard` |
| `-p, --project <id>` | Проект (по умолчанию связанный, иначе ваш проект по умолчанию) |

Lizard тарифицирует каждый размер посекундно по фиксированной ставке, пока sandbox работает, включая простой. В цену входят локальный диск и [2 ТБ исходящего трафика на аккаунт за последние 30 дней](/platform/limits#sandbox-egress). Успешная пауза останавливает оплату вычислений; хранение в Persistent Volumes оплачивается по [тарифу тома](/cli/volume), в том числе после отключения тома от sandbox.

| Размер | vCPU | Память | Диск | Цена |
|------|------|--------|------|-------|
| `small` | 2 | 4 GiB | 5 GB | $0.0162/h |
| `medium` | 4 | 8 GiB | 20 GB | $0.0324/h |
| `large` | 8 | 16 GiB | 50 GB | $0.0648/h |

Ключ, который устанавливает `--with-token`, может прочитать любой процесс в sandbox и пользоваться им в проекте sandbox, пока sandbox не удалят.

Пока не начался пробный период или план Pro, `create` возвращает HTTP 402 со ссылкой на Checkout; выполните `lizard billing start`. Во время пробного периода можно одновременно запускать 5 sandbox, а после первого оплаченного счёта — 100. Приостановленные sandbox не учитываются. В пробном периоде sandbox должен быть размера `small` и в регионе США; другой размер или регион возвращает HTTP 403. См. [Лимиты](/platform/limits#sandbox-account-limits).

### `lizard sandbox list`

Выводит список sandbox в связанном проекте (псевдоним `ls`).

| Флаг | Описание |
|------|-------------|
| `-p, --project <id>` | Вывести список для указанного проекта |
| `--all` | Вывести все sandbox во всех ваших рабочих пространствах |

### `lizard sandbox rm <id>`

Удаляет sandbox (псевдонимы `delete` и `kill`).

| Флаг | Описание |
|------|-------------|
| `-y, --yes` | Пропустить подтверждение |

### `lizard sandbox timeout <id> <ms>`

Задаёт новое время жизни, отсчитываемое с текущего момента, в миллисекундах (не меньше `1000`). Это не таймер простоя: выполнение команд его не сбрасывает.

### `lizard sandbox exec <id> -- <command>`

Запускает одну команду внутри sandbox через `sh -c`, передаёт её вывод потоком и завершается с её кодом выхода.

<span id="sandbox-ssh" />

### `lizard sandbox ssh <id>`

Открывает интерактивную оболочку в работающем sandbox (псевдоним `shell`). Используется ваш вход в Lizard, поэтому настраивать SSH-ключи не нужно; ограниченный API-ключ получает доступ только к sandbox в своей области. Ctrl-C, стрелки и автодополнение по Tab передаются в sandbox. Чтобы выйти, введите `exit` или нажмите Ctrl-D.

Нужен интерактивный терминал; в скрипте используйте `lizard sandbox exec`. Это не протокол SSH, поэтому SSH-клиенты, `scp` и проброс портов не работают.

### `lizard sandbox expose <id> <port>`

Назначает порту в sandbox HTTPS-адрес. Порт приватный: запросам нужен токен доступа sandbox — в заголовке `X-Lizard-Access-Token` или в query-параметре `lizard_token`, который уже есть в выведенном URL. Запросы без него получают HTTP 401. С `--json` результат дополнительно содержит `hostname` и `accessToken`.

`lizard sandbox unexpose <id> <port>` удаляет URL.

### `lizard sandbox desktop <id>`

Запускает графический рабочий стол sandbox, созданного с `-t desktop`, и выводит URL для браузера и URL только для просмотра. Относитесь к обеим ссылкам как к паролям.

| Флаг | Описание |
|------|-------------|
| `--view-only` | Вывести или открыть только URL для просмотра |
| `--resolution <WxH>` | Размер экрана, от 640x480 до 3840x2160 |
| `--open` | Открыть рабочий стол в браузере |
| `--status` | Показать состояние рабочего стола и URL, не запуская его |
| `--stop` | Остановить рабочий стол и удалить его URL |

<span id="sandbox-vnc" />

### `lizard sandbox vnc <id>`

Подключает VNC-приложение (macOS Screen Sharing, TigerVNC, RealVNC) к рабочему столу sandbox, созданного с `-t desktop`. У рабочего стола нет публичного VNC-порта, поэтому CLI слушает `localhost` и передаёт каждое подключение в sandbox через защищённый WebSocket. При необходимости он запускает рабочий стол, выводит адрес и VNC-пароль и работает до нажатия Ctrl-C.

| Флаг | Описание |
|------|-------------|
| `--port <port>` | Локальный порт (по умолчанию `5900`; если он занят — следующий свободный) |
| `--view-only` | Использовать пароль только для просмотра: наблюдение без управления |
| `--open` | Открыть адрес в VNC-приложении (`vnc://`, Screen Sharing в macOS) |

<span id="pause-resume-and-snapshots" />

### Пауза, возобновление и снапшоты

| Команда | Что делает |
|---------|--------------|
| `lizard sandbox pause <id>` | Сохраняет память и процессы sandbox, затем ставит его на паузу. Успешная пауза останавливает оплату вычислений; хранение в Persistent Volumes оплачивается отдельно |
| `lizard sandbox pause <id> --fast` | Пауза примерно за секунду с сохранением только файлов: память не сохраняется, запущенные процессы завершаются, а `resume` загружает песочницу заново с её файлами |
| `lizard sandbox resume <id>` | Снова запускает приостановленный sandbox с сохранёнными памятью и файлами |
| `lizard sandbox snapshot <id> --name <name>` | Сохраняет работающий sandbox вместе с памятью и файлами как снапшот, который принадлежит вам. `--scope` задаёт, где его можно восстановить: `workspace` (по умолчанию) — в любом проекте рабочего пространства sandbox, `user` — в любом проекте любого из ваших рабочих пространств, `project` — только в его собственном проекте |
| `lizard sandbox restore <snapshot-id>` | Запускает новый sandbox из снапшота в регионе снапшота. `-p <project>` выбирает проект (по умолчанию — проект тома, иначе проект самого снапшота), `--volume <name-or-id>` монтирует том в `/workspace`, `--timeout <ms>` задаёт время жизни (по умолчанию `300000`) |
| `lizard sandbox snapshots` | Выводит список снапшотов, сделанных в проекте (`-p` для другого проекта, `--mine` для всех снапшотов, которые сделали вы) |
| `lizard sandbox snapshot-scope <snapshot-id> <scope>` | Меняет, где можно восстановить сделанный вами снапшот: `user`, `workspace` или `project` |
| `lizard sandbox snapshot-rm <snapshot-id>` | Удаляет снапшот (псевдоним `snapshot-delete`, `-y` пропускает подтверждение) |

`pause`, `resume` и `snapshot` ждут завершения работы; укажите `--no-wait`, чтобы вернуться сразу после постановки в очередь. О том, что сохраняет каждый шаг, см. [Пауза, возобновление и снапшоты](/sandboxes/quickstart#pause-and-resume).

Снапшот sandbox с подключённым томом содержит копию файлов тома на момент создания снапшота. Каждое восстановление получает эту копию и не принимает `--volume`, а любой, кто может восстановить снапшот, может прочитать эти файлы. `--volume` работает только со снапшотом sandbox, у которого не было тома, и том должен быть в регионе снапшота.

<span id="sandbox-fork" />

### `lizard sandbox fork <id>`

Запускает живые копии работающего sandbox. Lizard ненадолго ставит sandbox на паузу, один раз снимает его память, процессы и файлы и запускает из этого снимка каждую копию. Исходный sandbox продолжает работать с тем же ID и временем жизни. Подготовьте один sandbox (инструменты установлены, приложение загружено), затем сделайте форк, чтобы раздать работу копиям без повторной настройки.

| Флаг | Описание |
|------|-------------|
| `-n, --count <n>` | Сколько копий запустить, от 1 до 100 (по умолчанию `1`) |
| `--timeout <ms>` | Время жизни каждой копии, не меньше `1000`; по умолчанию — время жизни исходного sandbox |

Каждая копия — это запуск sandbox: она учитывается в [лимитах запущенных sandbox и запусков](/platform/limits#sandbox-account-limits), работает с размером исходного sandbox и оплачивается по этому размеру. С `--json` вывод содержит по одной записи на копию: `{"sandbox": {...}}` или `{"error": "..."}`. Если хотя бы одна копия не запустилась, команда завершается с кодом `1`, а запущенные копии работают, пока вы их не удалите. Нельзя сделать форк sandbox на паузе или sandbox с подключённым томом (HTTP 409).

### `lizard sandbox files`

| Команда | Что делает |
|---------|--------------|
| `lizard sandbox files ls <id> [path]` | Выводит содержимое директории (по умолчанию `/`) |
| `lizard sandbox files cat <id> <path>` | Выводит содержимое файла |
| `lizard sandbox files put <id> <local> <remote>` | Загружает локальный файл |
| `lizard sandbox files get <id> <remote> <local>` | Скачивает файл |
| `lizard sandbox files rm <id> <path>` | Удаляет файл или директорию |

<span id="coding-agents" />

### Coding-агенты

Запускайте coding-агента внутри sandbox со своими учётными данными. Сначала подключите их через [`lizard agents`](/cli/agents). Создайте sandbox из шаблона агента (`codex`, `claude`, `opencode`, `pi` или `prime`); в шаблоне `base` нет Node.js, и агенты в нём работать не могут.

`lizard sandbox prompt <id> <prompt...>` отправляет промпт и передаёт потоком действия агента.

| Флаг | Описание |
|------|-------------|
| `--agent <name>` | `codex` (по умолчанию), `claude`, `pi`, `opencode` или `prime` |
| `-c, --conversation <id>` | Продолжить эту беседу |
| `--new` | Начать новую беседу |
| `-m, --model <model>` | Используемая модель |
| `--effort <level>` | Усилие рассуждения: `minimal`, `low`, `medium`, `high` или `xhigh` |
| `--cwd <dir>` | Рабочая директория в sandbox (по умолчанию `/workspace`) |
| `-v, --verbose` | Также выводить вывод команд |
| `--no-wait` | Вернуться сразу после принятия промпта |

Ctrl-C прекращает наблюдение; агент продолжает работу. `lizard sandbox interrupt <id> [-c <conversation>]` останавливает его текущий ход. `lizard sandbox conversations <id>` выводит список бесед, сначала новые.

<span id="examples" />

## Примеры

<span id="create-a-sandbox-and-run-a-command" />

### Создание sandbox и запуск команды

```bash
lizard sandbox create --size small --timeout 600000
lizard sandbox exec genuine-toddler-jasj -- python3 -c "print(1 + 1)"
```

<span id="open-a-shell" />

### Открытие оболочки

```bash
lizard sandbox ssh genuine-toddler-jasj
```

<span id="attach-a-persistent-volume" />

### Подключение Persistent Volume

```bash
lizard volume create agent-workdir --size 10
lizard sandbox create --volume agent-workdir
```

<span id="serve-a-port" />

### Публикация порта

```bash
lizard sandbox exec genuine-toddler-jasj -- sh -c "nohup python3 -m http.server 3000 --bind 0.0.0.0 >/tmp/http.log 2>&1 &"
lizard sandbox expose genuine-toddler-jasj 3000
```

<span id="use-a-desktop-from-a-vnc-app" />

### Использование рабочего стола через VNC-приложение

```bash
lizard sandbox create -t desktop
lizard sandbox vnc genuine-toddler-jasj --open
```

<span id="run-codex-in-a-sandbox" />

### Запуск Codex в sandbox

```bash
lizard agents login chatgpt
lizard sandbox create -t codex
lizard sandbox prompt genuine-toddler-jasj "add a health check endpoint and test it"
```

<span id="save-and-restore-a-sandbox" />

### Сохранение и восстановление sandbox

```bash
lizard sandbox snapshot genuine-toddler-jasj --name my-app
lizard sandbox snapshots --mine                     # find the snapshot ID
lizard sandbox restore <snapshot-id> -p other-project
```

<span id="fork-a-prepared-sandbox" />

### Форк подготовленного sandbox

```bash
lizard sandbox fork genuine-toddler-jasj -n 8 --json   # 8 copies with the same memory and files
lizard sandbox rm <copy-id>                            # delete a copy when its work is done
```
