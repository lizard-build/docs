# Справочник по CLI

Lizard CLI (`lizard`) развёртывает приложения, базы данных и Sandboxes в Lizard (lizard.build) и управляет ими из терминала, CI или агента для разработки. Эта страница охватывает установку, глобальные флаги, коды выхода и автоматическое обнаружение. У каждой команды есть собственная справочная страница в боковой панели. См. [`lizard up`](/cli/up), [`lizard service`](/cli/service), [`lizard secrets`](/cli/secrets), [`lizard pause` и `lizard resume`](/cli/pause), [`lizard sleep`](/cli/sleep) и остальные. Обзор возможностей CLI смотрите на [странице Lizard CLI](https://lizard.build/cli).

> Справочник написан для Lizard CLI **v4.0.65**. Выполните `lizard <cmd> --help --json` для получения точной схемы, соответствующей версии, для любой команды.

## Установка и обновление

```bash
curl -fsSL https://lizard.build/install.sh | bash   # macOS and Linux
lizard --version
lizard upgrade            # update to the latest version
lizard upgrade --check    # check without installing
```

Флаги описаны на странице [`lizard upgrade`](/cli/upgrade).

На Windows выполните `irm https://lizard.build/api/cli/install.ps1 | iex` в PowerShell. С Node.js можно установить CLI из npm: `npm install -g @lizard-build/cli`.

На macOS и Linux бинарный файл из скрипта установки также сам обновляется в фоне, не чаще раза в 6 часов и только при запуске в интерактивном терминале. Проверка пропускается, если задана переменная `CI` или `LIZARD_NO_UPDATE=1`. Агенты, скрипты и задачи CI в фоне не обновляются, поэтому запускайте там `lizard upgrade` сами. Бинарный файл для Windows сам не обновляется: запустите установщик снова. Для установки из npm `lizard upgrade` сам запускает npm и выводит команду npm, только если это не удалось.

Всегда используйте глобально установленный бинарный файл `lizard` — **не** `npx`. См. [Быстрый старт](/getting-started#1-install-the-cli) для исправления ошибок доступа.

## Аутентификация

```bash
lizard login                  # GitHub or Google in the browser, then the Pro trial offer
lizard login --token liz_xxx  # API key auth
lizard logout
lizard whoami                 # current user, workspace, linked project
```

Справочные страницы: [`lizard login`](/cli/login), [`lizard logout`](/cli/logout), [`lizard whoami`](/cli/whoami) и [`lizard workspace`](/cli/workspace): список и создание рабочих областей.

API-ключи начинаются с `liz_`. Создайте ключ командой [`lizard keys create <name>`](/cli/keys). В CI задайте `LIZARD_TOKEN` (или `LIZARD_API_KEY`) в переменных окружения вместо запуска `login`.

## Глобальные флаги

| Флаг | Описание |
|------|-------------|
| `-V, --version` | Вывести версию CLI |
| `--json` | Машинно-читаемый вывод. Комбинируйте с `--help`, чтобы выгрузить схему команды |

Большинство команд также принимают `-p, --project` и `-s, --service` для обращения к конкретному ресурсу вместо связанного. В папке без привязки они используют ваш проект по умолчанию. Команды `init`, `link` и `project` также принимают `-w, --workspace`. У `lizard add` нет `--project`: команда использует связанный проект или проект по умолчанию.

<span id="exit-codes" />

## Коды выхода

| Код | Значение | Что делать |
|------|---------|------------|
| `0` | успех | продолжать |
| `1` | общая ошибка | прочитать сообщение |
| `2` | аутентификация (401/403) | выполните `lizard login` |
| `3` | не найдено (404): в API нет ничего с таким ID | проверьте ID с помощью `lizard ps` / `lizard project list` |
| `4` | таймаут (408/504) | повторите попытку |
| `5` | отменено пользователем | остановиться |

Имя проекта или сервиса, которому ничего не соответствует, даёт код `1`, а не `3`. `lizard run`, `lizard sandbox exec` и `lizard sandbox ssh` завершаются с кодом самой команды (`127`, если `run` не находит команду), так что `2` от них может прийти от вашей команды, а не от аутентификации.

## Автоматическое обнаружение

CLI является самодокументирующимся. Чтобы увидеть полное дерево команд, глобальные флаги и коды выхода:

```bash
lizard --help --json
```

Для точных аргументов и опций любой команды или подкоманды:

```bash
lizard <cmd> --help --json
lizard <cmd> <sub> --help --json     # e.g. lizard service set --help --json
```

Это всегда отражает вашу установленную версию — используйте это вместо угадывания формата флагов. Так агент узнаёт CLI без обучения на нём: см. [развёртывание из Claude Code](https://lizard.build/blog/deploy-from-claude-code).

## Конфигурация и состояние

- CLI хранит аутентификацию и ссылку на проект для каждой директории в `~/.lizard/config.json`. Ссылка действует только для этой директории, не для её поддиректорий. В директории без ссылки команды для проектов используют проект по умолчанию вашего аккаунта — самый старый проект в вашей личной рабочей области.
- [`lizard status`](/cli/status) показывает ссылку на рабочую область/проект/сервис текущей директории (аутентификация не требуется). [`lizard link`](/cli/link) задаёт эту ссылку, [`lizard unlink`](/cli/unlink) удаляет её, а [`lizard project`](/cli/project) выводит список проектов, создаёт, ставит на паузу, возобновляет и удаляет их.
- [`lizard config apply`](/cli/config) применяет файл `lizard-config.json` к проекту (используйте `--dry-run` для предварительного просмотра).
- [`lizard open`](/cli/open) открывает связанный проект в дашборде, а [`lizard docs`](/cli/docs) открывает эту документацию.

<span id="environment-variables" />

## Переменные окружения

| Переменная | Эффект |
|----------|--------|
| `LIZARD_TOKEN` | API-ключ или токен, используемые вместо сохранённого входа |
| `LIZARD_API_KEY` | То же, что `LIZARD_TOKEN` |
| `LIZARD_API_URL` | Базовый URL API (по умолчанию `https://lizard.build`) |
| `LIZARD_HOME` | Хранить состояние CLI в `$LIZARD_HOME/.lizard` вместо `~/.lizard` |
| `LIZARD_NO_UPDATE` | Отключить фоновое самообновление |
| `CI` | Также отключает фоновое самообновление |
| `LIZARD_SKILLS_DIR` | Читать навыки из этой директории вместо встроенных в CLI |

## Тома Sandbox

Управляйте [Persistent Volumes](/sandboxes/volumes) по имени в пределах проекта. Полный справочник: [`lizard volume`](/cli/volume) и [`lizard sandbox`](/cli/sandbox).

```bash
lizard volume create agent-workdir --size 10 --project proj_123
lizard volume list --project proj_123
lizard volume resize agent-workdir --size 20 --project proj_123
lizard sandbox create --volume agent-workdir --project proj_123
```

Имена уникальны в проекте: строчные латинские буквы, цифры и дефисы, до 64 символов; первая и последняя позиция — буква или цифра. Новые тома принимают целые GB от 1 до 50, по умолчанию 5. CLI читает текущие ограничения сервера перед созданием тома и учитывает изменения настроек. Существующие тома большего размера сохраняют размер.

После отключения тома команда `lizard volume rm agent-workdir --project proj_123` удаляет его и данные. `volume list` показывает имена; `--json` включает сгенерированные ID.
