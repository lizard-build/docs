# lizard service

Управление конфигурацией, источником и жизненным циклом отдельного сервиса.

<span id="usage" />

## Использование

```bash
lizard service set [service] [flags]
lizard service show [service] [flags]
lizard service rename <new-name> [flags]
lizard service delete [service] [flags]
lizard service logs [service] [flags]
lizard service link [name]
```

<span id="subcommands" />

## Подкоманды

### `lizard service set`

Применяет изменения параметров сборки, запуска, источника, переменных или переименования к сервису.

| Флаг | Описание |
|------|-------------|
| `--set <path>=<value>` | Установить поле (можно указывать несколько раз; требуется аргумент `service`) |
| `-f, --file <path>` | JSON-файл конфигурации для применения |
| `--force` | Перезаписать даже при наличии удалённых изменений |

Общие поля плоские и отображаются 1:1 в схему API: `sourceType`, `repoUrl`, `branch`, `rootDirectory`, `dockerfilePath`, `buildCommand`, `startCommand`, `preDeployCommand`, `watchPatterns`, `containerPort`, `cpuLimit` (например, `2000m`), `memoryLimit` (например, `2Gi`), `name`. `variables.<KEY>=<value>` задаёт секрет сервиса, так же как `lizard secrets set --service`.

`service set` использует оптимистичную блокировку через `configRevision`. При `409` перечитайте конфигурацию с помощью `lizard service show`, приведите в соответствие и повторите попытку — или передайте `--force`.

### `lizard service show`

Показывает текущую конфигурацию сервиса в JSON. Используйте `-s`, чтобы ограничить вывод одним сервисом.

### `lizard service rename <new-name>`

Переименовывает сервис или аддон: связанный или тот, который вы указали через `-s`. Ссылки используют текущее имя целевого объекта, поэтому после переименования обновите все `${{old-name.KEY}}` на новое имя.

### `lizard service delete`

Удаляет сервис (псевдоним `rm`). `-y, --yes` пропускает запрос подтверждения; без TTY этот флаг обязателен.

### `lizard service logs`

Выводит логи сервиса в потоке (см. также [lizard logs](/cli/logs)).

| Флаг | Описание |
|------|-------------|
| `--build` | Показать логи последней сборки |
| `-n, --tail <n>` | Вывести последние N строк (до 2000) и завершить работу; `--tail all` выводит 2000 |
| `--page <n>` | Постраничный просмотр более старых логов, по 200 строк на страницу (1 = самые свежие) |

### `lizard service link`

Связывает сервис с текущей директорией.

## Примеры

<span id="update-a-services-build-and-start-commands" />

### Обновление команд сборки и запуска сервиса

```bash
lizard service set api --set branch=main --set buildCommand="npm run build"
```

<span id="inspect-a-services-full-configuration" />

### Просмотр полной конфигурации сервиса

```bash
lizard service show -s api
```

<span id="delete-a-service-without-a-confirmation-prompt" />

### Удаление сервиса без запроса подтверждения

```bash
lizard service delete -y
```
