# lizard workspace

Создание, просмотр, пауза и удаление рабочих пространств, их лимиты и цены перепродажи.

<span id="usage" />

## Использование

```bash
lizard workspace list
lizard workspace create <name>
lizard workspace pause <name-or-id>
lizard workspace resume <name-or-id>
lizard workspace limits <name-or-id> [flags]
lizard workspace resale-pricing <name-or-id> [flags]
lizard workspace rm <name-or-id> [flags]
```

<span id="subcommands" />

## Подкоманды

<span id="lizard-workspace-list" />

### `lizard workspace list`

Список рабочих пространств, в которых вы состоите, с вашей ролью и количеством проектов (псевдоним `ls`).

<span id="lizard-workspace-create-name" />

### `lizard workspace create <name>`

Создайте рабочее пространство. Добавлять в него проекты можно командой `lizard project create <name> --workspace <slug>`.

<span id="lizard-workspace-pause-name-or-id" />

### `lizard workspace pause <name-or-id>`

Ставит на паузу каждое приложение, каждую базу данных и каждый работающий sandbox во всех проектах рабочего пространства. Приложения и базы данных сохраняют URL, пароли, настройки и данные; бакеты Managed Object Storage на паузу не ставятся. Поставить на паузу всё рабочее пространство может только владелец. Чтобы поставить на паузу один сервис или проект, см. [lizard pause](/cli/pause).

<span id="lizard-workspace-resume-name-or-id" />

### `lizard workspace resume <name-or-id>`

Снова запускает все приложения и базы данных рабочего пространства, которые кто-то поставил на паузу вручную, и sandboxes, которые остановила `lizard workspace pause`. Приложения и базы, которые Lizard поставил на паузу из-за оплаты, остаются на паузе, пока с оплатой не наладится. Это может только владелец, и рабочему пространству нужен запас в пределах его [лимитов](/platform/limits#workspace-limits).

<span id="lizard-workspace-limits-name-or-id" />

### `lizard workspace limits <name-or-id>`

Показывает, сколько может использовать рабочее пространство и сколько использует сейчас. С флагами задаёт его лимиты. Задаёт их только владелец, войдя через браузер или с API-ключом без ограничения области; прочитать их может любой участник. Каждый флаг принимает `none`, чтобы снять этот лимит.

| Флаг | Описание |
|------|----------|
| `--sandboxes <n>` | Sandboxes, запущенные одновременно |
| `--cpu <vcpus>` | vCPU, которые могут использовать приложения и базы данных рабочего пространства |
| `--memory <size>` | Память, которую могут использовать приложения и базы данных рабочего пространства, например `4GB` или `512MB` |
| `--disk <size>` | Диск, который могут занимать его базы данных и тома, например `20GB` или `1TB` |

CPU и память считаются по тому, что приложения и базы данных используют сейчас, а не по их настройкам. На лимите в рабочем пространстве не запускается ничего нового, а работающие сервисы продолжают работать. На лимите диска нельзя создать новый том или базу данных и увеличить том; уже записанные данные остаются. Ошибки описаны в разделе [лимиты рабочего пространства](/platform/limits#workspace-limits).

<span id="lizard-workspace-resale-pricing-name-or-id" />

### `lizard workspace resale-pricing <name-or-id>`

Показывает или задаёт цены, которые видят API-ключи, ограниченные этим рабочим пространством или одним из его проектов (псевдоним `resale`). Каждая цена — это кратное цены Lizard, от 1 до 100. Ваш собственный счёт, ваша панель и ключи без ограничения области видят цены Lizard. Видеть и задавать их может только владелец, войдя через браузер или с API-ключом без ограничения области.

| Флаг | Описание |
|------|----------|
| `--all <x>` | Задать это кратное для всех ресурсов |
| `--cpu <x>` | CPU |
| `--memory <x>` | Память |
| `--storage <x>` | Тома |
| `--egress <x>` | Исходящий трафик |
| `--object-storage <x>` | Managed Object Storage |
| `--sandbox <x>` | Почасовые цены sandbox |
| `--off` | Выключить цены перепродажи; ключи с ограниченной областью снова видят цены Lizard |

<span id="lizard-workspace-rm-name-or-id" />

### `lizard workspace rm <name-or-id>`

Удаляет рабочее пространство (псевдоним `delete`). Удалить его может только владелец, и только если в нём не осталось проектов, sandboxes и томов. Проекты в корзине не считаются: они удаляются вместе с рабочим пространством, у которого своей корзины нет. API-ключ с ограниченной областью не может удалить рабочее пространство. Личное рабочее пространство удалить нельзя.

| Флаг | Описание |
|------|----------|
| `-y, --yes` | Пропустить подтверждение |

<span id="examples" />

## Примеры

<span id="list-your-workspaces" />

### Список ваших рабочих пространств

```bash
lizard workspace list
```

<span id="create-a-workspace" />

### Создание рабочего пространства

```bash
lizard workspace create my-team
```

<span id="cap-a-workspace" />

### Ограничение рабочего пространства

```bash
lizard workspace limits my-team                                   # show limits and current use
lizard workspace limits my-team --sandboxes 5 --cpu 2 --memory 4GB --disk 20GB
lizard workspace limits my-team --cpu none                        # remove one limit
```

<span id="set-resale-prices" />

### Цены перепродажи

```bash
lizard workspace resale-pricing my-team --all 3                   # every price x3
lizard workspace resale-pricing my-team --off
```

<span id="delete-an-empty-workspace" />

### Удаление пустого рабочего пространства

```bash
lizard workspace rm my-team --yes
```
