# lizard keys

Создавайте, просматривайте и удаляйте API-ключи. Псевдоним: `lizard apikey`.

<span id="usage" />

## Использование

```bash
lizard keys create <name> [flags]
lizard keys list
lizard keys rm <name-or-id> [flags]
```

API-ключи начинаются с `liz_`. Используйте ключ там, где нельзя войти через браузер:

- `LIZARD_TOKEN` или `LIZARD_API_KEY` для CLI в CI
- `lizard login --token liz_…` на машине
- `LIZARD_API_KEY` для [Lizard SDK](/sandboxes/sdk-reference)
- `lizard sandbox create --with-token liz_…`, чтобы войти в `lizard` внутри sandbox; см. [ключи в sandbox](#sign-in-lizard-inside-a-sandbox)

<span id="subcommands" />

## Подкоманды

### `lizard keys create <name>`

Создаёт ключ и выводит его один раз. Скопируйте его сразу: Lizard больше его не покажет. Ключ без области действия имеет полный доступ ко всем рабочим пространствам и проектам, которые вам доступны. Ограничьте его с помощью этих флагов, каждый из них можно повторять:

| Флаг | Описание |
|------|-------------|
| `-p, --project <id>` | Ограничить ключ этим проектом (имя, slug или ID) |
| `-w, --workspace <id>` | Ограничить ключ этим рабочим пространством (имя, slug или ID) |

Ключ с ограниченной областью работает только в своих проектах или рабочих пространствах. Он не может:

- видеть оплату, тариф, карты и расход всего аккаунта
- создавать, просматривать и удалять API-ключи, поэтому `lizard keys` с ним не работает
- создавать рабочее пространство, переименовывать или удалять своё, менять лимиты рабочего пространства и цены перепродажи
- видеть участников рабочих пространств и проектов и управлять ими
- направлять сервис на приватный репозиторий GitHub, если из него ещё не собирается приложение в его области

Если вы вошли с ключом с ограниченной областью, [`lizard whoami`](/cli/whoami) показывает области ключа, а не аккаунт, которому он принадлежит. Если владелец рабочего пространства задал [цены перепродажи](/cli/workspace#lizard-workspace-resale-pricing-name-or-id), ключ видит эти цены.

### `lizard keys list`

Выводит список ваших ключей с коротким превью, областью действия, временем создания и последнего использования (псевдоним `ls`). Превью — это не начало ключа, поэтому сопоставляйте ключи по имени или ID.

### `lizard keys rm <name-or-id>`

Удаляет ключ (псевдоним `delete`). Если у двух ключей одинаковое имя, удаляйте по ID.

| Флаг | Описание |
|------|-------------|
| `-y, --yes` | Пропустить подтверждение |

<span id="examples" />

## Примеры

<span id="create-a-key-for-ci" />

### Создание ключа для CI

```bash
lizard keys create github-actions --project my-project
```

Сохраните выведенный ключ как секрет CI с именем `LIZARD_TOKEN`.

<span id="sign-in-lizard-inside-a-sandbox" />

### Вход в `lizard` внутри sandbox

```bash
lizard sandbox create --with-token liz_xxx
```

Sandbox получает собственный новый ключ, ограниченный проектом sandbox и удаляемый вместе с ним. В `lizard keys list` он виден как `sandbox-session:<sandbox-id>`. Переданный ключ `liz_` только подтверждает запрос и в sandbox не попадает. С `--with-token` без значения CLI берёт ключ, с которым вы вошли; это должен быть ключ `liz_`.

<span id="delete-a-key" />

### Удаление ключа

```bash
lizard keys rm github-actions --yes
```
