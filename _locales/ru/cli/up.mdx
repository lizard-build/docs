# lizard up

Загружает текущую директорию и выполняет деплой.

<span id="usage" />

## Использование

```bash
lizard up [path] [flags]
```

`up` упаковывает рабочую директорию (или `path`) в tarball, отправляет на узлы сборки и выполняет деплой. Принудительно включает `sourceType=upload` для целевого сервиса, стримит логи сборки через SSE и выводит живой URL по завершении.

Если текущая директория ещё не привязана к проекту, `up` сначала запускает `init`. В интерактивном TTY это происходит в диалоговом режиме; в неинтерактивном окружении (CI) проект **не** создаётся автоматически — команда выдаёт ошибку и просит выполнить `lizard init --name <project>` (или передать в `up` флаг `--project <project>`), чтобы опечатка не привела к созданию пустого проекта.

<span id="flags" />

## Флаги

| Флаг | Описание |
|------|-------------|
| `-s, --service <name>` | Нацелиться на существующий сервис |
| `-p, --project <id>` | Имя, slug или ID проекта |
| `--build-command <cmd>` | Переопределить команду сборки |
| `--start-command <cmd>` | Переопределить команду запуска |
| `--pre-deploy-command <cmd>` | Выполняется перед командой запуска при каждом старте контейнера (каждая реплика, каждый перезапуск). Требует команды запуска; сделайте её безопасной для многократного выполнения |
| `--port <number>` | Порт контейнера (`0` = режим воркера). Новые сервисы по умолчанию используют `3000`, если порт не задан через `EXPOSE` в Dockerfile |
| `--region <code>` | Регион для нового сервиса; для существующего игнорируется |
| `-d, --detach` | Запустить деплой и выйти без стриминга логов |
| `-c, --ci` | Только стримить логи сборки и выйти, когда сборка завершится |
| `--no-gitignore` | Загрузить всё, игнорируя `.gitignore` |

<span id="subcommands" />

## Подкоманды

### `lizard up status <app-id>`

Показывает статус сервиса, его URL и статус последней сборки. Передайте ID сервиса, который выводит `up --detach`.

## Примеры

<span id="deploy-the-current-directory" />

### Деплой текущей директории

```bash
lizard up
```

<span id="deploy-to-a-specific-service-with-a-custom-start-command-and-port" />

### Деплой в конкретный сервис с пользовательской командой запуска и портом

Сначала создайте именованный сервис командой `lizard add --service api`, если он ещё не существует.

```bash
lizard up --service api --start-command "node server.js" --port 8080
```

<span id="deploy-headlessly-in-ci" />

### Безголовый деплой в CI

```bash
export LIZARD_TOKEN=liz_xxx
lizard init --name my-project
lizard add --service api
lizard up --ci --service api
```

Пропустите `lizard add`, если сервис уже существует. Неудачная сборка или деплой завершается с кодом `1`. С `--ci` код выхода отражает только сборку, поэтому перед тем, как считать релиз завершённым, проверьте `lizard ps --json`. `--detach` завершается с кодом `0`, как только загрузка принята. См. [настройку фреймворка](/framework-guides#prepare-the-project).
