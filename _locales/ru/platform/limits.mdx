# Лимиты

Лимиты зависят от ресурса, тарифа и аккаунта. Настройка на реплику — это не общий объём, доступный сервису или аккаунту. Проверьте текущий тариф и результат запроса на создание или масштабирование перед подбором размера рабочей нагрузки.

<span id="applications" />

## Приложения

| Настройка | Область | Что проверить |
|---|---|---|
| CPU и память | Каждая реплика | У трёх реплик с потолком 2 vCPU / 2 GiB общий настроенный потолок составляет 6 vCPU / 6 GiB. Это не прогноз использования. |
| Количество реплик | Сервис и тариф | Лимит задаёт тариф: 1 на приложение в пробном периоде Pro, 5 в Pro после первого оплаченного счёта и в Enterprise. API принимает не больше 10, и этого можно достичь только через переопределение для аккаунта. |
| Общий лимит ресурсов аккаунта | Владелец аккаунта | Второй проект не обязательно создаёт вторую квоту. Уточните действующий лимит аккаунта перед планированием крупного развёртывания. |
| Режим воркера | Сервис | `containerPort=0` работает без приёма HTTP-запросов и публичного маршрута балансировщика нагрузки. |
| Пользовательский домен | Имя хоста | Поддомены с wildcard не принимаются. Используйте конкретное имя хоста и пройдите проверки владения и DNS. |

Sandboxes запускают короткие команды и задачи агентов как microVM Firecracker, каждая со своим ядром. Sandbox, к которому подключён существующий persistent volume на базе pod, или который восстановлен из более старого снимка pod, работает как pod Kubernetes с runtime runc и использует ядро хоста. Какой вариант используется, показывает `getInfo().runtime` в Lizard SDK. Ограничивайте доступ к ключам и сети при запуске недоверенного кода.

### Лимиты аккаунта

Эти лимиты ограничивают, сколько песочниц аккаунт запускает одновременно и как быстро стартует новые. Они зависят от тарифа владельца аккаунта. Лимиты пробного периода действуют до первого оплаченного счёта, см. [Оплата](/platform/billing#limits).

| Тариф | Одновременно запущено | Запусков в минуту | В час | В день |
|---|---|---|---|---|
| Пробный период Pro | 5 | 6 | 30 | 100 |
| Pro | 100 | 24 | 120 | 400 |
| Enterprise | Индивидуально | Индивидуально | Индивидуально | Индивидуально |

- Лимиты считаются по владельцу аккаунта, по всем его рабочим пространствам. Второе рабочее пространство не даёт второй лимит.
- Запущенной считается песочница, которая работает или возобновляется. Приостановленная не считается; чтобы возобновить её, нужен свободный слот.
- Запуск — это новая песочница. Возобновление запуском не считается. Создание, которое не удалось по вине Lizard, не учитывается.
- При превышении лимита создание и возобновление возвращают HTTP 429 с `code`, равным `SANDBOX_LIMIT_REACHED` (одновременно запущенные) или `SANDBOX_RATE_LIMITED` (запуски). Отказ по частоте запусков содержит заголовок `Retry-After`.
- В панели рядом с **New Sandbox** показано, сколько песочниц запущено и каков ваш лимит. Если нужно больше 100 одновременно, напишите нам про Enterprise.

<span id="sandbox-egress" />

### Исходящий трафик

Исходящий трафик песочниц включён до 2 ТБ на аккаунт за скользящие 30 дней, по всем песочницам аккаунта. Сверх этого песочницы аккаунта теряют исходящую сеть, пока сумма за 30 дней снова не опустится ниже 2 ТБ. Дополнительная плата не взимается.

<span id="sandbox-lifetime" />

### Время жизни

| Параметр | Текущий API создания |
|---|---|
| Шаблоны | `base`, `interpreter`, `codex`, `desktop`, `opencode`, `pi`, `prime`, `claude` |
| Время жизни по умолчанию в Raw API | `timeoutMs: 0`, без срока |
| Время жизни по умолчанию в Lizard SDK | 300000 мс, пять минут |
| Диапазон явного времени жизни | Целые миллисекунды от 0 до 2147483647 |
| Изменение времени жизни | Не меньше 1000 мс; это не таймер простоя |
| Подключение Persistent Volume | Одна песочница за раз, на узле тома |

SDK и CLI по умолчанию задают время жизни пять минут. Raw API и панель по умолчанию не задают срок. Указывайте время жизни явно: `timeoutMs: 0` при создании отключает срок; положительное значение задаёт крайний срок. `setTimeout` принимает 1000–2147483647 мс, но не ноль. Команды не продлевают срок. Это не таймер простоя.

Создайте sandbox, выполните команды и вызовите `kill`. `connect` подключается к существующему sandbox и не меняет его состояние, поэтому не возобновляет приостановленный или остановленный sandbox. Пауза, возобновление, snapshot и restore доступны; см. [Пауза, возобновление и снимки](/sandboxes/quickstart#pause-and-resume). Fork (`sandbox.fork({ count })`) работает на sandbox Firecracker; при подключённом томе он возвращает HTTP 409, а для sandbox на pod — HTTP 501. `lizard sandbox ssh` открывает интерактивную оболочку с учётными данными CLI. Доступа по протоколу SSH нет, поэтому SSH-клиенты, `scp` и проброс портов не работают.

## Регионы

Текущие настроенные регионы включают US East (Virginia), `us-east-1`, и EU West (Limburg), `eu-west-lim-a`. Наличие региона в каталоге не гарантирует доступную вместимость для каждого ресурса. Проверяйте выбор региона при создании ресурса; Песочница с существующим томом должен запускаться на узле этого тома.

<span id="before-increasing-scale" />

## Перед увеличением масштаба

Проверьте активный тариф, настройки на реплику, лимит аккаунта, лимит подключений к базе данных и рост хранилища вместе. Используйте [масштабирование](/deploy/scaling), [метрики](/observability/metrics) и [цены](https://lizard.build/pricing), чтобы сравнить настроенную вместимость с измеренным использованием.
