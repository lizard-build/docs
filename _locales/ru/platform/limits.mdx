# Лимиты

В Lizard (lizard.build) приложение запускает до 5 реплик на сервис после первого оплаченного счёта Pro и 1 в пробном периоде. На Pro одновременно работают до 100 sandbox, а запускать можно до 24 в минуту; в пробном периоде доступны до 5 одновременно. Доступны размеры sandbox от Small (2 vCPU / 4 GB) до Large (8 vCPU / 16 GB), а исходящий трафик sandbox входит в цену до 2 TB на аккаунт за скользящие 30 дней. Владелец рабочего пространства может также задать [лимиты рабочего пространства](#workspace-limits) для одного из них. Лимиты зависят от ресурса, тарифа и аккаунта: настройки одной реплики не определяют общий объём ресурсов сервиса или аккаунта. Проверьте текущий тариф и результат запроса на создание или масштабирование перед выбором ресурсов для приложения.

## Приложения

| Настройка | Область | Что проверить |
|---|---|---|
| CPU и память | Каждая реплика | У трёх реплик с потолком 2 vCPU / 2 GiB общий настроенный потолок составляет 6 vCPU / 6 GiB. Это не прогноз использования. |
| Количество реплик | Сервис и тариф | Лимит задаёт тариф: 1 на приложение в пробном периоде Pro, 5 в Pro после первого оплаченного счёта и в Enterprise. API принимает не больше 10, и этого можно достичь только через переопределение для аккаунта. |
| Общий лимит ресурсов аккаунта | Владелец аккаунта | Второй проект не обязательно создаёт вторую квоту. Уточните действующий лимит аккаунта перед планированием крупного развёртывания. |
| Режим воркера | Сервис | `containerPort=0` работает без приёма HTTP-запросов и публичного маршрута балансировщика нагрузки. |
| Пользовательский домен | Имя хоста | Поддомены с wildcard не принимаются. Используйте конкретное имя хоста и пройдите проверки владения и DNS. |

## Sandboxes

[Sandboxes](/sandboxes) запускают команды и задачи агентов в Firecracker microVM; см. [runtime и изоляция](/sandboxes#runtime-and-templates). Лимиты ниже действуют для каждого sandbox аккаунта.

<span id="sandbox-sizes" />

### Размеры

| Размер | CPU и память | Диск (`/workspace`) | Цена, пока работает |
|---|---|---|---|
| Small | 2 vCPU / 4 ГБ | 5 ГБ | $0.0162 в час |
| Medium (по умолчанию) | 4 vCPU / 8 ГБ | 20 ГБ | $0.0324 в час |
| Large | 8 vCPU / 16 ГБ | 50 ГБ | $0.0648 в час |

CPU и память включены в цену. Persistent Volumes оплачиваются отдельно.

<span id="sandbox-account-limits" />

### Лимиты аккаунта

Эти лимиты ограничивают, сколько песочниц аккаунт запускает одновременно и как быстро стартует новые. Они зависят от тарифа владельца аккаунта. Лимиты пробного периода действуют до первого оплаченного счёта, см. [Оплата](/platform/billing#limits).

| Тариф | Одновременно запущено | Запусков в минуту | В час | В день |
|---|---|---|---|---|
| Пробный период Pro | 5 | 6 | 30 | 100 |
| Pro | 100 | 24 | 120 | 400 |
| Enterprise | На рабочее пространство, по вашему договору | 120 на пользователя | Без лимита | Без лимита |

- Лимиты считаются по владельцу аккаунта, по всем его рабочим пространствам. Второе рабочее пространство не даёт второй лимит.
- В Pro и в пробном периоде запущенной считается песочница, которая работает или возобновляется. Приостановленная не считается; чтобы возобновить её, нужен свободный слот.
- Запуском считается создание новой песочницы. Возобновление запуском не считается. Создание, которое не удалось по вине Lizard, не учитывается.
- При превышении лимита создание и возобновление возвращают HTTP 429 с `code`, равным `SANDBOX_LIMIT_REACHED` (одновременно запущенные) или `SANDBOX_RATE_LIMITED` (запуски). Отказ по частоте запусков содержит заголовок `Retry-After`.
- У Enterprise нет фиксированного лимита на число песочниц, запущенных одновременно. Договор каждого клиента задаёт лимит на рабочее пространство. В него входят все песочницы: запущенные, приостановленные и упавшие. Сверх него создание и fork возвращают HTTP 429 с `code`, равным `SANDBOX_LIMIT_REACHED`. Один пользователь может создать до 120 песочниц в минуту в каждом регионе.
- В панели рядом с **New Sandbox** показано, сколько песочниц запущено и каков ваш лимит. Если нужно больше 100 одновременно, напишите нам про Enterprise.

<span id="sandbox-egress" />

### Исходящий трафик

У исходящего трафика sandbox нет отдельной платы за ГБ. В цену входят 2 ТБ на аккаунт за последние 30 дней, суммарно для всех sandbox аккаунта. Если вашей задаче нужно больше, свяжитесь с нами до её запуска.

<span id="sandbox-lifetime" />

### Время жизни

| Параметр | Текущий API создания |
|---|---|
| Шаблоны | `base`, `interpreter`, `codex`, `desktop`, `opencode`, `pi`, `prime`, `claude`; `desktop-camoufox` только в US East |
| Время жизни по умолчанию в Raw API | `timeoutMs: 0`, без срока |
| Время жизни по умолчанию в Lizard SDK | 300000 мс, пять минут |
| Диапазон явного времени жизни | Целые миллисекунды от 0 до 2147483647 |
| Изменение времени жизни | Не меньше 1000 мс; это не таймер простоя |
| Подключение Persistent Volume | Одна песочница за раз, на узле тома |

CLI тоже по умолчанию задаёт пять минут; панель по умолчанию не задаёт срок. Команды не продлевают срок. Про паузу, снимки, fork и то, что сохраняет каждый из них, см. [жизненный цикл](/sandboxes#lifecycle) sandbox.

## Лимиты рабочего пространства

Владелец рабочего пространства может ограничить одно из них, например то, с которым клиент работает через API-ключ с ограниченной областью. Эти лимиты действуют поверх лимитов аккаунта выше и касаются всех, кто работает в этом рабочем пространстве.

| Лимит | Что считается | Флаг |
|---|---|---|
| Sandboxes | Песочницы, которые работают или возобновляются одновременно; приостановленные не считаются | `--sandboxes <n>` |
| CPU | vCPU, которые приложения и базы данных рабочего пространства используют сейчас, по замерам | `--cpu <vcpus>` |
| Память | Память, которую приложения и базы данных рабочего пространства используют сейчас, по замерам | `--memory <size>` |
| Диск | Данные, записанные в базы данных и тома рабочего пространства | `--disk <size>` |

Задаёт их только владелец командой [`lizard workspace limits`](/cli/workspace#lizard-workspace-limits-name-or-id), войдя через браузер или с API-ключом без ограничения области. Любой участник и любой ключ с доступом к рабочему пространству могут прочитать их вместе с текущим расходом.

- При достижении лимита песочниц создание, fork и возобновление возвращают HTTP 429 с `code`, равным `WORKSPACE_SANDBOX_LIMIT`.
- Пока приложения и базы данных используют столько CPU или памяти, сколько разрешено, деплой, повторный деплой, перезапуск, масштабирование вверх, новые базы данных и возобновление приложения или базы данных с паузы возвращают HTTP 429 с `code`, равным `WORKSPACE_USAGE_LIMIT`. Работающие сервисы продолжают работать.
- Пока данные занимают весь лимит диска, новые тома, увеличение томов, новые базы данных и деплой шаблонов возвращают тот же `WORKSPACE_USAGE_LIMIT`. Уже записанные данные остаются.
- Собственный диск `/workspace` песочницы в лимит диска не входит.

## Регионы

Текущие настроенные регионы включают US East (Virginia), `us-east-1`, и EU West (Limburg), `eu-west-lim-a`. Наличие региона в каталоге не гарантирует свободные мощности для каждого типа ресурса. Проверяйте выбор региона при создании ресурса; sandbox с существующим томом должен запускаться на узле этого тома. [`lizard regions`](/cli/regions) выводит регионы, доступные вашему аккаунту; см. [регионы](/deploy/regions).

<span id="before-increasing-scale" />

## Перед увеличением масштаба

Проверьте активный тариф, настройки на реплику, лимит аккаунта, лимиты рабочего пространства, лимит подключений к базе данных и рост хранилища вместе. Используйте [масштабирование](/deploy/scaling), [метрики](/observability/metrics) и [цены](https://lizard.build/pricing), чтобы сравнить выделенные ресурсы с фактическим расходом. Ставки для каждого ресурса смотрите на [странице оплаты](/platform/billing#resource-rates).
