# Сетевое взаимодействие

Каждому сервису в момент деплоя выдается сгенерированный `*.onlizard.com` домен с автоматическим TLS, независимо от региона. Подключите свой хостнейм, когда будете готовы выйти в прод.

<span id="generated-domains" />

## Сгенерированные домены

Сервису автоматически создается домен по умолчанию в формате `<name>-<suffix>.onlizard.com`. У более старых сервисов остается `<words>.<region>.onlizard.com`. Посмотреть его:

```bash
lizard domain                    # show the service's current domain
lizard domain generate           # claim a *.onlizard.com subdomain if the service has none
```

`lizard domain generate` возвращает уже существующий сгенерированный домен, если он есть, и завершается ошибкой, пока у сервиса есть собственный домен. Файлы, обслуживаемые через [Managed Object Storage](/addons/storage), используют шлюз с отдельным хостом: `s3-eu-west-1.onlizard.com` или `s3-us-east-1.onlizard.com`.

<span id="attach-a-custom-domain" />

## Подключение собственного домена

Хостнейм — это **позиционный аргумент**, отдельного `add` подкоманды не существует:

```bash
lizard domain app.example.com --service web
```

Lizard вернет DNS-записи, которые нужно создать (`CNAME` для хостнейма и `TXT` для верификации). Добавьте их у своего DNS-провайдера.

<span id="verify" />

## Верификация

После распространения DNS активируйте домен:

```bash
lizard domain verify app.example.com --service web
```

Команда проверяет `TXT` запись и активирует домен. TLS подготавливается автоматически.

<span id="remove-a-domain" />

## Удаление домена

```bash
lizard domain delete app.example.com --service web
lizard domain rm app.example.com --service web --yes   # alias, skip confirmation
```

<span id="exposing-a-specific-port" />

<span id="change-the-port-your-service-listens-on" />

## Смена порта, который слушает сервис

Домены направляют трафик на порт контейнера сервиса. Если сервис слушает другой порт, измените порт контейнера и сделайте редеплой:

```bash
lizard port 8080 --service web
lizard redeploy --service web
```

<span id="worker-services" />

## Worker-сервисы

У [сервисов в режиме worker](/deploy/workers) (`containerPort=0`) может всё равно отображаться сгенерированный домен, но он ничего не обслуживает — слушателя и маршрута балансировщика нет. Не подключайте собственный домен к worker-сервису.

<span id="private-networking" />

## Приватная сеть

Сервисы одного проекта обращаются друг к другу по адресу `<service>.lizard.internal` на любом порту, который слушает сервис, без публичного домена. Хостнейм можно указать как `${{api.LIZARD_PRIVATE_DOMAIN}}`. Managed Postgres и Managed Redis в той же сети предоставляют `DATABASE_PRIVATE_URL` и `REDIS_PRIVATE_URL`. Эти имена разрешаются только внутри проекта.

```bash
lizard secrets set API_URL='http://${{api.LIZARD_PRIVATE_DOMAIN}}:8080' --service web
```

<span id="manage-in-the-dashboard" />

## Управление в дашборде

Откройте сервис в дашборде (`lizard open`) и перейдите в **Settings → Networking**. Там показан статус верификации и DNS для каждого домена, а также можно добавлять и удалять хостнеймы.
