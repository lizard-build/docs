# Масштабирование

Командой `lizard scale` можно добавить реплики сервиса, увеличить CPU или память и расширить хранилище аддона. Чтобы сократить сервис до нуля реплик, включите [сон при простое](#sleep-when-idle) или [поставьте его на паузу](#pause-a-service).

<span id="scale-a-service" />

## Масштабирование сервиса

```bash
lizard scale --service api --replicas 3
lizard scale --service api --cpu 2 --memory 2048
```

| Флаг | Применяется к | Допустимые значения |
|------|-----------|----------------|
| `--replicas <n>` | приложения | от `1` до [лимита](/platform/limits#applications) вашего тарифа: `1` в пробном периоде, `5` в Pro и Enterprise |
| `--cpu <cores>` | приложения и аддоны | целые ядра: `1`, `2`, `3`, `4` |
| `--memory <mb>` | приложения и аддоны | `128`–`8192` МБ (шаг 1 МБ) |
| `--storage <mb>` | **только аддоны**, только увеличение | `512`, `1024`, `2048`, `4096`, `8192`, `16384` |

Флаги можно комбинировать в одной команде. Изменение количества реплик разворачивается без пересборки. Изменение CPU и памяти перезапускает сервис с новыми лимитами.

<span id="horizontal-scaling" />

## Горизонтальное масштабирование

Запустите несколько реплик приложения за балансировщиком нагрузки:

```bash
lizard scale --service api --replicas 5
```

Каждая реплика работает в отдельном поде. Убедитесь, что ваше приложение бесстаточное (храните состояние в [Managed Postgres](/addons/postgres), [Managed Redis](/addons/redis) или [Managed Object Storage](/addons/storage)), чтобы реплики были взаимозаменяемыми.

<span id="vertical-scaling" />

## Вертикальное масштабирование

Дайте одной реплике больше ресурсов:

```bash
lizard scale --service api --cpu 4 --memory 8192
```

<span id="growing-addon-storage" />

## Увеличение хранилища аддонов

Тома данных аддонов **только для увеличения** — вы можете увеличить хранилище, но не уменьшить его:

```bash
lizard scale --service postgres --storage 8192
```

<span id="sleep-when-idle" />

## Сон при простое

`lizard sleep --on` позволяет веб-сервису засыпать, когда к нему нет трафика, и просыпаться примерно за секунду при следующем запросе. По умолчанию сервис засыпает после 10 минут без трафика; через `--idle` можно задать от 5 до 1440 минут. При включении сервис один раз перезапускается. Сон работает только для сервиса с портом и одной репликой, поэтому воркерам он недоступен. Managed Postgres и Managed Redis тоже умеют засыпать.

```bash
lizard sleep --on --idle 30 --service api
lizard sleep --off --service api    # always on
```

См. [`lizard sleep`](/cli/sleep).

<span id="pause-a-service" />

## Пауза сервиса

`lizard pause` останавливает сервис или базу данных, не удаляя их: число реплик падает до нуля, а URL, пароль, настройки и данные сохраняются. `lizard resume` снова запускает их. GitHub-сервис на паузе игнорирует пуши, пока вы его не возобновите.

```bash
lizard pause api
lizard resume api
```

Чтобы поставить на паузу все сервисы проекта или рабочего пространства, используйте `lizard project pause` или `lizard workspace pause`. См. [`lizard pause`](/cli/pause).

<span id="verifying" />

## Проверка

```bash
lizard ps                 # replica status + URL
lizard events             # deploy history + current replicas
lizard metrics            # live CPU / memory / network / disk
lizard metrics --cost     # cost instead of metrics
```

Изменение числа реплик не создаёт развёртывание, поэтому `lizard events` его не показывает; смотрите таблицу Replicas.
