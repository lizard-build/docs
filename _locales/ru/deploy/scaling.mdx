# Масштабирование

Масштабируйте сервис горизонтально (больше реплик) или вертикально (больше CPU/памяти) с помощью `lizard scale`. Хранилище аддонов увеличивается тем же способом.

<span id="scale-a-service" />

## Масштабирование сервиса

```bash
lizard scale --service api --replicas 3
lizard scale --service api --cpu 2 --memory 2048
```

| Флаг | Применяется к | Допустимые значения |
|------|-----------|----------------|
| `--replicas <n>` | приложения | `1`–`10` |
| `--cpu <cores>` | приложения | целые ядра: `1`, `2`, `3`, `4` |
| `--memory <mb>` | приложения | `128`–`8192` МБ (шаг 1 МБ) |
| `--storage <mb>` | **только аддоны**, только увеличение | `512`, `1024`, `2048`, `4096`, `8192`, `16384` |

Флаги можно комбинировать в одной команде. Изменение количества реплик разворачивается без пересборки.

<span id="horizontal-scaling" />

## Горизонтальное масштабирование

Запустите несколько реплик приложения за балансировщиком нагрузки:

```bash
lizard scale --service api --replicas 5
```

Каждая реплика — это отдельный под. Убедитесь, что ваше приложение бесстаточное (храните состояние в [Postgres](/addons/postgres), [Redis](/addons/redis) или [S3](/addons/storage)), чтобы реплики были взаимозаменяемыми.

<span id="vertical-scaling" />

## Вертикальное масштабирование

Дайте одной реплике больше ресурсов:

```bash
lizard scale --service api --cpu 4 --memory 8192
```

<span id="growing-addon-storage" />

## Увеличение хранилища аддонов

Тома данных аддонов **только для увеличения** — вы можете увеличить хранилище, но не уменьшить его:

```bash
lizard scale --service postgres --storage 8192
```

<span id="verifying" />

## Проверка

```bash
lizard ps                 # replica status + URL
lizard events             # per-replica deploy/scale history
lizard metrics            # live CPU / memory / network / disk
lizard metrics --cost     # include cost
```
