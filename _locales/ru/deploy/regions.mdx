# Регионы

Сервисы и аддоны создаются в конкретном регионе. Посмотрите список регионов, доступных вашему аккаунту, и выберите нужный при создании.

<span id="list-regions" />

## Список регионов

```bash
lizard regions
lizard regions --json
```

<span id="choose-a-region" />

## Выбор региона

Передайте `--region <code>` при создании сервиса или аддона:

```bash
lizard add -r your-org/your-app --region <code>
lizard add postgres --region <code>
lizard up --region <code>          # new services only
```

У проектов нет региона по умолчанию. Без `--region` команда `lizard add` создаёт ресурс в `us-east-1`, а `lizard up` создаёт новый сервис в регионе API-сервера, который обрабатывает запрос. Передайте `--region`, чтобы выбрать регион.

> **Размещайте состояние в одном регионе.** Размещайте сервис и аддоны, с которыми он общается (Managed Postgres, Managed Redis, Managed Object Storage), в **одном регионе**, чтобы сохранить низкую задержку и избежать платы за межрегиональный трафик.

<span id="generated-domains" />

## Генерируемые домены

Каждый сервис получает генерируемый домен с автоматическим TLS: `<name>-<suffix>.onlizard.com` для новых сервисов, тогда как старые сервисы сохраняют `<words>.<region>.onlizard.com`. [Managed Object Storage](/addons/storage) использует отдельный шлюз для каждого региона: `s3-us-east-1.onlizard.com` для `us-east-1` и `s3-eu-west-1.onlizard.com` для `eu-west-lim-a`. Чтобы подключить свой хостнейм, см. [Networking](/networking).
