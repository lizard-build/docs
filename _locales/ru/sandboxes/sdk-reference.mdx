Установите Lizard SDK и создайте API-ключ в Settings → API keys. Сохраните его в `LIZARD_API_KEY`. Каждому sandbox нужен проект: передайте `projectId` (в Python — `project_id`) или ID, slug либо имя через `project`.

## Параметры создания

| TypeScript | Python |
|---|---|
| `projectId / project` | `project_id / project` |
| `timeoutMs` | `timeout_ms` |
| `region` | `region` |
| `volumeName / volumeId` | `volume_name / volume_id` |
| `size` | `size` |
| `snapshotId` | `snapshot_id` |
| `envs` | `envs` |
| `metadata` | `metadata` |
| `lizardToken` | `lizard_token` |
| `apiKey` | `api_key` |

Выбирайте шаблон из текущего каталога: `base`, `interpreter`, `codex`, `claude`, `opencode`, `pi`, `prime` или `desktop`. Наличие зависит от региона и свободных ресурсов пула. `interpreter` содержит Python и основные библиотеки для работы с данными. `desktop` запускает графический рабочий стол, которым вы управляете через `sandbox.desktop` или `lizard sandbox desktop`. Проверяйте версии программ внутри sandbox. Публичный CLI не поддерживает загрузку своих шаблонов.

SDK и CLI по умолчанию задают срок жизни пять минут. Прямой API и кабинет по умолчанию не задают срок. Укажите его явно: `timeoutMs: 0` при создании отключает истечение срока; положительное значение задаёт срок жизни. `setTimeout` принимает 1000–2147483647 мс, но не ноль. Команды не продлевают срок. Это не таймер простоя.

## Методы

| API (TypeScript) | Методы |
|---|---|
| `Sandbox.create(template, options)` | Создать в проекте из шаблона каталога. |
| `Sandbox.connect(sandboxId)` | Подключиться к существующему sandbox без возобновления. |
| `Sandbox.list()` | Получить список доступных Sandboxes; проверяйте их статус. |
| `sandbox.getInfo()` | Получить статус и сведения. |
| `sandbox.process.exec(cmd)` | Выполнить shell-команду; вернуть stdout, stderr и exitCode. |
| `sandbox.fs.write(path, data)` | Записать текст или байты; создать родительские папки. |
| `sandbox.fs.read(path)` | Прочитать текст UTF-8. |
| `sandbox.fs.readBytes(path)` | Прочитать байты файла. |
| `sandbox.fs.list(path)` | Получить список файлов и папок. |
| `sandbox.fs.makeDir(path)` | Создать папку и её родителей. |
| `sandbox.fs.remove(path)` | Удалить файл или папку. |
| `sandbox.exposePort(port)` | Опубликовать порт; вернуть `url`, `hostname` и `accessToken`. |
| `sandbox.getHost(port)` | Опубликовать порт и вернуть его имя хоста; для запросов нужен `sandbox.accessToken`. |
| `sandbox.setTimeout(ms)` | Задать оставшийся срок жизни, минимум 1000 мс. |
| `sandbox.pause()` / `sandbox.resume()` | Поставить паузу или возобновление в очередь и сразу вернуть ответ. |
| `sandbox.waitForStatus(status)` | Дождаться `paused` или `running`; выбросить ошибку, если пауза не удалась. |
| `sandbox.fork({ count })` | Скопировать работающий sandbox вместе с памятью и процессами. |
| `sandbox.snapshot(name, { poolSize })` | Сохранить память и файлы `/workspace` в приватный снимок. |
| `Sandbox.waitForSnapshot(snapshotId)` | Дождаться готовности снимка. |
| `Sandbox.restore(snapshotId)` | Запустить новый sandbox из готовой копии. |
| `sandbox.kill()` | Остановить sandbox и отключить том. |

Python: `exec_`, `get_info`, `expose_port`, `get_host`, `access_token`, `set_timeout`, `sandbox_id`, `read_bytes`, `make_dir`, `wait_for_status`, `wait_for_snapshot`, `pool_size`.

## Текущие ограничения runtime

Результат команды содержит stdout, stderr и код завершения. Таймаут команды ограничен 1–600 секундами. `process.exec` принимает `envs`, `workdir` и `user`. Параметр `envs`, заданный при создании, доступен каждой команде в sandbox на Firecracker; sandbox в виде pod его игнорирует, поэтому там передавайте переменные в каждой команде. `getInfo()` и `list()` возвращают `metadata`, заданные при создании.

`fs.write` записывает текст или байты, а `fs.read` читает текст. Для двоичных файлов записывайте байты и читайте их обратно через `fs.readBytes` (в Python — `read_bytes`).

Передайте `size` (`'small'`, `'medium'` или `'large'`), чтобы выбрать 2 vCPU / 4 GB, 4 vCPU / 8 GB (по умолчанию) или 8 vCPU / 16 GB; см. [размеры и цены](/platform/limits#sandbox-sizes). Для sandbox, восстановленного из снимка, `size` не действует: он работает с размером источника. При необходимости укажите регион явно; наличие региона в каталоге не гарантирует свободные ресурсы.

## Запуск кода с сохранением состояния

`CodeSandbox` запускает шаблон `interpreter` и выполняет код через `runCode` (в Python — `run_code`). В этом шаблоне Python работает в постоянном ядре Jupyter для каждого контекста, поэтому переменные сохраняются между вызовами, а результаты могут включать графики в виде `image/png`. JavaScript и bash при каждом вызове запускаются как новый процесс. См. [Запуск Python](/sandboxes/code-interpreter).

## Недоступные API

Наблюдение за файлами пока недоступно. `sandbox.fork()` возвращает 409, если подключён том, и 501 для sandbox, работающего как pod. `Sandbox.connect` не возобновляет приостановленный или остановленный sandbox; для приостановленного вызовите `resume()`. Доступа по протоколу SSH нет; `lizard sandbox ssh` открывает интерактивную оболочку с учётными данными CLI.

## Хранение и оплата

Файлы и процессы доступны, пока sandbox работает. После остановки следующий sandbox может получить только файлы, записанные на подключённый Persistent Volume в `/workspace`. Без тома `/workspace` — временная папка. Том подключается только к одному sandbox и хранится на одном узле; отдельно сохраняйте файлы, которые должны пережить потерю узла.

У каждого размера фиксированная почасовая цена; оплата идёт посекундно, пока sandbox работает, включая простой. Исходящий трафик входит в цену до [2 TB на аккаунт](/platform/limits#sandbox-egress) за скользящие 30 дней. Sandbox, восстановленный из снимка, работает с размером и по цене источника; восстановленный из снимка pod оплачивается по измеренному расходу. За приостановленный sandbox плата не берётся; Persistent Volumes оплачиваются отдельно, пока вы храните данные. Ставьте sandbox на паузу или останавливайте его, когда задача завершена.
