## Установка и вход

Установите Lizard SDK и создайте API-ключ в Settings → API keys. Сохраните его в `LIZARD_API_KEY`. Каждому sandbox нужен проект: передайте `projectId` (в Python — `project_id`) или ID, slug либо имя через `project`.

```sh
npm install @lizard-build/sdk
pip install lizard-sdk
export LIZARD_API_KEY="<your-api-key>"
```

## Запуск команды

```ts
import { Sandbox } from '@lizard-build/sdk';

const sandbox = await Sandbox.create('interpreter', {
  projectId: 'proj_123', timeoutMs: 300_000,
});
try {
  const result = await sandbox.process.exec("python -c 'print(2 ** 10)'");
  console.log(result.stdout, result.stderr, result.exitCode);
} finally {
  await sandbox.kill();
}
```

```python
from lizard import Sandbox

sandbox = Sandbox.create("interpreter", project_id="proj_123", timeout_ms=300_000)
try:
    result = sandbox.process.exec_("python -c 'print(2 ** 10)'")
    print(result.stdout, result.stderr, result.exit_code)
finally:
    sandbox.kill()
```

## Файлы

`fs.write` записывает текст или байты, а `fs.read` читает текст. Для двоичных файлов записывайте байты и читайте их обратно через `fs.readBytes` (в Python — `read_bytes`).

Файлы и процессы доступны, пока sandbox работает. После остановки следующий sandbox может получить только файлы, записанные на подключённый Persistent Volume в `/workspace`. Без тома `/workspace` — временная папка. Том подключается только к одному sandbox и хранится на одном узле; отдельно сохраняйте файлы, которые должны пережить потерю узла.

```ts
await sandbox.fs.write("/tmp/task.py", "print(42)\n");
const result = await sandbox.process.exec("python /tmp/task.py");
console.log(result.stdout);
```

## Публичные порты

Запустите сервер на `0.0.0.0`, затем вызовите `exposePort(port)` (в Python — `expose_port`). Он возвращает `url`, `hostname` и `accessToken`. Порт закрыт: откройте `url` в браузере (в нём есть `?lizard_token=`) или передайте токен в заголовке `X-Lizard-Access-Token`. Запросы без токена получают 401. После остановки sandbox порт больше не обслуживается.

```ts
await sandbox.process.exec(
  "nohup python -m http.server 3000 --bind 0.0.0.0 --directory /tmp >/tmp/http.log 2>&1 </dev/null &",
);
const { url, hostname, accessToken } = await sandbox.exposePort(3000);
console.log(url); // open in a browser
const res = await fetch(`https://${hostname}/`, {
  headers: { 'X-Lizard-Access-Token': accessToken },
});
```

## Подключение к работающему sandbox

Создайте sandbox, выполните команды и вызовите `kill`. `connect` подключается к существующему sandbox и не меняет его состояние, поэтому не возобновляет приостановленный или остановленный sandbox. Пауза, возобновление, snapshot и restore доступны; см. [Пауза, возобновление и снимки](/sandboxes/quickstart#pause-and-resume). `fork` копирует работающий sandbox вместе с памятью и процессами; при подключённом томе он возвращает 409, а для sandbox, работающего как pod, — 501. Наблюдение за файлами пока недоступно. `lizard sandbox ssh` открывает интерактивную оболочку с учётными данными CLI. Доступа по протоколу SSH нет, поэтому SSH-клиенты, `scp` и проброс портов не работают.

```ts
const connected = await Sandbox.connect(sandbox.sandboxId);
console.log(await connected.getInfo());
```

## Пауза, возобновление и снимки

`pause()` сохраняет память и запущенные процессы sandbox, оставляет `/workspace` на его узле и останавливает оплату. `resume()` восстанавливает sandbox с тем же ID. Оба вызова ставят задачу в очередь и сразу возвращают ответ; дождитесь нового статуса.

```ts
await sandbox.pause();
await sandbox.waitForStatus('paused');
await sandbox.resume();
await sandbox.waitForStatus('running');
```

- Пауза закрывает открытые сетевые соединения. После возобновления программы в sandbox должны подключиться заново.
- Если процессы не удаётся сохранить, sandbox продолжает работать, а `waitForStatus` выбрасывает ошибку с причиной. Если возобновление не удалось, sandbox остаётся на паузе с сохранённым состоянием; вызовите `resume()` ещё раз.
- Пока sandbox на паузе, срок жизни не расходуется; после возобновления отсчёт продолжается. Приостановленный sandbox не учитывается в лимите запущенных.
- Приостановленный sandbox возобновляется на том же узле. Если узел выйдет из строя, сохранённое состояние пропадёт; выгрузите нужные файлы заранее.

Снимок (snapshot) сохраняет память и файлы `/workspace` работающего sandbox как приватный шаблон проекта. Каждый restore запускает новый sandbox в регионе снимка. Перед снимком закройте клиенты и терминалы и остановите запись в `/workspace`. Подключённые Persistent Volumes в снимок не входят.

```ts
const saved = await sandbox.snapshot('my-app', { poolSize: 5 });
await Sandbox.waitForSnapshot(saved.id);
const copy = await Sandbox.restore(saved.id);
```

Снимок sandbox на Firecracker готов сразу после возврата вызова и восстанавливается с диска, поэтому `poolSize` к нему не применяется. Каждый restore запускается с размером источника и оплачивается по почасовой цене этого размера. Снимок sandbox, работающего как pod, держит готовые копии, по умолчанию пять (от одной до десяти); если готовых копий нет, restore может вернуть HTTP 503, пока пул не пополнится, а восстановленный sandbox оплачивается по измеренному расходу. В обоих случаях `size` к restore не применяется. В CLI используйте `lizard sandbox pause <id>`, `lizard sandbox resume <id>`, `lizard sandbox snapshot <id> --name my-app` и `lizard sandbox restore <snapshot-id>`.

## Текущие ограничения runtime

SDK и CLI по умолчанию задают срок жизни пять минут. Прямой API и кабинет по умолчанию не задают срок. Укажите его явно: `timeoutMs: 0` при создании отключает истечение срока; положительное значение задаёт срок жизни. `setTimeout` принимает 1000–2147483647 мс, но не ноль. Команды не продлевают срок. Это не таймер простоя.

Результат команды содержит stdout, stderr и код завершения. Таймаут команды ограничен 1–600 секундами. `process.exec` принимает `envs`, `workdir` и `user`. Параметр `envs`, заданный при создании, действует для каждой команды в sandbox на Firecracker; sandbox, работающий как pod, его игнорирует, поэтому там передавайте переменные для каждой команды отдельно. `getInfo()` и `list()` возвращают `metadata`, заданные при создании.
