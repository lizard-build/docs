<span id="ways-to-drive-sandboxes" />

Sandboxes в Lizard (lizard.build) выполняют код и задачи AI-агента на изолированных Linux-машинах. Sandboxes работают как Firecracker microVM, каждая со своим ядром. Ваш код создаёт sandbox с помощью Lizard SDK (`@lizard-build/sdk` для TypeScript, `lizard-sdk` для Python), или вы выполняете `lizard sandbox create` в терминале; затем вы запускаете команды, читаете и записываете файлы и открываете порты. В тесте 2026-10-12 медианное время от создания sandbox до первого вывода Python составило 228 мс.

<span id="when-to-use-sandboxes" />

## Когда использовать Sandboxes

- **Запускайте код, который написала модель.** Дайте LLM [интерпретатор кода](/sandboxes/code-interpreter), который сохраняет состояние Python между вызовами.
- **Дайте агенту для кодирования отдельный компьютер.** Запускайте [Claude Code](/sandboxes/guides/claude-code), [OpenCode](/sandboxes/guides/opencode) или Codex в sandbox, а не на своём ноутбуке. Подключите его учётные данные через [`lizard agents`](/cli/agents) и отправляйте промпты через [`lizard sandbox prompt`](/cli/sandbox#coding-agents).
- **Смотрите, что собрал агент.** Запустите dev-сервер и откройте его по [приватному URL предпросмотра](/sandboxes/preview-urls).
- **Пробуйте несколько вариантов сразу.** Скопируйте работающий sandbox через fork вместе с памятью и процессами или восстановите много копий из одного снимка.
- **Управляйте браузером.** Шаблон `desktop` запускает графический рабочий стол, которым агент управляет через скриншоты, клики и нажатия клавиш.

Для веб-сервиса или воркера, который должен работать постоянно, разверните приложение; см. [быстрый старт приложения](/getting-started).

<span id="how-fast-does-a-sandbox-start" />

## Как быстро запускается sandbox?

В тесте 2026-10-12 медианное время от создания sandbox до первого вывода Python составило 228 мс, а 95-й перцентиль составил 310 мс. Тест запускали 300 раз из региона US East в Railway на `us-east-1`, с шаблоном `base` и размером Small. Результаты того же теста для E2B, Daytona и Modal смотрите на [странице Sandboxes](https://lizard.build/ru/#sandbox-benchmarks).

## Runtime и шаблоны

Выбирайте шаблон из текущего каталога: `base`, `interpreter`, `codex`, `claude`, `opencode`, `pi`, `prime`, `desktop` или `desktop-camoufox`. Наличие зависит от региона и свободных ресурсов пула. `interpreter` содержит Python, основные библиотеки для работы с данными и Node 22. `desktop` запускает графический рабочий стол, которым вы управляете через `sandbox.desktop` или `lizard sandbox desktop`. `desktop-camoufox` — это шаблон `desktop` плюс Camoufox, сборка Firefox для сбора данных с сайтов, которой вы управляете через Playwright; пока он работает только в `us-east-1`. Проверяйте версии программ внутри sandbox. Публичный CLI не поддерживает загрузку своих шаблонов.

Lizard Sandboxes работают как Firecracker microVM, каждая со своим ядром. Давайте агенту только те ключи и права доступа, которые нужны для задачи.

<span id="lifecycle" />

## Жизненный цикл

Создайте sandbox, выполните команды и вызовите `kill`. `connect` подключается к существующему sandbox и не меняет его состояние, поэтому не возобновляет приостановленный или остановленный sandbox. Пауза, возобновление, snapshot и restore доступны; см. [Пауза, возобновление и снимки](/sandboxes/quickstart#pause-and-resume). `fork` копирует работающий sandbox вместе с памятью и процессами; если подключён том, возвращается 409. Наблюдение за файлами пока недоступно. `lizard sandbox ssh` открывает интерактивную оболочку с учётными данными CLI. Доступа по протоколу SSH нет, поэтому SSH-клиенты, `scp` и проброс портов не работают.

```text
create -> running -> stopped (kill / expiration)
running -> paused -> running (pause / resume)
running -> new sandboxes (fork)
snapshot -> new sandbox (restore)
```

<span id="resources-and-timeouts" />

## Ресурсы и сроки жизни

Выберите размер при создании sandbox: Small (2 vCPU / 4 GB), Medium (4 vCPU / 8 GB, по умолчанию) или Large (8 vCPU / 16 GB). В пробном периоде каждый sandbox имеет размер Small и работает в регионе США. См. [размеры и цены](/platform/limits#sandbox-sizes). При необходимости укажите регион явно; наличие региона в каталоге не гарантирует свободные ресурсы.

SDK и CLI по умолчанию задают срок жизни пять минут. Прямой API и кабинет по умолчанию не задают срок. Укажите его явно: `timeoutMs: 0` при создании отключает истечение срока; положительное значение задаёт срок жизни. `setTimeout` принимает 1000–2147483647 мс, но не ноль. Команды не продлевают срок. Это не таймер простоя.

<span id="storage-and-billing" />

## Хранение и оплата

Файлы и процессы доступны, пока sandbox работает. Пауза сохраняет весь диск, включая пакеты, установленные вне `/workspace`, а также память и запущенные процессы; после возобновления всё на месте. Снимок хранит то же самое, и его можно восстановить, даже когда исходного sandbox уже нет. Остановка (kill или истечение срока) удаляет диск sandbox: остаются только файлы на подключённом томе Persistent Volumes в `/workspace` и ваши снимки. Без тома `/workspace` лежит на этом же диске. Том подключается только к одному sandbox и хранится на одном узле; отдельно сохраняйте файлы, которые должны пережить потерю узла.

У каждого размера фиксированная почасовая цена; оплата идёт посекундно, пока sandbox работает, включая простой. Исходящий трафик входит в цену до [2 TB на аккаунт](/platform/limits#sandbox-egress) за скользящие 30 дней. Sandbox, восстановленный из снимка, работает с размером и ценой исходного sandbox. Успешная пауза останавливает оплату вычислений; Persistent Volumes оплачиваются отдельно, пока вы храните данные. Ставьте sandbox на паузу или останавливайте его, когда задача завершена. Ставки на все ресурсы смотрите на [странице оплаты](/platform/billing) и в [ценах](https://lizard.build/pricing).
