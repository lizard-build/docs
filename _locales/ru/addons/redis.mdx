# Managed Redis

Managed Redis в Lizard (lizard.build) запускает сервер Redis для кэширования, очередей, ограничения частоты запросов и pub/sub. Новые экземпляры по умолчанию работают на Redis 8. Добавьте его командой `lizard add redis`; ваши сервисы читают `REDIS_PRIVATE_URL` или `REDIS_URL` через ссылку вида `${{redis.REDIS_PRIVATE_URL}}`. В нём нет политики вытеснения и append-only файла, поэтому храните в нём только данные, которые можно восстановить. Обзор и цены смотрите на [странице Managed Redis](https://lizard.build/redis).

<span id="provision" />

## Создание

```bash
lizard add redis
```

Первое дополнение Redis называется `redis`, поэтому `${{redis.REDIS_URL}}` работает сразу.

<span id="environment-variables" />

## Переменные окружения

| Переменная | Описание |
|----------|-------------|
| `REDIS_URL` | Полная строка подключения через публичную конечную точку (`redis://…`) |
| `REDIS_PRIVATE_URL` | Строка подключения через приватную сеть проекта (`<name>.lizard.internal:6379`) |

Обе строки имеют вид `redis://default:<password>@<host>:<port>`. Приватная работает только из сервисов того же проекта; см. [приватную сеть](/networking#private-networking).

<span id="connect-a-service" />

## Подключение сервиса

```bash
lizard secrets set REDIS_URL='${{redis.REDIS_PRIVATE_URL}}' --service api
lizard redeploy --service api
```

Ссылка разрешается при развёртывании; сервисы получают актуальные значения дополнения при следующем развёртывании. Используйте `REDIS_URL` для клиентов вне проекта. Каждый сервис в проекте также получает публичный `REDIS_URL` дополнения с самым низким приоритетом; явная ссылка переопределяет его.

<span id="does-managed-redis-keep-data" />

## Сохраняет ли Managed Redis данные?

Managed Redis сохраняет не каждую запись. В Managed Redis нет политики вытеснения и append-only файла. Если память заканчивается, экземпляр перезапускается, и последние записи могут пропасть. Используйте его для данных, которые можно восстановить, а данные, которые нельзя потерять, храните в [Managed Postgres](/addons/postgres).

<span id="common-uses" />

## Типовые варианты использования

- **Кэширование** — сохраняйте вычисленные результаты с ключом запроса.
- **Очередь / воркер**: используйте Redis вместе с [сервисом в режиме воркера](/deploy/workers), который обрабатывает задания. Пример redis-worker разобран в разделе [Запуск потребителя очереди](/deploy/workers#run-a-queue-consumer).
- **Ограничение частоты запросов / сессии** — быстрое разделяемое состояние для [реплик](/deploy/scaling).

```bash
# A worker that drains a Redis queue
lizard add -r your-org/worker -n jobs --no-deploy
lizard service set jobs --set containerPort=0
lizard secrets set REDIS_URL='${{redis.REDIS_PRIVATE_URL}}' --service jobs
lizard redeploy --service jobs
```

<span id="browse-keys" />

## Просмотр ключей

Откройте **Браузер Redis** в панели управления (`lizard open`), чтобы просмотреть ключи и значения. Для локального доступа со значениями подключения дополнения:

```bash
lizard run --service redis -- sh -c 'exec redis-cli -u "$REDIS_URL"'
```

<span id="grow-storage" />

## Расширение хранилища

```bash
lizard scale --service redis --storage 4096
```
