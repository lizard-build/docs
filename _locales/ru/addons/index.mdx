# Управляемые дополнения

Lizard (lizard.build) запускает базы данных и хранилище внутри проекта как управляемые дополнения: **Managed Postgres**, **Managed Redis** и S3-совместимое **Managed Object Storage**. `lizard add postgres redis s3` создаёт все три одной командой. Каждое дополнение предоставляет фиксированный набор переменных окружения, например `DATABASE_URL`, а ваши сервисы читают их через [ссылки](/concepts/architecture#cross-resource-references) вида `${{postgres.DATABASE_URL}}`. Используйте дополнения, когда приложению нужны данные, которые сохранятся после развёртывания или перезапуска.

<span id="provision-an-addon" />

## Создание дополнения

```bash
lizard add postgres            # one addon
lizard add postgres redis s3   # several at once
lizard add --list              # show available types
```

<span id="naming" />

## Имена

**Первое** дополнение каждого типа получает в качестве имени само название типа, поэтому `${{postgres.DATABASE_URL}}` работает сразу после создания. Остальные дополнения того же типа получают сгенерированное имя, например `postgres-autumn-bear`. Удалённое дополнение сохраняет своё имя в корзине в течение 3 дней, поэтому новое дополнение, добавленное в этот период, получит сгенерированное имя; восстановите старое дополнение или направьте ссылки на новое имя.

Псевдонимы типов не поддерживаются: ссылка должна содержать **текущее** имя дополнения. Переименование дополнения нарушает ссылки на старое имя, поэтому после переименования обновите их:

```bash
lizard service rename main-db --service postgres   # addons rename through the same command
lizard secrets set DATABASE_URL='${{main-db.DATABASE_URL}}' --service api
```

<span id="consuming-an-addon" />

## Использование дополнения

Ссылки на переменные дополнения можно использовать из любого сервиса. Ссылка разрешается во время развёртывания, поэтому сервис получает актуальные значения дополнения при следующем развёртывании:

```bash
lizard secrets set DATABASE_URL='${{postgres.DATABASE_URL}}' --service api
lizard redeploy --service api
```

Lizard также передаёт `DATABASE_URL` и `REDIS_URL` от каждого запущенного дополнения Postgres и Redis во все сервисы проекта с наименьшим приоритетом. Явная ссылка переопределяет их и позволяет выбрать конкретное дополнение. Для сервисов в том же проекте и том же регионе лучше использовать приватный URL:

```bash
lizard secrets set DATABASE_URL='${{postgres.DATABASE_PRIVATE_URL}}' --service api
```

См. [Ограничение области действия секретов](/variables#scoping).

<span id="variables-by-type" />

## Переменные по типам

| Дополнение | Переменные |
|-------|-----------|
| **postgres** | `DATABASE_URL`, `DATABASE_PRIVATE_URL`, `PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD`, `PGDATABASE`, `POSTGRES_USER`, `POSTGRES_DB`, `POSTGRES_PASSWORD` |
| **redis** | `REDIS_URL`, `REDIS_PRIVATE_URL` |
| **s3** | `S3_ENDPOINT`, `S3_DEFAULT_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_REGION` |

`DATABASE_URL` и `REDIS_URL` используют публичную конечную точку. `DATABASE_PRIVATE_URL` и `REDIS_PRIVATE_URL` используют `<name>.lizard.internal` в [приватной сети](/networking#private-networking) и работают только из сервисов того же проекта и того же региона. Сервис в другом регионе должен использовать `DATABASE_URL` или `REDIS_URL`; чтобы он мог работать через приватный URL, создайте дополнение в его регионе, например `lizard add postgres --region <code>`. `<name>` — имя, которое было у дополнения, когда оно получило приватный адрес; переименование его не меняет.

## Просмотр данных в панели управления

В [панели управления](/dashboard) есть браузер данных для каждого дополнения: редактор SQL и таблиц для Postgres, просмотр ключей для Redis и просмотр бакетов и объектов для S3. Вы сможете просматривать и изменять данные, не покидая Lizard.

<span id="storage" />

## Хранилище

Объём томов данных Postgres и Redis можно только увеличивать. Чтобы увеличить ёмкость, используйте:

```bash
lizard scale --service postgres --storage 8192
```

Допустимые размеры: 512, 1024, 2048, 4096, 8192 или 16384 MB. При увеличении Lizard останавливает базу, копирует её данные на том побольше и снова запускает, поэтому база ненадолго станет недоступна. Базу на паузе сначала возобновите командой [`lizard resume`](/cli/pause).
