# Агенты для кодирования

Lizard спроектирован так, чтобы им можно было управлять от AI-агентов для кодирования так же легко, как людьми. В Lizard CLI встроен **встроенный навык (skill)**, который обучает агента всей платформе, а каждая команда **самоописывается** через `--json`, поэтому агентам никогда не нужно угадывать.

<span id="the-embedded-skill" />

## Встроенный навык

Авторитетное руководство по использованию находится внутри CLI и версионируется вместе с ним, поэтому оно всегда соответствует установленной версии. Агент читает его с помощью:

```bash
lizard skills get core --json
```

Это возвращает `{ name, frontmatter, content, … }` — `content` является полным руководством (конвейер сборки, приоритет переменных окружения, аддоны, обнаружение, коды выхода). Связанные подкоманды:

```bash
lizard skills list        # available embedded skills
lizard skills get core    # the core guide
lizard skills path        # where skills are stored
```

Так как руководство поставляется в составе бинарника, `lizard upgrade` обновляет и инструкции агента.

<span id="self-describing-commands" />

## Самоописывающиеся команды

Агенты обнаруживают точную форму флагов во время выполнения вместо того, чтобы полагаться на запомненный синтаксис:

```bash
lizard --help --json                # full command tree + exit codes
lizard <cmd> --help --json          # a specific command's schema
```

См. [JSON и автоматизация](/cli/json).

<span id="bootstrapping-in-an-agent" />

## Бутстраппинг в агенте

Типичный поток работы агента:

1. **Загрузите руководство:** `lizard skills get core --json` → прочитайте `content`.
2. **Проверьте авторизацию оптимистически:** выполните задачу пользователя; при коде выхода `2` запустите `lizard login`, передайте пользователю выведенный URL, затем повторите попытку.
3. **Запустите пробный период, если попросят:** у нового аккаунта нет тарифа, поэтому первое создание завершится ошибкой HTTP 402 (`code: "PAYMENT_REQUIRED"`, код выхода `1`). Выполните `lizard billing start --json`, передайте пользователю `url` страницы Checkout, затем повторите попытку после того, как он добавит карту.
4. **Определите контекст перед мутацией:** `lizard status` (связка cwd) и `lizard ps --json` (сервисы).
5. **Действуйте** с помощью руководства — `add`, `up`, `secrets`, `domain` и т.д., всегда с `--json`.

Если бинарник `lizard` отсутствует, сначала установите его. На macOS или Linux используйте скрипт установки:

```bash
curl -fsSL https://lizard.build/install.sh | bash
```

Ему не нужны ни Node.js, ни `sudo`. Скрипт создает ссылку на `lizard` в папке, которая уже есть в `PATH`, поэтому агент может вызвать его в той же сессии. Если скрипт пишет, что `lizard` может быть не найден, вызывайте `~/.lizard/bin/lizard`. На Windows выполните в PowerShell:

```powershell
irm https://lizard.build/api/cli/install.ps1 | iex
```

Или установите из npm в любой системе:

```bash
npm install -g @lizard-build/cli
```

## Соглашения, которым должны следовать агенты

- **Всегда передавайте `--json`** при неинтерактивных вызовах.
- **Подтверждайте деструктивные действия** (удаление сервиса, удаление аддона, перезапись секрета на уровне проекта, перезагрузка продакшена) с пользователем — встроенные подсказки CLI срабатывают только при наличии TTY.
- **Ограничивайте область действия секретов потребляющим сервисом** по умолчанию; резервируйте `--global` для явно публичных значений. См. [Переменные и секреты](/variables#scoping).
- **Не пишите Dockerfile без запроса** — lizardpack автоматически определяет большинство стеков. Сначала попробуйте задеплоить. См. [Конвейер сборки](/concepts/build-pipeline).
- **Не используйте `lizard up` для переключения git-базированного сервиса на загрузку** — используйте `service set` + `redeploy`.

## Интеграции с редакторами

Lizard Skill распространяется как публичный бутстрап, чтобы агенты в редакторах и ассистентах могли устанавливать и загружать его по требованию, а затем управлять тем же CLI, который описан во всей этой документации. Установите его один раз для всех своих агентов:

```bash
npx skills add lizard-build/skill -g
```

Он работает с Claude Code, Cursor, Codex, Copilot, Gemini CLI и другими агентами, которые читают формат Agent Skills. Для клиентов, которые работают через MCP, а не выполняют shell-команды, используйте [Lizard MCP](#lizard-mcp).

Это относится и к AI IDE: они пишут и тестируют приложение, но не хостят его. См. [развертывание приложения, созданного в Google Antigravity](https://lizard.build/blog/google-antigravity-how-to-deploy-your-app-to-production#deploy-from-the-antigravity-chat), где весь деплой выполняется одним промптом.

<span id="lizard-mcp" />

## Lizard MCP

Lizard MCP позволяет ChatGPT, Claude и другим MCP-клиентам управлять вашими проектами Lizard: создавать сервисы и аддоны, выполнять повторный деплой, читать логи и метрики, задавать секреты, масштабировать реплики и подключать домены. Это размещенный сервер, который работает по Streamable HTTP по адресу:

```text
https://employ-woman-g1q2.us-east-1.onlizard.com/mcp
```

Клиент с поддержкой OAuth авторизует вас при первом использовании. Другие клиенты передают API-ключ `liz_` в заголовке `Authorization: Bearer`; создайте его командой `lizard keys create <name>`.

Добавьте его в Claude Code:

```bash
claude mcp add --transport http lizard https://employ-woman-g1q2.us-east-1.onlizard.com/mcp
```

Для Cursor и других клиентов, настраиваемых через JSON:

```json
{
  "mcpServers": {
    "lizard": {
      "url": "https://employ-woman-g1q2.us-east-1.onlizard.com/mcp",
      "headers": { "Authorization": "Bearer liz_your_key" }
    }
  }
}
```

Запуск пробного периода, оплата и отмена Pro выполняются на странице Billing. Если аккаунту нужно оплатить тариф, прежде чем он сможет что-то создать, ошибка инструмента содержит `PAYMENT_REQUIRED` и ссылку, которую нужно открыть.

<span id="hosting-your-own-mcp-server" />

## Хостинг собственного MCP-сервера

Агент, использующий Lizard CLI, и приложение, предоставляющее MCP — это отдельные рабочие процессы. Команды CLI, описанные выше, не предоставляют MCP-транспорт. Чтобы развернуть собственный сервер с Streamable HTTP, следуйте [руководству по удаленному MCP](/guides/deploy-mcp-server).
