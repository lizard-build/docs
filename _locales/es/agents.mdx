# Agentes de programación

Claude Code, Codex, Cursor y otros agentes de programación con IA crean sandboxes, despliegan apps y las gestionan en Lizard (lizard.build) mediante Lizard CLI. Instala Lizard Skill una vez con `npx skills add lizard-build/skill -g`; después, el agente carga la guía integrada en la CLI con `lizard skills get core --json` y lee los flags de cualquier comando con `--help --json`. Así obtiene la sintaxis de la versión instalada. Los clientes compatibles con MCP, como ChatGPT y Claude, pueden usar [Lizard MCP](#lizard-mcp) en su lugar. Para un despliegue completo desde un agente, consulta [Desplegar desde Claude Code, Codex o Cursor](/guides/deploy-from-coding-agent).

<span id="the-embedded-skill" />

## La skill integrada

La CLI incluye la guía de uso de su propia versión. Un agente la lee con:

```bash
lizard skills get core --json
```

Esto devuelve `{ name, frontmatter, content, references, … }`: `content` es la guía principal (sandboxes, despliegues, bases de datos, secretos, descubrimiento, códigos de salida), y `references` lista las guías detalladas de despliegues, sandboxes y Lizard SDK. Subcomandos relacionados:

```bash
lizard skills list                     # available embedded skills
lizard skills get core                 # the core guide
lizard skills get core --ref deploys   # one reference: deploys, sandboxes or sdk
lizard skills get core --full          # the guide plus every reference
lizard skills path                     # where skills are stored
```

Como la guía viene incluida con el binario, `lizard upgrade` también actualiza las instrucciones del agente.

<span id="self-describing-commands" />

## Comandos autodescriptivos

Los agentes descubren la sintaxis exacta de los flags en tiempo de ejecución en lugar de depender de una sintaxis memorizada:

```bash
lizard --help --json                # full command tree + exit codes
lizard <cmd> --help --json          # a specific command's schema
```

Consulta [JSON y automatización](/cli/json).

## Inicialización dentro de un agente

Un flujo típico de un agente:

1. **Cargar la guía:** `lizard skills get core --json` → leer `content` y luego la referencia que necesite la tarea (`--ref sandboxes`, `deploys` o `sdk`).
2. **Comprobar la autenticación al ejecutar la tarea:** ejecuta la tarea del usuario. Con el código de salida `2` (`NOT_AUTHENTICATED`), el campo `body.login` del error trae los enlaces de inicio de sesión: pregunta al usuario si inicia sesión con GitHub o con Google, entrégale ese enlace de `authUrls` y reintenta cuando el navegador muestre "CLI authorized". [`lizard login --json`](/cli/login#output-for-agents) imprime los mismos enlaces y, con la sesión iniciada, informa del plan en `account.state`.
3. **Iniciar la prueba si se solicita:** una cuenta nueva no tiene plan, así que su primera creación falla con HTTP 402 (`code: "PAYMENT_REQUIRED"`, código de salida `1`). Pregunta primero al usuario. Si acepta, ejecuta `lizard billing start --json`, entrega al usuario la `url` de Checkout y reintenta cuando haya añadido una tarjeta.
4. **Resolver el contexto antes de modificar:** `lizard status` (enlace cwd) y `lizard ps --json` (servicios). En una carpeta sin enlazar, `up`, `add`, `sandbox create` y los demás comandos de proyecto usan el proyecto predeterminado de la cuenta.
5. **Actuar** usando la guía: `sandbox create`, `add`, `up`, `secrets`, `domain`, etc., siempre con `--json`.

Si el binario `lizard` no está presente, instálalo primero. En macOS o Linux, usa el script de instalación:

```bash
curl -fsSL https://lizard.build/install.sh | bash
```

No necesita Node.js ni `sudo`, y enlaza `lizard` en una carpeta que ya está en el `PATH`, así que el agente puede llamarlo en la misma sesión. Si el script avisa de que quizá no se encuentre `lizard`, llama a `~/.lizard/bin/lizard`. Sin terminal, el script termina con la salida de `lizard login --json`: los enlaces de inicio de sesión y una `instruction`. Entrega el enlace al usuario. En Windows, ejecuta esto en PowerShell:

```powershell
irm https://lizard.build/api/cli/install.ps1 | iex
```

O instala desde npm en cualquier sistema (requiere Node.js 20 o posterior):

```bash
npm install -g @lizard-build/cli
```

<span id="conventions-agents-should-follow" />

## Convenciones que los agentes deben seguir

- **Pasa siempre `--json`** en llamadas no interactivas.
- **Confirma las acciones destructivas** (eliminar servicio, quitar addon, sobrescribir un secreto de todo el proyecto, reinicio de prod) con el usuario: los propios prompts de la CLI solo se activan en un TTY.
- **Limita los secretos al servicio que los consume** por defecto; reserva `--global` para valores que sepas que son públicos. Consulta [Variables y secretos](/variables#scoping).
- **No escribas Dockerfiles sin que se soliciten**: lizardpack detecta automáticamente la mayoría de los stacks. Prueba primero un despliegue. Consulta [Pipeline de build](/concepts/build-pipeline).
- **No uses `lizard up` para cambiar un servicio respaldado por git a upload**: usa `service set` + `redeploy`.

<span id="editor-integrations" />

## Integraciones con editores

Lizard Skill incluye las instrucciones iniciales que permiten a los agentes de editores y asistentes cargar la guía cuando la necesiten y usar la CLI que describe esta documentación. Instálala una sola vez para todos tus agentes:

```bash
npx skills add lizard-build/skill -g
```

Funciona con Claude Code, Cursor, Codex, Copilot, Gemini CLI y otros agentes que leen el formato Agent Skills. Para los clientes que usan MCP en lugar de ejecutar comandos de shell, usa [Lizard MCP](#lizard-mcp).

Eso también cubre los IDE con IA: escriben y prueban una app, pero no la alojan. Consulta [desplegar una app creada en Google Antigravity](https://lizard.build/blog/google-antigravity-how-to-deploy-your-app-to-production#deploy-from-the-antigravity-chat), que muestra cómo pedir el despliegue con un solo prompt.

Para que Claude Code o ChatGPT editen la página que tienes abierta en Chrome, usa [Lizard Studio](/studio/getting-started).

<span id="lizard-mcp" />

## Lizard MCP

Lizard MCP permite que ChatGPT, Claude y otros clientes MCP gestionen tus proyectos de Lizard: crear sandboxes, ejecutar comandos y leer o escribir archivos en ellos; crear servicios y addons, redesplegar, [pausar y reanudar](/cli/pause) un servicio, un proyecto o un workspace, dejar que un servicio [duerma cuando está inactivo](/cli/sleep), leer logs y métricas, definir secretos, escalar réplicas y asociar dominios. Es un servidor alojado que usa Streamable HTTP en:

```text
https://employ-woman-g1q2.us-east-1.onlizard.com/mcp
```

Un cliente que admita OAuth te hace iniciar sesión en el primer uso. Otros clientes envían una clave de API `liz_` en la cabecera `Authorization: Bearer`; crea una con `lizard keys create <name>`.

Añádelo a Claude Code:

```bash
claude mcp add --transport http lizard https://employ-woman-g1q2.us-east-1.onlizard.com/mcp
```

Para Cursor y otros clientes configurados mediante JSON:

```json
{
  "mcpServers": {
    "lizard": {
      "url": "https://employ-woman-g1q2.us-east-1.onlizard.com/mcp",
      "headers": { "Authorization": "Bearer liz_your_key" }
    }
  }
}
```

Puedes iniciar la prueba, pagar, cambiar de plan y cancelar desde la página de Billing. Cuando la cuenta tiene que pagar antes de poder crear algo, el error de la herramienta incluye `PAYMENT_REQUIRED` y el enlace que hay que abrir.

<span id="hosting-your-own-mcp-server" />

## Alojar tu propio servidor MCP

Un agente que usa Lizard CLI y una aplicación que expone MCP son flujos de trabajo separados. Los comandos de CLI anteriores no proporcionan un transporte MCP. Para desplegar tu propio servidor con Streamable HTTP, sigue la [guía de MCP remoto](/guides/deploy-mcp-server).
