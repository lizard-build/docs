# Inicio rápido de apps

Lanza tu primera app en Lizard en unos minutos. Se crea una cuenta de Lizard automáticamente la primera vez que `lizard login`. Instalarás Lizard CLI, iniciarás sesión, empezarás la prueba de Pro y desplegarás, ya sea directamente desde un repositorio de GitHub o desde un directorio local.

<span id="1-install-the-cli" />

## 1. Instala la CLI

En macOS o Linux, ejecuta el script de instalación:

```bash
curl -fsSL https://lizard.build/install.sh | bash
```

Instala el binario `lizard` en `~/.lizard/bin`, añade esa carpeta a tu `PATH` en `~/.zshrc` o `~/.bashrc`, y enlaza `lizard` en una carpeta que ya está en tu `PATH`, así que funciona al momento en esta terminal. Desde entonces el binario se actualiza solo, salvo en CI. Si el script avisa de que quizá no se encuentre `lizard`, abre una terminal nueva. Comprueba la versión:

```bash
lizard --version
```

En Windows, ejecuta esto en PowerShell:

```powershell
irm https://lizard.build/api/cli/install.ps1 | iex
```

**O instala desde npm** (requiere Node.js 18+):

```bash
npm install -g @lizard-build/cli
```

> **No uses `npx`.** Usa siempre el binario `lizard` instalado globalmente. Ejecutar `npx @lizard-build/cli` descarga una copia temporal cuya versión puede diferir de la plataforma. Para actualizar más adelante una instalación de npm, ejecuta `npm install -g @lizard-build/cli@latest`.

> **¿Errores de permisos (EACCES)?** No uses `sudo`. Usa el script de instalación de arriba, que no necesita permisos de administrador, o haz que npm apunte a un prefijo propiedad de tu usuario:
> ```bash
> mkdir -p ~/.npm-global
> npm config set prefix ~/.npm-global
> echo 'export PATH=~/.npm-global/bin:$PATH' >> ~/.zshrc && source ~/.zshrc
> npm install -g @lizard-build/cli
> ```

<span id="2-log-in" />

## 2. Inicia sesión

```bash
lizard login
```

Esto abre tu navegador para autenticarte y luego vuelve a tu terminal una vez que confirmes. En CI u otros entornos no interactivos, autentícate con un token en su lugar:

```bash
export LIZARD_TOKEN=liz_xxx
# or
lizard login --token liz_xxx
```

Las claves de API empiezan por `liz_`. Crea una con `lizard keys create <name>`. `LIZARD_API_KEY` funciona en lugar de `LIZARD_TOKEN`.

Comprueba quién eres en cualquier momento:

```bash
lizard whoami
```

<span id="3-start-the-pro-trial" />

## 3. Empieza la prueba de Pro

Una cuenta nueva no tiene plan, así que crear cualquier cosa devuelve HTTP 402 con un enlace de Checkout. Empieza primero la prueba de Pro de 7 días:

```bash
lizard billing start
```

Esto abre Stripe Checkout, donde añades una tarjeta. La prueba incluye $5 en créditos de prueba y no se cobra nada hasta que termina. Consulta [Facturación](/platform/billing).

<span id="4-deploy" />

## 4. Despliega

Elige la ruta que coincida con dónde vive tu código.

<span id="option-a--deploy-a-github-repo-recommended" />

### Opción A — Desplegar un repositorio de GitHub (recomendado)

Si tu código está en GitHub, crea un servicio directamente desde el repositorio. Lizard lo clona, detecta automáticamente el stack, lo compila y devuelve una URL activa:

```bash
lizard add -r your-org/your-app
```

A partir de entonces, los pushes a la rama seguida volverán a desplegar automáticamente. Para repositorios privados, conecta primero la GitHub App:

```bash
lizard git connect
```

<span id="option-b--deploy-local-code" />

### Opción B — Desplegar código local

Desde dentro del directorio de tu proyecto, sube y despliega la carpeta actual (respeta `.gitignore`):

```bash
lizard up
```

Si el directorio aún no está vinculado a un proyecto, `up` creará o seleccionará uno de forma interactiva. En CI, vincúlalo explícitamente primero con `lizard init --name my-project`.

De cualquier forma, cuando termine la compilación obtendrás una URL generada como `https://your-app-x1y2z.onlizard.com`.

<span id="5-watch-it-build-and-run" />

## 5. Observa cómo compila y se ejecuta

```bash
lizard ps          # services in the project, with status + URL
lizard logs        # last runtime log lines
lizard logs --build  # the most recent build's logs
lizard open        # open the project in the dashboard
```

<span id="6-add-a-database-optional" />

## 6. Añade una base de datos (opcional)

Aprovisiona Managed Postgres y haz referencia a él desde tu servicio:

```bash
lizard add postgres
lizard secrets set DATABASE_URL='${{postgres.DATABASE_PRIVATE_URL}}' --service your-app
lizard redeploy --service your-app
```

La referencia `${{postgres.DATABASE_PRIVATE_URL}}` se resuelve en el momento del despliegue y se conecta por la red privada del proyecto. Coincide con el nombre actual del addon, así que actualiza la referencia si le cambias el nombre al addon. Las credenciales no rotan solas; un servicio recoge los valores nuevos en su siguiente despliegue. Consulta [Managed Addons](/addons).
