# Desplegar desde GitHub

Conecta un repositorio de GitHub y Lizard (lizard.build) compila y vuelve a desplegar tu app en cada push a la rama seguida: git push to deploy. Ejecuta `lizard add -r owner/repo` para crear el servicio; para un repositorio privado, conecta primero la GitHub App de Lizard con `lizard git connect`. Es la forma recomendada de ejecutar una app que guardas en GitHub. Para código sin remoto, [despliega desde código local](/deploy/upload).

<span id="create-a-service-from-a-repo" />

## Crear un servicio desde un repositorio

```bash
lizard add -r your-org/your-app
```

Esto crea un servicio con origen `github` y empieza el primer build en segundo plano: Lizard clona el repositorio y detecta el stack ([lizardpack](/concepts/build-pipeline)). El comando no muestra ninguna URL. Sigue el build con `lizard logs --build --service <name>`; cuando el servicio esté en marcha, `lizard ps` muestra la URL. Banderas útiles:

| Bandera | Propósito |
|------|---------|
| `-r, --repo <owner/repo>` | Repositorio de origen |
| `-n, --name <name>` | Nombre del servicio (se usa en las referencias `${{name.KEY}}` y en el panel) |
| `-v, --variables <K=V>` | Inicializar una variable de entorno; repetible |
| `--region <code>` | Región donde desplegar |
| `--no-deploy` | Adjunta el repositorio pero omite el primer build |

<span id="private-repositories" />

## Repositorios privados

Conecta la GitHub App de Lizard una vez por cuenta para conceder acceso a repositorios privados:

```bash
lizard git connect
lizard git status        # show connection + repo status
```

También puedes conectar y gestionar el acceso a repositorios desde la página de **integración de GitHub** en el panel (`lizard open`).

<span id="point-an-existing-service-at-a-repo" />

## Apuntar un servicio existente a un repositorio

Para cambiar un servicio a un origen git (o cambiar el repositorio/rama):

```bash
lizard service set api \
  --set sourceType=github \
  --set repoUrl=https://github.com/your-org/your-app \
  --set branch=main
```

Cambiar un campo de build vuelve a compilar un servicio en ejecución. Si después ejecutas `redeploy`, [cancela ese build y empieza otro](/deploy/troubleshooting/double-build). Un servicio que se ha caído o que nunca se ha desplegado necesita `lizard redeploy`.

> **Nota:** `lizard up` siempre fuerza `sourceType=upload`. No lo uses para actualizar un servicio respaldado por git: haz push al remoto o usa `lizard redeploy` en su lugar. En una carpeta sin servicio vinculado, `up` elige el servicio que se llama como la carpeta o como indica `package.json`, así que en un clon del repositorio puede convertir tu servicio de GitHub en uno de subida.

<span id="auto-redeploy-on-push" />

## Redespliegue automático en push

Una vez que `repoUrl` está configurado, los push a la `branch` correspondiente redespliegan automáticamente mediante el webhook de GitHub. Conecta la GitHub App de Lizard (`lizard git connect`) para que Lizard reciba los eventos de push del repositorio. Para limitar qué push activan un redespliegue:

- **`rootDirectory`**: solo compila un subdirectorio (monorepos).
- **`watchPatterns`**: solo redespliega cuando cambian rutas coincidentes.

```bash
lizard service set api --set watchPatterns='apps/api/**,packages/**'
```

Para que los push no desplieguen, desactiva **Auto-deploy** en la configuración del servicio en el panel. Un servicio [en pausa](/cli/pause) también ignora los push hasta que lo reanudes.

<span id="switch-branches" />

## Cambiar de rama

```bash
lizard git checkout api staging      # move the `api` service to the `staging` branch and redeploy
```

## Monorepos

Para un repositorio que contiene varias apps, crea un servicio por app y configura su `rootDirectory` con la subruta:

```bash
lizard add -r your-org/monorepo -n api --no-deploy
lizard service set api --set rootDirectory=apps/api
lizard redeploy --service api
```

Si tu directorio actual es una subapp dentro de un repositorio cuyo directorio padre ya está vinculado, añade el servicio en el proyecto del padre y configura `rootDirectory` con la subruta del cwd.
