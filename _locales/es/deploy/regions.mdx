<span id="regions" />

# Regiones

Los servicios y addons se aprovisionan en una región. Lista las regiones disponibles para tu cuenta y elige una al crear.

<span id="list-regions" />

## Listar regiones

```bash
lizard regions
lizard regions --json
```

<span id="choose-a-region" />

## Elegir una región

Pasa `--region <code>` al crear un servicio o addon:

```bash
lizard add -r your-org/your-app --region <code>
lizard add postgres --region <code>
lizard up --region <code>          # new services only
```

Los proyectos no tienen una región predeterminada. Sin `--region`, `lizard add` crea en `us-east-1`, y `lizard up` crea un servicio nuevo en la región del servidor de API que gestiona la solicitud. Pasa `--region` para elegir.

> **Ubica juntos los recursos con estado.** Coloca un servicio y los addons con los que se comunica (Managed Postgres, Managed Redis, Managed Object Storage) en la **misma región** para mantener baja la latencia y evitar cargos por datos entre regiones.

<span id="generated-domains" />

## Dominios generados

Cada servicio recibe un dominio generado con TLS automático: `<name>-<suffix>.onlizard.com` para los servicios nuevos, mientras que los servicios más antiguos conservan `<words>.<region>.onlizard.com`. [Managed Object Storage](/addons/storage) usa un host de gateway por región: `s3-us-east-1.onlizard.com` para `us-east-1` y `s3-eu-west-1.onlizard.com` para `eu-west-lim-a`. Para asociar tu propio nombre de host, consulta [Networking](/networking).
