# lizard domain

Muestra o lista los dominios de un servicio, o adjunta uno personalizado.

<span id="usage" />

## Uso

```bash
lizard domain [hostname] [flags]
```

El hostname es un argumento posicional: no existe el subcomando `add`. Ejecutar `lizard domain` sin argumentos muestra el dominio actual del servicio, o genera uno si no tiene ninguno. Alias: `lizard domains`.

<span id="flags" />

## Banderas

| Bandera | Descripción |
|------|-------------|
| `-s, --service <name>` | Servicio |
| `-p, --project <id>` | Nombre, slug o ID del proyecto |
| `--port <n>` | Se ignora: un dominio siempre lleva al puerto del contenedor del servicio. Cambia ese puerto con [`lizard port`](/cli/port) |
| `-f, --force` | Mueve el dominio aquí si está adjunto a otro de tus servicios |

Los subcomandos usan las mismas banderas `-s` y `-p`. Verifica y elimina un dominio en el servicio al que lo adjuntaste.

<span id="subcommands" />

## Subcomandos

### `lizard domain generate`

Da al servicio un subdominio de `*.onlizard.com`. Si ya tiene uno, `generate` lo devuelve. Falla mientras el servicio usa un dominio personalizado; elimínalo primero.

### `lizard domain list`

Lista los dominios del servicio y los dominios personalizados que aún esperan la verificación de DNS, con los registros que hay que crear (alias `ls`).

### `lizard domain verify <hostname>`

Comprueba el registro TXT y activa el dominio. TLS se aprovisiona automáticamente.

### `lizard domain delete <hostname>`

Elimina un dominio (alias `rm`).

| Bandera | Descripción |
|------|-------------|
| `-y, --yes` | Omitir confirmación |

<span id="examples" />

## Ejemplos

<span id="show-the-current-domain" />

### Mostrar el dominio actual

```bash
lizard domain
```

<span id="generate-a-subdomain" />

### Generar un subdominio

```bash
lizard domain generate
```

<span id="attach-a-custom-domain" />

### Adjuntar un dominio personalizado

```bash
lizard domain app.example.com --service web
```

Lizard devuelve los registros DNS que debes crear: un registro `CNAME` para el hostname y, a menos que ya hayas verificado el dominio, un registro `TXT` en `_lizard-verify.<apex domain>` (para `app.example.com`, es `_lizard-verify.example.com`). Agrégalos en tu proveedor de DNS y luego verifica en el mismo servicio:

```bash
lizard domain verify app.example.com --service web
```

Para un dominio raíz como `example.com`, la mayoría de los proveedores de DNS no permiten un `CNAME`. Crea en su lugar un registro `ALIAS` o `ANAME` con el mismo destino, o usa el CNAME flattening de tu proveedor.

<span id="list-a-services-domains" />

### Listar los dominios de un servicio

```bash
lizard domain list --service web
```

<span id="move-a-domain-from-another-of-your-services" />

### Mover un dominio desde otro de tus servicios

```bash
lizard domain app.example.com --service web --force
```

<span id="remove-a-domain" />

### Eliminar un dominio

```bash
lizard domain delete app.example.com --service web
lizard domain rm app.example.com --service web --yes
```
