# lizard up

Sube el directorio actual y lo despliega.

<span id="usage" />

## Uso

```bash
lizard up [path] [flags]
```

`up` empaqueta tu árbol de trabajo (o `path`) como un tarball, lo envía a los nodos de compilación y lo despliega. Fuerza `sourceType=upload` en el servicio de destino, transmite los logs de compilación por SSE e imprime la URL activa al terminar.

Si el directorio actual todavía no está vinculado a un proyecto, `up` ejecuta primero `init`. En un TTY eso es interactivo; en un entorno sin TTY (CI) **no** creará un proyecto silenciosamente: devolverá un error y te pedirá que ejecutes `lizard init --name <project>` (o que pases `--project <project>` a `up`), para evitar que un error tipográfico genere un proyecto vacío.

<span id="flags" />

## Banderas

| Bandera | Descripción |
|------|-------------|
| `-s, --service <name>` | Apunta a un servicio existente |
| `-p, --project <id>` | Nombre, slug o ID del proyecto |
| `--build-command <cmd>` | Sobrescribe el comando de compilación |
| `--start-command <cmd>` | Sobrescribe el comando de inicio |
| `--pre-deploy-command <cmd>` | Se ejecuta antes del comando de inicio cada vez que arranca un contenedor (cada réplica, cada reinicio). Requiere un comando de inicio; haz que sea seguro ejecutarlo muchas veces |
| `--port <number>` | Puerto del contenedor (`0` = modo worker). Los servicios nuevos usan `3000` por defecto, salvo que un `EXPOSE` del Dockerfile lo defina |
| `--region <code>` | Región para un servicio nuevo; se ignora en un servicio existente |
| `-d, --detach` | Inicia el despliegue y sale sin transmitir logs |
| `-c, --ci` | Transmite solo los logs de compilación y sale cuando termina la compilación |
| `--no-gitignore` | Sube todo, ignorando `.gitignore` |

<span id="subcommands" />

## Subcomandos

### `lizard up status <app-id>`

Muestra el estado de un servicio, su URL y el estado de su última compilación. Pasa el ID de servicio que imprime `up --detach`.

<span id="examples" />

## Ejemplos

<span id="deploy-the-current-directory" />

### Desplegar el directorio actual

```bash
lizard up
```

<span id="deploy-to-a-specific-service-with-a-custom-start-command-and-port" />

### Desplegar en un servicio específico con un comando de inicio y un puerto personalizados

Crea primero el servicio con nombre con `lizard add --service api` si no existe.

```bash
lizard up --service api --start-command "node server.js" --port 8080
```

<span id="deploy-headlessly-in-ci" />

### Desplegar sin interacción en CI

```bash
export LIZARD_TOKEN=liz_xxx
lizard init --name my-project
lizard add --service api
lizard up --ci --service api
```

Omite `lizard add` cuando el servicio ya exista. Una compilación o un despliegue fallido sale con el código `1`. Con `--ci`, el código de salida solo cubre la compilación, así que revisa `lizard ps --json` antes de marcar la versión como terminada. `--detach` sale con `0` en cuanto se acepta la subida. Consulta [framework setup](/framework-guides#prepare-the-project).
