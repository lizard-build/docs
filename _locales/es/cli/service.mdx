# lizard service

Administra la configuración, el origen y el ciclo de vida de un servicio individual.

<span id="usage" />

## Uso

```bash
lizard service set [service] [flags]
lizard service show [service] [flags]
lizard service rename <new-name> [flags]
lizard service delete [service] [flags]
lizard service logs [service] [flags]
lizard service link [name]
```

<span id="subcommands" />

## Subcomandos

### `lizard service set`

Aplica cambios de compilación/inicio/origen/variables/cambio de nombre a un servicio.

| Bandera | Descripción |
|------|-------------|
| `--set <path>=<value>` | Establece un campo (repetible; requiere el argumento `service`) |
| `-f, --file <path>` | Archivo de configuración JSON para aplicar |
| `--force` | Sobrescribe incluso si cambió de forma remota |

Los campos comunes son planos y se asignan 1:1 al esquema wire: `sourceType`, `repoUrl`, `branch`, `rootDirectory`, `dockerfilePath`, `buildCommand`, `startCommand`, `preDeployCommand`, `watchPatterns`, `containerPort`, `cpuLimit` (por ejemplo `2000m`), `memoryLimit` (por ejemplo `2Gi`), `name`. `variables.<KEY>=<value>` establece un secreto del servicio, igual que `lizard secrets set --service`.

`service set` usa concurrencia optimista mediante `configRevision`. Ante un `409`, vuelve a leer la configuración con `lizard service show`, reconcilia y reintenta, o pasa `--force`.

### `lizard service show`

Muestra la configuración actual del servicio como JSON. Usa `-s` para limitarlo a un servicio.

### `lizard service rename <new-name>`

Cambia el nombre de un servicio o addon: el vinculado, o el que indiques con `-s`. Las referencias usan el nombre actual del destino, así que después de cambiar el nombre actualiza cada `${{old-name.KEY}}` al nuevo nombre.

### `lizard service delete`

Elimina un servicio (alias `rm`). `-y, --yes` omite la confirmación; sin un TTY es obligatorio.

### `lizard service logs`

Transmite los registros de un servicio (consulta también [lizard logs](/cli/logs)).

| Bandera | Descripción |
|------|-------------|
| `--build` | Muestra los registros de la última compilación |
| `-n, --tail <n>` | Imprime las últimas N líneas (hasta 2000) y termina; `--tail all` imprime 2000 |
| `--page <n>` | Recorre los registros más antiguos, 200 líneas por página (1 = la más reciente) |

### `lizard service link`

Vincula un servicio al directorio actual.

<span id="examples" />

## Ejemplos

<span id="update-a-services-build-and-start-commands" />

### Actualizar los comandos de compilación e inicio de un servicio

```bash
lizard service set api --set branch=main --set buildCommand="npm run build"
```

<span id="inspect-a-services-full-configuration" />

### Inspeccionar la configuración completa de un servicio

```bash
lizard service show -s api
```

<span id="delete-a-service-without-a-confirmation-prompt" />

### Eliminar un servicio sin un aviso de confirmación

```bash
lizard service delete -y
```
