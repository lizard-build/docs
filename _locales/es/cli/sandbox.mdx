# lizard sandbox

Crea y gestiona [Sandboxes](/sandboxes) desde la terminal. Alias: `lizard sb`.

<span id="usage" />

## Uso

```bash
lizard sandbox create [flags]
lizard sandbox list [flags]
lizard sandbox exec <id> -- <command>
lizard sandbox ssh <id>
lizard sandbox fork <id> [flags]
lizard sandbox rm <id> [flags]
```

Cada sandbox pertenece a un proyecto: el que indiques con `-p`; si no, el vinculado al directorio actual; y si no, el proyecto predeterminado de tu cuenta (el proyecto más antiguo de tu espacio de trabajo personal).

<span id="subcommands" />

## Subcomandos

### `lizard sandbox create`

Crea un sandbox y muestra su ID.

| Bandera | Descripción |
|------|-------------|
| `-t, --template <name>` | Plantilla (por defecto `base`). Plantillas habilitadas: `base`, `interpreter`, `codex`, `desktop`, `desktop-camoufox` (solo en US East), `opencode`, `pi`, `prime`, `claude`. El servidor comprueba la lista de la región |
| `-s, --size <size>` | `small`, `medium` (por defecto) o `large` |
| `--timeout <ms>` | Duración en milisegundos (por defecto `300000`, cinco minutos); `0` desactiva la caducidad |
| `--region <code>` | Región donde crear el sandbox |
| `--snapshot <id>` | Partir de un snapshot guardado; no se puede combinar con `--size` |
| `--volume <name-or-id>` | Conectar un [Persistent Volume](/cli/volume) |
| `--with-token [key]` | Iniciar sesión en `lizard` dentro del sandbox con una clave nueva limitada al proyecto del sandbox y que se elimina con el sandbox. La clave `liz_` que pases o, sin valor, la clave `liz_` con la que ejecutas el comando solo autoriza la solicitud; un inicio de sesión desde el navegador no tiene ninguna. La plantilla `base` no incluye `lizard` |
| `-p, --project <id>` | Proyecto (por defecto, el vinculado; si no, tu proyecto predeterminado) |

Lizard factura cada tamaño por segundo con una tarifa fija mientras el sandbox está en marcha, incluido el tiempo inactivo. El precio incluye el disco local y [2 TB de tráfico saliente por cuenta durante los últimos 30 días](/platform/limits#sandbox-egress). Una pausa completada detiene los cargos de cómputo; el almacenamiento en Persistent Volumes mantiene la [tarifa de volúmenes](/cli/volume), tanto si el volumen está conectado como si no.

| Tamaño | vCPU | Memoria | Disco | Precio |
|------|------|--------|------|-------|
| `small` | 2 | 4 GiB | 5 GB | $0.0162/h |
| `medium` | 4 | 8 GiB | 20 GB | $0.0324/h |
| `large` | 8 | 16 GiB | 50 GB | $0.0648/h |

Cualquier proceso dentro del sandbox puede leer la clave que instala `--with-token` y usarla en el proyecto del sandbox hasta que se elimine el sandbox.

Hasta que empiece tu prueba o tu plan Pro, `create` devuelve HTTP 402 con un enlace de Checkout; ejecuta `lizard billing start`. Durante la prueba puedes ejecutar 5 sandboxes a la vez, y 100 después de la primera factura pagada. Los sandboxes en pausa no cuentan. Consulta [Límites](/platform/limits#sandbox-account-limits).

### `lizard sandbox list`

Lista los sandboxes del proyecto vinculado (alias `ls`).

| Bandera | Descripción |
|------|-------------|
| `-p, --project <id>` | Listar este proyecto en su lugar |
| `--all` | Listar todos los sandboxes de todos tus espacios de trabajo |

### `lizard sandbox rm <id>`

Elimina un sandbox (alias `delete` y `kill`).

| Bandera | Descripción |
|------|-------------|
| `-y, --yes` | Omitir la confirmación |

### `lizard sandbox timeout <id> <ms>`

Fija una nueva duración, contada desde ahora, en milisegundos (al menos `1000`). No es un temporizador de inactividad: ejecutar comandos no lo reinicia.

### `lizard sandbox exec <id> -- <command>`

Ejecuta un comando dentro del sandbox mediante `sh -c`, transmite su salida y termina con su código de salida.

<span id="sandbox-ssh" />

### `lizard sandbox ssh <id>`

Abre una shell interactiva en un sandbox en ejecución (alias `shell`). Usa tu sesión de Lizard, así que no hay claves SSH que configurar; una clave de API con ámbito solo llega a los sandboxes de su ámbito. Ctrl-C, las flechas y el autocompletado con tabulador van al sandbox. Escribe `exit` o pulsa Ctrl-D para salir.

Necesita una terminal interactiva; en un script, usa `lizard sandbox exec`. No es el protocolo SSH, así que los clientes SSH, `scp` y el reenvío de puertos no funcionan.

### `lizard sandbox expose <id> <port>`

Asigna una URL HTTPS a un puerto del sandbox. El puerto es privado: las solicitudes necesitan el token de acceso del sandbox, ya sea en la cabecera `X-Lizard-Access-Token` o como el parámetro de consulta `lizard_token`, que la URL mostrada ya incluye. Las solicitudes sin él reciben HTTP 401. Con `--json`, el resultado también incluye `hostname` y `accessToken`.

`lizard sandbox unexpose <id> <port>` elimina la URL.

### `lizard sandbox desktop <id>`

Inicia el escritorio gráfico de un sandbox creado con `-t desktop` y muestra su URL para el navegador y una URL de solo visualización. Trata ambos enlaces como contraseñas.

| Bandera | Descripción |
|------|-------------|
| `--view-only` | Mostrar o abrir únicamente la URL de solo visualización |
| `--resolution <WxH>` | Tamaño de pantalla, de 640x480 a 3840x2160 |
| `--open` | Abrir el escritorio en el navegador |
| `--status` | Mostrar el estado y las URL del escritorio sin iniciarlo |
| `--stop` | Detener el escritorio y eliminar su URL |

<span id="sandbox-vnc" />

### `lizard sandbox vnc <id>`

Conecta una app VNC (Compartir Pantalla de macOS, TigerVNC, RealVNC) al escritorio de un sandbox creado con `-t desktop`. El escritorio no tiene un puerto VNC público, así que la CLI escucha en `localhost` y lleva cada conexión al sandbox a través de un WebSocket seguro. Inicia el escritorio si hace falta, muestra la dirección y la contraseña VNC, y sigue en marcha hasta que pulses Ctrl-C.

| Bandera | Descripción |
|------|-------------|
| `--port <port>` | Puerto local (por defecto `5900`; si está ocupado, el siguiente libre) |
| `--view-only` | Usar la contraseña de solo visualización: ver, sin controlar |
| `--open` | Abrir la dirección en tu app VNC (`vnc://`, Compartir Pantalla en macOS) |

<span id="pause-resume-and-snapshots" />

### Pausa, reanudación y snapshots

| Comando | Qué hace |
|---------|--------------|
| `lizard sandbox pause <id>` | Guarda la memoria y los procesos y pausa el sandbox. Una pausa completada detiene los cargos de cómputo; el almacenamiento en Persistent Volumes se cobra aparte |
| `lizard sandbox resume <id>` | Vuelve a iniciar un sandbox en pausa con su memoria y sus archivos guardados |
| `lizard sandbox snapshot <id> --name <name>` | Guarda un sandbox en ejecución, con su memoria y sus archivos, como un snapshot que te pertenece. `--scope` fija dónde se puede restaurar: `workspace` (por defecto) en cualquier proyecto del espacio de trabajo del sandbox, `user` en cualquier proyecto de cualquiera de tus espacios de trabajo, `project` solo en su propio proyecto |
| `lizard sandbox restore <snapshot-id>` | Inicia un sandbox nuevo desde un snapshot, en la región del snapshot. `-p <project>` elige el proyecto (por defecto, el proyecto del volumen; si no, el del snapshot), `--volume <name-or-id>` monta un volumen en `/workspace` y `--timeout <ms>` fija la duración (por defecto `300000`) |
| `lizard sandbox snapshots` | Lista los snapshots tomados en el proyecto (`-p` para otro proyecto, `--mine` para todos los snapshots que tomaste) |
| `lizard sandbox snapshot-scope <snapshot-id> <scope>` | Cambia dónde se puede restaurar un snapshot que tomaste: `user`, `workspace` o `project` |
| `lizard sandbox snapshot-rm <snapshot-id>` | Elimina un snapshot (alias `snapshot-delete`; `-y` omite la confirmación) |

`pause`, `resume` y `snapshot` esperan hasta que termina el trabajo; pasa `--no-wait` para volver en cuanto quede en cola. Consulta [Pausa, reanudación y snapshots](/sandboxes/quickstart#pause-and-resume) para ver qué conserva cada paso.

Un snapshot de un sandbox con un volumen conectado incluye una copia de los archivos del volumen tal como estaban al capturar. Cada restauración recibe esa copia y no acepta `--volume`, y cualquiera que pueda restaurar el snapshot puede leer esos archivos. `--volume` solo funciona con un snapshot de un sandbox que no tenía volumen, y el volumen debe estar en la región del snapshot.

<span id="sandbox-fork" />

### `lizard sandbox fork <id>`

Inicia copias en vivo de un sandbox en ejecución. Lizard pausa el sandbox un momento, captura una vez su memoria, sus procesos y sus archivos, y arranca cada copia desde esa captura. El original sigue en ejecución con el mismo ID y la misma duración. Prepara un sandbox (herramientas instaladas, app cargada) y luego haz fork para repartir el trabajo entre copias sin repetir la preparación.

| Bandera | Descripción |
|------|-------------|
| `-n, --count <n>` | Copias que iniciar, de 1 a 100 (por defecto `1`) |
| `--timeout <ms>` | Duración de cada copia, al menos `1000`; por defecto, la duración del original |

Cada copia es un inicio de sandbox: cuenta para los [límites de sandboxes en ejecución y de inicios](/platform/limits#sandbox-account-limits), se ejecuta con el tamaño del original y se factura según ese tamaño. Con `--json`, la salida tiene una entrada por copia: `{"sandbox": {...}}` o `{"error": "..."}`. Si alguna copia no pudo iniciarse, el comando sale con `1`, y las copias que sí se iniciaron siguen en ejecución hasta que las elimines. No puedes hacer fork de un sandbox pausado ni de uno con un volumen conectado (HTTP 409).

### `lizard sandbox files`

| Comando | Qué hace |
|---------|--------------|
| `lizard sandbox files ls <id> [path]` | Lista un directorio (por defecto `/`) |
| `lizard sandbox files cat <id> <path>` | Muestra un archivo |
| `lizard sandbox files put <id> <local> <remote>` | Sube un archivo local |
| `lizard sandbox files get <id> <remote> <local>` | Descarga un archivo |
| `lizard sandbox files rm <id> <path>` | Elimina un archivo o un directorio |

<span id="coding-agents" />

### Agentes de programación

Ejecuta un agente de programación dentro de un sandbox con tus propias credenciales. Conéctalas antes con [`lizard agents`](/cli/agents). Crea el sandbox desde una plantilla de agente (`codex`, `claude`, `opencode`, `pi` o `prime`); la plantilla `base` no tiene Node.js y no puede ejecutar agentes.

`lizard sandbox prompt <id> <prompt...>` envía un prompt y transmite lo que hace el agente.

| Bandera | Descripción |
|------|-------------|
| `--agent <name>` | `codex` (por defecto), `claude`, `pi`, `opencode` o `prime` |
| `-c, --conversation <id>` | Continuar esta conversación |
| `--new` | Iniciar una conversación nueva |
| `-m, --model <model>` | Modelo que se usará |
| `--effort <level>` | Esfuerzo de razonamiento: `minimal`, `low`, `medium`, `high` o `xhigh` |
| `--cwd <dir>` | Directorio de trabajo en el sandbox (por defecto `/workspace`) |
| `-v, --verbose` | Mostrar también la salida de los comandos |
| `--no-wait` | Volver en cuanto se acepte el prompt |

Ctrl-C deja de mostrar la actividad; el agente sigue trabajando. `lizard sandbox interrupt <id> [-c <conversation>]` detiene su turno en curso. `lizard sandbox conversations <id>` lista las conversaciones, de la más reciente a la más antigua.

<span id="examples" />

## Ejemplos

<span id="create-a-sandbox-and-run-a-command" />

### Crear un sandbox y ejecutar un comando

```bash
lizard sandbox create --size small --timeout 600000
lizard sandbox exec genuine-toddler-jasj -- python3 -c "print(1 + 1)"
```

<span id="open-a-shell" />

### Abrir una shell

```bash
lizard sandbox ssh genuine-toddler-jasj
```

<span id="attach-a-persistent-volume" />

### Conectar un Persistent Volume

```bash
lizard volume create agent-workdir --size 10
lizard sandbox create --volume agent-workdir
```

<span id="serve-a-port" />

### Servir un puerto

```bash
lizard sandbox exec genuine-toddler-jasj -- sh -c "nohup python3 -m http.server 3000 --bind 0.0.0.0 >/tmp/http.log 2>&1 &"
lizard sandbox expose genuine-toddler-jasj 3000
```

<span id="use-a-desktop-from-a-vnc-app" />

### Usar un escritorio desde una app VNC

```bash
lizard sandbox create -t desktop
lizard sandbox vnc genuine-toddler-jasj --open
```

<span id="run-codex-in-a-sandbox" />

### Ejecutar Codex en un sandbox

```bash
lizard agents login chatgpt
lizard sandbox create -t codex
lizard sandbox prompt genuine-toddler-jasj "add a health check endpoint and test it"
```

<span id="save-and-restore-a-sandbox" />

### Guardar y restaurar un sandbox

```bash
lizard sandbox snapshot genuine-toddler-jasj --name my-app
lizard sandbox snapshots --mine                     # find the snapshot ID
lizard sandbox restore <snapshot-id> -p other-project
```

<span id="fork-a-prepared-sandbox" />

### Hacer fork de un sandbox preparado

```bash
lizard sandbox fork genuine-toddler-jasj -n 8 --json   # 8 copies with the same memory and files
lizard sandbox rm <copy-id>                            # delete a copy when its work is done
```
