# lizard logs

Transmite los logs de ejecución de un servicio, las últimas 200 líneas seguidas de una cola en vivo. Para los logs de ejecución sin `-s`, `logs` no usa el servicio vinculado: en un TTY pregunta qué servicio mostrar; de lo contrario, muestra todos los servicios del proyecto. `--build` y `--restarts` usan el servicio vinculado.

<span id="usage" />

## Uso

```bash
lizard logs [flags]
```

<span id="flags" />

## Banderas

| Bandera | Descripción |
|------|-------------|
| `--build` | Mostrar los logs de compilación en su lugar |
| `--tail <n>` | Imprimir las últimas N líneas (máx. 1000) y salir |
| `-l, --level <level>` | Solo logs de ejecución de este nivel: `error`, `warn`, `info` o `debug` |
| `--restarts [n]` | Listar los últimos N reinicios (por defecto 20) |
| `--restart <id>` | Logs alrededor de un reinicio específico (`latest` para el más reciente) |
| `-s, --service <id>` | Servicio |
| `-p, --project <id>` | Nombre, slug o ID del proyecto |

Con `--json`, `lizard logs` no es un flujo: devuelve las últimas 200 líneas (anúlalo con `--tail N`, máximo 1000) y sale. Úsalo para capturas y scripts; transmite en vivo solo sin `--json`.

<span id="examples" />

## Ejemplos

<span id="tail-runtime-logs" />

### Ver logs de ejecución en tiempo real

```bash
lizard logs
```

<span id="tail-logs-for-a-specific-service" />

### Ver logs de un servicio específico en tiempo real

```bash
lizard logs --service api
```

<span id="get-more-history" />

### Obtener más historial

```bash
lizard logs --tail 1000
```

<span id="filter-by-log-level" />

### Filtrar por nivel de log

```bash
lizard logs --level error
```

<span id="check-the-most-recent-build" />

### Revisar la compilación más reciente

```bash
lizard logs --build
```

<span id="inspect-a-crash-or-restart" />

### Inspeccionar un fallo o reinicio

```bash
lizard logs --restarts
lizard logs --restart latest
lizard logs --restart <id>
```
