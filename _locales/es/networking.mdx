# Redes

Cada servicio recibe un dominio generado `*.onlizard.com` con TLS automático en el momento en que se despliega, sin importar la región. Asocia tu propio hostname cuando estés listo para salir a producción.

<span id="generated-domains" />

## Dominios generados

El dominio predeterminado de un servicio se crea para ti, con la forma `<name>-<suffix>.onlizard.com`. Los servicios más antiguos conservan `<words>.<region>.onlizard.com`. Muéstralo:

```bash
lizard domain                    # show the service's current domain
lizard domain generate           # claim a *.onlizard.com subdomain if the service has none
```

`lizard domain generate` devuelve el dominio generado existente si lo hay, y falla mientras el servicio tenga un dominio personalizado. Los archivos servidos desde [Managed Object Storage](/addons/storage) usan en su lugar un host de gateway: `s3-eu-west-1.onlizard.com` o `s3-us-east-1.onlizard.com`.

<span id="attach-a-custom-domain" />

## Asociar un dominio personalizado

El hostname es un **argumento posicional** — no existe un subcomando `add`:

```bash
lizard domain app.example.com --service web
```

Lizard devuelve los registros DNS que debes crear (un `CNAME` para el hostname y un registro `TXT` para la verificación). Agrégalos en tu proveedor de DNS.

<span id="verify" />

## Verificar

Una vez que el DNS se haya propagado, activa el dominio:

```bash
lizard domain verify app.example.com --service web
```

Esto comprueba el registro `TXT` y activa el dominio. El TLS se aprovisiona automáticamente.

<span id="remove-a-domain" />

## Eliminar un dominio

```bash
lizard domain delete app.example.com --service web
lizard domain rm app.example.com --service web --yes   # alias, skip confirmation
```

<span id="change-the-port-your-service-listens-on" />

## Cambiar el puerto en el que escucha tu servicio

Los dominios dirigen el tráfico al puerto del contenedor del servicio. Si tu servicio escucha en otro puerto, cambia el puerto del contenedor y vuelve a desplegar:

```bash
lizard port 8080 --service web
lizard redeploy --service web
```

<span id="worker-services" />

## Servicios worker

Un [servicio en modo worker](/deploy/workers) (`containerPort=0`) puede seguir mostrando un dominio generado, pero no sirve nada — no hay listener ni ruta de load balancer. No asocies un dominio personalizado a un worker.

<span id="private-networking" />

## Redes privadas

Los servicios del mismo proyecto se conectan entre sí en `<service>.lizard.internal`, en cualquier puerto en el que escuche el servicio, sin un dominio público. Haz referencia al hostname como `${{api.LIZARD_PRIVATE_DOMAIN}}`. Managed Postgres y Managed Redis exponen `DATABASE_PRIVATE_URL` y `REDIS_PRIVATE_URL` en la misma red. Estos nombres solo se resuelven dentro del proyecto.

```bash
lizard secrets set API_URL='http://${{api.LIZARD_PRIVATE_DOMAIN}}:8080' --service web
```

<span id="manage-in-the-dashboard" />

## Gestionar en el dashboard

Abre un servicio en el dashboard (`lizard open`) y ve a **Settings → Networking**. Muestra el estado de verificación y DNS de cada dominio y te permite agregar o eliminar hostnames.
