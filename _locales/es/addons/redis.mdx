# Managed Redis

Managed Redis en Lizard (lizard.build) es un servidor Redis para caché, colas, limitación de tasa y pub/sub. Las instancias nuevas usan Redis 8 de forma predeterminada. Añade una con `lizard add redis`; tus servicios leen `REDIS_PRIVATE_URL` o `REDIS_URL` mediante una referencia como `${{redis.REDIS_PRIVATE_URL}}`. No tiene política de expulsión ni append-only file, así que guarda en él solo datos que puedas reconstruir. Para ver un resumen y los precios, consulta la [página de Managed Redis](https://lizard.build/redis).

<span id="provision" />

## Aprovisionar

```bash
lizard add redis
```

El primer addon de Redis se llama `redis`, así que `${{redis.REDIS_URL}}` funciona de inmediato.

<span id="environment-variables" />

## Variables de entorno

| Variable | Descripción |
|----------|-------------|
| `REDIS_URL` | Cadena de conexión completa a través del endpoint público (`redis://…`) |
| `REDIS_PRIVATE_URL` | Cadena de conexión a través de la red privada del proyecto (`<name>.lizard.internal:6379`) |

Ambas cadenas tienen la forma `redis://default:<password>@<host>:<port>`. La privada solo funciona desde servicios del mismo proyecto; consulta [red privada](/networking#private-networking).

<span id="connect-a-service" />

## Conectar un servicio

```bash
lizard secrets set REDIS_URL='${{redis.REDIS_PRIVATE_URL}}' --service api
lizard redeploy --service api
```

La referencia se resuelve en el momento del despliegue; los consumidores obtienen los valores actuales del addon en su siguiente despliegue. Usa `REDIS_URL` para clientes fuera del proyecto. Todos los servicios del proyecto también reciben el `REDIS_URL` público del addon con la prioridad más baja; una referencia explícita lo sobrescribe.

<span id="does-managed-redis-keep-data" />

## ¿Managed Redis conserva los datos?

No todas las escrituras. Managed Redis no tiene política de expulsión ni append-only file. Si se queda sin memoria, la instancia se reinicia y se pueden perder escrituras recientes. Úsalo para datos que puedas reconstruir, y guarda los datos que no puedas perder en [Managed Postgres](/addons/postgres).

<span id="common-uses" />

## Usos comunes

- **Caché**: almacena resultados calculados indexados por solicitud.
- **Cola / worker**: combina Redis con un [servicio en modo worker](/deploy/workers) que consume trabajos. [Ejecutar un consumidor de cola](/deploy/workers#run-a-queue-consumer) explica el ejemplo redis-worker.
- **Limitación de tasa / sesiones**: estado compartido rápido entre [réplicas](/deploy/scaling).

```bash
# A worker that drains a Redis queue
lizard add -r your-org/worker -n jobs --no-deploy
lizard service set jobs --set containerPort=0
lizard secrets set REDIS_URL='${{redis.REDIS_PRIVATE_URL}}' --service jobs
lizard redeploy --service jobs
```

<span id="browse-keys" />

## Explorar claves

Abre el **navegador de Redis** en el panel (`lizard open`) para inspeccionar claves y valores. Para acceso local con los valores de conexión del addon:

```bash
lizard run --service redis -- sh -c 'exec redis-cli -u "$REDIS_URL"'
```

<span id="grow-storage" />

## Ampliar almacenamiento

```bash
lizard scale --service redis --storage 4096
```
