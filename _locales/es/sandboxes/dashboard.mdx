# Panel

Abre un proyecto y selecciona Sandboxes. Al crear, elige una plantilla y una región. La región por defecto no tiene por qué ser la más cercana. Los límites de recursos son fijos. Los Sandboxes creados en el panel no caducan salvo que fijes una duración mediante la API.

## Instalar y autenticar

Instala Lizard SDK y crea una clave API en Settings → API keys. Guárdala en `LIZARD_API_KEY`. Cada sandbox necesita un proyecto: pasa `projectId` (Python: `project_id`) o resuelve su ID, slug o nombre con `project`.

## Inspeccionar y detener

La vista de detalle muestra estado, plantilla, región, consumo medido y puertos abiertos. El runtime de Kubernetes actual no proporciona credenciales SSH, así que la terminal basada en SSH no está disponible. Ejecuta comandos mediante el SDK o la CLI.

Se factura el consumo medido de CPU, memoria, almacenamiento y tráfico saliente. Un sandbox inactivo puede seguir usando memoria y disco. Deténlo al terminar; los datos guardados siguen generando cargos de almacenamiento.

## Plantillas y volúmenes

La pestaña Templates muestra plantillas de la plataforma para nuevos Sandboxes, no snapshots de sesiones en ejecución. No se admiten snapshots propios, pausa ni reanudación. Kill Sandbox detiene el sandbox y separa su volumen.

La pestaña Persistent Volumes permite gestionar volúmenes con nombre y sus conexiones. Adjunta un volumen al crear el sandbox y escribe en `/workspace`. Detén el sandbox actual antes de adjuntar el volumen a otro.
