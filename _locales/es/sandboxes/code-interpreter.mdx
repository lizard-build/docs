Ejecuta Python con la plantilla `interpreter`. `CodeSandbox` conserva el estado entre llamadas: Python se ejecuta en un kernel de Jupyter persistente por contexto, y los resultados pueden incluir el valor de la última expresión y gráficos como `image/png`.

```ts
import { CodeSandbox } from '@lizard-build/sdk';

const sandbox = await CodeSandbox.create({ projectId: 'proj_123', timeoutMs: 300_000 });
try {
  await sandbox.runCode('x = 21');
  const run = await sandbox.runCode('x * 2');
  console.log(run.results[0]?.data, run.stdout, run.error);
} finally {
  await sandbox.kill();
}
```

```python
from lizard import CodeSandbox

sandbox = CodeSandbox.create(project_id="proj_123", timeout_ms=300_000)
try:
    sandbox.run_code("x = 21")
    run = sandbox.run_code("x * 2")
    print(run.results[0].data, run.stdout, run.error)
finally:
    sandbox.kill()
```

`createContext()` (Python: `create_context()`) inicia un kernel aparte con sus propias variables. JavaScript y bash se ejecutan como un proceso nuevo en cada llamada.

## Ejecutar comandos

`process.exec` inicia un proceso distinto para cada comando, por lo que las variables de Python no persisten entre llamadas. Guarda los resultados intermedios en archivos. Devuelve stdout, stderr y un código de salida.

```ts
import { Sandbox } from '@lizard-build/sdk';

const sandbox = await Sandbox.create('interpreter', {
  projectId: 'proj_123', timeoutMs: 300_000,
});
try {
  const result = await sandbox.process.exec("python -c 'print(2 ** 10)'");
  console.log(result.stdout, result.stderr, result.exitCode);
} finally {
  await sandbox.kill();
}
```

```python
from lizard import Sandbox

sandbox = Sandbox.create("interpreter", project_id="proj_123", timeout_ms=300_000)
try:
    result = sandbox.process.exec_("python -c 'print(2 ** 10)'")
    print(result.stdout, result.stderr, result.exit_code)
finally:
    sandbox.kill()
```

## Almacenamiento y facturación

Los archivos y procesos siguen disponibles mientras el sandbox está en ejecución. Tras detenerlo, otro sandbox solo puede recuperar los archivos escritos en un Persistent Volume adjunto en `/workspace`. Sin volumen, `/workspace` es temporal. Cada volumen se adjunta a un solo sandbox y usa almacenamiento local de un nodo; exporta los archivos que deban sobrevivir a la pérdida del nodo.
