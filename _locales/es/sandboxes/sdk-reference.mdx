# Referencia del SDK

Instala Lizard SDK y crea una clave API en Settings → API keys. Guárdala en `LIZARD_API_KEY`. Cada sandbox necesita un proyecto: pasa `projectId` (Python: `project_id`) o resuelve su ID, slug o nombre con `project`.

## Opciones de creación

| TypeScript | Python |
|---|---|
| `projectId / project` | `project_id / project` |
| `timeoutMs` | `timeout_ms` |
| `region` | `region` |
| `volumeName / volumeId` | `volume_name / volume_id` |
| `apiKey` | `api_key` |

Elige una plantilla del catálogo actual. Las plantillas habilitadas incluyen `base`, `codex` e `interpreter`; su disponibilidad depende de la región y de la capacidad del pool. `interpreter` incluye Python y bibliotecas de datos habituales. Comprueba las versiones dentro del sandbox. La CLI pública no permite subir plantillas propias.

El SDK y la CLI fijan cinco minutos de duración por defecto. La API directa y el panel no fijan caducidad por defecto. Indica la duración: `timeoutMs: 0` al crear desactiva la caducidad; un valor positivo fija un plazo. `setTimeout` acepta 1000–2147483647 ms, no cero. Los comandos no reinician el plazo. No es un temporizador de inactividad.

## Métodos

| API (TypeScript) | Métodos |
|---|---|
| `Sandbox.create(template, options)` | Crear en un proyecto desde una plantilla del catálogo. |
| `Sandbox.connect(sandboxId)` | Conectar a un sandbox existente; no reanuda. |
| `Sandbox.list()` | Listar Sandboxes accesibles; comprobar su estado. |
| `sandbox.getInfo()` | Obtener estado y metadatos. |
| `sandbox.process.exec(cmd)` | Ejecutar shell; devolver stdout, stderr y exitCode. |
| `sandbox.fs.write(path, data)` | Escribir texto o UTF-8; crear directorios superiores. |
| `sandbox.fs.read(path)` | Leer texto UTF-8. |
| `sandbox.fs.readBytes(path)` | Leer los bytes de un archivo. |
| `sandbox.fs.list(path)` | Listar un directorio. |
| `sandbox.fs.makeDir(path)` | Crear un directorio y los superiores que falten. |
| `sandbox.fs.remove(path)` | Eliminar un archivo o directorio. |
| `sandbox.getHost(port)` | Registrar un nombre HTTPS público para un puerto. |
| `sandbox.setTimeout(ms)` | Fijar la duración restante, mínimo 1000 ms. |
| `sandbox.kill()` | Detener el sandbox y separar su volumen. |

Python: `exec_`, `get_info`, `get_host`, `set_timeout`, `sandbox_id`, `read_bytes`, `make_dir`.

## Límites actuales del runtime

Los resultados incluyen stdout, stderr y el código de salida. El tiempo máximo de un comando está entre 1 y 600 segundos. El runtime actual no aplica las opciones `envs`, `workdir` ni `user`; fija el directorio y las variables en el comando de shell. Tampoco aplica `envs` ni `metadata` al crear.

`fs.write` escribe texto o bytes UTF-8 válidos; `fs.read` lee texto. El endpoint de escritura actual no admite subidas binarias. Para descargar un archivo binario usa `fs.readBytes` (Python: `read_bytes`).

Los sandboxes actuales tienen límites fijos de 4 vCPU y 4096 MiB de RAM. Las opciones de creación no cambian estos límites. Elige una región si lo necesitas; aparecer en el catálogo no garantiza capacidad libre.

## API no compatibles

Crea un sandbox, ejecuta comandos y llama a `kill`. `connect` se conecta a un sandbox existente; no reanuda uno detenido. Pausar, reanudar, fork, snapshot, restore y observar archivos devuelven HTTP 501 en el runtime actual. SSH no está disponible.

`CodeSandbox`, `runCode` / `run_code` y los métodos de contexto siguen en el SDK, pero el catálogo alojado no ofrece el servidor de ejecución que requieren. La plantilla antigua por defecto `code-interpreter-v1` no está disponible. Cambiar su nombre a `interpreter` no activa esa API. Usa `Sandbox.create("interpreter")` y comandos de procesos como se muestra abajo.

## Almacenamiento y facturación

Los archivos y procesos siguen disponibles mientras el sandbox está en ejecución. Tras detenerlo, otro sandbox solo puede recuperar los archivos escritos en un Persistent Volume adjunto en `/workspace`. Sin volumen, `/workspace` es temporal. Cada volumen se adjunta a un solo sandbox y usa almacenamiento local de un nodo; exporta los archivos que deban sobrevivir a la pérdida del nodo.

Se factura el consumo medido de CPU, memoria, almacenamiento y tráfico saliente. Un sandbox inactivo puede seguir usando memoria y disco. Deténlo al terminar; los datos guardados siguen generando cargos de almacenamiento.
