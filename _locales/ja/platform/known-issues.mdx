# 既知の問題

<span id="redeploy-is-not-rollback" />

このページでは、注意が必要な挙動や、リリースによる確認が必要な挙動を記録しています。レビュー中のコード修正は、稼働中のサービスについての保証ではありません。

<span id="sandbox-pause-and-expiration" />

## サンドボックス の一時停止と有効期限

sandbox を作成してコマンドを実行し、終了後に `kill` を呼び出します。`connect` は既存の sandbox に接続するだけで状態を変えないため、一時停止中や停止済みの sandbox を再開しません。一時停止、再開、snapshot、restore は利用できます。[一時停止、再開、スナップショット](/sandboxes/quickstart#pause-and-resume)を参照してください。fork とファイル監視は HTTP 501 を返します。`lizard sandbox ssh` は CLI の認証情報で対話型シェルを開きます。SSH プロトコルでのアクセスはできないため、SSH クライアント、`scp`、ポートフォワーディングは使えません。

一時停止すると、開いているネットワーク接続は閉じられます。プロセスを保存できない場合、sandbox は実行を続け、理由を `pauseError` に記録します。一時停止中の sandbox は元のノードでしか再開できず、そのノードが故障すると一時停止した状態は失われます。

sandbox の実行中はファイルとプロセスを維持します。停止後、別の sandbox で使えるのは、接続した Persistent Volume の `/workspace` に保存したファイルだけです。ボリュームがなければ `/workspace` は一時領域です。各ボリュームは同時に 1 つの sandbox に接続し、単一ノードに保存します。ノード障害後も必要なファイルは別の場所へ書き出してください。

## 再デプロイはロールバックではありません

`lizard redeploy` は、選択したソースを現在の構成でもう一度ビルドします。以前のビルドを選択するわけではありません。ビルド失敗と起動失敗では影響が異なります。復旧手順を選ぶ前に、アクティブなサービスとそのログを確認してください。起動失敗時でも、すべてのランタイムが古いリリースの提供を維持するとは限りません。

<span id="dockerfile-precedence" />

## Dockerfile の優先順位

明示的な build コマンドまたは start コマンドは、リポジトリの Dockerfile より優先されます。`dockerfilePath` を選択する場合は、これらのオーバーライドをクリアしてください。設定更新それ自体がビルドを開始することがあるため、別の再デプロイを送る前にイベントを確認してください。[Dockerfile のトラブルシューティング](/deploy/troubleshooting/incomplete-dockerfile)を参照してください。

<span id="templates-and-mcp" />

## テンプレートと MCP

現在のカタログからテンプレートを選びます。有効なテンプレートには `base`、`codex`、`interpreter` があり、利用可否はリージョンとプールの空き容量によって変わります。`interpreter` には Python と一般的なデータ処理ライブラリが含まれます。ツールのバージョンは sandbox 内で確認してください。公開 CLI には独自テンプレートのアップロード機能はありません。

Lizard Skill は Lizard CLI を使用します。そのワークフローでは MCP トランスポートは公開されません。独自のリモート MCP サーバーをホストするには、別個のアプリケーションデプロイが必要です。[ガイド](/guides/deploy-mcp-server)を参照してください。

<span id="service-port-changes-fixed-and-verified-on-2026-09-09" />

## サービスポートの変更: 2026-09-09 に修正済み・確認済み

9 月 7 日の確認では、準備完了のプロセスがあるにもかかわらず、アップロードサービスのポートを `3000` から `80` に変更した後に HTTP 503 が発生しました。本番修正により、選択したポートが実行中のサービスに適用され、アップロード時および再ビルド時にも明示的なポートが維持されるようになりました。実環境でのポート変更確認は 9 月 9 日に成功しました。デプロイ後は、サービス状態だけでなく公開 URL も確認してください。

<span id="upload-archives-and-failed-build-exit-codes-fixed" />

## アップロードアーカイブとビルド失敗時の終了コード: 修正済み

Lizard CLI 0.3.95 は、ソースアップロードから macOS の `._*` メタデータエントリを除外し、クラウドビルド失敗時に非ゼロの終了コードを返します。古い CLI バージョンは更新してください。`COPYFILE_DISABLE` はもう不要です。[フレームワークチェック](/framework-guides/validation)では、現在の CLI を使った macOS からのアップロードをカバーしています。

ビルドの成功だけでは、アプリが動作する証明にはなりません。デプロイ後に公開 URL、ルート、フォーム、データ操作を確認してください。
