# 制限

制限は、リソース、プラン、アカウントによって異なります。レプリカごとの設定は、サービスまたはアカウント全体で利用可能な合計ではありません。ワークロードのサイズを決める前に、現在のプランと、作成またはスケールリクエストの結果を確認してください。

<span id="applications" />

## アプリケーション

| 設定 | スコープ | 確認すべき項目 |
|---|---|---|
| CPU and memory | 各レプリカ | 上限が 2 vCPU / 2 GiB のレプリカが 3 つある場合、設定上の合計上限は 6 vCPU / 6 GiB です。これは使用量の予測ではありません。 |
| Replica count | サービスとプラン | 上限はプランで決まります。Pro のトライアル中はアプリあたり 1、最初の請求書の支払い後の Pro と Enterprise では 5 です。API が受け付けるのは最大 10 で、そこに届くのはアカウントごとの上書きがある場合だけです。 |
| アカウント リソース上限 | アカウント所有者 | 2 つ目のプロジェクトを作成しても、必ずしも 2 つ目のクォータが作成されるわけではありません。大規模なデプロイを計画する前に、実効アカウント上限を確認してください。 |
| Worker mode | サービス | `containerPort=0` は、HTTP リスナーや公開ロードバランサールートなしで実行されます。 |
| Custom domain | ホスト名 | ワイルドカードカスタムドメインは受け付けられません。特定のホスト名を使用し、所有権確認と DNS チェックを完了してください。 |

Sandboxes は、それぞれ独自のカーネルを持つ Firecracker microVM として、短時間のコマンドやエージェントのタスクを実行します。既存の pod ベースの永続ボリュームを接続する sandbox や、古い pod スナップショットから復元する sandbox は、runc ランタイムを使う Kubernetes Pod として動作し、ホストのカーネルを共有します。どちらで動作しているかは、Lizard SDK の `getInfo().runtime` でわかります。信頼できないコードを実行する際は、認証情報とネットワークへのアクセスを制限してください。

## Sandboxes

<span id="sandbox-sizes" />

### サイズ

| サイズ | CPU とメモリ | ディスク（`/workspace`） | 実行中の料金 |
|---|---|---|---|
| Small | 2 vCPU / 4 GB | 5 GB | 1 時間あたり $0.0162 |
| Medium（既定） | 4 vCPU / 8 GB | 20 GB | 1 時間あたり $0.0324 |
| Large | 8 vCPU / 16 GB | 50 GB | 1 時間あたり $0.0648 |

CPU とメモリは料金に含まれます。Persistent Volumes は別途課金されます。

<span id="sandbox-account-limits" />

### アカウントの上限

これらの上限は、アカウントが同時に実行できるサンドボックスの数と、新しいサンドボックスを起動できる速さを決めます。上限はアカウント所有者のプランで決まります。トライアルの上限は最初の請求書の支払いまで適用されます。[請求](/platform/billing#limits)を参照してください。

| プラン | 同時実行数 | 1 分あたりの起動数 | 1 時間あたり | 1 日あたり |
|---|---|---|---|---|
| Pro のトライアル | 5 | 6 | 30 | 100 |
| Pro | 100 | 24 | 120 | 400 |
| Enterprise | カスタム | カスタム | カスタム | カスタム |

- 上限はアカウント所有者ごとに、所有するすべてのワークスペースを合算して数えます。ワークスペースを増やしても枠は増えません。
- 実行中とは、実行中または再開中のことです。一時停止中のサンドボックスは含まれません。再開するには空き枠が必要です。
- 起動とは新しいサンドボックスのことです。再開は起動に含まれません。Lizard 側で失敗した作成は数えません。
- 上限を超えると、作成と再開は HTTP 429 を返し、`code` は `SANDBOX_LIMIT_REACHED`（同時実行数）または `SANDBOX_RATE_LIMITED`（起動数）になります。起動数による拒否には `Retry-After` ヘッダーが付きます。
- ダッシュボードの **New Sandbox** の横に、上限に対する実行中のサンドボックス数が表示されます。同時に 100 個を超えて必要な場合は、Enterprise についてお問い合わせください。

<span id="sandbox-egress" />

### 送信トラフィック

サンドボックスの送信トラフィックは、アカウントのすべてのサンドボックスを合算して、直近 30 日間でアカウントあたり 2 TB まで含まれます。これを超えると、30 日間の合計が 2 TB を下回るまで、アカウントのサンドボックスは外部への通信ができなくなります。追加料金はかかりません。

<span id="sandbox-lifetime" />

### 有効期間

| 設定 | 現在の作成 API |
|---|---|
| テンプレート | `base`、`interpreter`、`codex`、`desktop`、`opencode`、`pi`、`prime`、`claude` |
| Raw API の既定の有効期間 | `timeoutMs: 0`、期限なし |
| Lizard SDK の既定の有効期間 | 300000 ms、5 分 |
| 明示的な有効期間の範囲 | 0 から 2147483647 までの整数ミリ秒 |
| 有効期間の更新 | 1000 ms 以上。アイドルタイマーではありません |
| Persistent Volume の接続 | 一度に 1 つのサンドボックス、ボリュームのノード上 |

SDK と CLI の既定の有効期間は 5 分です。Raw API とダッシュボードは既定で期限を設定しません。有効期間は明示的に指定してください。作成時の `timeoutMs: 0` は期限を無効にし、正の値は期限を設定します。`setTimeout` は 1000～2147483647 ms を受け付け、0 は受け付けません。コマンドを実行しても期限はリセットされません。これはアイドルタイマーではありません。

sandbox を作成してコマンドを実行し、終了後に `kill` を呼び出します。`connect` は既存の sandbox に接続するだけで状態を変えないため、一時停止中や停止済みの sandbox を再開しません。一時停止、再開、snapshot、restore は利用できます。[一時停止、再開、スナップショット](/sandboxes/quickstart#pause-and-resume)を参照してください。fork（`sandbox.fork({ count })`）は Firecracker の sandbox で使えます。ボリュームが接続されている場合は HTTP 409 を、pod の sandbox では HTTP 501 を返します。`lizard sandbox ssh` は CLI の認証情報で対話型シェルを開きます。SSH プロトコルでのアクセスはできないため、SSH クライアント、`scp`、ポートフォワーディングは使えません。

<span id="regions" />

## リージョン

現在設定されているリージョンには、US East (Virginia)、`us-east-1`、EU West (Limburg)、`eu-west-lim-a` が含まれます。カタログにリージョンがあっても、すべてのリソースで利用可能な容量が保証されるわけではありません。リソース作成時にリージョンの選択肢を確認してください。既存のボリュームを使用する sandbox は、そのボリュームのノード上で実行する必要があります。

<span id="before-increasing-scale" />

## スケールを増やす前に

アクティブなプラン、レプリカごとの設定、アカウント上限、データベース接続上限、ストレージ増加をあわせて確認してください。[スケーリング](/deploy/scaling)、[メトリクス](/observability/metrics)、[料金](https://lizard.build/pricing)を使って、設定済み容量と実測使用量を比較してください。
