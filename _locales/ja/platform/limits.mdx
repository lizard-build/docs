# 制限

Lizard (lizard.build) では、アプリはPro の初回請求の支払い後はサービスあたり最大 5 レプリカ、トライアル中は 1 レプリカで実行されます。Pro では最大 100 個の sandbox を同時に実行でき、1 分あたり最大 24 個を起動できます。トライアルでは同時に 5 個までです。sandbox のサイズは Small（2 vCPU / 4 GB）から Large（8 vCPU / 16 GB）まであり、sandbox の送信トラフィックは直近 30 日間でアカウントあたり 2 TB まで含まれます。ワークスペースの所有者は、1 つのワークスペースに[ワークスペースの上限](#workspace-limits)を設定することもできます。制限は、リソース、プラン、アカウントによって異なります: レプリカごとの設定は、サービスまたはアカウント全体で利用可能な合計ではありません。ワークロードのサイズを決める前に、現在のプランと、作成またはスケールリクエストの結果を確認してください。

<span id="applications" />

## アプリケーション

| 設定 | スコープ | 確認すべき項目 |
|---|---|---|
| CPU and memory | 各レプリカ | 上限が 2 vCPU / 2 GiB のレプリカが 3 つある場合、設定上の合計上限は 6 vCPU / 6 GiB です。これは使用量の予測ではありません。 |
| Replica count | サービスとプラン | 上限はプランで決まります。Pro のトライアル中はアプリあたり 1、最初の請求書の支払い後の Pro と Enterprise では 5 です。API が受け付けるのは最大 10 で、そこに届くのはアカウントごとの上書きがある場合だけです。 |
| アカウント リソース上限 | アカウント所有者 | 2 つ目のプロジェクトを作成しても、必ずしも 2 つ目のクォータが作成されるわけではありません。大規模なデプロイを計画する前に、実効アカウント上限を確認してください。 |
| Worker mode | サービス | `containerPort=0` は、HTTP リスナーや公開ロードバランサールートなしで実行されます。 |
| Custom domain | ホスト名 | ワイルドカードカスタムドメインは受け付けられません。特定のホスト名を使用し、所有権確認と DNS チェックを完了してください。 |

<span id="sandboxes" />

## Sandboxes

[Sandboxes](/sandboxes) は Firecracker microVM でコマンドやエージェントのタスクを実行します。[ランタイムと分離](/sandboxes#runtime-and-templates) を参照してください。以下の制限はアカウントの各 sandbox に適用します。

<span id="sandbox-sizes" />

### サイズ

| サイズ | CPU とメモリ | ディスク（`/workspace`） | 実行中の料金 |
|---|---|---|---|
| Small | 2 vCPU / 4 GB | 5 GB | 1 時間あたり $0.0162 |
| Medium（既定） | 4 vCPU / 8 GB | 20 GB | 1 時間あたり $0.0324 |
| Large | 8 vCPU / 16 GB | 50 GB | 1 時間あたり $0.0648 |

CPU とメモリは料金に含まれます。Persistent Volumes は別途課金されます。

<span id="sandbox-account-limits" />

### アカウントの上限

これらの上限は、アカウントが同時に実行できるサンドボックスの数と、新しいサンドボックスを起動できる速さを決めます。上限はアカウント所有者のプランで決まります。トライアルの上限は最初の請求書の支払いまで適用されます。[請求](/platform/billing#limits)を参照してください。

| プラン | 同時実行数 | 1 分あたりの起動数 | 1 時間あたり | 1 日あたり |
|---|---|---|---|---|
| Pro のトライアル | 5 | 6 | 30 | 100 |
| Pro | 100 | 24 | 120 | 400 |
| Enterprise | お客様ごとの契約で定めるワークスペースあたりの上限 | ユーザーあたり 120 | 上限なし | 上限なし |

- 上限はアカウント所有者ごとに、所有するすべてのワークスペースを合算して数えます。ワークスペースを増やしても枠は増えません。
- Pro とトライアルでは、実行中とは、実行中または再開中のことです。一時停止中のサンドボックスは含まれません。再開するには空き枠が必要です。
- 起動とは新しいサンドボックスのことです。再開は起動に含まれません。Lizard 側で失敗した作成は数えません。
- 上限を超えると、作成と再開は HTTP 429 を返し、`code` は `SANDBOX_LIMIT_REACHED`（同時実行数）または `SANDBOX_RATE_LIMITED`（起動数）になります。起動数による拒否には `Retry-After` ヘッダーが付きます。
- Enterprise には同時に実行できるサンドボックス数の固定の上限はありません。お客様ごとの契約でワークスペースあたりの上限を定めます。実行中、一時停止中、クラッシュしたサンドボックスがすべて数に入ります。超えると、作成と fork は HTTP 429 を返し、`code` は `SANDBOX_LIMIT_REACHED` になります。1 人のユーザーが作成できるのは、リージョンごとに 1 分あたり最大 120 個です。
- ダッシュボードの **New Sandbox** の横に、上限に対する実行中のサンドボックス数が表示されます。同時に 100 個を超えて必要な場合は、Enterprise についてお問い合わせください。

<span id="sandbox-egress" />

### 送信トラフィック

sandbox の送信トラフィックには GB ごとの別料金はありません。アカウントごとに直近 30 日間で 2 TB まで含まれ、アカウント内の全 sandbox で共有します。それ以上必要な場合は、実行前にお問い合わせください。

<span id="sandbox-lifetime" />

### 有効期間

| 設定 | 現在の作成 API |
|---|---|
| テンプレート | `base`、`interpreter`、`codex`、`desktop`、`opencode`、`pi`、`prime`、`claude`。`desktop-camoufox` は US East のみ |
| 直接の API の既定の有効期間 | `timeoutMs: 0`、期限なし |
| Lizard SDK の既定の有効期間 | 300000 ms、5 分 |
| 明示的な有効期間の範囲 | 0 から 2147483647 までの整数ミリ秒 |
| 有効期間の更新 | 1000 ms 以上。アイドルタイマーではありません |
| Persistent Volumes の接続 | 一度に 1 つのサンドボックス、ボリュームのノード上 |

CLI の既定値も 5 分です。ダッシュボードは既定で期限を設定しません。コマンドを実行しても期限はリセットされません。一時停止、スナップショット、fork、それぞれで保持する状態については、sandbox の [ライフサイクル](/sandboxes#lifecycle) を参照してください。

<span id="workspace-limits" />

## ワークスペースの上限

ワークスペースの所有者は、1 つのワークスペースに上限を設定できます。たとえば、顧客がスコープ付き API キーで使うワークスペースです。これらの上限は上のアカウントの上限に加えて適用され、そのワークスペースで作業するすべての人が対象です。

| 上限 | 数える対象 | フラグ |
|---|---|---|
| Sandboxes | 同時に実行中または再開中のサンドボックス。一時停止中のものは含まれません | `--sandboxes <n>` |
| CPU | ワークスペースのアプリとデータベースが現在使っている vCPU（実測値） | `--cpu <vcpus>` |
| メモリ | ワークスペースのアプリとデータベースが現在使っているメモリ（実測値） | `--memory <size>` |
| ディスク | ワークスペースのデータベースとボリュームに書き込まれたデータ | `--disk <size>` |

設定できるのは所有者だけです。ブラウザでサインインした状態か、スコープのない API キーで [`lizard workspace limits`](/cli/workspace#lizard-workspace-limits-name-or-id) を使います。メンバー全員と、そのワークスペースに届くキーは、現在の利用量とあわせて上限を読めます。

- サンドボックスの上限に達すると、作成、fork、再開は HTTP 429 を返し、`code` は `WORKSPACE_SANDBOX_LIMIT` になります。
- アプリとデータベースが許可された量の CPU またはメモリを使っている間、デプロイ、再デプロイ、再起動、スケールアップ、新しいデータベース、一時停止したアプリやデータベースの再開は HTTP 429 を返し、`code` は `WORKSPACE_USAGE_LIMIT` になります。実行中のサービスは動き続けます。
- データがディスクの上限に達している間、新しいボリューム、ボリュームの拡張、新しいデータベース、テンプレートのデプロイは同じ `WORKSPACE_USAGE_LIMIT` を返します。書き込み済みのデータは残ります。
- サンドボックス自体の `/workspace` ディスクは、ディスクの上限に数えません。

<span id="regions" />

## リージョン

現在設定されているリージョンには、US East (Virginia)、`us-east-1`、EU West (Limburg)、`eu-west-lim-a` が含まれます。カタログにリージョンがあっても、すべてのリソースで利用可能な容量が保証されるわけではありません。リソース作成時にリージョンの選択肢を確認してください。既存のボリュームを使用する sandbox は、そのボリュームのノード上で実行する必要があります。[`lizard regions`](/cli/regions) は、アカウントで利用できるリージョンを一覧表示します。[リージョン](/deploy/regions) を参照してください。

<span id="before-increasing-scale" />

## スケールを増やす前に

アクティブなプラン、レプリカごとの設定、アカウント上限、ワークスペースの上限、データベース接続上限、ストレージ増加をあわせて確認してください。[スケーリング](/deploy/scaling)、[メトリクス](/observability/metrics)、[料金](https://lizard.build/pricing)を使って、設定済み容量と実測使用量を比較してください。すべてのリソースの料金は [請求ページ](/platform/billing#resource-rates) に記載されています。
