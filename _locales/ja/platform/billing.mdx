# 請求

Lizard (lizard.build) のセルフサービス向けプランは Pro の 1 つだけです。月額 $19 で、毎月 $19 分のクレジットが含まれます。クレジットはプラットフォーム全体の利用に使えます。対象はアプリ、Sandboxes、Managed Postgres、Managed Redis、Managed Object Storage、Persistent Volumes、送信トラフィックです。クレジットを使い切ったあとは、公開料金での pay as you go になります。

プランはアカウント設定の **請求** ページ、または [`lizard billing`](/cli/billing) で管理します。プランはワークスペースの所有者に属します。あなたが所有するすべてのワークスペースの利用があなたのプランに計上され、メンバーを追加してもシート料金はかかりません。

## Pro

| | Pro |
| --- | --- |
| 料金 | 月額 $19 |
| 毎月のクレジット | $19、プラットフォーム全体の利用に使用可能 |
| クレジットを超えた利用 | [リソース料金](#resource-rates)での pay as you go |
| トライアル | 7 日間、$5 のトライアルクレジット付き |
| 支払い方法 | カード、毎月請求 |

Pro は解約するまで毎月更新されます。使わなかった毎月のクレジットは翌月に繰り越されません。

<span id="monthly-credits-and-overage" />

## 毎月のクレジットと超過分

毎月 $19 のクレジットから始まり、利用はまずそこから差し引かれます。$19 を超えた利用は超過分となり、同じ料金で請求されます。

Lizard は超過分を月末にまとめてではなく、たまるたびに請求します。未請求の超過分が $20 に達すると、Lizard はカードに請求します。請求が支払われるたびに次の段階が上がり、$100、$200、$400、$1,000 と進み、その後は $1,000 ずつになります。段階は毎月 $20 に戻ります。月末には、まだ請求していない超過分を 1 通の最終請求書にまとめます。支出の上限はありません。

請求ページには、今月 $19 のうちどれだけ使ったか、現時点の超過分、次回の請求が表示されます。

<span id="resource-rates" />

## リソース料金

価格は米ドルです。

| リソース | 料金 |
| --- | ---: |
| CPU | vCPU秒あたり $0.000006948 |
| メモリ | GB秒あたり $0.000003474 |
| Persistent Volumes | GB秒あたり $0.000000054 |
| Managed Object Storage | GB月あたり $0.0135 |
| 送信トラフィック | GBあたり $0.045、最初の1バイトから |

受信トラフィックは無料です。アプリ、Managed Postgres、Managed Redis にはこの料金が適用されます。Sandboxes にはサイズごとに 1 時間あたりの固定料金があります。[Sandboxes のサイズ](/platform/limits#sandbox-sizes)を参照してください。

たとえば、1 vCPU と 1 GB のメモリを 1 時間使うと、コンピュート料金は $0.0375192 です。ストレージと送信トラフィックの料金が加わる場合があります。提供内容の全体は[料金](https://lizard.build/pricing)ページを参照してください。

<span id="trial" />

## トライアル

新しいアカウントでは画面を見て回れますが、アプリ、Sandboxes、データベース、ボリュームを作成するには Pro が必要です。Pro は 7 日間のトライアルと $5 のトライアルクレジットから始まります。開始するにはカードを登録します。Apple Pay も使えます。トライアル開始時には何も請求されません。トライアルが終わると、その前に解約しない限り、月額 $19 の Pro が始まります。

トライアルは 1 つのアカウントにつき 1 回、1 枚のカードにつき 1 回です。アカウントで以前にトライアルを使ったことがある場合、Pro はすぐに始まり、その日に $19 が請求されます。カードで以前にトライアルを使ったことがある場合、トライアルは始まらず、何も請求されません。請求ページから月額 $19 の Pro を開始してください。

トライアルでは Pro のすべての機能を使えますが、最初の請求書の支払いまでは[上限](#limits)が低くなります。

<span id="when-trial-credits-run-out" />

### トライアルクレジットを使い切ったとき

- トライアルクレジットを使い切ると、実行中のリソースが一時停止し、新しいリソースを作成できなくなります。データは保持されます。
- 続けるには、請求ページで **Start Pro now** を選ぶか、`lizard billing start-now` を実行します。トライアルが終わり、$19 が請求され、$19 のクレジット付きで最初の有料月が始まります。一時停止していたアプリとデータベースは、支払いが完了すると再び起動します。

使わなかったトライアルクレジットはトライアルとともに失効し、有料月には移りません。

<span id="promo-codes" />

## プロモコード

プロモコードを使うと、最長 730 日の長いトライアルと、より多くのトライアルクレジットを受け取れる場合があります。コードは標準の 7 日間と $5 に置き換わります。コードは請求ページか `lizard billing promo <code>` で利用します。

- トライアル開始前なら、Lizard がコードを保存し、カードを登録したときに適用します。
- トライアル中なら、期間とクレジットがコードの内容まで引き上げられます。今ある分に加算されるわけではありません。
- コードは最初の支払いの前にのみ使えます。
- コードは 1 つのアカウントにつき 1 つ、1 枚のカードにつき 1 つです。

<span id="limits" />

## 上限

| | トライアル（最初の請求書の支払いまで） | Pro |
| --- | ---: | ---: |
| 同時に実行できる Sandboxes | 5 | 100 |
| アプリあたりのレプリカ数 | 1 | 5 |

Pro の上限は最初の請求書の支払いから適用されます。**Start Pro now** による支払いも含みます。Sandboxes の起動レートなどの上限は[制限](/platform/limits#sandbox-account-limits)を参照してください。

<span id="payment-failures" />

## 支払いに失敗した場合

毎月の $19 でも超過分の請求でも、支払いに失敗すると次のようになります。

- 失敗した時点から、新しいリソースを作成できなくなります。
- 実行中のリソースは 72 時間動いたあと、一時停止します。
- 一時停止したリソースのデータは保持されます。

請求ページで未払いの請求書を支払ってください。支払いが済むと、Lizard は制限を解除し、一時停止していたアプリとデータベースを再び起動します。一時停止した Sandboxes はご自身で再開してください。Stripe は失敗した請求を再試行します。最後の再試行も失敗すると、Pro は終了します。

<span id="cancelling" />

## 解約

解約はいつでも、請求ページ、Stripe のカスタマーポータル、または `lizard billing cancel` で行えます。Pro は今月またはトライアルの終わりまで有効です。その日までの超過分は最終請求書に含まれます。トライアル中の解約に費用はかかりません。

終了日までなら、請求ページか `lizard billing resume` で解約を取り消せます。

Pro が終了すると、リソースを作成できなくなり、実行中のリソースは一時停止します。データは保持されます。再び使うには、請求ページで Pro を開始してください。2 回目のトライアルはないため、Pro はすぐに $19 で始まります。

## Enterprise

Enterprise アカウントは pay as you go で、毎月、前月分の請求書を受け取ります。料金、上限、支払い条件は契約に従います。Pro の上限を超える規模が必要な場合は、[料金](https://lizard.build/pricing)ページから Enterprise についてお問い合わせください。

<span id="idle-apps-and-stored-data" />

## アイドル状態のアプリと保存データ

アプリはリクエストがなくてもメモリと CPU を使うことがあります。コンピュートの利用を止めるには、アプリを停止してください。Persistent Volumes と Managed Object Storage は、データを保存している間は料金がかかります。アプリを停止していても同じです。

データを削除する前に[ストレージと復旧](/platform/storage-and-recovery)を確認してください。設定した上限と実際の利用量の比較には[メトリクス](/observability/metrics)を参照してください。
