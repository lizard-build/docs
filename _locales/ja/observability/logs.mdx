# ログ

Lizard は、**ランタイム**ログ、**ビルド**ログ、そして**クラッシュ**前後のログ末尾を収集します。ターミナルでライブストリーミングすることも、ダッシュボードで閲覧することもできます。

ランタイムログが収集されるのは、ログストリームが開いている間（`lizard logs` またはダッシュボードの Logs ページ。閉じてから 60 秒間を含む）、デプロイと再起動の前後、そしてサービスがクラッシュループしている間です。ストリームを開くと、レプリカごとに直近 500 行が補完されます。

<span id="runtime-logs" />

## ランタイムログ

```bash
lizard logs                       # last 200 runtime lines, then live tail
lizard logs --service api         # a specific service
lizard logs --tail 1000           # print the last 1000 lines and exit (max 1000)
lizard logs --level error         # filter by level
```

<span id="behavior-with---json" />

### `--json` を使った場合の動作

`lizard logs --json` は直近 200 行を返し（`--tail N` で上書き可能、最大 1000）、終了します。スナップショットやスクリプトで使用してください。誰もストリーミングしていない間に取ったスナップショットでは、最近の行が欠けることがあります。それらが必要な場合は、先にストリームを開いてください。

ターミナルがない場合（出力をパイプしたとき、CI、エージェント）、`lizard logs` は `--json` を渡したときと同じように動作し、直近 200 行を表示して終了します。ログをライブで追うには、ターミナルで `--json` を付けずに実行してください。

<span id="build-logs" />

## ビルドログ

```bash
lizard logs --build               # the most recent build's logs
```

デプロイが失敗したときは、まず最初にここを確認してください。内容を読み、原因を修正してから、`lizard redeploy` を実行します。[ビルド Pipeline](/concepts/build-pipeline) を参照してください。

<span id="restart--crash-logs" />

## 再起動 / クラッシュログ

レプリカがクラッシュすると、Lizard はクラッシュ前後のログ末尾を保存します。手動の再起動や変数の変更も一覧に表示されますが、ログ末尾はありません。

```bash
lizard logs --restarts            # list recent restarts with their ids
lizard logs --restart <id>        # the log tail of one crash
lizard logs --restart latest      # the most recent event, which may be a manual restart
```

<span id="paging-through-history" />

## 履歴をページングしてたどる

`lizard service logs` は、さらに古い期間をページングして取得できます。

```bash
lizard service logs --service api --tail all     # last 2,000 lines (no follow)
lizard service logs --service api --page 2       # older window (implies --tail 200)
```

<span id="dashboard" />

## ダッシュボード

ダッシュボード（`lizard open`）では、検索とレベルフィルター付きでランタイムログとビルドログをストリーミングできます。サービスを開き、その履歴にあるデプロイをクリックすると、そのデプロイのビルド出力を確認できます。
