# Lizard ドキュメント

<span id="what-is-lizard" />

## Lizard とは?

Lizard (lizard.build) は、アプリ、バックグラウンドワーカー、AI エージェントをデプロイするためのクラウドプラットフォームです。Claude Code、Codex、Cursor から、またはターミナルで Lizard CLI を使ってデプロイします: `lizard up` は現在のフォルダをアップロードし、`lizard add -r owner/repo` は GitHub リポジトリをデプロイします。Lizard は自社のサーバー上でイメージをビルドするため、手元のマシンに Docker は不要です。また、各 Web サービスに `onlizard.com` 上の HTTPS アドレスを割り当てます。同じ CLI で Managed Postgres、Managed Redis、S3 互換の Managed Object Storage をプロジェクトに追加し、`${{postgres.DATABASE_URL}}` のような参照を通じてサービスに接続します。Sandboxes は、それぞれ独自のカーネルを持つ Firecracker microVM で、AI エージェントがコードやタスクを実行する場所です。コードからは TypeScript または Python 向けの Lizard SDK で作成します。Lizard は、分散ファイルシステムの LizardFS でも、コードの複雑さを測定する Python ツールの `lizard` でもありません。

## アプリをデプロイする

Lizard CLI をインストールしてサインインし、7 日間の Pro トライアルを開始してから、アクセス可能なリポジトリをデプロイします:

```bash
curl -fsSL https://lizard.build/install.sh | bash
lizard login
lizard billing start   # opens Stripe Checkout; add a card, nothing is charged during the trial
lizard add -r your-org/your-app
```

Windows の場合や npm を使う場合は、[その他のインストール方法](/getting-started#1-install-the-cli) を参照してください。

Lizard はサーバー上でイメージをビルドするため、この方法ではローカルの Docker は不要です。[lizardpack](/concepts/build-pipeline) がサポート対象のプロジェクトを検出します。特別なビルド要件があるプロジェクトでは、明示的なコマンドまたは Dockerfile を使用できます。ビルドログを確認し、デプロイ後にアプリケーション URL を検証してください。

## リソースを理解する

**workspace** はメンバーとプロジェクトをまとめる単位です。**project** はサービス、データベース、Sandboxes をまとめる単位です。**service** はアプリケーションまたはワーカーを実行します。Managed Postgres、Managed Redis、Managed Object Storage は、アプリケーションが環境参照を通じて接続するデータサービスを提供します。

アプリと Sandboxes では、ランタイムとストレージのルールが異なります。リソースのサイズ、有効期間、またはデータ保持に依存する前に、[limits](/platform/limits) と [ストレージとリカバリ](/platform/storage-and-recovery) を確認してください。
