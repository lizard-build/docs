# lizard up

現在のディレクトリをアップロードしてデプロイします。

<span id="usage" />

## 使い方

```bash
lizard up [path] [flags]
```

`up` は作業ツリー（または `path`）を tarball としてパッケージ化し、ビルドノードに送信してデプロイします。対象サービスで `sourceType=upload` を強制し、SSE 経由でビルドログをストリーミングし、完了時に稼働中の URL を表示します。

ディレクトリがプロジェクトにリンクされていない場合、`up` はディレクトリをアカウントのデフォルトプロジェクト（個人ワークスペースで最も古いプロジェクト）にリンクし、そこへデプロイします。TTY でも CI でも同じです。別の場所にデプロイするには、先に `lizard init --name <project>` を実行するか、`--project` を渡してください。

<span id="which-service-up-deploys-to" />

### `up` のデプロイ先サービス

1. `--service` で指定したサービス。その名前のサービスがプロジェクトにない場合、`up` が作成します。
2. ディレクトリにリンクされたサービス。
3. それ以外の場合、`package.json` の `name`（スコープを除く）またはディレクトリ名を名前にしたサービス。TTY では `up` が名前を尋ね、この名前を候補として示します。

最後のケースで、その名前のサービスがプロジェクトにすでにある場合、`up` はそこへデプロイします。`up` は毎回デプロイ先をアップロードソースに切り替えるため、GitHub のサービスは push でデプロイされなくなります。デプロイ先を自分で選ぶには `--service` を渡してください。

<span id="flags" />

## フラグ

| フラグ | 説明 |
|------|-------------|
| `-s, --service <name>` | デプロイ先のサービス（既定値はリンク済みのサービス）。その名前のサービスがなければ `up` が作成します |
| `-p, --project <id>` | プロジェクトの名前、スラッグ、または ID。リンクされていないディレクトリでは、`up` はディレクトリをこのプロジェクトにリンクし、その名前のプロジェクトがなければ作成します |
| `--build-command <cmd>` | ビルドコマンドを上書きします |
| `--start-command <cmd>` | 起動コマンドを上書きします |
| `--pre-deploy-command <cmd>` | コンテナが起動するたびに（すべてのレプリカ、すべての再起動で）起動コマンドの前に実行します。起動コマンドが必要です。何度実行しても問題ないようにしてください |
| `--port <number>` | コンテナポート（`0` = worker mode）。Dockerfile の `EXPOSE` で指定されていない限り、新しいサービスの既定値は `3000` です |
| `--region <code>` | 新しいサービスのリージョン。既存のサービスでは無視されます |
| `-d, --detach` | デプロイを開始し、ログをストリーミングせずに終了します |
| `-c, --ci` | ビルドログだけをストリーミングし、ビルドが終わると終了します |
| `--no-gitignore` | `.gitignore` を無視して、すべてをアップロードします |

<span id="subcommands" />

## サブコマンド

### `lizard up status <app-id>`

サービスの状態、URL、最新のビルドの状態を表示します。`up --detach` が表示するサービス ID を渡してください。

<span id="examples" />

## 例

<span id="deploy-the-current-directory" />

### 現在のディレクトリをデプロイする

```bash
lizard up
```

<span id="deploy-to-a-specific-service-with-a-custom-start-command-and-port" />

### カスタム起動コマンドとポートを指定して特定のサービスにデプロイする

`api` がまだ存在しない場合、`up` が作成します。

```bash
lizard up --service api --start-command "node server.js" --port 8080
```

<span id="deploy-headlessly-in-ci" />

### CI でヘッドレスにデプロイする

```bash
export LIZARD_TOKEN=liz_xxx
lizard init --name my-project
lizard up --ci --service api   # creates api on the first run
```

ビルドまたはデプロイが失敗すると、終了コード `1` で終了します。`--ci` では終了コードはビルドだけを対象にするため、リリースを完了とする前に `lizard ps --json` を確認してください。`--detach` はアップロードが受け付けられた時点で `0` で終了します。[framework setup](/framework-guides#prepare-the-project) を参照してください。
