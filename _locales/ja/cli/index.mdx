# CLI リファレンス

Lizard CLI (`lizard`) は、ターミナル、CI ジョブ、コーディングエージェントから Lizard (lizard.build) 上のアプリ、データベース、Sandboxes をデプロイして管理します。このページでは、インストール、グローバルフラグ、終了コード、実行時検出について扱います。各コマンドのリファレンスはサイドバーから開けます。[`lizard up`](/cli/up)、[`lizard service`](/cli/service)、[`lizard secrets`](/cli/secrets) などを参照してください。CLI でできることの概要については、[Lizard CLI のページ](https://lizard.build/cli) を参照してください。

> Lizard CLI **v4.0.34** を基準に書かれたリファレンスです。任意のコマンドのインストール済みバージョンの正確なスキーマを確認するには、`lizard <cmd> --help --json` を実行してください。

<span id="install--upgrade" />

## インストールとアップグレード

```bash
curl -fsSL https://lizard.build/install.sh | bash   # macOS and Linux
lizard --version
lizard upgrade            # update to the latest version
lizard upgrade --check    # check without installing
```

フラグについては [`lizard upgrade`](/cli/upgrade) を参照してください。

Windows では、PowerShell で `irm https://lizard.build/api/cli/install.ps1 | iex` を実行します。Node.js があれば、代わりに `npm install -g @lizard-build/cli` で npm からインストールすることもできます。

macOS と Linux では、インストールスクリプトで入れたバイナリは、バックグラウンドで自動更新もされます（最大で 6 時間に 1 回）。`CI` または `LIZARD_NO_UPDATE=1` が設定されているときは、更新の確認を行いません。Windows のバイナリは自動更新されないため、インストーラーをもう一度実行してください。npm でインストールした場合は npm で更新します。そのコマンドは `lizard upgrade` が表示します。

必ずグローバルにインストールした `lizard` バイナリを使ってください。`npx` は使わないでください。権限エラーの修正については [Quickstart](/getting-started#1-install-the-cli) を参照してください。

<span id="authentication" />

## 認証

```bash
lizard login                  # browser OAuth
lizard login --token liz_xxx  # API key auth
lizard logout
lizard whoami                 # current user, workspace, linked project
```

リファレンスページ: [`lizard login`](/cli/login)、[`lizard logout`](/cli/logout)、[`lizard whoami`](/cli/whoami)、およびワークスペースの一覧表示と作成を行う [`lizard workspace`](/cli/workspace)。

API キーは `liz_` で始まります。[`lizard keys create <name>`](/cli/keys) で作成できます。CI では、`login` を実行する代わりに、環境変数に `LIZARD_TOKEN`（または `LIZARD_API_KEY`）を設定してください。

<span id="global-flags" />

## グローバルフラグ

| フラグ | 説明 |
|------|-------------|
| `-V, --version` | CLI バージョンを表示 |
| `--json` | 機械可読な出力。`--help` と組み合わせると、コマンドのスキーマをダンプします |

ほとんどのコマンドは、リンク済みのものではなく特定のリソースを対象にするために、`-p, --project` と `-s, --service` も受け付けます。`init`、`link`、`project` は `-w, --workspace` も受け付けます。`lizard add` は常にリンク済みのプロジェクトを使います。

<span id="exit-codes" />

## 終了コード

| コード | 意味 | 実行すべき手順 |
|------|---------|------------|
| `0` | 成功 | 続行 |
| `1` | 一般的なエラー | メッセージを確認 |
| `2` | 認証 (401/403) | `lizard login` を実行 |
| `3` | 見つからない (404) | `lizard ps` / `lizard project list` で名前を確認 |
| `4` | タイムアウト (408/504) | 再試行 |
| `5` | ユーザーによってキャンセル | 停止 |

<span id="runtime-discovery" />

## 実行時検出

CLI のヘルプでコマンドの仕様を確認できます。完全なコマンドツリー、グローバルフラグ、終了コードを確認するには、次を実行します。

```bash
lizard --help --json
```

任意のコマンドまたはサブコマンドの正確な引数とオプションを確認するには、次を実行します。

```bash
lizard <cmd> --help --json
lizard <cmd> <sub> --help --json     # e.g. lizard service set --help --json
```

インストール済みバージョンの情報を返すため、フラグの構文はこの出力で確認してください。エージェントも、事前学習なしでこの情報を使って CLI を操作できます。 [Claude Code からのデプロイ](https://lizard.build/blog/deploy-from-claude-code) を参照してください。

<span id="configuration--state" />

## 設定と状態

- CLI は認証情報と現在のディレクトリのプロジェクトリンクを `~/.lizard/config.json` に保存します。
- [`lizard status`](/cli/status) は cwd の workspace/project/service リンクを表示します（認証不要）。[`lizard link`](/cli/link) はこのリンクを設定し、[`lizard unlink`](/cli/unlink) は削除し、[`lizard project`](/cli/project) はプロジェクトの一覧表示、作成、削除を行います。
- [`lizard config apply`](/cli/config) は `lizard-config.json` ファイルをプロジェクトに適用します（プレビューには `--dry-run` を使用）。
- [`lizard open`](/cli/open) はリンクされたプロジェクトをダッシュボードで開き、[`lizard docs`](/cli/docs) はこのドキュメントを開きます。

<span id="environment-variables" />

## 環境変数

| 変数 | 効果 |
|----------|--------|
| `LIZARD_TOKEN` | 保存されたログインの代わりに使う API キーまたはトークン |
| `LIZARD_API_KEY` | `LIZARD_TOKEN` と同じ |
| `LIZARD_API_URL` | API のベース URL（既定値 `https://lizard.build`） |
| `LIZARD_HOME` | CLI の状態を `~/.lizard` ではなく `$LIZARD_HOME/.lizard` に保存します |
| `LIZARD_NO_UPDATE` | バックグラウンドの自動更新を無効にします |
| `CI` | これもバックグラウンドの自動更新を無効にします |
| `LIZARD_SKILLS_DIR` | CLI に組み込まれたスキルの代わりに、このディレクトリからスキルを読み込みます |

<span id="sandbox-volumes" />

## Sandbox のボリューム

プロジェクト内の [Persistent Volumes](/sandboxes/volumes) を名前で管理します。完全なリファレンスは [`lizard volume`](/cli/volume) と [`lizard sandbox`](/cli/sandbox) を参照してください。

```bash
lizard volume create agent-workdir --size 10 --project proj_123
lizard volume list --project proj_123
lizard volume resize agent-workdir --size 20 --project proj_123
lizard sandbox create --volume agent-workdir --project proj_123
```

名前はプロジェクト内で一意で、小文字の英字、数字、ハイフンを使った64文字以内です。先頭と末尾は英字または数字にします。新規ボリュームは1〜50 GB の整数を受け付け、既定値は5です。CLI は作成前にサーバーの現在の制限を取得し、設定変更に従います。既存の大きなボリュームはサイズを維持します。

切断後に `lizard volume rm agent-workdir --project proj_123` を実行すると、ボリュームとデータを削除します。`volume list` は名前を表示し、`--json` は生成された ID も含めます。
