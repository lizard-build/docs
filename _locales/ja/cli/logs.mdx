# lizard logs

サービスのランタイムログをストリーミングします。直近 200 行を表示したあと、ライブ tail を続けます。`-s` を付けずにランタイムログを表示する場合、`logs` はリンク済みのサービスを使いません。TTY ではどのサービスを表示するか尋ね、それ以外ではプロジェクト内のすべてのサービスを表示します。`--build` と `--restarts` はリンク済みのサービスを使います。

<span id="usage" />

## 使い方

```bash
lizard logs [flags]
```

<span id="flags" />

## フラグ

| フラグ | 説明 |
|------|-------------|
| `--build` | 代わりにビルドログを表示 |
| `--tail <n>` | 直近 N 行（最大 1000）を表示して終了 |
| `-l, --level <level>` | このレベルのランタイムログのみ：`error`、`warn`、`info`、`debug` のいずれか |
| `--restarts [n]` | 直近 N 回の再起動を一覧表示（デフォルトは 20） |
| `--restart <id>` | 特定の再起動前後のログ（最新は `latest`） |
| `-s, --service <id>` | サービス |
| `-p, --project <id>` | プロジェクト名、スラッグ、または ID |

`--json` を使うと、`lizard logs` はストリームではありません。直近 200 行を返し（`--tail N` で上書き、最大 1000）、終了します。スナップショットやスクリプトで使用してください。ライブストリームになるのは `--json` がない場合だけです。

<span id="examples" />

## 例

<span id="tail-runtime-logs" />

### ランタイムログを tail する

```bash
lizard logs
```

<span id="tail-logs-for-a-specific-service" />

### 特定のサービスのログを tail する

```bash
lizard logs --service api
```

<span id="get-more-history" />

### より多くの履歴を取得する

```bash
lizard logs --tail 1000
```

<span id="filter-by-log-level" />

### ログレベルでフィルタする

```bash
lizard logs --level error
```

<span id="check-the-most-recent-build" />

### 最新のビルドを確認する

```bash
lizard logs --build
```

<span id="inspect-a-crash-or-restart" />

### クラッシュまたは再起動を調査する

```bash
lizard logs --restarts
lizard logs --restart latest
lizard logs --restart <id>
```
