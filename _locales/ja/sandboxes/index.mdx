Lizard (lizard.build) の Sandboxes は、AI エージェントがコードやタスクを実行するための、隔離された Linux マシンです。Sandboxes は Firecracker microVM として動作し、それぞれが独自のカーネルを持ちます。コードからは Lizard SDK（TypeScript 向けは `@lizard-build/sdk`、Python 向けは `lizard-sdk`）で作成するか、ターミナルで `lizard sandbox create` を実行します。その後、コマンドの実行、ファイルの読み書き、ポートの公開を行います。2026-10-12 のテストでは、sandbox の作成から最初の Python 出力までの時間の中央値は 228 ms でした。

<span id="when-to-use-sandboxes" />

## Sandboxes を使う場面

- **モデルが書いたコードを実行する。** 呼び出し間で Python の状態を保持する [コードインタープリター](/sandboxes/code-interpreter) を LLM に与えます。
- **コーディングエージェントに専用のマシンを与える。** [Claude Code](/sandboxes/guides/claude-code)、[OpenCode](/sandboxes/guides/opencode)、Codex を、ノート PC ではなく sandbox 内で実行します。認証情報は [`lizard agents`](/cli/agents) で接続し、プロンプトは [`lizard sandbox prompt`](/cli/sandbox#coding-agents) で送ります。
- **エージェントが作ったものをプレビューする。** 開発サーバーを起動し、[プライベートプレビュー URL](/sandboxes/preview-urls) から開きます。
- **複数の方針を同時に試す。** 実行中の sandbox をメモリとプロセスごと fork するか、1 つのスナップショットから多数のコピーを復元します。
- **ブラウザーを操作する。** `desktop` テンプレートはグラフィカルなデスクトップを実行し、エージェントはスクリーンショット、クリック、キー入力で操作します。

動き続ける必要がある Web サービスやワーカーには、代わりにアプリをデプロイしてください。[アプリ クイックスタート](/getting-started) を参照してください。

<span id="how-fast-does-a-sandbox-start" />

## sandbox の起動はどのくらい速いですか?

2026-10-12 のテストでは、sandbox の作成から最初の Python 出力までの時間の中央値は 228 ms、95 パーセンタイルは 310 ms でした。テストは Railway の US East リージョンから `us-east-1` に対して、`base` テンプレートと Small サイズで 300 回実行しました。E2B、Daytona、Modal に対する同じテストの結果は、[Sandboxes のページ](https://lizard.build/ja/#sandbox-benchmarks) に掲載しています。

## ランタイムとテンプレート

現在のカタログからテンプレートを選びます: `base`、`interpreter`、`codex`、`claude`、`opencode`、`pi`、`prime`、`desktop`、`desktop-camoufox`。利用可否はリージョンとプールの空き容量によって変わります。`interpreter` には Python、一般的なデータ処理ライブラリ、Node 22 が含まれます。`desktop` はグラフィカルなデスクトップを実行し、`sandbox.desktop` または `lizard sandbox desktop` で操作します。`desktop-camoufox` は `desktop` テンプレートに Camoufox を加えたものです。Camoufox はスクレイピング用の Firefox ビルドで、Playwright で操作します。今のところ `us-east-1` でだけ動作します。ツールのバージョンは sandbox 内で確認してください。公開 CLI には独自テンプレートのアップロード機能はありません。

Lizard Sandboxes は Firecracker microVM として動作し、それぞれが独自のカーネルを持ちます。エージェントにはタスクに必要な認証情報とアクセス権だけを渡してください。

<span id="lifecycle" />

## ライフサイクル

sandbox を作成してコマンドを実行し、終了後に `kill` を呼び出します。`connect` は既存の sandbox に接続するだけで状態を変えないため、一時停止中や停止済みの sandbox を再開しません。一時停止、再開、snapshot、restore は利用できます。[一時停止、再開、スナップショット](/sandboxes/quickstart#pause-and-resume)を参照してください。`fork` は、メモリとプロセスを含めて実行中の sandbox をコピーします。ボリュームが接続されている場合は 409 を返します。ファイル監視はまだ利用できません。`lizard sandbox ssh` は CLI の認証情報で対話型シェルを開きます。SSH プロトコルでのアクセスはできないため、SSH クライアント、`scp`、ポートフォワーディングは使えません。

```text
create -> running -> stopped (kill / expiration)
running -> paused -> running (pause / resume)
running -> new sandboxes (fork)
snapshot -> new sandbox (restore)
```

<span id="resources-and-timeouts" />

## リソースと有効期間

作成時にサイズを選びます: Small (2 vCPU / 4 GB)、Medium (4 vCPU / 8 GB、既定)、Large (8 vCPU / 16 GB)。トライアル中の sandbox はすべて Small で、US リージョンで動きます。[サイズと料金](/platform/limits#sandbox-sizes)を参照してください。必要に応じてリージョンを指定してください。カタログへの掲載は空き容量を保証しません。

SDK と CLI の既定の有効期間は 5 分です。API の直接呼び出しとダッシュボードでは、既定で期限を設けません。有効期間を明示してください。作成時の `timeoutMs: 0` は期限を無効にし、正の値は期限を設定します。`setTimeout` は 1000～2147483647 ミリ秒を受け付け、0 は指定できません。コマンド実行で期限は延長されません。アイドル時間のタイマーではありません。

<span id="storage-and-billing" />

## 保存と課金

sandbox の実行中はファイルとプロセスを維持します。一時停止ではディスク全体（`/workspace` 以外にインストールしたパッケージも含む）と、メモリ、実行中のプロセスが保持され、再開するとすべて戻ります。スナップショットも同じ内容を保持し、元の sandbox がなくなった後でも復元できます。停止（kill または期限切れ）すると sandbox のディスクは削除され、残るのは接続した Persistent Volumes の `/workspace` 上のファイルと、自分で作成したスナップショットだけです。ボリュームがなければ `/workspace` はそのディスクの一部です。各ボリュームは同時に 1 つの sandbox に接続し、単一ノードに保存します。ノード障害後も必要なファイルは別の場所へ書き出してください。

各サイズは固定の時間単価で、sandbox の実行中は秒単位で課金されます。アイドル時間も含みます。送信トラフィックはアカウントごとに直近 30 日間で [2 TB まで](/platform/limits#sandbox-egress)料金に含まれます。スナップショットから復元した sandbox は、復元元と同じサイズと料金で実行されます。一時停止が完了すると計算料金は止まります。Persistent Volumes はデータを保存している間、別途課金されます。タスクが終わったら sandbox を一時停止するか停止してください。すべてのリソースの料金は [請求ページ](/platform/billing) と [料金](https://lizard.build/pricing) に記載されています。
