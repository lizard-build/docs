Lizard SDK をインストールし、Settings → API keys で API キーを作成します。`LIZARD_API_KEY` に保存してください。各 sandbox にはプロジェクトが必要です。`projectId`（Python では `project_id`）、または `project` に ID、slug、名前を渡します。

## 作成オプション

| TypeScript | Python |
|---|---|
| `projectId / project` | `project_id / project` |
| `timeoutMs` | `timeout_ms` |
| `region` | `region` |
| `volumeName / volumeId` | `volume_name / volume_id` |
| `apiKey` | `api_key` |

現在のカタログからテンプレートを選びます。有効なテンプレートには `base`、`codex`、`interpreter` があり、利用可否はリージョンとプールの空き容量によって変わります。`interpreter` には Python と一般的なデータ処理ライブラリが含まれます。ツールのバージョンは sandbox 内で確認してください。公開 CLI には独自テンプレートのアップロード機能はありません。

SDK と CLI の既定の有効期間は 5 分です。API の直接呼び出しとダッシュボードでは、既定で期限を設けません。有効期間を明示してください。作成時の `timeoutMs: 0` は期限を無効にし、正の値は期限を設定します。`setTimeout` は 1000～2147483647 ミリ秒を受け付け、0 は指定できません。コマンド実行で期限は延長されません。アイドル時間のタイマーではありません。

## メソッド

| API (TypeScript) | メソッド |
|---|---|
| `Sandbox.create(template, options)` | カタログのテンプレートからプロジェクト内に作成。 |
| `Sandbox.connect(sandboxId)` | 既存の sandbox に接続。自動再開はしません。 |
| `Sandbox.list()` | アクセスできる Sandboxes を一覧表示。状態を確認してください。 |
| `sandbox.getInfo()` | 状態とメタデータを取得。 |
| `sandbox.process.exec(cmd)` | シェルコマンドを実行し、stdout、stderr、exitCode を返す。 |
| `sandbox.fs.write(path, data)` | テキストまたは UTF-8 を書き込み、親ディレクトリを作成。 |
| `sandbox.fs.read(path)` | UTF-8 テキストを読み取る。 |
| `sandbox.fs.readBytes(path)` | ファイルのバイトを読み取る。 |
| `sandbox.fs.list(path)` | ディレクトリの項目を一覧表示。 |
| `sandbox.fs.makeDir(path)` | ディレクトリと不足する親を作成。 |
| `sandbox.fs.remove(path)` | ファイルまたはディレクトリを削除。 |
| `sandbox.getHost(port)` | ポートの公開 HTTPS ホスト名を登録。 |
| `sandbox.setTimeout(ms)` | 残りの有効期間を設定。最小 1000 ミリ秒。 |
| `sandbox.kill()` | sandbox を停止し、ボリュームを切り離す。 |

Python: `exec_`, `get_info`, `get_host`, `set_timeout`, `sandbox_id`, `read_bytes`, `make_dir`.

## 現在のランタイムの制限

コマンドの結果には stdout、stderr、終了コードが含まれます。タイムアウトは 1～600 秒です。現在のランタイムは SDK の `envs`、`workdir`、`user` オプションを適用しません。ディレクトリと環境変数はシェルコマンド内で指定してください。作成時の `envs` と `metadata` も適用しません。

`fs.write` はテキストまたは有効な UTF-8 バイトを書き込み、`fs.read` はテキストを読み取ります。現在の書き込み API はバイナリアップロードに対応していません。バイナリのダウンロードには `fs.readBytes`（Python では `read_bytes`）を使います。

現在の sandbox の上限は 4 vCPU、4096 MiB RAM で固定です。作成時のオプションでは変更できません。必要に応じてリージョンを指定してください。カタログへの掲載は空き容量を保証しません。

## 未対応の API

sandbox を作成してコマンドを実行し、終了後に `kill` を呼び出します。`connect` は既存の sandbox に接続するもので、停止済みの sandbox を再開しません。一時停止、再開、fork、snapshot、restore、ファイル監視は現在 HTTP 501 を返します。現在のランタイムでは SSH を利用できません。

`CodeSandbox`、`runCode` / `run_code`、実行コンテキストのメソッドは SDK に残っていますが、公開テンプレートには必要な実行サーバーがありません。旧既定テンプレート `code-interpreter-v1` は利用できません。名前を `interpreter` に変えてもこの API は使えません。以下のように `Sandbox.create("interpreter")` とプロセスのコマンドを使ってください。

## 保存と課金

sandbox の実行中はファイルとプロセスを維持します。停止後、別の sandbox で使えるのは、接続した Persistent Volume の `/workspace` に保存したファイルだけです。ボリュームがなければ `/workspace` は一時領域です。各ボリュームは同時に 1 つの sandbox に接続し、単一ノードに保存します。ノード障害後も必要なファイルは別の場所へ書き出してください。

CPU、メモリ、ストレージ、送信トラフィックの実測使用量に応じて課金します。アイドル状態でもメモリやストレージを使う場合があります。タスク終了後は停止してください。データを保存している間はストレージ料金が続きます。
