## インストールと認証

Lizard SDK をインストールし、Settings → API keys で API キーを作成します。`LIZARD_API_KEY` に保存してください。各 sandbox にはプロジェクトが必要です。`projectId`（Python では `project_id`）、または `project` に ID、slug、名前を渡します。

```sh
npm install @lizard-build/sdk
pip install lizard-sdk
export LIZARD_API_KEY="<your-api-key>"
```

## コマンドの実行

```ts
import { Sandbox } from '@lizard-build/sdk';

const sandbox = await Sandbox.create('interpreter', {
  projectId: 'proj_123', timeoutMs: 300_000,
});
try {
  const result = await sandbox.process.exec("python -c 'print(2 ** 10)'");
  console.log(result.stdout, result.stderr, result.exitCode);
} finally {
  await sandbox.kill();
}
```

```python
from lizard import Sandbox

sandbox = Sandbox.create("interpreter", project_id="proj_123", timeout_ms=300_000)
try:
    result = sandbox.process.exec_("python -c 'print(2 ** 10)'")
    print(result.stdout, result.stderr, result.exit_code)
finally:
    sandbox.kill()
```

## ファイル

`fs.write` はテキストまたは有効な UTF-8 バイトを書き込み、`fs.read` はテキストを読み取ります。現在の書き込み API はバイナリアップロードに対応していません。バイナリのダウンロードには `fs.readBytes`（Python では `read_bytes`）を使います。

sandbox の実行中はファイルとプロセスを維持します。停止後、別の sandbox で使えるのは、接続した Persistent Volume の `/workspace` に保存したファイルだけです。ボリュームがなければ `/workspace` は一時領域です。各ボリュームは同時に 1 つの sandbox に接続し、単一ノードに保存します。ノード障害後も必要なファイルは別の場所へ書き出してください。

```ts
await sandbox.fs.write("/tmp/task.py", "print(42)\n");
const result = await sandbox.process.exec("python /tmp/task.py");
console.log(result.stdout);
```

## 公開ポート

`0.0.0.0` で待ち受けるサーバーを起動し、`getHost(port)` で公開 HTTPS ホスト名を登録します。ポートは公開されるため、必要に応じて認証を追加してください。sandbox を停止するとポートは応答しなくなります。

```ts
await sandbox.process.exec(
  "nohup python -m http.server 3000 --bind 0.0.0.0 --directory /tmp >/tmp/http.log 2>&1 </dev/null &",
);
const host = await sandbox.getHost(3000);
console.log(`https://${host}`);
```

## 実行中の sandbox への再接続

sandbox を作成してコマンドを実行し、終了後に `kill` を呼び出します。`connect` は既存の sandbox に接続するだけで状態を変えないため、一時停止中や停止済みの sandbox を再開しません。一時停止、再開、snapshot、restore は利用できます。[一時停止、再開、スナップショット](/sandboxes/quickstart#pause-and-resume)を参照してください。fork とファイル監視は HTTP 501 を返します。`lizard sandbox ssh` は CLI の認証情報で対話型シェルを開きます。SSH プロトコルでのアクセスはできないため、SSH クライアント、`scp`、ポートフォワーディングは使えません。

```ts
const connected = await Sandbox.connect(sandbox.sandboxId);
console.log(await connected.getInfo());
```

## 一時停止、再開、スナップショット

`pause()` は sandbox のメモリと実行中のプロセスを保存し、`/workspace` をそのノードに残したまま課金を止めます。`resume()` は同じ ID で sandbox を復元します。どちらも処理をキューに入れてすぐに戻るため、新しい状態になるまで待ってください。

```ts
await sandbox.pause();
await sandbox.waitForStatus('paused');
await sandbox.resume();
await sandbox.waitForStatus('running');
```

- 一時停止すると、開いているネットワーク接続は閉じられます。再開後、sandbox 内のプログラムは再接続する必要があります。
- プロセスを保存できない場合、sandbox は実行を続け、`waitForStatus` が理由付きのエラーを投げます。再開に失敗した場合、sandbox はチェックポイントを保持したまま一時停止状態に残ります。`resume()` を再度呼び出してください。
- 一時停止中は有効期間の期限が止まり、再開後に続きから進みます。一時停止中の sandbox は実行数の上限に数えられません。
- 一時停止中の sandbox は同じノードで再開します。そのノードが故障すると一時停止した状態は失われます。必要なファイルはエクスポートしてください。

スナップショットは、実行中の sandbox のメモリと `/workspace` のファイルを、プロジェクト専用のテンプレートとして保存します。restore するたびに、スナップショットと同じリージョンで新しい sandbox が起動します。取得前にクライアントとターミナルを閉じ、`/workspace` への書き込みを止めてください。接続中の Persistent Volumes は保存されません。

```ts
const saved = await sandbox.snapshot('my-app', { poolSize: 5 });
await Sandbox.waitForSnapshot(saved.id);
const copy = await Sandbox.restore(saved.id);
```

Lizard は既定で 5 つのコピーを待機させ (1〜10 で変更可能)、restore は待機中のコピーから起動します。待機中のコピーがないときは、プールが補充されるまで restore が HTTP 503 を返すことがあります。復元した sandbox は実測使用量で課金され、`size` は適用されません。CLI では `lizard sandbox pause <id>`、`lizard sandbox resume <id>`、`lizard sandbox snapshot <id> --name my-app`、`lizard sandbox restore <snapshot-id>` を使います。

## 現在のランタイムの制限

SDK と CLI の既定の有効期間は 5 分です。API の直接呼び出しとダッシュボードでは、既定で期限を設けません。有効期間を明示してください。作成時の `timeoutMs: 0` は期限を無効にし、正の値は期限を設定します。`setTimeout` は 1000～2147483647 ミリ秒を受け付け、0 は指定できません。コマンド実行で期限は延長されません。アイドル時間のタイマーではありません。

コマンドの結果には stdout、stderr、終了コードが含まれます。タイムアウトは 1～600 秒です。現在のランタイムは SDK の `envs`、`workdir`、`user` オプションを適用しません。ディレクトリと環境変数はシェルコマンド内で指定してください。作成時の `envs` と `metadata` も適用しません。
