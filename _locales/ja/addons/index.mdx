# マネージドアドオン

マネージドアドオンは、Lizard (lizard.build) がプロジェクト内で実行するデータベースとストレージで、**Managed Postgres**、**Managed Redis**、S3 互換の **Managed Object Storage** を使えます。`lizard add postgres redis s3` を実行すると、1 つのコマンドで 3 つすべてが作成されます。各アドオンは `DATABASE_URL` などの固定の環境変数セットを公開し、サービスは `${{postgres.DATABASE_URL}}` のような [参照](/concepts/architecture#cross-resource-references) で値を読み取ります。デプロイや再起動の後もデータを残したいアプリで使ってください。

<span id="provision-an-addon" />

## アドオンをプロビジョニングする

```bash
lizard add postgres            # one addon
lizard add postgres redis s3   # several at once
lizard add --list              # show available types
```

<span id="naming" />

## 命名

各種類の **最初の** アドオンには、その種類の名前が付きます。つまり、`${{postgres.DATABASE_URL}}` はそのまま使えます。同じ種類の追加アドオンには、`postgres-autumn-bear` のような生成された名前が付きます。削除したアドオンは 3 日間ゴミ箱で名前を保持するため、その期間内に追加した新しいアドオンには生成された名前が付きます。古いアドオンを復元するか、参照を新しい名前に向け直してください。

種類エイリアスへのフォールバックはありません。参照では、アドオンの **現在の** 名前を使う必要があります。アドオン名を変更すると古い名前への参照は壊れるため、名前の変更後に参照を更新してください:

```bash
lizard service rename main-db --service postgres   # addons rename through the same command
lizard secrets set DATABASE_URL='${{main-db.DATABASE_URL}}' --service api
```

<span id="consuming-an-addon" />

## アドオンを利用する

任意のサービスからアドオンの変数を参照できます。参照はデプロイ時に解決されるため、サービスは次回のデプロイ時にアドオンの現在の値を取り込みます:

```bash
lizard secrets set DATABASE_URL='${{postgres.DATABASE_URL}}' --service api
lizard redeploy --service api
```

Lizard は、実行中のすべての Postgres と Redis アドオンの `DATABASE_URL` と `REDIS_URL` を、プロジェクト内のすべてのサービスに最も低い優先順位で注入します。明示的な参照はこれらを上書きし、特定のアドオンを選びます。同じプロジェクト内のサービスでは、プライベート URL を使ってください:

```bash
lizard secrets set DATABASE_URL='${{postgres.DATABASE_PRIVATE_URL}}' --service api
```

[Secret scoping](/variables#scoping) を参照してください。

<span id="variables-by-type" />

## 種類ごとの変数

| アドオン | 変数 |
|-------|-----------|
| **postgres** | `DATABASE_URL`, `DATABASE_PRIVATE_URL`, `PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD`, `PGDATABASE`, `POSTGRES_USER`, `POSTGRES_DB`, `POSTGRES_PASSWORD` |
| **redis** | `REDIS_URL`, `REDIS_PRIVATE_URL` |
| **s3** | `S3_ENDPOINT`, `S3_DEFAULT_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_REGION` |

`DATABASE_URL` と `REDIS_URL` はパブリックエンドポイントを使います。`DATABASE_PRIVATE_URL` と `REDIS_PRIVATE_URL` は [プライベートネットワーク](/networking#private-networking) 上の `<name>.lizard.internal` を使い、同じプロジェクト内のサービスからのみ利用できます。

<span id="dashboard-browsers" />

## ダッシュボードブラウザー

[dashboard](/dashboard) には各アドオン用のデータブラウザーが用意されています。Postgres には SQL/テーブルエディター、Redis にはキーブラウザー、S3 にはバケット/オブジェクトブラウザーがあり、Lizard 内でデータを確認・編集できます。

<span id="storage" />

## ストレージ

Postgres と Redis のデータボリュームは **拡張のみ可能** です。次のコマンドで容量を増やします:

```bash
lizard scale --service postgres --storage 8192
```
