# App dashboard

The Lizard dashboard is the visual companion to Lizard CLI. Everything you do with `lizard …` is reflected here, plus things that are easier with a UI — streaming logs, charts, the data browsers, Sandboxes, and team/billing management.

If you would rather not open a terminal at all, let the agent run the commands and watch the result here — the route in [deploying an Antigravity app to production](https://lizard.build/blog/google-antigravity-how-to-deploy-your-app-to-production#deploy-from-the-antigravity-chat), where one prompt drives the deploy.

Open it from the CLI:

```bash
lizard open          # open the current project
lizard docs          # open this documentation
```

## What's in the dashboard

### Services

**Apps & databases** in the sidebar lists every service with its status badge, generated domain, and a quick path to logs, metrics, secrets, and settings. Create a service with **New Service**: from a GitHub repository, from a folder on your computer, or as a database (Managed Postgres, Managed Redis) or Managed Object Storage.

A service's **Settings** tab also has **Serverless**, which lets it sleep when idle ([`lizard sleep`](/cli/sleep)), and **Pause**, which stops it without deleting anything ([`lizard pause`](/cli/pause)).

### Deployments

Each service's **Overview** tab lists its deploys. Open one to see its status, trigger, source, build logs and restarts. This is the visual equivalent of `lizard events` + `lizard logs --build`.

### Logs

Live runtime and build log streaming with search and level filters — the UI counterpart to [`lizard logs`](/observability/logs).

### Metrics & Usage

CPU, memory, network, and disk charts per service, plus the **Usage** page, which breaks down consumption and cost across the project. Mirrors [`lizard metrics --cost`](/observability/metrics).

### Variables & Secrets

Manage service-scoped secrets in a service's **Secrets** tab and project-scoped ones in **Global Secrets**, with masked values and reference (`${{…}}`) support. See [Variables & Secrets](/variables).

### Domains

In a service's **Settings** tab, add custom domains, view DNS records, and track verification and TLS status. See [Networking](/networking).

### Data browsers

Each managed addon ships a data browser:

- **Managed Postgres** — a SQL/table editor to query and edit data.
- **Managed Redis** — a key/value browser.
- **Managed Object Storage** — a bucket and object browser with upload/download and bucket access settings.

### Sandboxes

The sidebar has **Sandboxes**, **Volumes** (Persistent Volumes), **Templates** and **Agents**. Create a sandbox with **New Sandbox** on the Sandboxes page; next to it, the dashboard shows the vCPU in use and your vCPU limit. During the trial, the dialog offers only the Small size in US regions. See [Sandboxes quickstart](/sandboxes/quickstart).

### GitHub integration

Connect GitHub from **New Service → GitHub Repository**. Once it is connected, **Configure access** under the repository list opens the GitHub App's settings, where you choose which repositories Lizard can build. A public repository also deploys from its pasted URL, without connecting. See [Deploy from GitHub](/deploy/github).

### Settings, team & billing

**Settings**, at the bottom of the sidebar, holds project and workspace settings, member invites and roles (**Team**), and your account settings. Open **Billing** from account settings or by clicking your plan at the top of the dashboard. It shows your plan, trial, usage in the current period, invoices and card. See [Billing](/platform/billing).

## CLI ↔ Dashboard

| Task | CLI | Dashboard view |
|------|-----|----------------|
| Deploy history | `lizard events` | Service → Overview |
| Stream logs | `lizard logs` | Logs |
| Resource charts | `lizard metrics` | Metrics / Usage |
| Manage secrets | `lizard secrets` | Secrets / Global Secrets |
| Custom domains | `lizard domain` | Service → Settings |
| Pause or resume a service | `lizard pause` / `lizard resume` | Service → Settings |
| Sleep when idle | `lizard sleep` | Service → Settings → Serverless |
| Query Managed Postgres, Managed Redis or Managed Object Storage | `lizard run --service <addon> -- <cmd>` | Data browsers |
| Invite teammates | — | Settings → Team |

Use whichever fits the moment — they operate on the same projects and services.
