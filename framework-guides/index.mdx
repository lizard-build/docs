# Framework guides

Deploy a framework app on Lizard from source. Choose your framework and rendering mode below, prepare its production build, then deploy with Lizard CLI or connect a GitHub repository. Server apps run a process; static sites serve the generated files through nginx.

## Choose your framework

These settings describe the standard project layouts in the linked guides. Commands assume npm for JavaScript projects. Custom output paths, adapters, and build overrides can change the result. To bring your own image instead, see [Deploy a Docker container from a Dockerfile](/deploy/dockerfile).

| Framework | Build | Runtime or output | Service port |
|---|---|---|---|
| [Next.js](/framework-guides/nextjs) | `npm run build` | `next start` through the start script | `3000` |
| [Next.js static export](/framework-guides/nextjs/static-export) | `npm run build` | `out/` through a Dockerfile | `80` |
| [React with Vite](/framework-guides/react) | `npm run build` | `dist/` | `80` |
| [Vue with Vite](/framework-guides/vue) | `npm run build` | `dist/` | `80` |
| [Astro](/framework-guides/astro) | `npm run build` | `dist/`, or the standalone Node adapter | `80` static; `3000` server |
| [Nuxt](/framework-guides/nuxt) | `npm run build` | `node .output/server/index.mjs` | `3000` |
| [SvelteKit](/framework-guides/sveltekit) | `npm run build` | `node build` with adapter-node | `3000` |
| [Node.js (Express)](/framework-guides/nodejs) | `build` script, if any | `start` script | `3000` |
| [FastAPI](/framework-guides/fastapi) | Install Python dependencies | `uvicorn main:app --host 0.0.0.0 --port 8000` | `8000` |
| [Django](/framework-guides/django) | Install Python dependencies | Gunicorn with your WSGI module | `8000` |
| [Streamlit](/framework-guides/streamlit) | Install Python dependencies | `streamlit run app.py` from a Procfile | `8501` |
| [Go](/framework-guides/go) | `go build` to a static binary | `/app/server` | `8080` |
| [Ruby on Rails](/framework-guides/rails) | The Dockerfile Rails generates | Thruster and Puma, or Puma alone | `8080` on Rails 8; `3000` on Rails 7.1 and 7.2 |
| [Docusaurus](/framework-guides/docusaurus) | `npm run build` | `build/` | `80` |
| [VitePress](/framework-guides/vitepress) | `npm run docs:build` | `docs/.vitepress/dist/` in this guide | `80` |
| [Hugo](/framework-guides/hugo) | `hugo --minify` | `public/` | `80` |

## Prepare the project

Run commands from the application directory. Commit source files, configuration, and the package lockfile. Exclude `.env`, local dependencies, and local build output from uploads. Node projects can select the Node major version in `.nvmrc`; the current default is `22`. This selects a major version, not an exact patch release. [Runtime versions](/deploy/runtime-versions) lists the version files for Node.js, Python, Go and Ruby.

Install Lizard CLI and sign in once:

```bash
curl -fsSL https://lizard.build/install.sh | bash
lizard login
```

On Windows, run `irm https://lizard.build/api/cli/install.ps1 | iex` in PowerShell. A new account starts on no plan: until you start the 7-day Pro trial (card required), `lizard add` and `lizard up` return a Checkout link. `lizard billing start` opens it.

Each guide uses a new project and a service named `web` or `api`. Create that service with `lizard add --service web` (or `api`) before the first `lizard up --service` call. `up --service` selects an existing service; it does not create a missing named service. For an existing project, check `lizard status --json` and `lizard ps --json` before deploying. The port must match the process inside the container, which must listen on `0.0.0.0`.

Lizard CLI 0.3.95 and later exclude macOS archive metadata during uploads. No `COPYFILE_DISABLE` setting is needed. Update older CLI versions before following these guides.

## Choose GitHub or local source

The guide commands use `lizard up` to upload the current folder. That command changes an existing service to upload source. To keep git push to deploy, [connect GitHub](/deploy/github) instead and use the guide's build settings in the repository. Configure the service port from the table: nginx for a Vite, Astro, SvelteKit, Docusaurus or VitePress build listens on the port you set, or on `3000` if you set none.

## Keep build settings consistent

These guides use lizardpack detection unless they call for a Dockerfile. Existing `buildCommand` or `startCommand` overrides take precedence over detection and the repository Dockerfile; a set `dockerfilePath` takes precedence over both. Check [build decision order](/concepts/build-pipeline#build-decision-order) before switching build methods. Set scripts in `package.json` when a guide tells you to; adding a CLI override is a different build path.

## Check a release

Read build logs, runtime logs, and the active URL. Test an inner route, a missing route, and any API or form action. A process that opens its port can still serve a broken page. For generated sites, use [static routes and 404s](/framework-guides/static-routing) to avoid returning the home page with HTTP 200 for every unknown URL.

Check shared caches, persistent local files and framework versions separately from runtime support. See [limits](/platform/limits), [storage and recovery](/platform/storage-and-recovery), and [known issues](/platform/known-issues) when your app relies on those features.

See [tested versions and cloud results](/framework-guides/validation) for the September 9, 2026 deployment checks and their limits.
