# Framework guide test results

On 2026-09-07, we tested 16 recipes across 11 frameworks through real `lizard up` deployments in an isolated test project. Each final recipe passed its build, runtime, and public HTTPS checks. These results apply to the versions and small test apps below.

## Routing recheck on 2026-09-08

We rebuilt Astro static, SvelteKit adapter-static, Docusaurus, Hugo, and both VitePress layouts without a Dockerfile, nginx config, or service command overrides. All 30 public HTTPS checks passed: home pages, inner pages, and real assets returned 200; missing pages and JavaScript paths returned 404. VitePress returned the inner page's content at its clean URL.

These results supersede the static-routing workaround described in the original run below. Existing images need a rebuild to receive the updated rules. The [source examples](https://github.com/lizard-build/docs/tree/main/_examples) include small Docusaurus, VitePress, Hugo, and SvelteKit projects. They do not establish support for every theme, plugin, or adapter configuration.

## What we checked

- Installed dependencies and built the apps in Linux containers, then uploaded source with `lizard up` and read cloud build and runtime logs.
- Requested the public home page, an inner route, a real asset, a missing page, and a missing JavaScript path. Server recipes also returned request-time API data.
- Opened inner routes directly in a browser and reloaded them. React interaction and Vue Router navigation worked. Next.js Server Actions and SvelteKit form responses returned the submitted value; SvelteKit rejected a form from an untrusted origin.
- Checked generated JavaScript and CSS responses. Docusaurus canonical URLs and its sitemap used the public host. Hugo's sitemap used the host after rebuilding its `baseURL`.
- Ran Django migrations against Managed Postgres (PostgreSQL 18.4), wrote and read a test row, served collected static files, accepted a valid CSRF form, and rejected a form without its token.

The test project used a separate service for each recipe, with test-specific names. Build and start overrides stayed unset. The guides' Dockerfiles and framework configs selected the documented runtime.

## Problems found and addressed on 2026-09-07

The initial commands omitted service creation. The guides now call `lizard add --service` before the first named upload. The Nuxt static recipe now uses `nuxt generate` and a prerender config without the Node server preset.

Default static nginx builds returned the home page with status 200 for missing URLs. VitePress clean URLs also needed `.html` lookup. The complete Dockerfile and nginx setup in [static routes and 404s](/framework-guides/static-routing) passed the cloud checks. This workaround does not change the default builder for existing services.

The cloud run also found macOS archive metadata and failed-build exit-code defects in Lizard CLI 0.3.92. CLI fixes are under review. A service port change could leave its public URL returning 503 even when the process was ready. See [known issues](/platform/known-issues) before relying on those paths.

## Limits of these results

These checks cover source uploads and the documented modes. They do not establish support for every plugin, custom adapter output, theme dependency, framework version, GitHub deployment path, database recovery procedure, or multiple-replica workload. Django’s `check --deploy` returned four HTTP security warnings in the small test app; this is not a complete security setup. They do not measure SEO rankings or AI citations. Recheck your app's own routes and data operations before release.
