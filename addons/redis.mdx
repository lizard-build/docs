# Managed Redis

Managed Redis on Lizard is a Redis server for caching, queues, rate limiting and pub/sub. New instances run Redis 8 by default. Add one with `lizard add redis`; your services read `REDIS_PRIVATE_URL` or `REDIS_URL` through a reference such as `${{redis.REDIS_PRIVATE_URL}}`. It has no eviction policy and no append-only file, so keep only data you can rebuild in it. For an overview and prices, see the [Managed Redis page](https://lizard.build/redis).

## Provision

```bash
lizard add redis
```

The first Redis addon is named `redis`, so `${{redis.REDIS_URL}}` works immediately.

## Environment variables

| Variable | Description |
|----------|-------------|
| `REDIS_URL` | Full connection string over the public endpoint (`redis://…`) |
| `REDIS_PRIVATE_URL` | Connection string over the project's private network (`<name>.lizard.internal:6379`) |

Both strings use the form `redis://default:<password>@<host>:<port>`. The private one works only from services in the same project and the same region; see [private networking](/networking#private-networking). A service in another region must use `REDIS_URL`; to give it the private URL, create Redis in its region with `lizard add redis --region <code>`. `<name>` is the name the addon had when it got its private address, `redis` for the first one; a rename does not change it.

## Connect a service

```bash
lizard secrets set REDIS_URL='${{redis.REDIS_PRIVATE_URL}}' --service api
lizard redeploy --service api
```

The reference resolves at deploy time; consumers pick up the addon's current values on their next deploy. Use `REDIS_URL` for clients outside the project or in another region. Every service in the project also gets the addon's public `REDIS_URL` at the lowest precedence; an explicit reference overrides it.

## Does Managed Redis keep data?

Managed Redis can lose recent writes. It has no eviction policy and no append-only file. If it runs out of memory, the instance restarts and may lose those writes. Use it for data you can rebuild, and keep data you cannot lose in [Managed Postgres](/addons/postgres).

## Common uses

- **Cache**: store computed results keyed by request.
- **Queue / worker**: pair Redis with a [worker-mode service](/deploy/workers) that consumes jobs. [Run a queue consumer](/deploy/workers#run-a-queue-consumer) walks through the redis-worker example.
- **Rate limiting / sessions**: fast shared state across [replicas](/deploy/scaling).

```bash
# A worker that drains a Redis queue
lizard add -r your-org/worker -n jobs --no-deploy
lizard service set jobs --set containerPort=0
lizard secrets set REDIS_URL='${{redis.REDIS_PRIVATE_URL}}' --service jobs
lizard redeploy --service jobs
```

## Browse keys

Open the **Redis browser** in the dashboard (`lizard open`) to inspect keys and values. For local access with the addon's connection values:

```bash
lizard run --service redis -- sh -c 'exec redis-cli -u "$REDIS_URL"'
```

## Grow storage

```bash
lizard scale --service redis --storage 4096
```

Storage is grow-only. Sizes are 512, 1024, 2048, 4096, 8192 or 16384 MB. Growing the volume stops Redis while Lizard copies its data to a bigger volume, then starts it again, so expect a short outage. Resume a paused instance with [`lizard resume`](/cli/pause) before you resize it.
