# Regions

Lizard runs services, addons and Sandboxes in regions such as US East (`us-east-1`) and EU West (`eu-west-lim-a`). You pick the region when you create a resource; if you don't, a new service or addon goes to `us-east-1`. Put a service and its databases in the same region to keep latency low. [`lizard regions`](/cli/regions) lists the regions open to your account.

## List regions

```bash
lizard regions
lizard regions --json
```

## Choose a region

Pass `--region <code>` when creating a service or addon:

```bash
lizard add -r your-org/your-app --region <code>
lizard add postgres --region <code>
lizard up --region <code>          # new services only
```

Projects have no default region. Without `--region`, `lizard up` and `lizard add` create new services and addons in `us-east-1`, as do the API, [Lizard MCP](/agents#lizard-mcp) and the dashboard. Pass `--region` to choose another.

> **Co-locate stateful resources.** Put a service and the addons it talks to (Managed Postgres, Managed Redis, Managed Object Storage) in the **same region** to keep latency low and avoid cross-region data charges. [Private networking](/networking#private-networking) also works only inside one region.

## Generated domains

Each service gets a generated domain with automatic TLS: `<name>-<suffix>.onlizard.com` for new services, while older services keep `<words>.<region>.onlizard.com`. [Managed Object Storage](/addons/storage) uses a gateway host per region: `s3-us-east-1.onlizard.com` for `us-east-1` and `s3-eu-west-1.onlizard.com` for `eu-west-lim-a`. To attach your own hostname, see [Networking](/networking).
