# Deploy

Deploy a service from GitHub, a local folder or a Dockerfile, then set its runtime, region and resources.

To compare hosts, the blog explains how [container as a service](https://lizard.build/blog/container-as-a-service) platforms differ and how to estimate their cost.

## In this section

- [Deploy from GitHub](/deploy/github): connect a repo so pushes to the tracked branch auto-redeploy.
- [Deploy from Local Code](/deploy/upload): ship the current directory with `lizard up`, no Git required.
- [Deploy from a Dockerfile](/deploy/dockerfile): build and host your own Docker container, or wrap a public image.
- [Runtime versions](/deploy/runtime-versions): set the Node.js, Python, Go or Ruby version with `.nvmrc`, `.python-version`, `go.mod` or `.ruby-version`.
- [Background Workers](/deploy/workers): run queue consumers, polling loops and bots such as a [Discord bot](/guides/discord-bot) with `containerPort=0`.
- [Scaling](/deploy/scaling): adjust replicas, resources, and storage.
- [Regions](/deploy/regions): where your services run.
- [Troubleshooting](/deploy/troubleshooting/incomplete-dockerfile): fixes for the most common build and deploy problems.
